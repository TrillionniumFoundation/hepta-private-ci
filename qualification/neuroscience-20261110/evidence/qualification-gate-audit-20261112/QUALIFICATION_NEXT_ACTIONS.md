## 原 owner 最小可实施补丁
这不是只有“权限尚缺”的问题：固定 EBE 源码存在具体未接通的生产路径。authority_host_learning_resident_stages.rs::require_stage 与 cell_q24_candidate_stage_owners.rs::execute_stage 同时拒绝非 TrainingNoUpdate 的 Selection/NextUse。prepare_proposal 仍拒绝独立 adoption；该拒绝不在本次最小补丁中解除。
1. 首个补丁只接真实负比较后的 S：从原 opaque Training + Evaluation 回执构造 OriginalCircuitEvaluatedRetentionContextV1::from_original_evaluation；该构造严格要求四 cut、真实 Evaluation::NoUpdate、changed candidate 和完整独立 T/B 签名。复用 create_evaluated 和 attest_original_evaluated_remote_selection 后端，以及固定 purpose 的 evaluated CURRENT read。新增初始原连接／一次 Execute／Readback adapter 和对应 concrete continuation；不改 legacy SelectionCommandContext 的三 cut TNU 认证。
2. C/Version 后续补丁必须单列：现 OriginalVersionCut.training 只接受旧 OriginalCircuitRetainedPublicationContextV1；旧 NextUseCommandContext 只接受四 cut TNU。因此不能把已有五 cut evaluated read 丢入旧 readiness/command。应复用 prepare_original_circuit_evaluated_retention_v1、publish_and_retain_original_evidence 和 evaluated NextUse receipt，加入明确独立 profile，保留原 T/B clients 到最后 CURRENT 读取；原不同 C/FinalUse 的执行与观察分开。
3. 已有原 typed 后端不是新的权限来源：OriginalCircuitEvaluatedSelectionReadbackOwnerV1 只消费一个已完成真实 Selector owner，不能执行新 S；OriginalCircuitEvaluatedLearningReadContextV1 的两个 constructor 永久衰减为只读；NextUse attestation 只证明已经完成的 C，不启动 C。
4. 真执行需原 host 初始交付：连接的 UnixStream、真实 peer uid/pid/boot/process_start_ticks、held pidfd、原 timeout/lifetime；Selector/Observer 的原 File+AnchorWitnessStore+TrustedLearningSignerV1+匹配 SigningKey；原 Cell/Circuit Source/CURRENT/Artifact owners；已由 from_root_stream 绑定的 AgentdUnixFinalUseGrantProvider。列出这些缺件不阻止先实现 adapter 和真实 socket 反例测试，也不授权生成替代 owner。
5. 首个补丁验收：正确四 cut 独立 NoUpdate 能进入原 S 后端；研究报告的字符串 NoUpdate、缺 B、错误 candidate／trust／模型／前驱、Qualified、TNU 冒 evaluated、跨 purpose、换 peer/boot、过期、恢复 NewWork、pending/lost ACK 再 Execute 全部拒绝。S 前后真实 T/B/CURRENT 读取仍存在；原 caller/format/source 与 native tests 要在新 exact tree 上实跑后才能报告通过。本审计没有执行这些测试。
