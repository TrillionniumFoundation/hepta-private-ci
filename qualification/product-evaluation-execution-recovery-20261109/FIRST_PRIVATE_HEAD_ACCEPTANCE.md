# First real private-head learning experiment

## Claim under test

One bounded ordinary-task family, one frozen semantic base and one private
linear or low-rank head. Does an actual authorized update improve future task
outcomes while preserving existing ability and paying its complete declared
cost? A functioning Adopt/NoUpdate transaction is a protocol result; it is not
itself evidence of useful learning.

Select the task family from existing ordinary tasks with verifiable original
outcome records. Freeze that one family and its utility before final evidence
collection. Generated fixtures, relabeled fixtures, the four exposed scoped-V2
questions or repeatedly queried development panels cannot become an independent
final cohort by assigning new IDs.

No new biological rule is needed. Freeze the semantic base, head structure,
ordinary optimizer, uniform replay, candidate budget and selection policy. Keep
serving weights immutable; submit separate candidates to the original adoption
owner.

Resource-query, allocation, actual computation, artifact retrieval and resource
release are separate receipts. Record the device actually used; an allocation
request or unconfirmed GPU is not a completed training run.

## Predeclare the decision

Fix the utility estimand, minimum useful gain, retention margin, primary
comparison, independent sampling unit, multiplicity, analysis and stop rules
before final data release. Choose a feasible sample size from development-only
evidence. EVOLVE-1's synthetic threshold and scoped-V2's exposed-question result
are not production effect sizes.

Evaluate candidate and retained models on the same registered task cohort where
pairing is valid. Retain failures, cancellations and UNKNOWN in the denominator,
plus all abandoned candidates and tuning effort. Keep confidence/uncertainty
bounds distinct from missing-label bounds.

Adopt requires both the scientific decision rule and existing authority gates.
NoUpdate is a completed control path but contributes zero useful improvements.
Inconclusive evidence preserves the original serving generation.

## Recovery matrix

| Interruption point | Required recovery | Remaining boundary |
| --- | --- | --- |
| Before durable execution claim | Original store determines whether a claim exists | A replacement empty journal cannot prove absence |
| After claim, before consumption | Pending survives; no automatic dispatch | Needs original-owner reconciliation |
| After consumption, before provider result | Same consumption/Pending preserved; no second release | UNKNOWN cannot be relabeled as failure for blind retry |
| After estimator, before attestation/completion | Original evaluator reconciles actual result/signing state | Current execution-recovery cut does not auto-complete Pending |
| After signed completion, before acknowledgement | Fresh process authenticates original bytes under current trust/fence | No provider, estimator or signer rerun |
| Before/after adoption acknowledgement | Original selection owner reconciles exact predecessor/epoch/generation | Execution recovery does not establish adoption recovery |
| After publication, before next task | Restarted consumer loads exact admitted generation and completes different task | Requires actual generation/bootstrap and NextUse assembly |
| Root session restart | New legitimate session recovers the same scoped operation through original owners | A test process restart alone does not close this gate |

Minima must come from the admitted recovery domain. Files beside the candidate
journal, written by the same test process, do not demonstrate independent
custody. Separately named keys generated by that process do not demonstrate an
independent evaluator.

## Later method and improver comparisons

After the one-head path is stable, compare eligibility traces, local errors,
slow feedback and uncertainty-dependent plasticity one at a time against the
fixed optimizer/uniform-replay baseline. Time-dependent traces bind actual
monotonic elapsed time, feedback identity and generation; checkpoints prevent
duplicate feedback application.

Improver claims require the S0/I0, S0/I1, S1/I0, S1/I1 design, independently formed
improvers and fresh task families absent from I1 discovery. Count qualified
improvements or complete cost per qualified improvement under matched resources.
Candidate counts, parameter changes and self-modification counts are insufficient.
