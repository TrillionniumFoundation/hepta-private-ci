## What this source connects

The materializer now obtains a bounded HQ24T002 training batch from sealed original
task observations, the committed Cell decision and authenticated Terminal records
in the original LedgerWriter. It binds all RunStartSnapshot fields, retains the
original Dataset/source capability through native fitting and durable recovery,
and checks authorization, withdrawal and relevant ledger frontiers again.
Historical artifact-set identity and the Cell bundle remain separate.

The original Ledger sorts candidate IDs. The adapter therefore compares the
complete sorted vector, without deduplicating it; the signed source still binds
the original policy order and weights. The Dataset tests cover missing, extra
and duplicate candidates, distinguish the mandatory-abstain Ledger refusal from
a missing nonselected candidate, and create multiple runs from one original
objective before authenticated ingress. Only original Linux capture capabilities
are platform-gated.

The merged local-decision path retains the original Selector's signed
LocalDecisionV2 and HEPLCP04 checkpoint/readback. It persists the local choice
before requiring actual Selection and NextUse. Local Defer/Retain stays distinct
from evaluator/training NoUpdate. The historical use exporter explicitly rejects
LocalDecisionV2 as a non-use record; only committed NextUse or RetainedModelNextUse
can be exported, subject to the original journal receipt/current checks.
The export still grants no authority.

These are counts for this work, not claims about all historical project training.
Test signing owners, role custody and CURRENT setup remain engineering fixtures.

The production launcher still refuses a retained learning checkpoint without
actual learning stage owners. The existing handoff carries checkpoint/session/
identity/scope; it does not deliver the actual task/Dataset writer, Generator and
Evaluator signing owners, independent holdout execution, Model file/witness
reservation or ordinary adopted C owner. Relevant product callers remain absent.

The next connected implementation unit is actual Root reservation and
purpose-specific handoff **together with** concrete stage-owner installation before
production launch, Model dispatch/recovery and its original B/C capabilities.
The existing scoped update rule commits the materialized Dataset batch, so the
Dataset must already be frozen before that profile is registered. Future-task
Dataset enrollment needs an explicit original Root protocol; a placeholder,
unscoped fallback or rewritten frozen rule cannot fill this gap.

The [Model enrollment ADR](../../codex-rs/hepta-agentd/Q24_MODEL_PROPOSAL_ENROLLMENT_ADR.md)
documents this proposed implementation and its missing original inputs. The ADR
adds no route, capability or acceptance.

## Chain interoperability boundary

[Trillionnium-Chain PR #909](https://github.com/TrillionniumFoundation/Trillionnium-Chain/pull/909)
adds HEPLCP04/tag-9 structural readback and preserves explicit local defer/retain.
Its native vectors are pinned to Hepta `afd2c91b3b9ef75ab9a174e3af772ad322118f7a`.
The corresponding codec, artifact coordinator, types and digest blobs are byte
identical in 54de; this is a source comparison, not a native replay from 54de.

A parsed observation, ACK or another run by the same actor is not independent C
adoption. Chain commitments do not replace local version/resource/execute authority.
