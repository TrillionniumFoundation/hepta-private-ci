# Hepta weight-space next-stage qualification

This source-only research snapshot accompanies Runtime semantic-source adapter
[Draft PR #143](https://github.com/TrillionniumFoundation/hepta-runtime/pull/143).
It contains three separable reviews. It changes no production registration,
training worker, runtime pointer, optimizer, service, or trading state.

## Results and review order

1. **evaluation/**: a bounded, standard-library provenance and finite net-value
   decision adapter. Forty synthetic tests passed. Version 2 supports retained
   quality with conservative future cost savings; unknown cost/horizon/conversion
   keeps the original. It does not prove globally optimal neural weights or
   externally independent label custody.
2. **hcsn/**: fixed-law finite-horizon transport compilation preserving complete
   state and pending flux. Six existing trained checkpoints passed a frozen
   tolerance contract; complete-call wall totals were 16.08, 19.41 and 43.55 times
   faster in three prescribed input groups. This is not bitwise equivalence,
   quality improvement, reduced full-state memory, or future cost bounds.
3. **neuron/**: causal interventions and joint representation/readout editing of
   five existing 85→48→4 models. The declared-law BQ rescue passed both primary
   utility gates. The ordinary DEV-selected weight program failed both utility
   and both calibration confirmation gates. KEEP_ORIGINAL_AND_STOP is retained.

The complete science claims and assumptions are in each directory's README.
Oracle BQ and the own-law analytic planner are inference interventions, not
ordinary parameter edits. Q/S/J_own interpretations are exploratory; they do
not identify a unique defective weight or transfer to a live trading model.

## Confirmation and retained failures

The Neuron study uses 40 development worlds, then 160 new confirmation worlds
after all selections are sealed. Statistical units are five independently
trained fits, not world/state counts. Eight prespecified Bonferroni comparisons
use df=4, with explicit Student-t assumptions. The known history now contains
3,456 schedules.

The first scientific attempt failed on a file-path lookup before any development
score; its five candidate families were retained. An explicit technical
revision authenticated and reused those exact candidates, excluded the unused
40 generated worlds, and used fresh development and confirmation entropy. No
solver/training was repeated and no scientific threshold was relaxed. Both
scientific children together used 137.826709 CPU seconds within the original
300-second budget.

The original frozen reader is also retained as failed. A separately named
reader-only erratum corrects summation order for exact action tie-breaking and
preserves every alternate Python-sum disagreement. Scientific sources, model
parameters, data, results and the eight primary gates are unchanged. The corrected
record review passes on 200 complete DAGs, 91,312 states and 45 models. All known
reader/diagnostic cost remains below the original eight-second budget.

## Execution boundary

Only `evaluation/` is self-contained. From that directory:

```sh
python -m unittest test_evaluation test_specialization -v
python demo.py
python demo_specialization.py
```

The dedicated workflow runs only those synthetic standard-library gates. It
does not fetch model captures, execute HCSN/Neuron, generate worlds, or launch
training. The numerical studies require the matching preserved input bundle and
previous research modules; their original source/protocol identities remain
separate from this source-only publication.

Raw model payloads, actual host captures, candidate identifiers, outcome DAGs,
private receipts and generated worlds are not published here. Their recorded
hashes, original failures and numerical arrays are retained for the research
owner. A source release is not independent-evaluation or production admission.
