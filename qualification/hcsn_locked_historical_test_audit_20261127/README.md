# Locked historical test audit

This lane performs one fixed final evaluation after the existing training,
development and retention selectors have finished. It is named
`LOCKED_HISTORICAL_TEST_AUDIT`. It is **not a fresh holdout**. The original
research protocol explicitly states that these actors and frozen scores were
already used in prior repository research. Earlier phases of the wider study
also extracted all four arrays and used historical test outcomes. The narrow
new fact is that the sender40, boundary8, transfer and explicit repair editing
lanes did not extract this test array or use it for their candidate selection.

The original benchmark selects training checkpoints by development accuracy
and Brier and seals them before its retain/test evaluation. That proves the
epoch-selection implementation. It does not establish that earlier choice of
the centered architecture, configuration or three parent checkpoints was
uninformed by already known historical results.

## Fixed choices and interpretation

The complete original `static_support.choose` function is reused without
changing its development-correct, Brier, realized-norm and KEEP-priority keys.
The lock was created before any new test access. All three parents select
`KEEP` for their analytic policy and `BP_TASK_16` for BP. The exact checkpoint
and actual40F32 byte hashes are in `SELECTED_MODELS.json`.

There are six unique evaluations:47 KEEP/BP16,83 KEEP/BP16,137 KEEP/BP16.
The original maximum remains7F/42ticks/336paired queries, but the completed
locked sequence must be6F/36ticks/288paired queries. Each KEEP is evaluated
once and its returned scores are reused for the analytic policy's KEEP choice.
No rejected analytic candidate is newly tested. A zero METHOD-minus-KEEP
contrast is therefore a policy fallback, not evidence that an edited model
improved or generalized.

Seed47 is the sender-role drift-target method. Seeds83/137 are the coupled
boundary-program method. They are not pooled as one analytic algorithm. The
two unavailable COPY slots per target, seed47 boundary inverse abstention,
seed83 multiple-root abstention, and original seed137 implementation failure
remain in the source inventory. The independent137 repair does not erase the
failed attempt or refund its fit.

`SOURCE137_INDEPENDENT_AUDIT.json` is the root's immutable raw tensor, metric
and call-count audit. `SOURCE137_SELECTOR_CORRECTION.json` supplements it: an
auxiliary independent selector used a wrong key, and a pure saved-row check
corrected that claim while preserving all actual experiment choices. This lane
uses the original qualified selector, not the superseded auxiliary key.

## Order of operations

The workflow accepts only a single new branch push, run_number1/run_attempt1,
and the exact frozen parent commit. It checks the added path set and all source
bytes before fetching the three exact predecessor artifacts. The official API
helper verifies artifact ID, run ID, head commit, name and whole ZIP hash; the
ephemeral read-only token is never forwarded to artifact storage.

The preparer verifies the full artifact member allowlists, re-evaluates the
already frozen selector against original train/dev/retain rows, compares the
complete serialized selection lock, and fsyncs its readback. Only then does it
extract `data/test.npz` from the exact public payload. It does not download
`lowlevel_results.json`, read historical test metrics, extract train/dev/retain
arrays, or execute the submitted payload script.

The original19F32 train mean/std/scale bytes supply normalization. Each of the
three parents runs in a fresh process using the original Hybrid/SmallHCSN body
and unchanged source-bound Adapter. Each selected checkpoint is reloaded from
its complete actual PT file; immutable registered tensor/buffer values and
readout aliases are checked. The scope claim concerns these actual values and
aliases, not equivalence of PT ZIP container metadata. All six original body
ticks run, with the original2e-9 physical checks. `compile_trace=False`; no
additional recurrent-linear trace reconstruction occurs.

There are no new parameter backwards, optimizer updates, shared fits or WSP
scalar target inversions. The original model's internal QVI, matrix exponential
and resolvent work still executes inside model initialization and each full
forward, and its time is charged. “Zero new roots” does not deny that internal
model work.

Each selected case runs once. A failure is preserved; no replacement dose,
parent, checkpoint or historical test score is chosen. An integrity failure or
unknown process/resource state stops further parent launches. Started counts
and returned valid forwards are separate. Incomplete counts are marked as
lower bounds. A case failure cannot be relabeled a successful scientific
abstention.

## Statistics and cost

Accuracy, binary Brier and cross entropy use actual F32 scores and the original
F64 probability/metric recipe. Six fixed actor groups are the paired units;
reciprocal queries are not treated as independent samples. Per-actor means use
eight queries. Same-family pooling first averages the fixed parent differences
within each actor, then gives the six actors equal weight. Missing parents
make a predeclared contrast unavailable rather than reducing its denominator.

Thirteen contrasts are fixed:three per parent, three pooled83/137 boundary
contrasts, and the three-parent BP-minus-KEEP contrast. Exploratory percentile
intervals enumerate all462 six-actor multiplicity patterns, representing46656
ordered draws with exact integer weights. No random search, confirmatory
p-value, coverage guarantee or fresh-population claim is made. The independent
stdlib statistics module has already passed its eight synthetic controls,
including an independent enumeration of all ordered draws; those controls are
not repeated in this evaluation.

One private hosted cgroup caps memory at1GiB, CPU at one core and tasks at64.
Each parent has30CPU/60wall seconds; the whole active audit has90CPU/180wall.
The210-second service lifetime reserves cleanup time. The original20-second
forward return gate remains. Setup, package acquisition, downloads and input
preparation have separate receipts. Model initialization, checkpoint reload,
all complete forwards, output serialization and final statistics have measured
costs. Original editing, BP, qualification, negative controls, failed work and
repair receipts are retained separately without double counting shared setup.
Unknown original count flags and unmeasured agent/token/energy costs stay
unknown. This does not establish a quality-matched speedup.

The source template is disabled until root independently reviews the full
binding and workflow. Root is the sole publisher and execution owner. This
lane has no production mutation, broker operation or native-owner claim.
