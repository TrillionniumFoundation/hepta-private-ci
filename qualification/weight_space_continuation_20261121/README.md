# Continuation compilation and finite-compute qualification

This isolated source stage follows the earlier weight_space_nextstage_20261120
study. Its three review units are independent:

- neuron: stored-law finite-policy compilation, local-radius necessary bounds,
  fresh endpoint-task confirmation, and an independent saved-record reader.
- cost: a predeclared finite workload for existing fixed-law HCSN specialization,
  including identity checks, full state, serialization, restore and continuation.
- finance: a narrowly scoped, read-only source/weight audit for the separately
  retained private financial receipts. It performs no model execution.

The finite cost study executed 864 complete calls. Each implementation received
288 confirmation calls. Specialized confirmation tasks used 4.170894 CPU seconds
versus 17.679146 for the original. Charging 15.876712 seconds of actual non-CONF
qualification investment brings the specialized total to 20.047606 seconds.
The pre-CONF chooser selected KEEP_ORIGINAL, and the actual finite workload also
failed to recover that investment. Empirical timing envelopes are predictions,
not enforceable future bounds; general NDU still stops without an independently
defined horizon and utility conversion.

These directories do not add a live model owner, broker action, runtime route,
automatic deployment or training service. All checkpoints, financial records,
host captures, actual protocol input pins, full result traces and source replay
artifacts remain outside this public source delivery. Dedicated CI runs syntax
checks and self-contained reader controls; it cannot replay private science.

The Rust execution counterpart is the standalone continuation qualification
crate in HeptaRuntime, stacked on the earlier source adapter. Its boundary is
stored-table law verification and policy execution, not a native CTMC exponential
generator or an end-to-end production weight-editing service.
