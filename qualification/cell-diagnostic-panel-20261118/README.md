## Execution

The new `diagnostic` catalog has its own fixed SHA-256. The old open and sealed
confirmation catalogs retain their original bytes and pins. Loading diagnostic
does not open the old confirmation catalog. The original subject extraction,
literal-only assertion validation, real subprocess execution and wrong-output
controls are unchanged. One explicit adapter converts a string to `Path` for
the existing archive suffix function; it performs no filesystem operation.

Load `repo_execution.load_catalog("diagnostic")`, then load each group's
`prepared-records.jsonl` through `data.load_records`. The prepared records work
with `online_v4.onpolicy_rollout.attempts` and the existing Circuit execution.
`collect_current` retains its original train-only constraint and is not used for
these evaluation records. Provider requests must keep using the existing
whitelisted task input/messages; final answers and verifier fields remain on
the evaluator side. Freeze the candidate, all arms and budgets before student
execution, and keep every resulting failure and actual cost.

## Actual material validation

Four prepared reference actions passed the real verifier. Four wrong values,
four noninformative tautologies and four malformed edits were rejected.
Tautologies passed the original function but rejected zero controls; they did
not count as business success. Source bytes were checked against each Git blob
before exact AST extraction. No model was called during preparation.

`PANEL.json` binds the prepared files and scope; `SOURCE_RETRIEVAL.json` retains
source identities. Each group keeps the original builder output and reference
probes, plus the prepared reference receipts. `NEGATIVE_CHECKS.json` retains
the exact negative actions and original verifier results. There were 12
reference verifier calls including builder probes and rechecks, plus 12
negative verifier calls. Preparation alone demonstrates no learning gain.

## Fixed inference runner

`scripts/cell_experiments/diagnostic_run_v4.py` freezes FF, TT, CC, TF, CF,
TF without the answer edge, TF without the feedback edge, and a single F call
before generation. Four tasks require 60 actual model calls when the whole run
completes. Each two-call arm pays for both calls even when the first succeeds;
the retained result is the earliest business success, otherwise the last output.
The report also preserves first and last success separately. This tests fixed
graphs and message removal; it does not test learned routing.

The provider is a separate process using the retained original core, research,
and helper04 modules, plus the explicitly frozen current online modules. The
shared pool includes the reviewed FP32 preservation repair from PR #6680; its
source SHA-256 is `110b33222dc620ce5fb61b1e4ff9fb4b4e5f7bb03ee25a4c9c726e99f7476d3c`.
It performs the unchanged original model, source, training and actual tensor
checks. The old online directory is preserved. The new verifier is imported
only by the main process. No manifest is rewritten and no source gate is patched.
The provider script and interpreter are explicit CLI paths, bound in `LAUNCH.json`
and `FREEZE.json`; a model manifest cannot nominate executable code.
