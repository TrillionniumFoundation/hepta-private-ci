# NDU 原始 pilot 成本补账（2026-11-07）

本附录补齐原始执行中已记录的延迟分位数、实际并行阶段吞吐和训练进程内存。**科学结论维持 Inconclusive / HOLD；完整成本尚未闭合。** 物理电能、提供商费用、全流程并发峰值内存和部署进程峰值仍为未知。本附录追加在历史报告之后，不覆盖 [README.md](README.md) 或 [TASK_CLASS_COVERAGE.md](TASK_CLASS_COVERAGE.md)。

## 1. 数据范围与检查

数据来自同一个冻结 pilot 计划 `139a8c0ce912f4eadb62d80463674ac7295b04fad4c455296654ec7630946880`。仅顺序读取已经由原分析绑定的两份 compact rows，保留计时、phase、arm、训练 seed、episode seed、终态等白名单元数据。另读取原有 phase receipts、训练成本 receipts 与计时实现；没有重新训练、重新执行 episode、运行原分析或 bootstrap，也没有访问 confirmation、任务答案、图像或权重。原始 row 全文件 SHA 与版本在读取前后完全一致。[方法与源绑定](cost-method-and-source-pins.json)

原 pilot 有 11,520 个终态：10,200 Completed、1,320 BudgetStop；另有 160 个 incumbent Completed。全部 11,680 个 episode 均记录部署延迟，缺失数为 0。所有 BudgetStop 保留在总延迟及其所在 arm 的分母中。Completed 表示执行终态，不等同答对任务；BudgetStop 也不能推断为全部达到 60 秒 wall 上限，因为执行还受动作预算约束。

原样本只有 **4 个独立训练 seed**；cost rows 中记录 **1 个不同的 evaluation episode seed**。每个核心 arm 的 400 个 development episode 不能当作 400 次独立训练。原 24 项质量比较、最小有用差异及 retention 门槛均未重新估计或修改。16 项 net 比较的原下界均未超过 MUD 0.05，8 项 retention 比较的原下界均未超过 −0.02；owner authentication 仍为 SEPARATE_REQUIRED。[复核结果](cost-review.json)

原生只读提取实际成功退出，364/364 输入与绑定检查通过；本地另完成 403/403 项聚合算术、分母、分组和原结论一致性复核。这些是成本取证检查，不代表新的科学资格。完整数值，包括所有原对照臂及 retention 分组，保存在 [cost-aggregates.json](cost-aggregates.json)。

## 2. 真实部署 episode 延迟

单位为秒，p50/p95/p99 使用排序后位置 `(n−1)×p` 的线性插值，仅作已观察样本的描述。原部署 meter 覆盖 actor 进程启动、导入及 host 未分类间隙，不含外部评分。因此这些数值代表现有独立进程执行路径，不能当作预热模型内核延迟。

| 范围 | episode 数 | 均值 | p50 | p95 | p99 | 最大值 |

| 其中 BudgetStop | 1,320 | 2.741932 | 2.567845 | 3.999913 | 6.054171 | 12.121070 |

1,320 个 BudgetStop 已消耗 **3,619.349895 秒部署时长**；失败或停止工作没有从成本中删除。下面每一行均含该臂的 400 个 development episode：A=Ordinary+Light，B=Ordinary+NDU，C=Hepta+Light，D=Hepta+NDU。

## 3. 吞吐：使用真实并行阶段 wall

以下分母来自 `run_requests` 的实际阶段计时：**请求文件准备完成后、创建进程池前开始，到所有 worker 完成并 join 后结束**。它包含并行执行及进程池生命周期，排除请求文件准备和最终 phase-result JSON 序列化。每阶段最大 worker 数均为 8。它是有明确边界的实际阶段吞吐，完整部署服务吞吐还需要包含边界外工作。

| 原阶段 | 全部终态数 | Completed / BudgetStop | 实际阶段 wall 秒 | 全部终态 / 秒 | Completed / 秒 |
| --- | ---: | ---: | ---: | ---: | ---: |
| collection-content | 200 | 200 / 0 | 58.843084 | 3.398870 | 3.398870 |
| collection-transitions | 200 | 200 / 0 | 83.640440 | 2.391188 | 2.391188 |
| search | 10,240 | 9,131 / 1,109 | 3836.120496 | 2.669363 | 2.380269 |
| pilot | 11,520 | 10,200 / 1,320 | 3741.698897 | 3.078815 | 2.726034 |
| incumbent-retention | 160 | 160 / 0 | 43.725999 | 3.659150 | 3.659150 |

所有阶段的 not-started 均为 0。BudgetStop 保留在“全部终态 / 秒”的分子，另列 Completed 吞吐以避免把执行结束误作任务成功。没有使用各 episode 秒数之和作为并行吞吐分母。

原完整 pipeline wall 为 **8,353.254944 秒**（13:26:07.589949 至 15:45:20.844865 UTC）。上述五段 episode 阶段 wall 之和为 **7,764.028917 秒**，其差值还包含训练、准备及阶段间工作，不能直接命名为测得的训练时间。pipeline、阶段、job、worker 与 episode 计时有包含或并行关系，不能逐层相加。原流程未保存完整训练阶段 elapsed envelope，因此不补造训练阶段吞吐。

## 4. 训练、搜索与 CPU 内存

此次补账核对 **154 份原始成本 receipt**：8 次独立 content 预训练、144 个原训练网格 fit，以及 2 个共享 collector job。前 152 份绑定于原 model index，另 2 份绑定于其原生外层结果；没有再次读取或检查 65 个已分析 checkpoint 的权重。`fit-fit-results.json` 已累计包含全部 152 个网格 job，不再重复加上 content-results。共享 collector 不能增加独立训练重复数。

| 原 job 范围 | 数量 | 外层 job wall 之和（秒） | 外层 CPU 之和（CPU秒） | 最大单 worker RSS（MiB） |
| --- | ---: | ---: | ---: | ---: |
| 共享 collector bootstrap | 1 | 1.370957 | 1.360720 | 221.867188 |
| 共享 collector content | 1 | 4.321912 | 4.256982 | 302.218750 |
| 独立 content 预训练 | 8 | 69.504678 | 69.357990 | 324.273438 |
| 原网格 fit（含搜索候选） | 144 | 4184.888817 | 4177.093355 | 336.132812 |

154 个原 job 的外层 wall 总和为 **4260.086364 秒**，CPU 总和为 **4252.069047 CPU 秒**。job wall 是并行 job 的持续时间之和，不是实际训练阶段 elapsed。144 个 fit 的单 job wall p50/p95/p99 为 **29.018849 / 41.689787 / 42.369465 秒**；内部 worker meter 是嵌套成本，不能再相加。所有 fit 保留原 FITTED_NOT_ADOPTED 状态，成本包含网格搜索候选。

154 份原训练 receipt 均记录 `gpu_used=false`、Torch `2.9.1+cpu`，并由固定源中的 CPU 构造及加载路径支持。因此仅对这些已验证 CPU 训练 worker，可以标注 GPU 训练显存“不适用”；部署 GPU 峰值和全流程 GPU 峰值仍没有测量值，不能填 0。

最大单训练 worker 的 CPU RSS 为 **352,460,800 字节 = 336.1328125 MiB**。指标来自 Linux `RUSAGE_SELF.ru_maxrss`，表示进程生命周期峰值。它不是同时运行的全部进程内存总峰值，更不是 GPU 显存。不同 worker 的峰值不能相加后声称为真实并发峰值；公开聚合文件已去掉原通用统计器产生的 RSS 求和字段。8 GiB 是原配置的内存上限，不是实际峰值。
