# Same acceptance gate in cold standalone processes

The first study measured complete fits in longer-lived Python processes that executed several method families in seed-rotated order. One seed paid first use of AdamW's lazy initialization. This follow-up reruns each recipe, including both direct and BP, in a fresh process, starting and ending at the same host boundary (launch through successful verification of the held gate). Use a single available CPU affinity selected from the current worker. Record actual process CPU and wall time. Run pairs in alternating order for three seeds, twice each. Refit from raw inputs; each run charges interpreter imports, data verification and decoding, table construction, initialization, training, development selection plus cold scoring. Collect 4.10 (direct ridge vs BP) and 3.75 (five-update readout vs BP). Original first development passing BP endpoints are respectively epochs one and three; re-run a first-passing rule with those checkpoints. Preserve the actual cold score and test against the original checkpoint. The held labels are already known for this cohort. A speed estimate is conditional on all compared runs passing, and the full direct fit cost is charged even if a different early exit might exist. Wall samples are paired within this workload and host. This is a new timing study, not an independent accuracy replication.
