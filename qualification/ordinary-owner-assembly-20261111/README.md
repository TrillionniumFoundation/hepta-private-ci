# Ordinary learning owner assembly

This work assembles guarded ordinary-task, training, evaluation, Root publication and successor components. It does **not** establish an accepted ordinary production learning loop. Execution claims belong to an immutable source commit and its original records; no later commit inherits an earlier pass.

## Ordinary reachability remains a code and protocol gap

The proposed ordinary A-to-successor path currently needs capabilities that cannot coexist through the existing lifecycle:

1. A running ordinary process has already consumed its initial configuration and provider installation.
2. Preparing the new Root-backed successor requires an unconfigured circuit and its original retained A capability.
3. A legitimate new Starting incarnation requires the prior process to exit and the supervisor to retire its lease. Root checkpoint adoption independently requires the old peer lifetime to have ended and the replacement lifetime to differ.
4. The retained A capability is a private in-memory object in the old process. Its actual exit destroys it.
5. There is no authorized historical-A capability reconstruction and rebinding path for the replacement incarnation, nor an authorized in-place phase transition for the running process.

Existing low-level durable Source, Dataset and Root checkpoint recovery does not itself supply this missing transition. A same-child fixture cannot be relabeled as a new incarnation, and the live registry cannot be manually forced into Exited or Starting to manufacture a positive result.

See the fixed-source [reachability report](retained-a-reachability-198947/README.md), its [source pins](retained-a-reachability-198947/RESULT.json), and the [cold recovery review](cold-recovery-2125/README.md). These are reports about their named source revisions, with no native production acceptance implied.

## B comparison and cost accounting remain strict

The current comparison contract requires equal capacity, equal cumulative training budgets and the actual previously selected baseline. Positive step, example, update and compute quantities, together with every required stage cost, must be authenticated and comparable.

An incrementally trained candidate without authenticated parent history does not establish its cumulative budget. Two freshly trained arms do not make one arm the old selected parent. Unknown CPU or wall-clock stage costs cannot be replaced with zero. A future versioned incremental-training experiment requires an explicit contract and compatible evidence; this branch does not silently change V1.

NoUpdate is a legitimate result when the original business decision concludes that no update is warranted. Missing evidence, a failed transport, an uncertain publication or an incomplete evaluation is not NoUpdate. The zero-gradient Trainer component exercise remains a component exercise, not an ordinary NoUpdate chain.

## Qualification requirements

The final qualification harness fixes the source SHA and tree, original tool and checker bytes, six crate scope, Rust 1.96.0, actual UID0, and the exact seventeen Root parent tests. It performs the repository maintenance commands before behavior tests and stops on source drift. Full source caller verification and all QA groups are separate gates.

The seventeen Root parents use component fixtures. Even a successful execution proves only those components under the recorded conditions. It cannot prove an ordinary independent C, true daemon and Root death/restart, the missing retained-A lifecycle bridge, or C-to-A experience formation.

The original caller checker remains Git blob `7a6709691c372504ca11b5d2a74e14ba819fca8f`; its typed helper remains `e23bb8aa42241b429ef5dbce5a4660853b66eb2f`. Receiver annotations identify the existing object. A definition file is not registered as its own external caller: internal calls retain explicit function-order protection. Test-context annotations mirror the existing private cfg(test) module ancestry; they do not hide production calls.

Root-owned execution records are read through a bounded read-only descriptor before ownership handoff. The original step must first prove terminal completion, exact source and command, and no timeout or output truncation. The transferred bytes and original log are then checked again. Unknown completion blocks further Rust dispatch and mutating cleanup.

## Evidence

Historical failed attempts remain failed and source-bound. [The earlier checkpoint](EVIDENCE_CHECKPOINT.json) and [original record archives](native-evidence/) retain their own scope. Compilation, partial receiver probes, all-boundary diagnostics, Root prediagnostics and full qualification have different meanings and must be reported separately.

Chain evidence can commit provenance and support settlement. It does not authorize a local runtime version, resource budget or execution capability. The Chain NextUse reader remains separate from ordinary Hepta FinalUse acceptance; independent consumption must be established by the actual succeeding owner and business task.
