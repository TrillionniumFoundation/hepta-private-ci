# Actual daemon + Root cold-recovery audit

## Fixed source and result

This is a read-only source audit of `TrillionniumFoundation/hepta-private-ci` at **2125da36a0e49a19b725c28bb150900f20caac7b**, tree **b1aed9bcf92573ac2618ddd6931b05f09659c41a**. The Git commit API and fixed tree confirm that identity. No Cargo/native test, daemon or Root restart, service stop, source edit, or ref update was performed for this audit. The accompanying `RESULT.json` contains the named source references and a 55-file content inventory; every retrieved file's computed Git blob matches the fixed source tree.

**The complete cold-restart continuation remains blocked by specific code and protocol gaps. It cannot be described as merely waiting for deployment keys or a restart test.** Existing original-owner recovery and readback APIs are useful, but they do not reconstitute a retired in-memory capability or authorize a newly started daemon to take over an immutable old operation.

There are two distinct “first” boundaries:

- At ordinary startup, an old process registration correctly fails the original pidfd/PID/boot/start checks. The new process needs genuine Fleet/Root admission.
- After that admission, the first missing A→Dataset product capability is **reacquiring the historical original A source/task read capabilities after every process retaining them has exited**. Dataset recovery requires those capabilities as inputs; it does not construct them.

## Why a new incarnation cannot simply reopen the old operation

The task-source configuration digest and producer signing-journal digest both contain `identity.spawn_generation`. The product installer passes the current Agentd identity into the active runtime/producer constructor. A new generation therefore does not match the old journal binding. Reusing the old number would conflict with the actual Fleet Starting admission; changing the journal binding would change the original evidence boundary. [circuit_task_source_codec.rs — configuration](https://github.com/TrillionniumFoundation/hepta-private-ci/blob/2125da36a0e49a19b725c28bb150900f20caac7b/codex-rs/hepta-agentd/src/circuit_task_source_codec.rs); [cell_q24_task_ledger_binding.rs — configuration](https://github.com/TrillionniumFoundation/hepta-private-ci/blob/2125da36a0e49a19b725c28bb150900f20caac7b/codex-rs/hepta-agentd/src/cell_q24_task_ledger_binding.rs); [cell_q24_task_ledger.rs — OriginalCellQ24TaskLedgerProducerV1::open_original; capture](https://github.com/TrillionniumFoundation/hepta-private-ci/blob/2125da36a0e49a19b725c28bb150900f20caac7b/codex-rs/hepta-agentd/src/cell_q24_task_ledger.rs); [config.rs — AgentdConfig::load_with_writer_source](https://github.com/TrillionniumFoundation/hepta-private-ci/blob/2125da36a0e49a19b725c28bb150900f20caac7b/codex-rs/hepta-agentd/src/config.rs).

The same issue persists beyond A. `neuron_generation_process_identity_digest_v1` binds the complete identity context and spawn generation. Root learning profiles bind it and the writer proof. The Model factory's persisted profile, learned publication profile and Initial profile retain those original bindings. Factory open requires full equality. Both publication recovery paths also require full equality; some failures persist a sticky fence. This protects the old owner. There is no implemented transition in these traced APIs that authorizes an old operation's custody to move to a newly admitted incarnation. **Do not use `Recover` with a speculative replacement identity as a diagnostic probe.** First inspect the immutable compatibility facts without mutation. A failed full-profile comparison can permanently fence the original enrolled operation. An existing fence or uncertain outcome is not permission to Reserve again.

This does not imply that every original store is permanently unreadable after a process exit. Original protected data can still be inspected by its legitimate original Root/owner interfaces. It means that **reading old facts and admitting a new execution owner are different operations**, and the latter transition is not provided by these recovery constructors.

## Minimal lawful transition boundary — design only

No new protocol or serializer is implemented by this report. The smallest missing boundary should preserve the following distinctions:

1. **Preserve the old subject.** Keep the old operation ID, source identity, original signatures, witness heads, CURRENT/intent and nonce history unchanged. A successor must not rewrite the historical identity or re-sign its evidence.
2. **Authorize the actual new reader/executor explicitly.** The original Root must bind a genuine new Fleet Starting identity and live consumer pidfd/boot/start, original writer authorization, exact historical subject and narrow purpose in a protected successor enrollment. Existing issuer/key authority remains the source of authorization; no default issuer, fabricated grant or caller JSON becomes a capability.
3. **Reacquire historical read access before execution access.** Add the missing purpose-specific route from original acknowledged source/Cell/Automation/Ledger files and witnesses to a sealed historical read capability. It must preserve withdrawal/trust/inode and original-owner checks and avoid reactivating the retired task writer merely to manufacture a read view.
4. **Choose the continuation contract explicitly.** Historical observation alone is not permission to resume unfinished stages. A new operation needs its own original admission, role/policy, deadline and FinalUse binding. If preserving one unfinished operation is required, an explicit original-Root old→new incarnation transition must define monotonic fencing, exact checkpoint/scope, owner custody and crash reconciliation. The current strict equality checks must not be weakened to approximate that transition.
5. **Keep uncertain effects uncertain.** Missing and Pending are not “not applied.” Do not retry Reserve, reuse/refund an old consumed nonce, renew a grant, or dispatch an old signed operation again to guess its result. Independent owner stores do not become a new cross-owner atomic transaction merely because a broker reads them.
6. **Define the negative and crash matrix before acceptance.** Required cases include old owner still alive; PID reuse/new start ticks or boot; stale Fleet generation; old handoff/trigger replay; crash before/after durable transition and before/after ACK; claim-before-CURRENT failure; CURRENT/journal disagreement; duplicate nonce; revoked/rolled-back source, Artifact or FinalUse state; and cancellation while an original blocking effect continues.

These are code/protocol design requirements. They are separate from the real deployment materials needed to exercise them: original protected stores and witnesses, full enrolled trust/keyring, valid Root/Fleet process authority, actual owner roles/keys, real tasks/Outcome, independent B/holdout inputs and ordinary consumer lifecycle.

## Minimal reverification sequence

1. Preserve and inventory the actual original state and owner lifetimes. Do not reset files, replace witnesses, renew evidence or infer retirement from a lost ACK.
2. Obtain real new Fleet/Root admission and actual new process pidfds. An old registration should fail.
3. Inspect old/new identity, scope, proof and immutable profile compatibility before calling a recovery constructor that can persist a fence. **For full cold continuation on fixed2125, stop at the missing historical A-cap/successor-authorization join.**
4. Once that join exists lawfully, recover Dataset from original materials; then reopen E/D, Training, Model/LocalDecision and Root checkpoint owners using explicit Recover and reauthenticate every saved stage.
5. Obtain the new real five-lane session, activate the original consumers, take the one purpose handoff/context, and wait for same-Root actual enrollment ACK.
6. For an already applied publication, inspect exact CURRENT plus the actual generation effect record; revalidate original Artifact/Selection/withdrawal and FinalUse state. Reconstruct only that existing published task, without a new claim or publish.
7. Run the actual daemon-and-Root exit/restart experiment and a normal successor task under the resulting real owners. Record new PID/start identity, source/nonce state and actual task result.

The concurrent Pending-successor draft is outside this fixed source audit. It can close runtime startup ordering, but it does not establish a cold-process transition by itself.

## Acceptance status

This review supplies **zero** new ordinary complete, adopted, NoUpdate/rollback, independently controlled ordinary C, or physical daemon+Root restart results. It neither inherits predecessor native results nor converts original-owner reopen tests into cold-restart acceptance. The failure to close the cold path is a concrete implementation/protocol boundary, while absence of real deployment materials and the unperformed restart experiment remain separate acceptance requirements.
