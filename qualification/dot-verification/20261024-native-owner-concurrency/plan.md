# Native SQLite concurrency challenge

Exact parent #3685 e795ae9b7b572f819cadb8cc7d53053b495d9b5e, tree 384e3843e62e9c0696c3c3cea663c16ca2715d36. Production owner lineage is #3649 95943a plus reviewed cancellation validation and scoped lint-contract fixes.

Existing coverage includes competing ModelCompleted successors, sequential terminal replay, dropped-dispatch recovery, cancel/reopen and generation refusal. This change adds three distinct tests using the existing AutomationStore, FinalUseAuthority, PreboundAutomationStatusEffect and FileProvider fixtures. It creates no new owner or ledger and makes no production implementation change.

1. Two independently opened AutomationStore connections submit the identical previously admitted intent/grant/key/command concurrently. At least one API call must succeed; failures may be fail-closed conflicts. Physical dispatch-entry count must equal one before and after one bounded original-attempt observation. Both connections must read the same complete terminal receipt and attempt 2 must not exist. The provider's entry counter increments before its own idempotent persistence, so provider deduplication cannot hide a second dispatch.
2. A controlled dispatch persists its file effect/receipt and then remains pending. Notify establishes that boundary (with a three-second bound), while a second owner recovers the original SQLite attempt through one provider lookup. The original future remains alive during settlement. Only then is it dropped; both stores close and a fresh store must read an identical complete receipt. Local cancel remains Unresolved, not a fabricated remote stop acknowledgement.
3. Two actual TaskFlowTurnOwners race ToolCompleted (using an actual status from the real effect path) against CancelRequested on the same frame. Directed cancel-first and tool-first controls cover each branch, followed by one concurrent join. Exactly one successor wins. A cancellation winner rejects stale completion; a tool winner can subsequently receive cancellation based on its actual new frame. Final cursor remains CancelRequested with unchanged charged tokens and a consistent history/revision, never Cancelled without stop evidence.

Limits: these are in-process, current-thread async schedules over independent SQLite connections, not exhaustive interleavings, multiple OS processes, power loss or real provider attestation. The file provider is an explicitly controlled test adapter, with pre-existing test-only issuer material. No external provider/network operation or remote CI query is performed. Correct behavior is validation, not a newly discovered vulnerability.
