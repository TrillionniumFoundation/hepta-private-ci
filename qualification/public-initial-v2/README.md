# Public initial V2 ordinary model experiment

This experiment reconstructs the initial model from seven pinned public files,
loads it through the original artifact, CURRENT, inference control, resource,
and FinalUse owners, and executes ordinary Agentd cognitive queries. It then
runs three real proposals against the same currently selected parent. Each
proposal executes the original five-arm evaluation and is followed by a fresh
ordinary Agentd incarnation reading the original CURRENT.

**This is not evidence of three installed upgrades.** A zero or negative gain
retains the selected parent. A positive experimental gain without the original
evaluated-child product qualification fails explicitly and retains the candidate
for review. The harness cannot issue that qualification or authorize rewards.
The public smoke tasks and deterministic repeated seed establish neither future
task generalization nor independent evaluation custody.

## Required behavior

- A clean public material reconstruction must match the published target and
  plan byte for byte before initial selection or model execution.
- Ordinary cognitive queries must perform actual forwards with distinct original
  control request IDs and the selected parameter, backbone, tokenizer, and adapter
  roots. Ready health alone is insufficient.
- Each ordinary session verifies CURRENT before and after use. Independent
  withdrawal must stop subsequent ordinary queries. Runtime failures must retain
  their observations and await owned task and model shutdown.
- Each proposal consumes the selected parent through the original parent-step V2
  trainer. Candidate, fresh LoRA, and full tuning retain ten steps and the same
  token schedule. Current backbone and randomized LoRA retain their original zero
  training steps. Actual runtime costs are measured separately; equal schedules
  do not imply equal resource consumption.
- All five actual artifacts are frozen before evaluation. Each arm reloads its
  produced bytes through the original evaluator. No score gate is lowered.

## Execution and evidence

`.github/workflows/hepta-public-initial-v2.yml` checks out the exact pull-request
head, Rust 1.96.0, CPython 3.12.3, and the fixed Chain revision. It installs the
complete hash-locked CPU wheels into a fresh environment and downloads the public
model at the fixed revision. The workflow calls `just test` for all three changed
packages, then explicitly executes both ignored real-model tests with the
`hepta-public-initial-v2` nextest profile.

Runtime snapshots verify wheel RECORDs and record the actual interpreter,
environment/stdlib file inventory, and native libraries selected by an import
probe. Before/after checks detect observed drift; they do **not** provide a held
immutable interpreter/stdlib/ELF namespace or attest every later worker mapping.
The ordinary physical worker clears ambient Python and loader injection. Its
supervisor and descendants disable user-site imports and bytecode writes.

The original per-phase 1,800-second training and 600-second inference budgets are
unchanged. A separate 2,700-second campaign guard bounds each complete proposal;
hitting it is a failed experiment, not a partial success. Original selector and
CURRENT trust windows remain binding, including the controlled one-hour trust
window. A new session receives a fresh signed selection, never an extended old
capsule.

The `records` artifact retains source identities, cold-install hashes, actual
native observations, control journals, training receipts, predictions, assessments,
exit status, and failures. The separate `checkpoints` artifact retains all actual
candidate and full-tuning weights. Presence of workflow source or a test launcher
is not proof of successful execution; inspect the terminal records and artifacts.

All signing/FinalUse issuer keys in these tests are controlled test identities.
Production enrollment, three genuinely qualified installed generations, immutable
runtime delivery, and independent future quality remain separate acceptance gates.

## Candidate descendants and the actual incumbent

The additional `hepta_smollm_descendant_v2.py` diagnostic executes a real candidate
lineage with ordinals 2, 3, and 4. The first step uses the original positive-zero
setup; later steps load the preceding candidate's exact factors through original
parent-step V1 without reinitialization. Every step preserves all five original
arms and adds a sixth: the actual ordinary CURRENT incumbent, reloaded from its
verified parameter bytes. The evaluator's original `candidate` protocol role is
used for this adapter; the separate directory and frozen roster identify it as
`actual-current-incumbent`. It never substitutes the unadapted backbone for an
installed adapted model.

These descendants remain unadmitted. The actual CURRENT snapshot stays at the
observed initial parent. A completed computation emits typed `ParentNotCurrent`,
`NoGain`, and `MissingSystemLongitudinalEvidence` blockers as applicable; positive
public-task scores cannot remove the last blocker. A zero exit status means the
six-arm diagnostic completed, not that a child qualified or was installed. The
three ordinary proposals retain their stricter existing failure on an unqualified
positive score. The extra diagnostic has a separate 9,000-second campaign guard;
it preserves every original per-phase budget and gradient step. Its evidence is
a recorded CURRENT snapshot, not a live owner admission or future quality claim.

Real later installed generations must use the existing
`prepare_smollm_neural_agentd_v1` evaluated-child path, following original
`ProductEvaluationRunnerV1::qualify_and_persist` and independent selection. That
path requires a `SystemLongitudinal` product qualification, including genuine
temporally ordered observations, multiple windows, native statistical evidence,
and the original signing and artifact owners. The single-window controlled
neural comparison provider and static six-arm scores cannot mint this receipt.

The ten-step match is **per round only**. Diagnostic descendants inherit the
previous candidate's ten or twenty training steps, while fresh LoRA and full
tuning restart from the common checkpoint for ten steps each round. Reports
therefore retain each arm's measured steps, tokens, supervised tokens, actual
parent lineage and ancestor receipt hashes, and distinguish cumulative schedules
from this-round schedules. Later descendants carry `CumulativeBudgetMismatch`.
`cumulative_budget_matched` and `budget_matched_gain_proven` remain false: neither
equal step counts nor profiler-supported FLOPs prove equal total resource cost.
Shared upstream pretraining cost is unknown and is not recorded as zero. These
score differences cannot show that descendants overcome controls at the same
cumulative budget. That separate experiment requires additional fresh and full
tuning controls at twenty and thirty steps, while retaining the existing ten-step
controls and original source records; this diagnostic does not silently change
their training plans.

Host resource probes record the actual process cgroup, mount mapping, and readable
v1/v2 limit files. Missing or unreadable files remain `null`/`unavailable`; they
never imply an unlimited cgroup. The twelve-GiB physical capacity check is only a
prerequisite. Visible limits provide upper bounds and can reject an insufficient
runner, but do not prove hidden-ancestor limits or available memory. The isolated
experiment therefore retains `resource_limit_unknown` and does not issue a
resource-capacity qualification. Earlier immutable host records are preserved
with their original source and must not be reinterpreted as controlled capacity.

The complete Rust package gate and its required first-party CLI build retain
their own outcomes. An executable model test target can continue isolated model
observations after an unrelated package-test failure. The final `always()` gate
still requires the CLI build, all three complete packages, cold installation,
ordinary inference, original three rounds, descendant diagnostics and final lint
to succeed. A failed, skipped or unavailable original gate keeps the job failed;
model observations never substitute for that gate. Missing compiled model targets
are recorded explicitly and cannot be counted as executed model experiments.
