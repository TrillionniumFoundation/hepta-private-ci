## Exactly what is fixed before future execution

The original V1 compared uniform group counts **6/6** against heterogeneous **9/3**, and executed uniform first on all four seeds. Those designs confound relative update timing with per-group optimizer-write and source-token exposure, and confound wall time with fixed order. The V2 **interleaved versus bursty** comparator gives each group six optimizer steps in *both* arms. Per seed and group, an independently generated ordered list of six `(event_id, source_sha256, input_tokens)` is consumed in the same order by both arms; only the chronological interleaving changes. Arm execution order is assigned by a frozen, salted seed permutation with equal AB/BA counts across an even number of seeds. These checks bound opportunity differences; they do **not** establish equal actual cost, wall clock, gradients, or outcomes.

`clock_pairing_v2.py` constructs and checks an immutable, source- and model-digest-declared `PairPlan`. Its SHA-256 is a local consistency witness, **not** a trusted signature. Each arm emits twelve explicit `(step, group, event)` entries. `verify_pair` rejects changed source identity, schedule, group event sequence, input tokens, plan digest, model/source-tree declaration or arm order. The model runner must consume this plan *rather than regenerate schedules*. Running V1 unchanged does not constitute V2 execution. No V2 model run is submitted here.

Before experiments, independently freeze and authenticate actual source/model/tokenizer/plan bytes and evaluation authority; commit the randomization salt **before** observing any model outcomes. Require training to log each executed step, effective group writes/optimizer state, activation and cache costs, real CPU/GPU/wall/energy/network/IO, delays, failures, full B/C independent tasks, old/OOD retention and cold-recovery evidence. An independent verifier must reconcile those actual logs against this plan and the original Owner. Add fixed-rate/direct-gradient/matched strong controllers, the remaining seven-lineage and NDU 2×2 designs as separate experiments; this two-group timing contrast is only one useful control.

Run the deterministic preflight tests with `python3 -m unittest -v test_clock_pairing_v2.py` from this directory. No heavy model dependencies required. Passing them does **not** close a scientific, independent-evaluation, Owner/NoUpdate or production blocker.
