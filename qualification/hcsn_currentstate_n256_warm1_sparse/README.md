# Independent N256 warm-1 sparse comparison

This new execution identity advances the immutable five-channel input only from
0 to 0.001. It independently assembles a CSR augmented operator and uses exactly
two `expm_multiply` actions. The emitted packet retains its initial coefficients,
full generator and output selector; the residual original packet and all signed
content channels remain present. The canonical capsule has 69,728 coordinates.

The reference is the already executed dense capsule, SHA-256
`b2a6e204e613fead7c0735b12a335a88d2394c8f4da99cab798133443c55dc18`.
This experiment executes no fresh dense oracle and calls no protected original
full-roster candidate. It does not satisfy or replace that candidate's admission.
Every coordinate is compared as bytes and FP64 values. Numerical tolerances are
descriptive only: any bitwise mismatch leaves the original bitwise gate **RED**.
The original first-step receipt and full-roster/large-grid gates stay unclaimed.

The new hosted job reuses the existing resource constants and stdlib observation
helpers, with its own identity, scope, source freeze, output directory and key.
It preserves the 10 GiB available-memory, 1 GiB free-swap, 6 GiB finite-ancestor
headroom, four-CPU, PSI and historical-OOM checks. The child receives a 4 GiB
address-space limit before exec, checks it before numerical imports, and runs
single-threaded with a 600-second timeout. All observations, errors, costs,
candidate bytes and comparisons are uploaded, including bitwise failures.

Local controls use only a three-state signed-content ODE comparison, a two-state
zero law, resource-denial checks and read-only manipulation of the archived
capsule. They do not run the authentic N256 dynamics. The complete child cost
includes imports and coordinate comparison, so it is not directly interchangeable
with the archived dense child's cost, which excluded the new comparison phase.
