# Original late-writer launch adapter

This additive component is based on `2125da36a0e49a19b725c28bb150900f20caac7b` / tree `b1aed9bcf92573ac2618ddd6931b05f09659c41a`. It has not been formatted, compiled or executed; the parent will qualify the final integrated immutable source with the original gates.

## Contract

`AgentdProductionLaunch::receive_original_late_writer(arguments, expected)` receives a new production Launch in an already dedicated non-Root process. The trusted supervisor must already have authorized its actual Starting identity and original Root writer; this method creates neither. It returns the original Config, closed Launch and untouched ordinary arguments.

The original parser still requires an actual Android, Notes or Desktop runtime input set, distinct inherited descriptors, paired Learning/Model capabilities and mutually exclusive initial/learned publication purposes. Here the existing handoff argument explicitly carries the existing THREE-right writer purpose. There is no fallback to the ordinary two-right handoff.

Ordering is: original parser → actual UID/GID match → original purpose-checked sealed bootstrap/Root pidfd/Root0600 writer FD → optional original handoff offers → all five actual Root lanes → original non-Root writer Config loader (actual Starting, inode, lease, peer and scope checks) → exact loaded identity and bound sockets → actual Learning and Model connections → final actual credentials, original deadlines and live writer verification → closed Launch.

Every failure or dropped future owns and drops its current attempt. No registration retry, lease renewal, cached session revival, caller-provided authority callback, artificial Ready state, mutable-owner export or new key/grant is introduced. The existing root pre-drop default entry is unchanged.

## Original capabilities required

- An actual supervisor-admitted Starting identity; `expected` only compares it with the genuine sealed/live inputs.
- The original Root-created three-right writer handoff, real consumer journals and same Root service.
- The selected primary runtime's original inputs and actual bound control/App Server sockets.
- If learning is requested, the original Learning handoff; a Model request additionally needs its original Model factory handoff. Learning/Model policy and scope remain validated by their original clients.
- An actual writer authorization and original process lifetime. This adapter never rotates or adopts a writer itself.

## Tests and remaining boundary

Two new unprivileged negative tests exercise partial/aliased inherited-descriptor refusal and actual credential mismatch through the public entry. They do not construct a Root authority, execute a positive phase, or claim an ordinary task.

A same-process two-phase A→new Starting→C fixture is blocked by a separate existing protocol constraint: actual Supervisor retirement and Root checkpoint adoption require the previous process to retire, while the retained A capability is currently in that process's memory. This adapter does not transport or recreate that capability. Low-level original source/Dataset and protected checkpoint recovery APIs still exist, but their predicates are not a new-incarnation retained-A custody transition. A fake process exit, hand-built Launch, raw JSON owner or manually installed Ready state would not be a valid workaround.

No new native, Root, ordinary-chain, independent-consumer or physical cold-restart acceptance is claimed.
