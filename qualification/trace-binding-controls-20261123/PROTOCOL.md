# Prospective controlled transfer of the four-stage historical script

This follow-on studies the earlier 0/12 changed-parameters failure on an exposed arithmetic family. It tests a narrower program induction bias separately from the six neural arms in #7034. The executable template, retried task and four actions come exclusively from the previously released single OpenHands demonstration. Its original archive SHA-256 is `28b46e1f84215a0f3554f737930bab93e1d46f890445b14eda61abdb7b32b327`. No live user, new teacher supervision, payment or operational adoption is available in this experiment.

## Candidate and controls

In the supported Python demonstration grammar (one ascending range and a modulo filter), align three source argument roles to literal tokens in the donor question and program. Infer the inclusive-endpoint adjustment from its executable text. A traced program reuses the stored actions and changes the three aligned literal fields. Engineering priors include English number boundaries, local semantic cues for a factor, lower and upper bound, one-to-one assignment, and default lower bound 1. The prior and grammar are hand authored. No free-form code or effect is executed.

Register (1) exact trace replay, (2) binding by donor ordinal, (3) a direct ridge estimate of the role scores, (4) gradient fitting of exactly the same linear weights and objective, (5) direct fit without semantic cues, (6) a deterministic hand-coded binding rule with a handwritten implementation of the same mathematical family, and (7) a trace-dependent candidate with its donor removed. Each arm gets the identical public request string and at most four actions. Report actual usable outputs, rejected writes and abstentions. Score accepted scripts by comparing their resulting sequence to an independent enumerator. Separately score an old zero-digit task and contrasting requests outside the declared skill. The historical old probe is a shared fallback and the denominator is one.

Fit only the single source demonstration. Numerical inputs in the assessment never supply labels or gradient updates. Expose numerical preferences, timing and number of iterations for the two fits. Run 51 alternating paired CPU repeats on one thread for descriptive medians of fitting the same prepared three-row matrix. Report separate end-to-end fit time. Refitting a low-dimensional linear map has its own speed and quality interpretation. It does not compare full-model training times.

## Chronology and decision

Publish this protocol first. Publish implementation before fitting. Publish material weights, template, manifests, program hashes and common scorer before drawing confirmatory numerals. Publish the new panel before any candidate evaluation. Retain the previous 19 exposed cases as their own table. The new authored panel has 24 cases in each of four equally weighted families (donor-like explicit numbers, reordered roles, implicit lower bound, and distracting numerals). Vary bounds and divisors independently, include nontrivial lower bounds. Add 16 out-of-scope contrast requests. Report per-family, overall, and worst-family scores for all arms; report paired gains/losses for direct versus ordinal and direct versus the handwritten family solver. Clear the controlled parameter-transfer gate if the direct candidate completes at least 10/12 of the exposed changed tasks, at least 18/24 in every new in-scope family and at least 15/16 outside-scope abstentions. An incremental scientific benefit over the task-specific hand solver additionally requires a positive net paired difference on the 96 new in-scope tasks without worse refusal or retention. All arms and thresholds remain visible if any gate fails. Real cross-user transfer still requires the original private A/B chronology and adoption.
