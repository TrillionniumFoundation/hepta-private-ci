# B16 guarded native execution bundle

This is V3, a narrow JUnit terminal-status correction on V2. The complete V1 bundle and its 28 Git objects remain preserved under `v1-frozen/` and delivery map `c4885b9005d85ddf4c1647b8a96538957a7a7ab1`; V2 is preserved under `v2-frozen/` and map `fb3357a64d69a5d276f103cd41ec7585f7803fac`. Executor safeguards and documentation changed; the source payloads, physical tests, original test budgets and frozen phase definitions remain byte-identical.

This bundle is executable preparation, **not an executed native qualification**. Its binding template deliberately has no `final_A_tree`, ordinary-index identity, actual lock identities, tool identities or native paths. The runner rejects that template before it starts a subprocess, creates an evidence directory or changes source.

The approved foundation, driver, pool and checkpoint source candidates are unchanged. The payload was reconstructed with real `git apply --check` and `git apply` in an isolated cloud directory. Its 24 source transitions finish at the same 81-file partial composition as frozen plan `dc12d596…`. This is source reconstruction, not a full product tree or a successful Rust build.

## Execution contract

The sole native executor binds one epoch at a time after A finishes its original gates, final fix/fmt and source review. It must fill the template from the **actual final A native source receipt**, not from cabc, f825, an earlier draft or a donor. The whole working tree, ordinary HEAD, ordinary index, both active lock files and the complete no-package-filter Cargo metadata must match that binding. A changed original preimage stops execution and requires a new reviewed delta; the runner never replaces it with the old file wholesale.

`final_A_tree` means the actual source after A's final fix/fmt. `last_tested_A_tree` and the immutable `last_tested_A_artifacts` receipt retain the real source of A's last full test/catalogue; they must not be relabeled if hygiene subsequently changes source. `last_tested_A_to_final_A_review` identifies the independent source-relation review. The complete helper basename roster and capacity observation come from that honestly labeled tested receipt. Each epoch's baseline metadata is separately bound to its current `initial_tree`, and every B scope rebuilds/catalogues its own current source. None of these bindings require rerunning A tests after final hygiene.

The per-epoch invocation, only after that explicit authorization, is:

```text
python3 b16_runner.py --binding <reviewed-epoch-binding.json> --epoch foundation
python3 b16_runner.py --binding <reviewed-epoch-binding.json> --epoch driver
python3 b16_runner.py --binding <reviewed-epoch-binding.json> --epoch pool
python3 b16_runner.py --binding <reviewed-epoch-binding.json> --epoch checkpoint
python3 b16_runner.py --binding <reviewed-epoch-binding.json> --epoch owning
```

Every later epoch requires the previous qualified terminal receipt by full hash, the same final-A identity and payload, source continuity, lock continuity, ordinary-index/HEAD continuity, the same target and B-cache identities, the full helper contract and the actual resolved graph. The ordinary index must be bound after A's final actual checks; no earlier index hash is prefilled. There is no automatic launch, retry, source reset, stash, ref update, shared-cache deletion, tool installation or permission change.

Exact full names and original authored argument arrays are retained in each `epoch-*.json`. Execution uses the original `just test` recipe with `--retries 0`, `--no-tests fail`, the existing local nextest profile and dev-small Cargo profile. The existing budgets remain unchanged. `--no-fail-fast` collects every selected expected failure without treating a partial vector as success. Full-workspace no-`-p` metadata and catalogue retain feature unification; `package(=…) & kind(lib) & test(=…)` selects the same library cases at the nextest layer. The official filterset reference documents these equality and binary-kind predicates: <https://nexte.st/docs/filtersets/reference/>.

Before each scope, the six real normal helpers are built through Cargo and recorded from compiler-artifact messages. The full catalogue may legitimately rebuild them with workspace features, so actual identities are independently captured after catalogue and before/after `just test`. The complete helper basename multiset must equal the roster from the pinned last-tested-A full-workspace artifact receipt, including the normal six and required original codex, Agentd, apply_patch and Linux sandbox helpers. A missing or additional helper fails this guard; observing a count alone is insufficient. Old A helper bytes are not reused as qualification: B records the actual rebuilt bytes. Package/graph counts are observed rather than hardcoded. All original ignored and filtered cases are recorded separately. The three ignored owned-child support entries must be present but are never counted as extra passes.

JUnit must be fresh, have a new run UUID and match the exact catalogue names. Complete raw output and XML remain intact. Early-return notices, including the actually observed `skipping capability test:` prefix, are associated with case blocks where possible; an unbound notice remains a qualification failure. Counterfactuals require the approved physical marker order and the exact unchanged assertion's source line. Compile errors, setup failures, missing child checkpoints, released/timed-out callbacks, generic timeout, no tests, earlier assertions or a passing counterfactual cannot satisfy a negative gate.

V3 also retains every JUnit failure/error/skipped element's complete attributes. A negative can reach its physical oracle only when its terminal element is exactly one ordinary Rust assertion failure, `type="test failure with exit code 101"`. Missing or unknown types, timeout, error, skip and leaked-handle variants fail the prerequisite gate even if panic text is already present. The original f825 full report contains a real `<failure type="test timeout"/>` with no text and no `TIMEOUT` in captured output, which exposed the previous text-only classification gap. This does not assert that that historical case was incorrectly qualified: its physical markers were absent. The new pure control covers the actual XML representation and the strict type boundary without changing a physical test.

Every negative has an exact-source `finally` transition. A bad causal result is saved, the known owned negative is restored to the approved positive, and execution stops. If source/index/HEAD/lock drift prevents proving ownership, restoration is refused rather than overwriting another change. The original and cleanup errors are retained separately.

## Real lock and Bazel gates

The two dependency epochs run normal `cargo metadata --format-version=1` without `--locked`, then the original root `just bazel-lock-update` and `just bazel-lock-check`. Only their declared active lock paths can change. Cargo package versions, checksums, graph nodes and features outside the reviewed driver or Memory edge must remain equal; an unexpected resolver change stops for review. No lock delta is predicted or handwritten. The nested published vendor Cargo.lock is preserved as source and is not the active workspace lock.

All five epochs explicitly reuse the same existing final-A `CARGO_TARGET_DIR` and dev-small profile. Each scope still performs actual helper builds and the full workspace catalogue against its current source; sharing a target is not permission to reuse an old test program without rebuilding and recording it. The driver epoch creates one private B Bazel cache root with a final-A/payload/target owner receipt. Registration, checkpoint lock generation and the final lock check reuse only that same owned root through the repository's existing `user.bazelrc` import. Existing caches are never deleted or overwritten. Original configuration flags remain in effect. The runner copies exact generated `@crates//:data.bzl` bytes located by Bazel, loads the actual new rule, and records its generated dependencies. B16/phase/B15 builds the new unit target under the original plain host configuration; **this is registration/compilation evidence, not a claim that Bazel ran the 12 tests or that hosted platform CI passed**. The original 12 cases are run by `just test` in B16/phase/B14. The final owning lock check uses the original recipe and the same B cache.

The capacity plan is conditional. The saved earlier f825 full-workspace receipt measures 321 test programs plus 33 helpers totaling 18,121,368,592 bytes; that is an executable-file observation, not total target size or a measured build peak. An illustrative allowance for one additional executable family, 12 GB of other Cargo growth, 8 GB of B Bazel growth, 2 GB of evidence and the unchanged 8 GB reserve requires 48,121,368,592 free bytes using that older observation. The reported approximately 49 GB therefore warrants a fresh check, not a guarantee. The launch binding must instead pin A's actual last-full-test receipt under its true source identity and explicitly review the remaining allowances. The runner verifies all four locations share the measured filesystem and reads actual free bytes before starting. Later epochs may use newly reviewed remaining-growth estimates while preserving the same target/cache/receipt identities. If space is insufficient, execution stops; it does not delete caches, reduce the test scope or alter the profile. `capacity-plan-v2.json` records the complete provenance and unmeasured limits.

A later root update reported 47.05 GB after A's full run. Its exact byte count and decimal/binary display unit are not bound here; it is not evidence that the illustrative allowance fits. The actual byte check and reviewed remaining-growth plan are prerequisites, and no cache deletion is authorized to satisfy them.

The default A host/toolchain values are not embedded. Binding requires actual tool files, Rust 1.95.0, the repository's Bazel version, original recipe file hashes, the actual final source and both lock receipts. The current concrete runner is Linux x86_64 only.

## Review and preservation

`payload-manifest.json` contains every pre/post source identity. Five bounded JSON payloads contain all 112 exact source objects. `operation-order-validation.json` verifies the proposed operation stream, including every finally transition, reaches the same frozen final partial map. `payload-reconstruction.json` retains the actual isolated patch reconstruction. The Python tests exercise private-index preservation, preimage drift refusal, exact restoration after an invalid negative, refusal to overwrite foreign drift, lock-path confinement, symlink rejection and false causal endpoints. They are pure Git/Python tests, not physical SQLite experiments.

Every native command gets separate command/status/raw receipts and whole-source guards. A terminal index preserves complete originals and offers lossless zlib/base64 retrieval pieces for larger files, with offsets, byte counts, SHA-256 and CRC32. No raw tail is substituted for a complete run. The final owning epoch returns `AWAITING_HYGIENE_DIFF_REVIEW` even when the commands pass, so automatic formatting cannot silently acquire qualification.

Remaining B16 limits stay open: authenticated Current and the three-pool binder; normal Root signed producer/lease/revocation/FinalUse; unbound independent or non-opt-in opens; the original platform matrix; and final runtime consumers. Successful selected controls establish their specific custody and commit-hook properties, not those broader contracts.
