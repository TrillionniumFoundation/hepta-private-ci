# B16 guarded native execution bundle

This bundle is executable preparation, **not an executed native qualification**. Its binding template deliberately has no `final_A_tree`, ordinary-index identity, actual lock identities, tool identities or native paths. The runner rejects that template before it starts a subprocess, creates an evidence directory or changes source.

The approved foundation, driver, pool and checkpoint source candidates are unchanged. The payload was reconstructed with real `git apply --check` and `git apply` in an isolated cloud directory. Its 24 source transitions finish at the same 81-file partial composition as frozen plan `dc12d596…`. This is source reconstruction, not a full product tree or a successful Rust build.

## Execution contract

The sole native executor binds one epoch at a time after A finishes its original gates, final fix/fmt and source review. It must fill the template from the **actual final A native source receipt**, not from cabc, f825, an earlier draft or a donor. The whole working tree, ordinary HEAD, ordinary index, both active lock files and the complete no-package-filter Cargo metadata must match that binding. A changed original preimage stops execution and requires a new reviewed delta; the runner never replaces it with the old file wholesale.

The per-epoch invocation, only after that explicit authorization, is:

```text
python3 b16_runner.py --binding <reviewed-epoch-binding.json> --epoch foundation
python3 b16_runner.py --binding <reviewed-epoch-binding.json> --epoch driver
python3 b16_runner.py --binding <reviewed-epoch-binding.json> --epoch pool
python3 b16_runner.py --binding <reviewed-epoch-binding.json> --epoch checkpoint
python3 b16_runner.py --binding <reviewed-epoch-binding.json> --epoch owning
```

Every later epoch requires the previous qualified terminal receipt by full hash, the same final-A identity and payload, source continuity, lock continuity, ordinary-index/HEAD continuity and the actual resolved graph. There is no automatic launch, retry, source reset, stash, ref update, shared-cache deletion, tool installation or permission change.

Exact full names and original authored argument arrays are retained in each `epoch-*.json`. Execution uses the original `just test` recipe with `--retries 0`, `--no-tests fail`, the existing local nextest profile and dev-small Cargo profile. The existing budgets remain unchanged. `--no-fail-fast` collects every selected expected failure without treating a partial vector as success. Full-workspace no-`-p` metadata and catalogue retain feature unification; `package(=…) & kind(lib) & test(=…)` selects the same library cases at the nextest layer. The official filterset reference documents these equality and binary-kind predicates: <https://nexte.st/docs/filtersets/reference/>.

Before each scope, the six real normal helpers are built through Cargo and recorded from compiler-artifact messages. The full catalogue may legitimately rebuild them with workspace features, so actual identities are independently captured after catalogue and before/after `just test`. Neither helper count nor package/graph counts are copied from the A lane. All original ignored and filtered cases are recorded separately. The three ignored owned-child support entries must be present but are never counted as extra passes.

JUnit must be fresh, have a new run UUID and match the exact catalogue names. Complete raw output and XML remain intact. Early-return notices are associated with case blocks where possible; an unbound notice remains a qualification failure. Counterfactuals require the approved physical marker order and the exact unchanged assertion's source line. Compile errors, setup failures, missing child checkpoints, released/timed-out callbacks, generic timeout, no tests, earlier assertions or a passing counterfactual cannot satisfy a negative gate.

Every negative has an exact-source `finally` transition. A bad causal result is saved, the known owned negative is restored to the approved positive, and execution stops. If source/index/HEAD/lock drift prevents proving ownership, restoration is refused rather than overwriting another change. The original and cleanup errors are retained separately.

## Real lock and Bazel gates

The two dependency epochs run normal `cargo metadata --format-version=1` without `--locked`, then the original root `just bazel-lock-update` and `just bazel-lock-check`. Only their declared active lock paths can change. Cargo package versions, checksums, graph nodes and features outside the reviewed driver or Memory edge must remain equal; an unexpected resolver change stops for review. No lock delta is predicted or handwritten. The nested published vendor Cargo.lock is preserved as source and is not the active workspace lock.

Each epoch uses its explicitly approved new private Bazel cache root, through the repository's existing `user.bazelrc` import. Original configuration flags remain in effect. The runner copies exact generated `@crates//:data.bzl` bytes located by Bazel, loads the actual new rule, and records its generated dependencies. B15 builds the new unit target under the original plain host configuration; **this is registration/compilation evidence, not a claim that Bazel ran the 12 tests or that hosted platform CI passed**. The original 12 cases are run by `just test` in B14. A final owning lock check uses the original recipe.

The default A host/toolchain values are not embedded. Binding requires actual tool files, Rust 1.95.0, the repository's Bazel version, original recipe file hashes, the actual final source and both lock receipts. The current concrete runner is Linux x86_64 only.

## Review and preservation

`payload-manifest.json` contains every pre/post source identity. Five bounded JSON payloads contain all 112 exact source objects. `operation-order-validation.json` verifies the proposed operation stream, including every finally transition, reaches the same frozen final partial map. `payload-reconstruction.json` retains the actual isolated patch reconstruction. The Python tests exercise private-index preservation, preimage drift refusal, exact restoration after an invalid negative, refusal to overwrite foreign drift, lock-path confinement, symlink rejection and false causal endpoints. They are pure Git/Python tests, not physical SQLite experiments.

Every native command gets separate command/status/raw receipts and whole-source guards. A terminal index preserves complete originals and offers lossless zlib/base64 retrieval pieces for larger files, with offsets, byte counts, SHA-256 and CRC32. No raw tail is substituted for a complete run. The final owning epoch returns `AWAITING_HYGIENE_DIFF_REVIEW` even when the commands pass, so automatic formatting cannot silently acquire qualification.

Remaining B16 limits stay open: authenticated Current and the three-pool binder; normal Root signed producer/lease/revocation/FinalUse; unbound independent or non-opt-in opens; the original platform matrix; and final runtime consumers. Successful selected controls establish their specific custody and commit-hook properties, not those broader contracts.
