# inference.control adversarial audit — v2 candidate

## Reviewed candidate and evidence

The reviewed v2 baseline is `0a8c7eea57fdafe36bf72eb59fb4916880a8e278` on `codex/inference-control-boundary-capacity-20260929` (draft PR #1203). Main at `a126987b84737dbc2ee2592442a314117bddb4a2` contains an older implementation and is not an adequate proxy for this candidate. The separate main-based adversarial branch is also not the v2 implementation.

The initial production hardening changes reached `33e47cfd2eee9f27a7d633bd0a18e7b9ce7fb699`. Subsequent real-fixture validation exposed a complete-message output omission; later commits repair that behavior, qualification fixtures, CI/Bazel helper wiring and source navigation. The final validated source candidate is recorded in `VALIDATION.json`; these local checks do not grant execution qualification.

This audit covers source, tests, the canonical current-state manifest, generated projections, the technical guide, operations, writer boundaries, module dossier, readiness guidance, and hosted CI failures. It does not establish live provider execution or authorize activation.

## Project-level optimization boundary

The module should remain the owner of inference requests, reservations and receipts. Provider execution stays in the native worker and Codex adapter; authority, secrets, scheduling, Neuron state and billing remain with their declared owners. The writer actor is the serialization boundary, and external provider waits must remain outside it.

The next completion packages require real integrations and evidence rather than more local control-layer abstractions:

1. Compose a real scheduler and Neuron daemon port with stable request identities and consumer deduplication.
2. Bind observed usage and device/local-weight measurements to independent economic and resource acceptance evidence.
3. Exercise live authority custody, rotation and revocation delivery at the final external-effect boundary.
4. Obtain vault encryption and deletion receipts, and establish archive retention/transfer and alert delivery.
5. Complete target-host provider, device, process-fault and long-duration capacity qualification, then independent acceptance.

Compaction is not an admission-identity garbage collector. Released and retired identities remain part of the bounded total identity set (default 16,384), and legacy durable events are retained. Extending lifetime requires an explicit deduplication/retention protocol before deleting identities. Archive references are bound by digest; startup does not traverse and rehash the entire archive chain.

## Iteration and validation

The first audit repaired replay, identity binding, writer ownership, state transitions and signed proof boundaries. A second independent cross-review identified application-time checks and checkpoint semantic/legacy-authority migration defects. These are included in the final candidate rather than left as recommendations.

Executable qualification fixtures now resolve a real local Codex helper, prepare the private evidence database with normal durability, verify App Server initialize/home binding before readiness, and own spawned tasks across startup errors or cancellation. The cold-start fixture budget is separate from unchanged worker RPC/provider deadlines. Eight message-event regressions cover full snapshots, streaming, ordering, duplicates, foreign events and bounds; actor expiry tests use an isolated deterministic writer clock. CI records prerequisite builds in all directly selected worker-library lanes, including the consolidated owner lane, and the artifact acceptor requires the corresponding build record. Bazel helper wiring was reviewed and formatted but was not executed locally.

The real Agentd fixture runs Agentd and App Server against loopback mock Responses using the compatibility `driver.run` test entry point. It does not prove the complete four-signature `run_authorized` production path or live paid-provider execution. The documented soak command now uses the complete libtest identity when selecting `--exact`, preventing a misleading zero-test invocation.
