## Minimal versioned protocol choices

1. **Keep the existing matched cumulative experiment.** Require the independent
   experiment owner to provide original authenticated historical capacity,
   cumulative work and allocation facts for both actual models, along with the
   matching training/update experiment. Preserve the original parent binding
   and every current B gate. This supports the existing scientific comparison
   but does not infer those histories from a new online delta.

2. **Design a separate online-incremental comparison profile.** Freeze a new
   protocol/version before training. Keep the exact original parent, common
   independently controlled holdout, prediction budget, input/feature contract
   and decision thresholds. Explicitly charge the candidate's measured new
   training, preparation and I/O work; retain any unavailable historical cost
   as unknown. Test net benefit and resource limits under that declared
   estimand rather than silently asserting equal cumulative histories. This is
   closer to ordinary incremental use but is a different experimental claim.

Neither option is implemented or selected by this slice. A future profile needs
an explicit digest/schema, original source and meter provenance, current role
and controller separation, retained holdout/experiment files, and conservative
handling of unmeasured work. It must not reinterpret old frozen profiles.

A real meter must observe the work it charges. Exact native CPU intervals,
pipeline overhead and verified no-work stages need explicit ownership and
allocation. Adding fixed twelve-stage entries, converting absent CPU to zero,
or double-counting shared work is not a valid adapter.
