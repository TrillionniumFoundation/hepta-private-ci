# Original learning / independent NextUse: byte-custody precheck (HOLD-only)

Run `python3 -m unittest discover -s qualification/learning-original-custody -p 'test_*.py'` and `python3 qualification/learning-original-custody/audit.py /authorized/manifest.json`.

This is an **offline integrity and inventory precheck**, not a source of truth, cryptographic verifier, evaluator, owner/holdout grant, selection authorization, or economic qualification. It can say `integrity=PASS` only for the **provided files**; `status` is always `HOLD`. A different credential chain, actor ID, controller or signing key does **not** prove different human/organization control. In particular, the `operator_custody` map is **self-reported**, not independently attested. Its role labels are compared after NFKC normalization, trimming and case-folding; aliases differing only in casing, surrounding spaces or compatibility glyphs fail the declared-separation precheck. This is not a real-world identity match: multiple distinct strings, signing keys or controller IDs can still belong to one operator. Declared costs are not proven complete against a provider's original invoice/attempt inventory. File bytes must be obtained from the original authorized owners and authenticated by those owners' existing signature/current-trust and rollback-frontier rules, *outside* this checker. Never promote a production model based on this result.

Expected manifest (`schema: hepta-original-learning-custody-precheck-v1`): pinned 40-hex `source_head`, original `operation_id`, distinct `next_operation_id`, distinct `source_task_id` and `next_task_id`, immutable 64-hex `baseline_bundle` and `selected_bundle`, `decision` (`adopt` for changed version, `no_update` for unchanged), and mandatory `no_update_origin` (`trainer`, `evaluation` or `proposal`) whenever the decision is `no_update`. `operator_custody` must claim distinct `trainer` / `selector` / `observer` operators, and additionally `evaluator` / `holdout` on evaluated paths. The **adopt** path requires ten named `original_receipts` (`experience`, `dataset`, `training`, `evaluation`, `proposal`, `selection`, `published_current`, `final_use`, `next_use`, `learning_next_use`). The `proposal` receipt is mandatory: the original coordinator requires `Evaluation(Qualified) -> Proposal(UpdateCandidates) -> Selection`. An original *trainer* `TrainingNoUpdateV2` instead requires eight inventory files, excluding both Evaluation and Proposal; an **evaluation-origin** NoUpdate requires nine, excluding only Proposal; and a **proposal-origin** NoUpdate (`Proposal(NoAdmissibleUpdate)`) requires all ten. The inventory has seven original coordinator stages along the longest branch (Experience through NextUse), plus external publication/FinalUse and an *independent ordinary consumer* receipt; the coordinator's terminal `learning_next_use` is not itself a distinct ordinary task's receipt. This corresponds to the real coordinator's stage transitions and prevents inventing an evaluator execution or Proposal when not executed. Selection, retained-version publication/FinalUse readback and a distinct-task NextUse remain mandatory; a NoUpdate does not create a newly published model. Each receipt is `{file, sha256, operation_id, task_id, bundle_sha256}`; `next_use` (the ordinary consumer's receipt) also supplies `learning_operation_id` linking back to the original learning operation; `learning_next_use` (the original coordinator's terminal signed-stage receipt) instead retains the **learning** `operation_id`, and supplies `next_operation_id` and `next_task_id` links to the ordinary consumer; files are regular, local, at most 64 MiB, rooted in the manifest directory, not symlinks, with distinct paths/digests. Stages except the ordinary consumer `next_use` bind the learning operation and source task; the ordinary consumer binds a **different operation and task**, with an explicit original-learning-operation reference. The terminal `learning_next_use` binds the original coordinator operation, never the consumer's operation: `LearningIterationCoordinatorV1::record()` rejects a terminal receipt with a foreign operation before recording it. The consumer and coordinator receipts are both mandatory; a single receipt cannot stand in for the two. Selection/publication/final/ordinary-next-use/learning-next-use bind the selected immutable bundle. Selection and the coordinator's terminal learning-next-use must additionally declare matching 64-hex `selection_digest` values: an unchanged bundle digest alone cannot establish that the original decision was the same. This is still only a declaration until both original signatures are revalidated by the real owner. As elsewhere, these manifest links are self-declarations and MUST be reconciled with the genuine signed originals by the authorized owner. The self-declared `admitted_attempt_ids` must match `attempts`, each with exact `id`, `state` (completed/failed/cancelled/pending/unknown) and nonnegative finite decimal-string `cost_usd`, including failed and cancelled attempts. Pending/Unknown are *not* success. Decimal arithmetic rejects overflow, nonfinite amounts and any nonzero cost digits silently dropped by the default precision: affected attempt entries fail integrity rather than crashing or overstating the precision of declared totals. This still does not verify the provider's real charges.

The manifest parser rejects ambiguous duplicate JSON keys at any nesting level, non-standard NaN/Infinity constants, and manifests over 2 MiB **without reading more than 2 MiB + 1 byte**; malformed/deeply nested documents fail closed. Original receipt files are read from a single opened descriptor with regular-file `fstat` checks and a 64 MiB byte ceiling enforced *during* hashing, not merely by a path-based pre-read `stat`; the checker pins each directory component via descriptor-relative `O_DIRECTORY | O_NOFOLLOW` and the leaf via `O_NOFOLLOW` before regular-file `fstat` and bounded hashing. Any symlink in the path, including a directory alias pointing within the manifest root, fails closed; platforms without these descriptor primitives return a failed byte check instead of falling back to unsafe path traversal. This is a defensive local precheck, **not** an atomic owner snapshot, cryptographic signature verification, an external trust anchor, or a proof of current custody. These checks prevent conflicting metadata from receiving a misleading byte-inventory PASS; they still do **not** authenticate an original receipt or actual operator custody.

The synthetic unit tests exercise only rejection and accounting logic and cannot be counted as real customers, external operator custody, independent holdout, real Q24 training, Root cold recovery, statistically significant net benefit, or authenticated receipts. External owner trust, original data rights / deletion frontier, signed one-time holdout admission, genuine Selection, CURRENT/FinalUse, Root restart and future NextUse, actual all-in opportunity cost and randomized prospective retention/benefit remain independent gates.

This tool is deliberately in a new qualification-only directory to avoid changing #5627 / #5735 Q24 native sources, #5720 delivery/recovery, daemon blocking CI, Rustfmt or RustSec. Its `PASS` must never be mapped to product `Eligible` or `Closed`.
