# Retained b12 failures and narrow successor

These are read-only verifications of the original failed run, not passing product qualifications. The complete original Windows and Bazel bridge logs are retained as gzip containers. Their decoded byte counts and SHA-256 values are in `DIAGNOSIS.json`; each original artifact ID, ZIP digest, exact source snapshot check and output check is recorded in its `*-VERIFIED.json`.

The Windows failure occurs in the new spelling test before recovery is invoked. Its test-owned home must use one physical spelling before testing native/verbatim namespace equivalence. The candidate leaves production comparison strict. The macro import is a compile fix using the existing assertion library.

A materialization creates a directory entry, so a retained directory snapshot is not expected to remain equal after that operation. The successor keeps the old validation before the copy, verifies database bytes and all three sidecar byte/absence observations afterward, then binds and validates a new source snapshot. It does not treat the new snapshot alone as proof of source preservation.

Bazel executed the original path, state and Memory targets successfully, but the old collector looked for an unsharded state report. Scoped Clippy was not reached. The successor retains all four fresh state shard log/XML pairs and checks their exact test-name partition against the compiled inventory; no missing, duplicate, retried or filtered-away case can stand in for the full library.

The macOS raw-error projection was still queued when this candidate was assembled. Two existing owned fixtures omit physical canonicalization, while the original Unix retained binding requires it. Only those fixture paths are normalized. The new original native run must establish the result; this source observation is not a claim that the macOS failures have passed.

The 24 reader controls and all original native/Bazel gates must execute on the new exact source. The product remains Draft/HOLD until then.
