## 2. Executed workload and causal boundaries

The new `v28_physical_lazy_vision.py` measures the actual frozen vision backend through the unchanged original `FrozenVision.encode` model owner. One CPU float32 DINO checkpoint is loaded once, verified before and after, then warmed up using a TRAIN image. Four repetitions run in predeclared **ABBA** order: all 64 original TEST images, conditional 21, conditional 21, all 64. Input batch ceiling = 8; for the known roster, expected real backend-call counters are **8, 3, 3, 8**. The conditional arm MUST NOT read any of the 43 non-triggered TEST image files; the all-64 arm reads each original image. Reuse of the same model/processor across arms controls for redundant weight loading. All 21 selected normalized 384D outputs must numerically match the corresponding original-image results from each all-64 arm within 1e-4 maximum absolute deviation.

Each measured arm reports actual count of source images, physical encode batches, input media bytes read, process CPU nanoseconds, and wall nanoseconds. Also record real checkpoint material SHA256, model load/acquisition wall nanoseconds, warmup count, and **one-process** Linux peak RSS. A process RSS high-water mark is *not* a per-arm memory saving; neither energy nor GPU is measured. The separate publisher image decode/staging, original text-Encoder inference, source download, original TRAIN bridge and Cell-Head learning, model acquisition and any future authentication/storage/recovery are **not** included in measured per-arm times. Consequently `physical_end_to_end_savings_proven=false` is mandatory even if conditional arm uses fewer actual DINO forwards.

This is an inference-cost diagnostic on a historical data sample, NOT an end-to-end policy or a prospective utility experiment. The original DINO vision encoder processes the image independently of text, so it is genuinely avoidable when the text-based route skips it. The published V25 original-publisher label revisit already established **text-only 17/64, conditional 17/64, 5 rescues, 5 harms, paired McNemar p=1.0**. V28 does not retrain, rescore labels, tune the threshold or claim any accuracy gain. The difference between an observed decrease in DINO-only CPU work and a beneficial quality-adjusted deployment remains an open acceptance question.
