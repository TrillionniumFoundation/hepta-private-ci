# V4：真实 token 表征与证据干预

本轮解决的具体问题是：上一轮共享句向量 Reader 对删除证据反应很弱。
代码改为保留真实冻结 Encoder 的 token 输出，并检查模型能否根据证据变化
改变答案。小样本拟合、使用独立人名与物品词表的受控任务和自然段落泛化分别评测。

## 实现和边界

共享基座仍是固定 revision 的 Granite 97M；74 个权重 tensor、97,441,152
个参数均冻结。它是当前已验证的实验基座，不是通过本轮证明的全局最优
“干细胞”。本轮没有训练 Encoder、增加图像或时间模态，也没有证明能力
已经沉淀回共享基座。

`token_features.py` 保留完整非特殊 token ID，以最多 64 个模型 token 分块，
每块含起始与终止两个特殊符号，净内容最多 62 个 token。证据、问题和
候选答案分别缓存。Encoder 的上下文在块边界重置；跨块信息需要 Reader 组合。按原字符串共享缓存，动态填充小批次；超过几何上限的
完整案例明确失败，不静默截断。公开特征不包含标签或证据标注。

`token_reader.py` 用共享低秩投影、问题/候选与证据 token 对齐、两级证据
注意力和有界递归状态分类。每个 hidden=32 的研究 Reader 共 38,466 个参数；
14 参数 critic 另计。池化对照先执行相同的逐 token 归一化和投影，再折叠 token，因此参数数目相同、实际工作量
不同。它是表征对照；不是经过专门优化的最便宜向量 Head。

`token_execution.py` 复用真实 `run_reasoning` 循环、独立冻结 verifier、
冻结 critic 和已有 Q32 Rust 控制器。原生决策发生在下一次 proposal 之前，
实际后续开销违反观测界限时关闭资格。这里使用一个经验 next-correctness
预测，不是一般 FBSDE 求解器或未来净收益保证；尚未接入生产 NDU owner。

## 训练内诊断与冻结配方

先检查 8 个完整自然训练问题，共 45 个候选、2 个源段落；再加入 16 个
受控候选。每对受控世界的问题、候选和词频完全相同，只交换所有权证据，
正确答案必须翻转。自然任务的删证据不会产生新的负标签。

真实特征暴露了模拟特征测试未发现的问题：

| 训练内方案 | 自然准确率 | 受控双世界全对 | 解释 |
| --- | ---: | ---: | --- |
| 原始混合批次，lr .003 | 100% | 0% | 单独记住自然案例不足以证明证据学习 |
| 合成任务单独训练 | 不适用 | 100% | 冻结表征可支持这个任务的拟合 |
| 交替批次，lr .003、干预概率 .25 | 86.67% | 0% | 稳定激活后仍出现联合学习干扰 |
| 投影后归一化，lr .003、概率 .25 | 100% | 25% | 未解决联合保留问题 |
| 合成预热 128 步再联合 512 步 | 100% | 25% | 预热后的能力仍会遗忘 |
| lr .001、干预概率 .5，1000 步 | 100% | 100% | 满足原定联合拟合门槛 |

另一个早期交替训练尝试暴露指数 sigmoid/tanh 的反向溢出。代码将指数输入
限制到 FP32 已饱和的范围，增加有限梯度检查，并在失败时保留完成更新和
包括失败尝试的真实成本。该旧失败运行未保存完整更新收据，其成本保持
未知，不能补成零。其日志与后续诊断均保留。

采用最后一行配方后，通过正式 CLI 再跑一次联合门槛：自然与受控任务均
100%；删证据后的受控准确率为 50%，双世界全对为零。这个门槛只证明
训练内可优化及保留，不证明泛化。学习率和采样概率同时改变，不能把改善
单独归因于某一个改动。没有为通过门槛而降低 95% 的原标准。

## 预先固定的数据与对照

官方 MultiRC-v2 的源段落以内容哈希划分，固定 seed 41：64 段训练、
16 段内部调参，verifier、critic fitting、critic calibration 各用另外
8 段，互不重叠。官方文件没有证据句标注；显式支持监督仅来自生成任务。
受控生成器的 train/tune/final 人名与物品词表互斥，语法和颜色词共享；
这不保证这些词从未出现在 Encoder 预训练或自然任务训练语料中。

新留出是 16 个此前未参与评测的官方验证段落：945 个候选、187 个完整
问题。V3 已评测的 16 段、747 个候选仅作回归，不能再次算作新留出。
全部 83 个官方验证段落此前已经由加载器解析；“新”指未参与成绩评测和
方案选择，不是从未打开过这些字节。三种子重复评测相同案例，不能把
2835 次运行当成 2835 个独立样本。

每个 seed（41、47、53）分别训练五个模型，每个 1000 次 Adam 更新：
池化一步、token 一步、干预 token 一步、干预递归、单独训练的无证据模型。
递归模型另外执行一步和状态重置对照，共七种设置。干预批次替换约一半
自然批次，真实曝光次数和递归深度保留在收据中。

每种设置只用同一组内部调参段落，在 0.05–0.95 的固定网格选择判定阈值：
依次比较 F1a、问题 EM、离 0.5 的距离和较低阈值。另保留固定概率 >0.5
结果及全正/全负基线。受控任务必须同时报告双世界全对，不能把删证据后
全预测正类得到的 F1a 2/3 当作推理成功。模型和阈值全部冻结后才评测新留出。

## 原生控制研究的解释范围

原生对照为 fixed1、fixed3、native NDU、no verifier 和 reset3，全部使用
相同的 argmax 判定规则。verifier 在独立段落训练，之后才采集另外两组
公共轨迹；每组全部轨迹执行完毕后才读取该组标签，两组数据均完成后
再训练及校准 critic。原生参数与成本配置必须早于主实验首次留出评测冻结。

本次主评测成功后，原生 CLI 的首次启动在推理前被元数据检查拒绝：
训练时把文档 `schema` 改成 native campaign 类型，评测时却要求它与
membership 协议类型相等。三方独立核对全部 14 个 membership 字段，只有
这一个命名空间不同；原 40 个源码、二进制、选择文件和权重均匹配。
失败日志和完整进程成本保留。`native_token_schema_recovery.py` 是主评测后
新增、单独记录摘要的兼容入口，不属于原 40 文件冻结清单。它重复执行原始
完整来源校验，分别验证两种固定 schema，并仅映射返回副本的 schema；
其余字段和原对象不变。它只允许尚无任何原生 final 输出时继续，记录
recovery start/completion，既不重跑主评测，也不更改数值计算或策略。
因此不能声称全部执行入口均早于主评测冻结；此前冻结的是全部学习产物、
数值执行逻辑和控制配置。恢复是否成功以独立审计为准。

主实验 token Reader 的反馈输入始终为零，对应参数列保持未训练的随机初值。
在任何原生拟合和新留出评测之前，原生 CLI 因此统一使用 `ZeroFeedbackReader`：
载入主实验递归模型的完全相同权重，但在每次 `step_prepared` 显式忽略反馈输入。
这项包装只位于原生 CLI，主实验已冻结的 39 个运行文件保持一致。
verifier 仍提供独立的接受/停止信号，既不修正 Reader 状态，也不提供正确答案。
critic 的六个数值特征仍来自状态、logit、步数及剩余步数，不使用 verifier 概率。
在该策略下，fixed3 与 no-verifier 的 Reader 预测应相同；该对照衡量验证开销。

learned verifier 的高置信同意不等于语义真值。现有模式没有新增普通自适应
门控对照，因此不能据此宣称 NDU 规则的独立优势。V3 的普通 gate 对照仍保留，
但不能替代本轮相同 token 基座的因果对照。

冻结执行器还有一个原始轨迹记录边界：决策 context 引用当前候选记录，
计量器稍后给该记录补上自身 value callback 的成本。原生请求绑定的是
补写前摘要，持久化 context 则可能含这个晚到的诊断字段。外部审计只允许
移除这一特定字段来重建 as-of 快照，并逐条核对原摘要；其他差异必须失败。
不能宣称原始 context 不可变。真实 Rust 自检已验证该重建，并拒绝七类
篡改；完整实验仍以逐条独立审计结果为准。

## 成本和审计

真实物理小批次的 CPU、wall 与可覆盖的前向公式工作量只计一次；它们
包含动态填充和计量开销，不是逐答案实测延迟。外层阶段收据还包含重载、
恢复、初始化、哈希、序列化和校验，内层拆解不能再相加。Encoder 缓存的
历史编码成本与当前重载成本分别保留。训练反向公式计量仍未知。

原生子进程 CPU 另加一次；原生 wall 已包含在父请求 wall 中。逐请求成本
不包含随后写原始轨迹文件的开销，外层阶段成本包含该部分。相同更新上限、
相同参数和相同预算上限都不能视为相同实际成本；本轮不宣称严格等算力
或完整生命周期经济资格。

独立审计重读官方文件、完整候选集合、阈值选择、冻结文件字节和物理批次
收据；受控任务从事实语法独立求解。审计验证记录的一致性，不独立认证
计时真实性或硬件执行。复跑命令、版本与源摘要见相邻 runbook。
