# Registered office-sensor boundary comparison (UCI 357)

Hypothesis: on temporally held-out office days, fixed nominal centering of an actual learned QVI boundary improves occupancy predictions over transmitting its raw level. Independent claims concern signed/joint messages, an ordinary learned threshold, and conventional sequence encoders. This campaign uses the Candanedo–Feldheim office dataset (UCI DOI 10.24432/C5X01N, CC BY 4.0) with one monitored room and its genuine measurement times. The earlier UCI 864 occupancy estimation campaign used a different dataset, target and model. Actor/source independence beyond a future date within this room is outside this design.

Pin LuisM78/Occupancy-detection-data at ba2b1d7b53a71292ff61b867d3e16f0e539c7eb6 and TrillionniumFoundation/hepta-private-ci at c4ae70d44613434aaf165529a6076fa3400ca431. Use the original published BoundaryControlHCSN and sequence baselines, no intervention in the source modules. Use 8 consecutive actual near-minute reads, maximum 32 disjoint windows uniformly selected per date per source file, without label-based balancing. Never cross source or date boundaries. Input consists of temperature, humidity, light, CO2, humidity ratio and within-window elapsed-time deviation in seconds (zero first). Standardize on training windows. Clock interval admission is [58,62] actual seconds; the physical kernel advances in fixed model time .25 and receives clock deviations as content. Target is last observed occupancy. Calendar date is used only for partitions and per-day assessment. Calendar train through 2015-02-08, dev 2015-02-09 through 2015-02-11, test 2015-02-12 onward. Only training/development records feed fitting. Test evaluated after every fit has fixed its candidate.

Nine arms, seeds 601/1601/2601: N32 mixed uniformized full QVI boundary-only raw or centered, signed-only, centered boundary+signed, free learned centered threshold, fixed centered threshold (noncommunicating control); width16 GRU, LIF and causal attention. Identical causal input accumulation within all six HCSN arms. The generic learned boundary uses the released learned tanh policy. The two primary arms share the same allocated weights, mask, initialization, optimizer, minibatches and checkpoint schedule. Other architectures have different parameter counts, input encodings and active masks. The historical model sums its first four input coordinates on the slow control steps; mark updates remain on raw measurements. Conventional encoders see the same six raw normalized source coordinates. All use last-logit CE, batch 12, Adam .003, norm clip 2, 128 updates, uniform unweighted training samples. Select lowest development Brier on steps 0/8/16/32/64/96/128. A second checkpoint only considers validations completed in the first 20 seconds of the optimization/validation loop, capped at 128 updates. It is a 20 s prefix of a 128-step run, not an unconstrained time-to-quality benchmark. Peak RSS and fit-process wall recorded; no GPU/energy claim.

Primary result: test Brier centered minus raw, per paired seed. Require strict improvement at all three seeds for reproducible improvement here. Also report accuracy, balanced accuracy, per-day accuracy, date and class counts. Whole-data quality hypothesis relative to a conventional encoder requires a predeclared test balanced accuracy >=0.90 and Brier <=0.10 together, all three seeds; report time-to-quality only where thresholds are met, without inferring general scaling. No selection or retraining from test results. Inputs and candidate outputs retain hashes. The original model has two output logits; a fixed boundary and centered-only delivery has zero external signal path to receivers.

Reproduction: place the study files together with archived model checkout on PYTHONPATH. For each registered arm and seed run `python run.py fit --data AUTHOR_DATA_DIR --output NEW_OUTPUT --arm ARM --seed SEED`. After all 27 runs finish, run `python run.py confirm --data AUTHOR_DATA_DIR --output NEW_OUTPUT`. Each fit and the final seal use create-only output. Standard Python, NumPy and CPU PyTorch are sufficient.
