# 真实办公室传感流上的自由边界通信

用仓库固定版本的 N32 `BoundaryControlHCSN` 训练 81 个独立进程，检验温度、湿度、照度、CO₂ 和湿度比随时间变化时，发送端的内生边界能否向接收端传递占用信息。目标是给出第八次记录时有人占用房间的概率。数据来自 Candanedo–Feldheim 的一间办公室，分钟照片产生占用真值。数据集 UCI 357 与此前仓库的 UCI 864 为不同研究。[UCI 数据与许可](https://archive.ics.uci.edu/dataset/357/occupancy+detection) · [作者固定数据版本](https://github.com/LuisM78/Occupancy-detection-data/tree/ba2b1d7b53a71292ff61b867d3e16f0e539c7eb6)

## 结果

数值依次给出三次初始化在同一测试窗口集合上的平均平衡准确率与正类概率 Brier。准确率越高越好，Brier 越低越好。达标数是同时满足 BA ≥ 0.90、Brier ≤ 0.10 的种子数，每项分母为 3。首两列在同一批 224 个窗口中有 41 个占用窗口。末列结果来自另选的 **224 个窗口，其中 39 个有占用，与先前 224 个窗口共用 0 条传感记录**。新窗口与先前窗口来自相同的七天，周末也包含在内。

原始边界与名义平衡边界中心化的差异，是本实验最严格的配对比较。相同种子的两模型具有相同初始化、数据、批次序列、物理模型、通信掩码和参数数目。固定步数下，三组 Brier 均下降，均值从 0.1578 降到 0.0809。修正早期验证后，互不重叠的新窗口逐种子差值为 601（-0.03199）、1601（-0.07451）、2601（-0.03595）。对首轮已冻结的三个中心化模型，发送者的边界消息保持原样、置零、跨样本置换分别得到 BA 0.873、0.500、0.488 和 Brier 0.0809、0.1626、0.2741。该干预使用已检验过的测试样本，说明接收端的占用预测依赖发送端传出的边界，不估计跨办公室泛化。

相同步数下，原始单边界和固定边界均落在 BA 0.500；中心化自由边界能学会任务，但未在三种初始化中达到完整双指标门槛。仅带符号的越界流和联合通道在首轮均 3/3 达标。联合通道有两倍的有效循环连接，不能将其增益全部归于中心化。全量训练 128 步时 HCSN 联合通道用时 24.97 秒，LIF 为 2.82 秒。补足早期检查点的 20 秒实验中，GRU 和自注意力的平均 BA 高于联合通道，Brier 也更低。两组实验同时更换了检验窗口和验证日程，差值无法归因于其中单一因素。训练时间受 CPU 核及并发负载影响。完整结果支持此任务上的特定通道效应；要估计训练大模型、长上下文、多房间、多任务和端到端耗能的差异，需相应规模和硬件的观测。

## 对照与排除条件

- 原始模型锁定于 `c4ae70d44613434aaf165529a6076fa3400ca431`。19 个模块的路径和 SHA-256 在 `upstream.json`。HCSN 共 32 个神经元，16 个发送、16 个接收。只有发送者看原始记录，只有接收者连到读出。边界或带符号越界率各有 768 条有效循环连接，联合有 1,536 条。有符号、无符号事件消息不同，本实验全部屏蔽无符号通道。HCSN 各有 3,522 个分配参数，GRU 1,186、LIF 386、因果自注意力 2,370，后者均宽 16。模型使用同批数据及共同质量标准，参数量、内部输入处理和图容量不同。
- 各窗口按源文件和日期连续切为八次采样的互不重叠块；有任何相邻间隔在 [58,62] 秒之外即排除。从每个文件每天的候选块中均匀选择不超过 32 个，不按标签分层，不跨文件或自然日，不输入日期和文件身份。五个测量通道与第六个 `delta_seconds – 60` 同时输入；首帧差为零。在训练窗口上按维度求均值与标准差并截断到 ±6。物理步长为固定模型时间 0.25，真实时钟偏差通过输入通道传入。慢控制每两步更新一次，沿上游原实现累积前四个特征，标记分支每步读取原输入。
- 训练用 2015-02-02 至 08（256 个窗口），开发用 02-09 至 11（96 个），测试用 02-12 至 18。按绝对日期划分可处理作者多个源文件含有同日样本。三种子为 601/1601/2601。Adam 0.003，batch 12，最后一步二分类交叉熵，梯度范数截断 2。所有候选均按开发集最小 Brier 选取。每次全体 27 个拟合封存后统一评测。数据检查会读源文件做完整 SHA-256，训练进程不构造测试样本与测试指标。
- 第一种协议提供 128 步和 20 秒前缀；后者受 128 步上限约束，仅为诊断。第二种协议无限制地训练 20 秒，在 0/3/7/12/16 秒验证。快速基线的第一次非零验证已训练数千步。第三种协议在相同墙钟点以及步数 0/8/16/32/64/96/128 验证，选出最小开发 Brier 且在 20 秒内完成验证与候选权重复制的模型。机器为共享 ROG CPU，每进程固定在单一逻辑核，分别为 6/4/6 并行。单独记录从子进程启动到退出的完整时长，此时间包含数据加载、优化器建立及导出。早期首次启动第三协议时系统解释器缺少 PyTorch，六个进程在模型创建前退出。其日志保存在 `wallplus_bundle.zip` 的 `setup_attempt` 中。切回前两轮同一环境后，81 个正式拟合全部成功。
- 第一、二种协议先于检视其测试得分登记；第三种协议在发现检查点调度可能给慢模型造成不同选点机会后登记。第三种保留原训练/开发窗口，另按同样规则从余下的测试块选择数据；测试日期和地点与先前一致。生成函数逐元素核验此前训练及测试张量，并断言旧测试窗口终点与新窗口无重合。块索引按八条完整传感记录互不重叠。三种子的差异描述初始化与训练，不能按三栋独立建筑计算置信区间。

## 复核与复现

在本目录执行 `python verify.py`。只依赖 Python 标准库，以封存文件校验每个原始权重、逐窗概率、完整流程退出码、适格检查点、指标和源版本。原始两个协议的汇总 JSON 与 CSV 必须与重新生成的文件逐字节一致。第三种的汇总为 `wallplus_summary.json`。`sender_intervention.json` 保留逐窗干预概率及权重指纹。

在授权可访问仓库的环境中，将上游模型固定到前述提交并加入 `PYTHONPATH`，在作者固定数据的目录上依次执行 `python launch.py --help`、`python wall.py --help`、`python wallplus.py --help` 所示的独立输出目录命令。`protocol.md`、`wall_protocol.md` 和 `wallplus_protocol.md` 是各自冻结的协议；训练运行所用源码与预先登记的 SHA-256 均进入归档。Data credit: Luis Candanedo and Véronique Feldheim, *Accurate occupancy detection of an office room from light, temperature, humidity and CO2 measurements using statistical learning models*, Energy and Buildings 112 (2016), 28–39.
