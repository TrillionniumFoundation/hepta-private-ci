## Common information, interface and oracle

All three models receive identical first-turn task messages, the same four original BEFORE files and unchanged upstream tests, the same greedy 8192-input/2048-output policy, the same native 32768-token context limit, and two current-policy calls per task. Complete input plus output reserve is checked before generation; no silent truncation occurs. Model manifests, actual adapter parameter digests and the original collection policy are checked on every cold load.

The interface accepts exactly one closed Python block containing the allowed complete function and, for platformdirs only, the explicitly permitted bounded regex constant. The trusted old span, file path and original SHA are derived from the bound BEFORE source. The new function text comes from the model. The adapter does not fill a repair from the reference. The converted edit is submitted to the unchanged original admission and native sandbox verifier.

Some structural negatives are rejected by this wrapper; signature, decorator and regex-literal changes remain rejected by the original native admission. Their actual stages are retained, not relabeled as wrapper coverage. The native oracle keeps immutable tests and dependencies, isolated network/PID namespaces, dropped capabilities and a writable output area.

Before generation, the original CPU qualification ran eight real before/after sandbox children: all four maintainer reference edits reconstruct exact complete AFTER bytes, all 114 after cases pass, and all 70 rejection controls fail closed. The combined before/after run contains 228 original case executions. There are no model calls or training updates in that qualification. Its original [CPU archive](cpu/CPU_QUALIFICATION.tar.xz), [result](cpu/RESULT.json) and [index](cpu/INDEX.json) remain unchanged.
