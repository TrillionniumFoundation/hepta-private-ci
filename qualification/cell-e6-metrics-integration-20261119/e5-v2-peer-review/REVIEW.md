# Independent source review of the frozen E5 retrieval v2 candidate

Reviewer: research subagent. This is a source-only review of the candidate and its explicit trust boundary. No model call, training update, upstream native task, target construction or future B/C access was performed. The review does not edit the candidate, its policy, frozen views or source order. The companion manifest pins the exact reviewed files and the independently observed input freeze.

## Overall finding

The reviewed implementation establishes a useful separation between a before/task-only selector and a compact action bound to a separately frozen view. I did not find an after-runtime channel, self-referential digest or unit-boundary truncation in the reviewed selector and action path. That conclusion assumes the caller supplies the original independently verified material identity and passes the expected view digest from the input freeze. It is not a proof of arbitrary-caller provenance, semantic closure, production authorization or training effectiveness.

The candidate still needs exact native-template token measurement and a separately frozen target path. Byte packing alone cannot establish the original 3200-token prefix reservation, 384-token full continuation allowance or 3584-position total SFT limit. Original optimizer-unit meaning, compute/verifier budgets and independent B/C bindings are not established by this implementation. The explicit training-admission rejection is appropriate.

## Concrete checks and their limits

1. **Digest graph is acyclic.** `select_once` hashes the payload before rendering. The digest is supplied to the renderer; the outer view separately hashes the resulting prompt. The payload does not contain its own digest or rendered prompt hash. This resolves the earlier design concern about embedding a self-dependent hash. The reviewed relationship is payload → view digest → rendered prompt → outer prompt receipt.

2. **Authority comes from an independent expected pin.** `validate_view` requires equality between the submitted digest, the separately supplied `expected_view_digest`, and the recomputed payload hash. It verifies exact code, policy, material and runtime binding identities, regenerates the prompt, and compares selected units against the original source inventory. This works only when the expected pin is obtained from the trusted immutable input freeze. A caller copying a submitted digest into that argument would remove this protection. Internally consistent hashes also cannot prove that a malicious caller labeled authentic after material as before; the original material/prefix binding remains a prerequisite.

3. **Visible input and task provenance are accurately scoped.** The selector's visible-data API accepts identity, identity SHA, runtime, task and original case diagnostics; it does not take a material-root, store or after argument. Reused trusted loading and independent material identities provide the source boundary. Original task/test bytes are the fixed tests used in the upstream before/after verification; some originate in a repair revision. They must be described as original task input, not universally as bytes predating every repair. Their presence is distinct from runtime-after supervision.

4. **Packing preserves complete selected units.** Mandatory diagnostic/task/runtime items are refused if they cannot fit. Optional items are omitted as whole items, and the omission is recorded. Python/Cython units with matching path counterpart, qualified name and kind are grouped or refused. Compact runtime ordinals resolve to the selected original inventory; strict integer checks reject booleans and edit scope is passed into the existing source-action checks. These checks do not establish semantic dependency closure or that the selected unit is sufficient to solve the task.

5. **The advertised AST counter is partial.** The 250000 counter bounds lexical semantic walks in `semantic_text`; it does not count every parse performed by the reused source inventory, second binding pass or primary-test parsing. Task data may be up to 32 MiB. CPU/wall checks run at work checkpoints and after work, not as hard parser preemption. This was reported as a material limitation. The separate `COST_AND_TRUST_ADDENDUM_1.md` now states it without changing the source, policy, view selection or refusal. The value must not be reported as a whole-pipeline AST bound or denial-of-service guarantee.

6. **Bytes and tokens remain separate gates.** The selector enforces a 12000-byte view bound, not the 3200-token native-template prefix reservation. Later CPU-only measurement must use the pinned tokenizer and complete original chat template, including envelope and generation prefix. Any overflow must remain a refusal at the original ordinal: no reranking, repeated retrieval, source substitution or target-informed packing. The eventual 384-token target must include the full compact action envelope and native continuation suffix/EOS convention. Multiple edits cannot silently become multiple updates or calls.
