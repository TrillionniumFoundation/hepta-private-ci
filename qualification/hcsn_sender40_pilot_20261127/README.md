# One sender-drive Weight-Space Programming CPU pilot

This package prepares one small, prospectively bounded scientific experiment on the already-public seed-47 SmallHCSN checkpoint. The repository named `hepta-private-ci` is publicly visible. Every model, task input, original Python source and historical qualification witness is pinned to an existing public commit in `public_inputs.json`. No Pocket4 checkpoint, account, quote, log, credential, private feature cache or other private artifact is an input to this lane.

The scientific question is whether a label-informed, closed-form sender-drive proposal can improve the fixed development task while preserving the historically observed retention task, compared with task-loss backpropagation using exactly the same 40 F32 parameters and radius. The editable values are `body.input_drive.weight[4,9]` and `body.input_drive.bias[4]`. The readout, all other registered tensor/buffer bytes and the original readout aliases stay fixed. The absolute combined Frobenius radius is 1.0; this is approximately 80% of this parent's sender norm and is not a small edit. Torch serialization creates a new container. It does not preserve the original ZIP/header bytes. Before candidate evaluation, the actual saved complete checkpoint is loaded with `weights_only=True`, all tensor/buffer values and aliases are checked, and the original full model is evaluated from that loaded state.

## Frozen scientific scope

`PROTOCOL.json` is the complete preexecution specification. Its predecessor and the independent CPU/native prerequisite amendment were preserved before code execution. This lane does not require the separate native Runtime qualification in order to establish a result about the original Torch graph. It also does not establish native owner, transaction, deployment or production eligibility. The older 12-call native core qualification and the separate 3-call hidden engineering protocol retain their own budgets and evidence.

The analytic rule uses actual sender drift at slow ticks 0, 2 and 4, averaged separately for semantic match and decoy roles among parent-correct training queries. A role means `choice_index == target_position`, not that one gallery slot always means match. The parent-correct mask and these prototypes are supervised fitting and their cost is included. A strict `atanh` inverse compiles the targets into a shared 10-by-4 affine update, including bias, with the old recurrent term held fixed. One protected ridge/trust-region solve produces the predeclared 0.25 and 1.0 candidates. Its optimality applies only to that frozen-key quadratic surrogate. A caller-selected drift prototype is not a Bellman or NDU ground truth, and the actual nonlinear recurrence is evaluated after the edit.

The BP rule uses the same 40 coordinates, a 1.0 radius, 16 Adam updates and batch size eight. It evaluates binary cross-entropy in F64 from actual F32 scores. The additional parent-margin term uses only the current minibatch's members of the fixed parent-correct training mask; an empty intersection contributes zero. Its snapshots are steps 4 and 16. This task objective differs from the analytic rule's physical surrogate, so this comparison does not isolate the optimizer alone. Every step is compiled into an exactly verified F32 dyadic radius. The wrong-role and fixed-seed random controls are never eligible for selection. The random control uses the full analytic candidate's actual norm as a cap, then the same inward rounding guard. Its actual norm and remaining gap are reported; exact equal norms are not claimed.

Each main method gets its two declared candidates and KEEP. Candidate bytes for all six slots are sealed before any candidate development or retention evaluation. The earlier parent-only combined development/retention call exists for the predeclared historical producer qualification and parent reference metrics; its outcomes do not enter candidate fitting. Protection requires zero formerly label-correct retention queries to become wrong and a Brier increase no greater than 0.01. Among eligible options, selection compares development correct count, Brier, actual displacement, KEEP on a full tie, then declaration order. A development signal requires at least one extra development query correct and strictly lower training CE.

## What the data can establish

The train80, dev32 and retain32 archives, actors and prior outcomes have already been observed in earlier research. Four retention queries are quarantined by the original public acquisition erratum, leaving 28 for this new quality gate. This does not alter the older 32-query cache, rank proofs or native qualification. The old test48 archive is not extracted or evaluated by this package. No compatible, genuinely unopened confirmation set was found. This is a one-parent developmental feasibility pilot, with no independent holdout, population-level or HeptaTrader production capability claim.

The lane qualifies the actual original public `Hybrid`/`SmallHCSN` producer without replacing its six-tick rollout. A fixed two-query finite-difference check consumes three forwards and one backward. The same parent scores/features are compared with the corresponding items in the budgeted 80-query call, using frozen tolerances. The 28 eligible historical retention margins are compared to a deterministic, SHA-bound export of the original public result. Full source/profile/tensor/buffer identities and alias relationships are checked. A single finite-difference direction is not a full Jacobian proof. The original QVI backward is its analytic implicit derivative of the physical residual, whereas forward computes a finite 56-step root in mixed precision; the pilot reports the actual qualification outcome without equating these mathematical objects.

## Budget and failure accounting

There is exactly one eligible workflow run and attempt, on the exact research branch, with one reviewed parent commit and eleven new code/protocol files. No `workflow_dispatch`, PR trigger, secret, shared runner, GPU or production workload is used. The audited existing workflows at the fixed base match none of these new branch/path changes. Dependency setup uses a new temporary venv and binary wheels only. Direct package versions and the resolved package inventory are recorded; transitive wheel hashes are not claimed to be locked.

The experiment budget is 33 complete wrapper forwards, 198 original body-tick calls, 1,114 paired-query rollouts, 17 outer backward calls, 16 optimizer steps and two protected quadratic solves including the wrong-role control. Six additional linear recurrences are replayed only to recover and bit-check the captured parent preactivation; they are separately counted and are not hidden full rollouts. Original QVI custom backward uses nested analytic `autograd.grad`, whose computation is included in the actual cost. All numerical work uses one CPU/thread. A dedicated cgroup requires at most 1 GiB memory, one core and 64 tasks. The supervisor stops at 180 aggregate CPU seconds or 300 wall seconds, subject to its 0.2-second observation interval and OS scheduling. The 20-second per-forward/per-backward gate is checked on return and is not an atomic preemption deadline. A 330-second service limit is a second outer guard.

Every model call and body tick is charged and durably logged before invocation. Failures retain started/partial counters, partial candidate files, stdout/stderr, complete preceding ledger records, resource status and the source/checkpoint readback. Qualification, physics or resource failure aborts the whole attempt. There is no automatic retry, substituted parent, relaxed threshold, new direction, changed epsilon or increased radius. A quality-negative completed run can select KEEP. The parent is restored in memory in the normal/error cleanup path; this is a scientific process restore, not proof of a Runtime owner transaction.

`METHOD_COSTS.json` reports each method's whole two-candidate fit/compile phase and both candidates' complete evaluation cost. Shared imports, model initialization, qualification and parent tracing are shown once, with an explicit allocation to each method if desired. Those allocations are not separately timed cold runs. Dependency setup is recorded separately. Raw process/cgroup cost and every failed call remain available. No speed advantage is inferred merely from direct editing avoiding parameter gradients.

## Prepared entry points

The single workflow performs the following fixed sequence:

1. Check the exact base parent and new-file publication scope.
2. Install the fixed CPU packages into an ephemeral venv.
3. Run synthetic `offline_controls.py` without importing Torch or opening task data.
4. Fetch and verify only public input bytes with `prepare_public.py`; decode the archived payload with AST, never execute its cloud submission script.
5. Invoke `supervise.py` inside the dedicated cgroup and start `pilot.py` exactly once.
6. Preserve the bounded public-derived result directory even when the run fails.

The preparation package itself contains no executed model result. Do not interpret authored controls, source review, or syntax checks as a successful native or Torch model qualification.
