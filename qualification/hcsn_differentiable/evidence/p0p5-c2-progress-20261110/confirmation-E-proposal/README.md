# Prospective E candidate — no execution authority

Read [PROPOSAL.md](PROPOSAL.md) for the decision and interpretation boundaries and [PLAN.json](PLAN.json) for the candidate roster, rules and unallocated budget.

The default is to preserve E. All six C2 continuations must terminate, independent recovery-chain/full-D replay checks must finish, and the selected common-LR three-seed groups must satisfy their declared training-adequacy heuristic. These are necessary conditions only. A separate root decision remains required; no script here launches evaluation or watches for an automatic trigger. This candidate is outside the separately frozen 1,800-second C2 auditor.

The original 12-configuration/three-tuning-seed and five-fresh-confirmation-seed protocol remains incomplete. This candidate considers one held-out-subject check of the existing seven families' three-seed systems. The 7,200-second/21-model proposal is neither an allocation nor permission to consume E.

[INPUTS.json](INPUTS.json) binds the exact protocol and source snapshots. Files under `source-context/` are byte-preserved historical input documents; their embedded relative links retain their original repository context and are not rewritten as new proposal links. [BUDGET-BASIS.json](BUDGET-BASIS.json) extracts only previously archived D replay timing and memory fields. No raw E data, active C2 output, production checkpoint or logits are read in preparing this candidate.

`assemble_candidate.py` is a create-only, standard-library document assembly script. It snapshots declared protocol/source files, parses already archived D timing JSON, validates internal proposal links, emits strict JSON and checks its archive. It does not import a model or a data loader. `ASSEMBLY-RECEIPT.json` records the narrow preparation scope; it does not confer numerical, training, scientific or whole-CI qualification.
