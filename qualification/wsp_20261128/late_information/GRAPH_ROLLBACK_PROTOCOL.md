# Graph and parameter rollback identity

This supplement is registered after the original late-task outcomes are known.
It is a structural restoration experiment, not a new held-out efficacy claim.

Use the existing three actual parent artifacts, deterministic DIRECT_SIGN
candidates and original 32-row RAVDESS RETAIN inputs. Preserve all source files,
input bytes, current parent hashes, outputs and the original failed unconditional
retention result. Only an isolated new artifact directory is written.

For each parent, reconstruct the candidate from the original parent with its
four explicit F32 price-coordinate replacements. Reverse those four edits into
a separate restored artifact, and require the complete restored file SHA256 to
equal the parent. Execute two fresh full-model evaluations on that exact restored
artifact and exact same RETAIN bytes: (1) keep the final-tick bridge graph as a
weights-only recovery negative control; (2) restore the original graph. The
second must equal the original saved parent feature, head and score bytes. The
first is reported even when it differs or loses decisions. No runtime deployment
or persistent-service crash recovery is claimed; this checks the semantic
contents that a real transaction has to bind and restore.

Additionally use retained full traces (zero new forwards) to compare DIRECT_SIGN
with bridge KEEP on the fresh late-quote task. All QVI boundary, drift, cost and
receiver probability-derived features must remain identical; only signed-mark
features may differ. Reset values, all readout parameters and all other model
bytes must be unchanged. Belief and learned Continuation-Q heads are not present
in this fixed model and are not declared repaired.

CPU cap 30 seconds, no optimization, six new native model evaluations. A
weights-only SHA match is insufficient for restored behavior: graph profile,
task route, source/evaluator identity, parameter bytes and input identity are
all part of the restored computational state.
