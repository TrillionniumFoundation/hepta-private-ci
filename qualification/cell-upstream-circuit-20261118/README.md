This study extends joint execution source `e52c4f67cb58a65409256f7be263cfb49ac22557`. ## Fixed arms and budget

The declared order is `native_FF`, `native_TT`, `native_CC`, `native_TF`, `native_CF`, `native_TF_no_answer`, `native_TF_no_feedback`, `native_FF_retrieval`, `native_TF_retrieval`, `native_F_one_call`, `native_T_one_call`. Each of the first nine arms executes two model calls per task. The final two execute only slot zero, deleting the other Cell before dispatch. Thus six tasks produce 66 graphs, 120 model calls and 120 primary verifier calls. Each actual call has the original 384 output-token cap, 4096 input-token cap and 2048-byte relay bound; unused call capacity is not charged as actual work. Both retrieved arms see exactly the same input-ranked reference selected from the original six A records. There are six additional reference-verifier calls.

Native assistant/action then tool/feedback turns, actual repository verification, earliest verified success selection, original output preservation and strict pool identity/parameter receipts are unchanged. FF and TT are strong two-call self-repair controls. TF/CF vary the route; answer and feedback are separately removed; single-call arms remove the second Cell. No learned routing claim is made. Costs are measured; equal maximum opportunity does not assert equal realized token use or complete monetary/energy cost.

## Explicit adapter admission and calibration

The original SharedAdapterPool constructor continues to reject non-original model schemas. A separate MatchedAdapterPool verifies both new manifests against the immutable E1 training source root, their original completed training receipts, base bundle and exact runtime. The actual shared numerical and chat code must have the training-source hashes. The current E4 execution source has its own freeze; no model manifest or historical source inventory is rewritten. The same FP32-preserving loader, actual active-tensor hashes, resident/active parameter accounting and cleanup path are reused.

Before any upstream generation, both F and T make a cold-Predictor call and a shared-pool call on the first fixed A training record. Exact output tokens, answer, model identity, rendered prompt and generation configuration must match. These four model calls and four verifier calls are separately retained and charged as setup. Failure is preserved and stops the study. No calibration may choose a model or prompt using B outputs. The full prospective run therefore has 124 model calls and 130 verifier calls including setup and reference preparation.
