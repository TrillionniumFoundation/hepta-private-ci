# Hepta Memory Cell 与 Meta Network：架构、证据和验收

日期：2026-11-05（UTC；America/New_York为2026-11-04）。源码基线：`6d2551388ed42355f02afbf528472ee2b4d8488b`，即 V14 及查询局部 fence 修复 #4687。本文区分已发表研究、本仓库历史实测、本轮代码验证和待验证假设。

## 1. 结论与可采用的架构

应把 Memory Cell 定义为有类型、有独立更新边界、可追溯和可回滚的记忆服务。小模型是这种服务的一种表示或读出实现。Meta Network 是这些服务及其目录、授权、路由、执行器和恢复协议的组合。专属化首先来自数据和任务契约；有实验收益时再引入参数化压缩或学习分裂。

当前证据支持继续推进工程机制和有针对性的研究，不支持宣称整体智能或产品收益已经提高。旧实验中，强检索、ridge、centroid 仍胜过指定神经候选；结构提案全部被拒绝。拒绝扩容是正确结果。

建议的单 Cell 状态分为三个部分：

\[
h_t=E_{\theta_E}(x_t,\tau),\qquad
s_{t+1}=F_\tau(s_t,h_t,\Delta t,u_t),\qquad
m_{t+1}=U_\tau(m_t,h_t,s_t,a_t).
\]

`s` 是活动、置信、时效等动态状态；`m` 是可持久记忆或其压缩表示；`a` 是读、写、检索、整理、拒答或迁移操作。Hepta 的 first-passage/reset 可作为 `F` 和触发策略的候选，NDU 可作为动作价值控制器。它们不自动提供实体绑定、事实真值、权限或存储事务。活动状态 reset 不能删除持久事实或撤销记录。

对外读出必须包含当前有效的 scope、cell、owner epoch、bundle、来源和错误语义；单独的模型向量或置信分数不够。

## 2. 怎样分化为不同类型

| 类型 | 应保留的信息和语义 | 首选可验证实现 | 可以研究的学习部分 |
|---|---|---|---|
| 项目与实体事实 | 精确值、实体身份、来源、有效时间、纠错与冲突 | 类型化 KV、版本记录、显式关系 | 实体解析、检索、抽取和候选排序 |
| 经历与事件 | 事件顺序、当时状态、因果证据链接 | append-only 事件及索引、可追溯摘要 | 事件编码、摘要与重要性预测 |
| 程序与技能 | 输入输出类型、前后置条件、工具版本 | 可验证程序/技能库与统一执行器 | Encoder+head、ridge、LoRA 的选择和参数映射 |
| 偏好与习惯 | 主体、适用情境、明确性、有效期 | 带 scope 和证据的规则记录 | 预测优先级、学习软偏好 |
| 连续环境状态 | 时间、缺测、不确定性、阈值和恢复状态 | 滤波/SSM/状态估计及记录 | Hepta 解析 cell、belief、continuation Q |
| 多模态记忆 | 原始证据位置、时间对齐、身份锚点 | 原文件/片段指针、向量索引、类型化绑定 | 专属编码器与相似性读出 |
| 工作记忆 | 当前任务临时状态、计划、缓存及预算 | 有界任务状态与明确生命周期 | 压缩、注意、优先读取策略 |

权限、owner 和来源撤销由权威控制面管理。学习模型可以建议读什么，不能通过高置信度改变授权。类型化记忆与物理表示正交：同一事实 Cell 可以同时有 KV 真值、检索索引和学习到的 head。

共享 Encoder 宜首先固定为允许共享的公共表示。若它在多租户私有资料上继续训练，仅把输出 head 分开并不能证明数据隔离。

## 3. 表示方法的比较

| 表示 | 合适用途 | 优点 | 必须计入或验证的代价 |
|---|---|---|---|
| 共享 Encoder + 专属 Head | 小类别技能选择、评分、抽取、预测 | 共享编码，可独立替换读出 | Encoder 占用与计算；表示不足；升级导致 head/index/calibration 不兼容 |
| 精确 KV | 实体事实、配置、版本、数值 | 精确读写、纠错、可审计 | 原始记录、历史、复制和索引；语义定位仍需解决 |
| Retrieval / RAG | 大量可追溯文档和经历 | 内容更新无需整体重训 | embedding/index/payload/token、漏召回、读错、版本冲突 |
| attention KV cache | 同模型同上下文的重复前缀 | 减少前缀计算 | 不是业务 KV；依赖层、模型、上下文身份，缺少数据库更新语义 |
| centroid | 粗路由、低成本类别代表 | 轻量、可增量维护 | 均值丢失少数模式；不能当任意事实无损存储 |
| ridge / 线性 head | 固定表示上的映射 | 稳定、便宜、强基线 | 特征维度、统计量和重训成本；精确删除不自然 |
| Transformer / LoRA | 重复规则、语义模式、任务适应 | 可以内化映射和复用规则 | 训练、基座、优化器、遗忘、来源污染、路由及冷加载 |

ridge 通常求解 `(XᵀX + λI)W = XᵀY`，不要显式求逆。若支持增量更新并保留 `XᵀX`、`XᵀY`，必须计入 `d² + do` 的状态。训练出 W 的方法已经是参数模型，不能把“ridge 胜 LoRA”解释成“参数记忆都无效”。

LoRA 的身份必须至少绑定基座、tokenizer、量化、target modules、rank、scaling 和权重。保留来源用于审计和重建时，原始信息仍计入总存储，参数变小只能证明某种活动表示变小。

## 4. 与 MoE 的关系

Switch Transformer 和 Mixtral 支持稀疏激活以控制每个 token 的计算量。MoE 专家通常是网络内部子层，不自动拥有独立数据库、持久身份、访问权限或事务。Mixtral 的分析也没有支持把每个专家直接命名成人类领域专家的普遍假设。[1][2]

| 维度 | 典型稀疏 MoE | Memory Cell Meta Network |
|---|---|---|
| 专用性 | 训练与 gate 共同形成的参数分工 | 数据类型、读写契约、更新规则和模型分工 |
| 路由粒度 | token / layer | 请求、实体、时间范围、类型及多步证据访问 |
| 输出 | 中间激活 | 带来源、版本、有效期和失败语义的记忆结果 |
| 共享部分 | attention、残差流、embedding 等 | 可共享 Encoder；可变内容必须显式隔离 |
| 状态 | 普通推理常使用固定权重 | 经常读写、纠错、撤销、更新和迁移 |
| 权限 | gate 概率不构成 ACL | 召回前、读取、训练、迁移和导出均检查 |
| 扩容 | 增加总参数与稀疏计算选择 | 增加目录、存储、通信、复制和恢复负担 |

MoE 可以是某个 Cell 内部的实现，也可以借鉴其稀疏路由思想。二者不应被定义为互斥技术。Meta Network 的节点可以只做可靠存储，也可以运行一个很小的模型；不要求每个节点都是完整 LLM。

## 5. 候选覆盖、专家内评分、跨专家路由

三个问题必须分别测量：

1. **候选覆盖**：正确、当前且授权的记忆是否在预算内被找到？测 Recall@k、有效版本覆盖和错误/过期候选率。
2. **专家内评分**：固定正确专家与候选池，是否排出正确记忆/动作？测条件准确率、MRR、margin、拒答和校准。
3. **跨专家路由**：固定各专家输出，是否在相同访问预算内选中正确组合？测实际成功率、oracle 差距、fallback 比例、延迟与错误代价。

不同专家的 cosine、ridge score 和局部 softmax 不可直接当作同一个概率。应校准一个共同目标：这个调用在当前预算内返回正确、可用证据的概率。改变候选策略、版本或分组后要重新验证校准。

Oracle routing 只用于诊断上界，不计入产品结果。已知正确 Cell 类型、答案所在论文、教师 posterior 等信息，只有在所有实际对照也可获得时才允许输入。

2026 年《Understanding LoRA as Knowledge Memory》在匹配训练参数、使用 oracle routing 时观察到多小适配器潜力；实际 embedding routing 会显著损失，甚至低于单 LoRA。多适配器合并也会产生干扰。这与本项目需要把局部容量和系统效用分开验收直接相关。[3]

## 7. 版本、唯一 owner 与迁移

逻辑身份需区分 `principal_id / node_id / process_incarnation / cell_id / owner_epoch / bundle_id`。节点身份应从认证凭证导出；不能信任调用者自己填写的字符串。

一个可执行 bundle 至少固定：模型、记忆快照、来源及版本、Encoder、tokenizer、schema、索引/路由、校准、运行时。需要继续训练时还必须固定 optimizer、RNG、sampler、步数与数值执行条件。网络上分别取几个 `latest` 文件会产生从未验收的组合。

唯一 owner 的要求是：在权威目录的一个已提交版本里，每个 Cell 至多一个有效 writer。每次提交都检查签名、当前 owner、epoch、前版本 CAS、权限和幂等键。旧进程即使暂停后恢复也不能绕过最终写入栅栏。Chubby 的 sequencer 设计说明了接收端检查旧持有者代次的重要性。[10]

最小迁移协议选择易验证的短暂停写：

1. 源 owner 以签名请求 prepare；冻结写入并推进 epoch，记录完整 bundle 和目标身份。
2. 接收方验证和保存组件，ready 签名绑定同一 bundle/epoch/迁移 ID。
3. 在权威事务中再次检查来源、权限、ready 和当前代次；原子切换 owner/路由。
4. 旧 owner 请求全部拒绝。提交回包丢失时查原幂等键或迁移状态，不创建另一套迁移身份。
5. 未提交时可以中止并以新 epoch 恢复源；已提交后只能走新的迁移或恢复，不能复活旧代次。

生产系统需要线性一致目录或明确的单权威。没有目录时拒绝提交，可以保留未提交意图。不能让网络分区两边独立授予 owner 然后同时声称全局唯一。Raft 等成熟共识协议及其当前领导权/线性读规则应作为权威实现基础。[11]

哈希说明字节相同；签名说明谁认可这些字节；两者都不证明记忆为真、模型有益或远端永久保管。接收方 ready 也不能单独证明它诚实落盘。

## 8. 回滚、split 与 merge

模型版本可以回到旧参数，但 owner epoch、权限收窄与来源撤销不能倒退。旧模型恢复为一次新的发布；旧来源或已删除内容不得随之重新合法。拒绝访问不等于已从所有旧权重和副本中删除知识。

Split 应先是有证据的结构提案。分区必须保持地址、版本、删除标记、权限和来源的守恒；一次目录事务退役父 Cell 并启用子 Cell。把同一父模型复制给两个子节点，不意味着权重已经按隐私来源分离。

Merge 必须验证 scope、schema、冲突规则和授权。权限并集不能使原来隔离的内容互相可读。参数通常需重训或独立验证；任意平均 LoRA/head 不构成可靠合并。版本回滚不覆盖新的安全事实。

本轮参考协调器采取保守规则：精确地址分区；同 owner/scope reshape；子 Cell 保留父模型完整来源依赖；合并采用 ACL 交集。它保证引用与路由行为，不证明学习分裂有效，也不证明参数遗忘。真正的来源独立化需从干净数据重训或另行验证。

## 9. 小设备获得大规模能力的条件

要分别报告本地容量、网络总容量、单次能访问的容量，以及实际完成任务的能力。

\[
M_{device}=M_{shared}+M_{active}+M_{context}+M_{cache}+M_{runtime}.
\]

\[
M_{system}=M_{models}+M_{sources}+M_{indexes}+M_{replicas}+M_{history}+M_{optimizer/replay}.
\]

必要条件包括：工作集稀疏；正确专家能被廉价定位；活跃对象装得下；网络/冷加载/尾延迟可接受；失联时有明确降级；执行器能理解和组合结果；权限允许访问。手机少算了多少不能代替全网总成本，远端可用能力也不能写成本地离线能力。

任意独立随机事实没有可凭空消除的信息量。参数压缩依赖共享结构、任务充分统计量或允许失真。小节点总数增加可以扩展容量或可用性，但不会自动增加执行器的推理深度和正确率。

若每次查询省下的完整成本为 `Δc>0`，单次构建、搜索、训练、更新、验证和迁移额外成本为 `F`，保留成本为 `S`，需要有效生命周期内的真实调用量 `Q` 满足 `QΔc>F+S`。更新很频繁或长尾记忆几乎不读时，参数化很可能无法摊销。

## 11. 严格实验设计

### 三层公平性

1. **相同信息**：同一来源字节、更新序列、当前有效视图、调用者payload、允许工具和教师信息。预训练基座不同必须单列，机制消融固定基座。
2. **相同预算**：先固定CPU/GPU训练与搜索、活动内存、总持久存储、查询token/专家数/调用次数/截止时间，再在各预算可行域内比较。总参数和每次活跃参数是不同维度，不能只匹配子模型而漏路由器。
3. **相同执行器**：各臂从同一个初始执行器快照出发；同样权限、工具和输出判定。失败、超时、恢复失败和拒答全部保留分母。

“同预算”指相同资源上限和机会，不要求低成本基线故意耗尽剩余预算；实际消耗必须另报。共同且已固定的底模成本可以在增量比较中抵消，但仍应出现在系统账本。比较不同预训练Encoder时，其知识来源、保存与推理成本也不同，不能把差值全部归因于记忆机制。

### 比较矩阵

先比较单节点 KV/检索、共享Encoder+centroid/ridge/head、参数记忆以及强混合基线。仅对通过筛选者比较固定类型分区、随机/负载分区、学习split、merge和继续训练；总搜索成本包括被拒绝提案。

Hepta机制应另做同一记忆表示下的2×2：A普通核心，B普通核心+价值控制，C解析核心，D解析核心+价值控制。核心增量看D−B，控制增量看B−A；不要将更好的外部记忆信息归功于解析核。不同表示和结构之间的对照与这组因子分开报告。

长期测试覆盖新增、纠错、删除、有效期、漂移、重复写、冷重启、网络失联和迁移。分别报告旧/新/长尾/每类型表现、最坏时间窗、恢复时间、未服务请求和已确认写入丢失。有限回归不证明无限期稳定。

### 净收益与拒绝

\[
\Delta U=\Delta\operatorname{TaskUtility}-\Delta C_{full}.
\]

`C_full`至少包含数据准备、基座与依赖、所有训练/搜索/失败、编码/路由/读取/执行、校准、版本/来源/索引/复制保存、迁移、恢复、网络、能耗和账单。真实物理共享对象只计一次；每机一份必须按复制数计。父进程总费用与子阶段不能重复相加。

冻结用途、调用量、保存周期、更新率、硬件、资源价格或Pareto门槛。只有预先指定比较的净收益下置信界为正、关键类型非劣、工程不变量通过才可增长。安全机制可以独立验收，科学收益不能用通过安全测试替代。

本轮 `admission.py` 使用同输入与隔离执行器，按独立cluster等权均值计算保守Hoeffding下界，并对预定比较和类型检查分配alpha。重用seed不扩大独立query数。它假设cluster独立、冻结数据可信和测量真实；这不是对任意相关日志有效的显著性证明。成本预测必须对应相同的cluster混合分布。

该统计下界覆盖任务结果，并未自动量化未来成本的不确定性。现场准入应使用保守成本估计或另行给出成本差的上界；不能把一次定时或固定价格下的算术结果称为所有部署条件下的保证。

本轮只实现拒绝不充分证据的机制；没有新完整预算模型训练、新长期现场运行或新的正收益结论。
