## 审查发现与修复

以下四个问题在修复前由独立反例实际触发：

| 问题 | 原来的失败行为 | 修复与复验 |
| --- | --- | --- |
| 冻结案例仍包含可变嵌套对象 | 构造评估器后修改原始 `expected` 或 `payload`，实际验收样本改变，已记录的数据摘要不变 | 规范 JSON 快照隔离外部引用；每次执行从快照解码；正例明确检查实际正确输出及批准结果 |
| 两臂共享有状态执行器 | 两个完全相同的 predictor，因先后消耗同一个执行器的状态而得到虚假的正增益与批准 | 同一可信 factory 创建相互隔离的执行器实例；复验差值为零；返回同一实例的 factory 被拒绝 |
| 无法撤销最后一个 reader | `restrict([])` 被当成权限扩张拒绝，只能考虑会影响其他 Cell 的 source 撤销 | 空 ACL 现在表示拒绝全部读取；冷重启及管理员恢复后仍保持该策略，使用同一 source 的另一个 Cell 继续可读 |
| 已拒绝请求的 ID 可以换载荷重用 | 第一次以某 request ID 被拒绝，改为有效载荷后可用同一 ID 成功写入 | `request_bindings` 固定首次请求指纹；修复后的独立反例拒绝第二次写入且当前 bundle 不变 |

最终代码审读还确认，拒绝结果不再经过“释放外事务写锁、重新开始事务”的间隙。业务操作在 `BEGIN IMMEDIATE` 中用 SAVEPOINT 包裹；拒绝时回滚业务修改并在同一外事务记录签名拒绝和请求绑定。已完成提交后出现的异常不会被错误记录成未执行的拒绝。

其他针对协议缺口的修复和最终控制包括：

- Cell gate 只能返回绑定候选、父版本和合法证据摘要的严格类型结果；字符串或整数真值、普通批准字典均不能代替批准。客户端 `approved=true` 不获得写入权限。
- 评估器获得已校验的不可变组件字节以及隔离的 manifest。修改回调所见 manifest 不能悄悄改变签名候选或提交一个摘要不匹配的 bundle。
- `reshape` 必须经过绑定完整父状态、子集合、地址分区和组件身份的联合结构门。逐个子 Cell 合格、缺失结构评估器、联合拒绝或复用其他 plan 的批准都不能完成结构变更。
- 新增管理员签名的 `recover_prepare`，使不可达 owner 的接管无需旧 owner 再次签名；仍须匹配当前 epoch/bundle，并完成接收方 `ready/commit`。旧 owner 无权取消管理员发起的恢复。
- `ready` 验证历史 bundle 的实际字节、来源与地址，迁移保留当前 Cell 的有效 ACL。权限收窄后恢复不再因历史 manifest ACL 较宽而卡住，也不会复活旧权限。
- 合并使用权限交集；地址必须完整且不重叠；子 Cell 不能悄悄丢掉祖先训练依赖。任一子门失败会回滚整个结构变更，父路由保持可服务。

## 独立覆盖的关键行为

| 范围 | 本次独立控制 |
| --- | --- |
| 所有权与 epoch | 迁移后重启拒绝旧 owner；prepare/abort 后拒绝旧代次；管理员恢复后旧 owner 不能写入或取消恢复 |
| 来源新鲜度 | `ready` 之后撤销 source 会阻止 `commit`；abort 不能使旧模型重新可读或可发布 |
| 权限 | 重放读取请求重新检查当前权限；收窄权限后重启、回滚旧 bundle、迁移与恢复均不扩权；最后 reader 可被撤销 |
| 结构事务 | 完整地址分区、祖先依赖保留、联合批准、合并 ACL 交集、父 ID 不复用、第二个子门失败后的原子回滚 |
| 请求身份 | 成功重试不重复执行；已成功和已拒绝的请求 ID 都不能换载荷重用 |
| 评估真实性 | 冻结样本、隔离执行器、严格批准类型、精确模型字节影响实际判定、负迁移和缺测成本阻止发布 |

上述覆盖是有限反例与行为测试，不是所有并发调度的形式证明。真实进程竞争和提交前后 OS kill 控制位于 `authority_tests.py`，其执行身份与结果由统一验证器记录。

## 必须保留的可信边界

1. **权威边界。** SQLite 文件系统、权威进程、管理员和签名密钥属于可信计算基。当前代码没有复制共识，也没有独立单调 witness。恢复整个旧数据库可同时恢复旧 epoch、权限、source 和请求记录；签名与本地事务不能独自发现这种整库回退。

2. **节点与持久化边界。** Ed25519 验证的是持钥者身份。它不证明硬件机器身份、独立进程 incarnation 或诚实存储。接收方提供正确字节并签名，仍不是其远端磁盘已经持久保存的证明。管理员接管是显式控制操作，不是自动主故障检测或共识选主。

3. **执行边界。** 实际读取和写入在该权威上检查当前状态。已发出的内容、远端执行器缓存、训练出的参数和历史导出物不会因此自动被删除。远端最终使用时的 fencing、机器遗忘、密钥销毁与恶意节点隔离尚未完成。

4. **评估边界。** 模型加载器、执行器 factory、资源测量、样本来源、cluster 独立性和预注册协议仍由可信宿主提供。摘要只能绑定这些输入，不能证明输入诚实。置信界针对等权独立 cluster 均值，不能直接改称所有请求的微平均准确率；成本摊销必须对应同一部署混合分布。

5. **资源边界。** 进程内 deadline 检查不能中断一个挂起的 predictor。训练、搜索和验证的硬预算需要外部受限 worker。当前 callback 在权威事务内运行，也会延长写锁持有时间；这不构成已验收的吞吐或尾延迟设计。

6. **模型与结构边界。** 当前结构操作保留完整祖先依赖，不证明模型已经按类型无泄漏地分化，也不证明参数拆分或合并有益。跨 owner/scope 的直接 reshape 不在本轮支持范围内。生产 Rust owner、真实 Hepta NDU 控制、物理多设备和长期漂移实验仍需分别验证。

## 仍不能宣称的结果

本轮不能宣称小模型已经获得大模型的通用能力、节点增长已改善整体智能、参数记忆优于强 KV/ridge/retrieval、长期稳定性达标，或完整成本后的产品净收益已经为正。当前正例只验证拒绝与激活机制能被真实执行的有限控制驱动。

后续收益验收仍需固定同一输入记忆、执行器和总预算，分别测量候选覆盖、专家内评分与跨专家路由，并纳入训练、失败搜索、原始来源、索引、共享底模副本、历史版本、网络、恢复及能耗。只有真实候选的联合净收益和保留能力通过预先固定的门槛，才允许增长；不能从本报告的协议通过推导该结论。
