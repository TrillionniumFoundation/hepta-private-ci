# Fresh single-call evaluation successor

This is a new evaluation scope for the frozen current-student correction
candidate `dc96ad0c29223dc0fbf0e6165854d8e7cf25331c3f77d57ad30c4f30fc6cf678`.
It does not extend or rerun the former 56 model calls or four future tasks.
Code review, synthetic controls and publication alone authorize no scientific
claim. Source acquisition requires both actual new children and a separately
published selection receipt. Evaluation additionally requires a sealed and
separately published four-source panel.

The direct `Predictor.predict` policy is
`manifest_predictor_single_native_chat_4096_384.v1`: one complete native chat
request, at most 4,096 input tokens and 384 generated tokens. It is a new policy,
not the old raw `CollectionPolicy` with 8,192 / 2,048 token limits. Their scores
are not directly comparable. The retained parent manifest supplies actual
generation parameters; code does not invent replacement defaults.

## Fixed population and budgets

Repositories are considered in this order: `tartley/colorama`,
`python-poetry/tomlkit`, `andialbrecht/sqlparse`, `theskumar/python-dotenv`,
`uiri/toml`, `jaraco/inflect`, `agronholm/exceptiongroup`, `jd/tenacity`.
The published exclusion inventory uses canonical GitHub owner namespaces and
all retained old content fingerprints. `jaraco` is excluded before scanning;
the sixth entry remains an explicit refusal and is never replaced.

Git stdout is retained up to 128 MiB and stderr up to 1 MiB per command.
The 2 GiB monitor can overshoot between samples; receipts retain observed bytes
and sampled peaks. Inherited base weights, verifier environments and physical
network traffic are outside that retained-material measure. Physical network
bytes remain unknown. Ordinary Git failure is a retained tool failure, not a
finding that source code is invalid. Resource exhaustion is terminal without
retry. Unconfirmed forced cleanup blocks further work pending owner-specific
read-only evidence; the code never clears that marker automatically.

Each earlier repository must reach its ordered qualification terminal before
the next source is opened. All failures consume the claimed slot. Claims bind
the selection identity and survive alternate output paths. Once four sources
qualify, further acquisition stops. Panel sealing closes acquisition even if
the result is refusal. Historical failures and exclusion inventories persist.

## Deployment and execution order

This Linux, Python 3.11+ successor requires all staged files. Do not release a
partially published stage to an execution owner. Run entry points with
`python -B`; do not write bytecode into old frozen source directories.
All JSON bindings use `{ "path": "/absolute/file", "sha256": "..." }`.
`fresh_contract.py` defines exact schemas, constants and owner-local claims.

1. After both eight-update children truly complete, retain a
   `hepta.current-student-fresh-weights.v1` envelope containing
   `training_candidate_digest`, `created_at_ns`, and `models` keyed by the two
   modes. Each mode binds its actual `manifest` and `training_result` files.
2. Publish `hepta.current-student-fresh-selection.v1`: `weights_digest`,
   `excluded_inventory_digest`, exact `repositories`, `caps`, `as_of`,
   `commit_order`, `request_policy`, independent absolute `e2-fresh-*`
   `owner_root`, `automatic_retry:false`, `old_raw_policy_comparable:false`.
   The selection publication binds `selection_digest`, actual 40-hex published
   `commit`, and `published_at_ns` observed after readback. Publication receipts
   are operator evidence; this local runner does not query GitHub to attest them.
3. Freeze an acquisition deployment with schema
   `hepta.current-student-fresh-acquisition.v1`. Bind `selection`, `weights`,
   `excluded`, `selection_publication`, and all five non-test entry source hashes
   in `source_files`. Supply `training_directory`, `prepared_directory`,
   `framework_root`, `engine_directory`, `artifact_root`, `scanner_source`,
   `materializer_source`, `context_source`, `native_source`, `ancestor`, `codec`,
   `native_environment`, `host_canary`, and canonical `repository_metadata`
   bindings. Optional `dependency_bundles` must be explicit bound originals.
4. Call `acquire_fresh.py --repository-index N`, then `prepare_fresh.py
   --stage materialize --repository-index N --ordinal K --scan-sha256 SHA` for
   the next ordered potential. Review and bind retained original license/notices
   before `--stage prepare --license-review PATH --license-review-sha256 SHA`.
   Each command also requires `--deployment PATH --deployment-sha256 SHA`.
   A preparation refusal consumes this candidate; do not change it and retry.
5. Call `assemble_fresh.py` with the same deployment binding. It writes
   `PANEL_FROZEN.json` or `PANEL_REFUSED.json`. Publish the resulting exact panel
   after all source preparation and sealing. No score is inspected for selection.
6. Freeze an evaluation deployment with schema
   `hepta.current-student-fresh-deployment.v1`, the applicable common bindings,
   `panel`, `panel_seal`, and `panel_publication`. The last binds `panel_digest`,
   an actual 40-hex commit, and a later `published_at_ns`. Run each declared
   `--mode document_evidence|native_feedback --arm frozen|retrieval|final_only`
   through `run_fresh.py`'s supervisor, serially. A fresh process cold-loads the
   actual frozen model with eager attention and a 70% CUDA allocation cap.

The supervisor owns finite arm deadlines. Forced TERM/KILL or an original
native call failing to return a waited receipt creates an uncertainty marker;
later arms cannot start. Confirmation of worker exit alone never establishes
native descendant cleanup. Normal native returns keep the original waited
receipt. No full-host process scan or automatic owner reset is introduced.

The panel represents four curated public short-function repairs that satisfy
these declared bounds. It establishes no authenticated real-user count,
independent human-controller identity, absence of pretraining contamination,
general advantage, production adoption, or consensus reward qualification.
All final scientific claims remain separate from code and native pass status.
