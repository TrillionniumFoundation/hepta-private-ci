## Frozen development protocol

This lane starts from the published data stage at `0e6634cadf4497c653e191e50e6394387190ca55`.
It is separate from the old eight-adapter, 624-generation protocol. No result
from that protocol is reused as a new model run here.

## The actual model experiment

SmolLM2-135M-Instruct supplies a frozen hidden representation and its original
full-vocabulary logits. Two small private linear heads adjust the first answer
token's `Yes` and `No` logits by opposite amounts. The remaining vocabulary is
unchanged and can win. Later tokens are generated by the original model; EOS
and the eight-token limit terminate generation. No two-candidate forced choice,
token suppression, sampling, answer repair, or label inversion is used.

The channel is chosen from the declared prompt domain (color or shape), never
from the expected answer. Retention channels are assigned by fact-cluster
index. All content examples are operator-authored, simple contextual records;
they are not independently collected natural-world tasks. The retention32
questions are deliberately reused from the prior prospective development
panel, with their exact source acknowledged in `PLAN.json`.

There are 64 training prompts, 64 new-name/paraphrase development prompts, and
32 descriptive retention prompts. Each source object belongs to exactly one
split. The model runner first reads training labels, extracts the 64 frozen
model features, and trains and saves every candidate before it parses or uses the
separate evaluation-label file. Its raw bytes are hashed earlier for source and
data integrity; this is not a claim that the file was never read. The investigator can see all labels, so this
program ordering does not establish independent custody or a sealed test set.

## Matched routing and separate ablations

Each training action records both groups' features and model expectations.
Exactly three paired-action clock steps later, an external two-coordinate
teaching vector supplies the two labels. This is a sequence-delay mechanism,
not a claim about biological or physical-time credit assignment.

- `routed`: each group receives its own coordinate.
- `shuffled`: the same vector's two coordinates are swapped. Input-vector
  digests, source order, initial heads, learning rate, trust region, and update
  opportunities match the routed arm.
- `no_eligibility`: the same feedback is processed, but the recorded feature
  trace is zero. Its update loop executes while parameters remain unchanged.
- `scalar`: the vector mean is delivered to both groups. This loses information
  and is a separate feedback-information ablation, not an information-matched
  routing comparison.

For a feature `e` and first-token logit displacement `d = w·e`, analytic
full-vocabulary cross-entropy descent uses
`w += lr * decay^3 * (target_sign - (p_Yes - p_No)) * e`, using the expectation
recorded at the original action. Every head is then projected to the same norm
ball. The other vocabulary mass is retained in the normalizer. This is actual
manual SGD on real model features; it is not full-body, LoRA, or Torch-optimizer
training. Four paired seeds change training order. Each of 16 conditions has
256 update calls, for 4,096 manual calls total, including zero-change ablations.

## Fixed denominator and evidence

The frozen base and all 16 candidates each generate answers on the same 96
evaluation prompts: 1,632 planned main generation attempts. Completed and failed generations are
reported separately; failed attempts never count as completed inference. The strict parser accepts
only an entire YES/NO string plus optional single period or exclamation mark.
Invalid text and per-task execution failures remain incorrect in the original
denominator. All emitted token IDs and complete decoded strings are retained.

A second process reloads all 17 saved head states and repeats the predeclared
12-prompt subset: 204 planned cold generation attempts. The cold journal retains every started
and completed/failed attempt, and any failure makes exact-replay qualification
false while remaining in the fixed denominator. It verifies exact token IDs,
first-token features, and logit shifts against the original result. This is a
model/head process-restart diagnostic, not owner/circuit cold recovery.

`PUBLICATION.json` must bind every named source byte to the immutable GitHub
commit read back by the launcher. Sources, inputs, and all six actual model assets
are pinned before and after execution. The fast tokenizer uses the vocabulary and
merges inside the pinned tokenizer.json; absent separate vocab/merges files
are neither synthesized nor silently downloaded. Journals and raw resource observations
remain retained even if a task or process fails. CPU-only four-thread main and
cold ceilings are 1,200 and 300 seconds, with 4 GiB memory. Setup, queueing,
prior base-model training, energy, and production owner costs are not measured.

All empirical outcomes remain **HOLD_NO_GO**. The earlier source-only stage
reported zero model calls; the observed native execution is documented above.
Independent future B, ordinary A→learn→B→C, native owner
authorization, old capability adequacy, content-core×NDU 2×2, and production
adoption remain separate gates. Four seeds and synthetic development records
cannot establish a broad generalization or neuroscience claim.

## Preexecution review correction

Prepared source `878faaba7388bc679027c0af34203192e8a3f319` was never used for
model execution. A separate reviewer found that the initial content template
parity predicted the color-task label. The successor switches template parity
to `floor(pair/4) mod 2`, and every group/template now contains eight YES and
eight NO prompts. An adversarial source-builder check rejects the original
confound. Both prepared histories and their source artifacts are retained;
this correction used zero model outputs or evaluation outcomes.
