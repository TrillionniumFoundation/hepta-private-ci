## Findings and remediation

Priorities below are audit judgments based on the bounded-input threat model.
They are not claims that an unauthenticated remote endpoint exposes these APIs.

| Priority | Finding | Remediation |
| --- | --- | --- |
| P1 | A conflicting digest for the same record ID/revision could hide in a policy-truncated channel event. | Validate the complete observed cut before truncation. |
| P1 | Rehashed generator wrappers accepted aggregate counts over 512, empty/unavailable owners paired with real results, and channels/counts inconsistent with owner receipts. | Aggregate receipt ceiling, availability and result/channel consistency checks. |
| P1 | Assignment creation accepted rehashed selected support metadata and omitted-count drift; plain recall could attribute an alternative legal action as the deterministic selection. | Compare every selected evidence field with the reconstructed legal union; check generation/coverage/budget/omissions; replay plain deterministic recall. |
| P1 | Bounded node counts still allowed unbounded per-node support arrays, including in public active-node receipts. | Cap each node's support list at 512; reject node/synapse construction bounds before sorting/hashing. |
| P2 | Public assignment sets lacked product caps and explicit nonzero record-digest checks. | Bound enumerated/legal/selected sets and event omissions before set allocation; reject zero candidate digests. |
| P2 | Public union/selection support/group arrays lacked cardinality bounds; union policy omissions could exceed raw-event capacity. | Evidence-list cardinality cannot exceed contributing channels; union plus omitted events cannot exceed 512. |
| P2 | Generic development prose could be read as if a digest authenticated a public caller. | Explicitly document owner authentication, contextual validation and the limits of standalone receipt checks. |

No valid digest domain or byte scope changed. The changes tighten rejection of
inconsistent/out-of-profile inputs. New `AssignmentErrorV1` variants are additive
Rust API changes; downstream exhaustive consumers require normal compile checks.
No durable-store schema, public wire contract, caller ownership or activation flag
was changed.

## Remaining work and stopping criterion

The read-only decision component is correctly placed between cognitive owner reads,
immutable KG/engram projections, Agentd context delivery and the sole learning writer.
Its optimization should preserve those boundaries rather than introduce a second
store, authentication authority or hot-path central RPC.

Remaining product work is the existing map's independently qualified current-context
provider for the actual `hnmf-required` process, real Vector encoder/index owner,
full downstream canonical migration, exact-head/synthetic-merge and owner-composition
CI, approved target-host measurements and independent semantic/operator acceptance.
Follow-up review found and fixed additional defects before concluding the scope:

| Priority | Finding | Remediation |
| --- | --- | --- |
| P1 | Settling accepted a different cue with the same generation vector. | Bind the actual cue digest to the union before expansion. |
| P1 | A zero minimum activation admitted zero-valued nodes as active, allowing unsupported recall. | Require strictly positive activity in construction and receipt validation. |
| P1 | A single selected record could be absent from declared engram support; HNMF assignment accepted a legal lower-ranked replacement. | Check packet support membership and replay the shared deterministic ranking against the full legal union. |
| P1 | Rehashed HNMF output could invent `NoCandidate` or turn an OOD abstention into a recalled assignment. | Share disposition precedence with generation; enforce all gates decidable from the available inputs. |
| P2 | HNMF candidate counts and the full active-support intersection were not verified for abstentions. | Verify exact union count and support intersection for every disposition. |
| P2 | Positive negative-relation paths, reversed contradiction pairs and zero traversal resources survived rehashing. | Enforce path sign, normalized pairs, retained-evidence traversal minimum and collection ceilings. |

Seven further adversarial regressions failed before their respective fixes (four
against the first published candidate, then deterministic-winner and two disposition
mutations against the partially hardened candidate). A positive composition test
also confirms that both actual owner dynamics contradiction policies remain valid.
These are the eight additional tests included in the final native total above.
Valid recall behavior, digest domains and byte scopes are preserved.

HNMF assignment observations consume trusted engine output: the observation API has
no engram snapshot/dynamics arguments and cannot independently replay settling from
arbitrary public receipt bytes. The actual dynamics policy is also absent: the
observer accepts either contradiction posture where that flag changes the outcome,
while enforcing the known no-candidate, coverage, OOD and floor gates. Owner
provenance remains necessary; these checks do not authenticate the dynamics flag.
