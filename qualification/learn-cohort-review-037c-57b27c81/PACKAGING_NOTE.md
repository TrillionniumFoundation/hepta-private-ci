# Packaging and provenance

- Original JSON files and raw logs are retained byte-for-byte, including their original line endings. Local paths in them describe the original execution environment.
- The six exact CALLERS layer plans and the a96 base manifest are stored as deterministic gzip files. `logical_original` in ARTIFACTS records the complete decompressed byte count, SHA256 and Git blob. The compressed bytes are a new lossless packaging representation; they are not mislabelled as the original disk files.
- The complete final CALLERS patch is stored the same way. The final 1,835,713-byte CALLERS source file is not redundantly copied into this evidence directory; REFERENCES and publication verification pin the complete published object `50077d9ffa5362358ae2234864be1f905217d184`.
- The pre-existing ROW_HISTORY.json.gz is copied unchanged. It contains the full before/proposed/merged row history. No row evidence was replaced by a summary.
- Final QA postimages, the previous failed attack suite/template, and the exact migration scripts are included. Product `.rs` source files are not added as standalone evidence copies. The original formatter request and payload contain their exact input, as required to audit that request.
- Builders and QA scripts remain original artifacts with their original workspace paths. To rerun them, first reconstruct the pinned base/component/source-overlay inputs described in their manifests. The small package verifier only audits this package and makes no source/native claim.
- The merged-lib actual manifest and Root verification are complete records. The remote empty log/patch artifacts and complete-postimages archive were not separately fetched for this package. NOT_SEPARATELY_COLLECTED.json states that gap explicitly; no empty reconstruction is presented as a fetched original.
- GitHub connector transcripts are serialized capture records. Their nested response content is preserved; these are not represented as raw HTTP response bytes. The large CALLERS contents endpoint returned an empty body with its exact blob SHA; that path-to-blob mapping was combined with the already independently fetched full blob. The five smaller published files were checked by full content.
- The old v1 EOF failure and both first QA attempts remain failures. Later successful attempts have their own input identities and logs.
- This checkpoint does not alter product source, global CALLERS, allowlists, prior frozen evidence packages or PUBLICATION.json. It adds only qualification evidence on the independent profile checkpoint branch.
