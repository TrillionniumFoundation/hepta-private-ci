## Correctness repairs

### Explicit production CLI must not reach legacy recovery

Before this change the CLI passed production descriptors through the same
configuration builder as legacy frontier files. The host selected the production
verifier from the descriptor's parent path. An external or nested descriptor
could therefore take the legacy route despite explicit production mode.

The CLI now invokes `require_production_descriptor` before constructing that
configuration. Both paths must be absolute; the descriptor must be lexically
canonical and a direct child of the registered Agent home. External, relative,
nested, parent/dot-alias and home-directory inputs are rejected. The subsequent
runtime still checks actual file ownership, permissions, stable identity,
backend, signatures, build, backup, receipts and snapshot. This structural check
is not evidence that those external authorities exist, and does not replace a
future explicit typed-mode configuration throughout the library.

Eight Rust profile regressions are compiled through the integration target
`kernel_evidence_profile`, because the Agentd binary disables its own test
harness. The governed command now includes both product and profile targets;
execution-record validation rejects the previous command that omitted the guard.

### Both qualification lanes for every supported event

The reusable workflow no longer skips deterministic merge for push/manual
invocations. A PR uses its exact event base. Other invocations use an explicitly
supplied full base OID or the source commit's first parent. Branch aliases, dirty
source, substituted checkout, non-commit objects, missing objects, duplicate
parents and mismatched object formats are rejected.

The existing synthetic-merge action retains fixed author/committer timestamps
and ordered base/source parents. Non-PR invocations use a fixed message label,
not a run-dependent label. This proves a candidate against its recorded base,
not compatibility with a later moving main branch. Production admission still
requires the existing governed PR workflow provenance; push/manual diagnostics
do not silently become deployment authority.

Initial negative runner diagnostics are written before checkout. Later command,
status and artifact steps retain partial failure evidence. Artifact names bind
source SHA and run attempt. The required fan-in now rejects any failed,
cancelled, skipped or missing source or merge lane for every supported event.
A runner that never starts still cannot manufacture a diagnostic artifact.

## Administrative and operational boundaries

The inherited convergence report records a 403 response for the branch-protection
endpoint. The current integration has no branch-protection write action. Naming
a job `required` or including it in `CI required` is not server-side enforcement.
An administrator must preserve existing requirements, resolve the actual stable
check contexts emitted by the final run and enforce the qualification fan-in.

No storage service, signing principal or backup receipt was invented. Provision
and qualify storage outside the rollback domain, carry out signer rotation and
revocation ceremonies, publish a real backup, and witness old-database,
old-frontier and old-trust rejection before recording deployment/restore gates.
Independent acceptance, canary and release require their actual authorities.

All persistent qualification/deployment/governance flags therefore remain false;
`workflowRunId` and `artifactDigest` remain null. This branch is a development and
qualification candidate, not a production activation or release.
