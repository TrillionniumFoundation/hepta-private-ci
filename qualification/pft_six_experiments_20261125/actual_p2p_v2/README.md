# 真实 SmallHCSN 的双机解析训练与独立测试

本目录把固定的真实 SmallHCSN 特征接入双机充分统计量协议。两台实际设备各自产生本地非 IID 训练数据、运行物理模型、形成统计量，通过既有 USB4/SSH 直接交换贡献，各自求得相同的读出层候选。控制器负责部署、冻结与取证，没有转发训练统计量。

**已完成 12 组真实跨机读出层更新、冻结后的独立测试，以及 12 个新进程中的预测复现。物理动力学参数保持固定；这不是整个非线性参数场的闭式求解，也不是两位真人的跨用户采用。**

## 模型、数据和目标

宽度为 8、16、32、64；每个宽度有三个预定 seed。每台设备每组有四个 32 样本的训练分区。两端的晚到信号支持区间和噪声分布不同；测试更换生成源编号、噪声实例、到达时间范围及状态初值范围。任务在早期收到 A、等待晚到的 B，最后判断 A+B 的符号。

每个接收单元提供五个特征，使用接收侧的一半单元。读出层以两类别 logit 之差表示，连同截距，更新维数分别为 21、41、81、161。共享坐标由统一准备阶段生成：对两种节点分布各取 32 个公开合成无标签 calibration 样本，固定同一 basis 后下发两端。calibration 不计算目标标签，也不是另一轮双机统计量归并。

令共享标准化设计矩阵为 X、冻结父读出为 w₀，各端只根据自己的训练标签计算：

\[
G_i=X_i^T X_i,\qquad b_i=X_i^T(y_i-X_iw_0).
\]

两个节点各自求解同一目标的更新：

\[
a=(G_1+G_2+0.01I)^{-1}(b_1+b_2),\qquad w_{new}=w_0+a.
\]

这里的正则项只加一次，作用于共享坐标中的更新，包括截距。共同父模型、坐标、provider、capsule、目标和轮次均进入身份绑定。不能把不同坐标下的统计量直接相加，也不能用局部最优权重的平均代替这个解。

## 双机协议证据

完整协议使用已有认证 SSH 通道的 USB4 直连路径，没有修改系统防火墙，也没有经过控制器中转。每组 pocket4 在接收首个远端贡献后真实 `exit(17)`，从五条已持久化贡献恢复到新 PID，再完成求解。

12 组每组 33 项只读审计全部通过：两端原始候选及 action 内容相同；逐帧散列和字节守恒；错父版本被拒绝；重复贡献幂等；原检查点字节、恢复后的贡献和新 PID 均对应。审计从双方合并账本重构了 24 个原 provider 文件，原字节 SHA-256 与各端的生成清单完全一致。

- 应用层双向数据总量：40,042,839 字节；这不包含 SSH/TCP 链路封装开销。
- 与独立 NumPy 集中解的最大相对 action 误差：`1.2580727370995353e-10`，预设容差为 `1e-7`。
- 最大相对正规方程残差：`5.821676675447782e-14`，预设容差为 `1e-10`。
- 同一只读审计在 `python -O` 下也通过，检查不会依赖可被优化移除的 assert。

这里证明的是固定、已认证的两个受信节点的协议行为。统计量不是隐私保证，散列不是数据诚实证明；没有建立任意参与者准入、Sybil 或 Byzantine 抵抗、广域网扩展性。

## 完整时间口径

| 实际阶段 | 时间 |
| --- | ---: |
| ai395 首次准备固定 Python/NumPy/Torch 环境 | 490.24 s |
| 12 组公共无标签坐标准备 | 11.19 s |
| pocket4 本地模型、特征、统计量准备 | 22.52 s |
| ai395 本地模型、特征、统计量准备 | 29.37 s |
| 12 组直接交换、退出恢复、双方求解的 supervisor | 42.47 s |
| 12 组独立测试 launcher | 49.38 s |
| 12 个新进程的冷启动预测复现 launcher | 33.16 s |

以上是分别测得的阶段耗时。两端准备并行，通信等待和对端计算也会重叠，不能逐项相加当作系统墙钟时间。环境任务创建至独立评估完成的实际观察窗口为 2287.491 秒（38.12 分钟），包含控制面等待、审核、发布和并行其他工作；冷启动复现及之后归档位于该窗口之外。它不是隔离的性能基准。

这些结果没有提供同一真实 HCSN 任务上与 BP、adapter、RLS 的完整系统同质量加速比；第一轮微基准、这里的固定读出更新、另一个 168 配置的受约束 BP 实验各有不同范围。耗电没有测量。计时与范围原件见 [SUMMARY.json](SUMMARY.json) 和相邻执行收据。
