# Prospective checklist, not an experiment authorization or execution claim

Status: software/handmade validation only. No real dataset was opened,
downloaded, synthesized as a substitute, or used for training. Existing 403 and
restricted Library-file boundaries remain binding. Do not run a real comparison
until lawful data access, a frozen design and applicable execution approval exist.

1. Pick one estimand: complete randomized H/A/N training-program effect on
   actual greedy/mean service, or auxiliary-law effect. Report both separately;
   do not rename an auxiliary improvement as user-visible quality.
2. Bind this package, all dependency hashes, legal data/split identities, model
   architecture/encoder, optimizer, initialization/training/sampler seeds,
   sample weights and explicit reduction normalizer. Use paired source rows,
   noisy inputs and fixed-K draws across H/A/N. No label/clean-image service input.
3. Freeze identical full CPU/work ceilings, candidate/seed opportunities,
   applicable optimization and static-decoder opportunities for all arms,
   including optimized A. Reallocation to extra real updates is allowed for
   cheaper methods; padding is not. Keep strong legitimate static alternatives.
4. Measure process/descendant CPU, shared full-use attribution, method-only
   costs, preparation/search/checks/export/receipt/service and tail reserves.
   Use one executor domain and interleaved/isolated timing as appropriate.
   State common versus dedicated work explicitly; quotes do not replace actuals.
5. Freeze the complete contrast/endpoint family, alpha allocation, stopping
   rule and independent units before observing new data. Whole-training claims
   require independent training-program blocks; repeated images/draws/seeds
   inside a reused block are not automatically independent replications. Plan
   power/precision first. `holm_gate` accepts only independently valid p-values.
6. Retain all seeds, failures, overruns, source views and selection history.
   Include actual classification errors, MSE, low/tail quality and wrong-class
   outcomes, not only aggregate loss. No new parameter scan or held-out retry.
7. Do not resurrect the failed CV implementation or reinterpret historical
   finite12 results. Recheck objective-to-wire correspondence and actual byte
   decoding with the real service implementation before making a service claim.
