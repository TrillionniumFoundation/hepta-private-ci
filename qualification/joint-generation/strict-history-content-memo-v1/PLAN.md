# One-history content-addressed payload SHA memo: fixed work qualification

Hypothesis: original saved 128 fresh validation can avoid exactly 82 of 256 payload SHA-256 computations (67,732 hashed bytes), while retaining all 256 actual fresh payload reads, all state/boundary/identity tests, and accept/refuse behavior. This is a deterministic work-count question, NOT a timing experiment or strict 256 admission. No model imports, NumPy, array decoding, learning, new data, native 256 run or old-source edits. Existing strict complete-budget proof gap, data denials and HOLD_NEW_TRAIN remain.

Rationale established only by source/metadata before freeze: saved 128 order references are 128 files of 826 bytes with 24 distinct declared hashes. Fixed reverse walk, no eviction, sixteen admitted contents predicts 82 hits and 46 misses. This is not evidence of actual bytes until the frozen run verifies them. Actor NPZ payloads are 12,303 bytes and remain uncached. Original complete read volume is 1,680,512 bytes per walk. Savings are 32.03125% of payload SHA invocation count but only about 4.03% of payload bytes hashed; ALL logical IO remains. These are not CPU savings; dictionary lookup/content hashing/byte equality and memory have additional real cost.

Implementation: exact original bytes_get AST is compiled with only its sha dependency replaced by ContentMemo. Original history, canonicalization, state identity hashing, JSON reader and all other behavior remain unchanged. This does NOT include the previous equality-helper experiment. ContentMemo receives the complete newly read immutable bytes, never path/mtime/oldstat. A dict hit uses Python exact bytes equality (hash collisions alone do not match), returns the previously computed digest, and original bytes_get still compares it to the supplied reference. A changed file is freshly read; changed content cannot reuse the old digest merely because its path/size matches. Wrong expected digest refuses even on a content hit. Cryptographic assumptions are unchanged from original SHA identities.

Memo reuse scope is exactly one history invocation: new object compiled into payload_reader on every call, never reused between independent calls. Each history-call finally block copies the stats then explicitly clears memo keys, including refusals, so exec-created function/global cycles cannot retain key payloads while awaiting GC. This is not a bound on total Python interpreter memory. Cache admits only byte strings of at most 4096 bytes, at most 16 distinct keys, no eviction. Retained key payload at most 65,536 bytes plus bounded 16-entry dictionary/object overhead; this is NOT a total process memory bound. The original per-read 1MiB limit and 256MiB process AS remain. No persistent cache/file authority or immutable-filesystem assumption is added.

Frozen comparisons: original and memo each complete the same 128 history with 17 checkpoints; new memo invocation repeats the same history once and must have identical IO/digest statistics, proving scope reset rather than measuring speed. Each implementation receives wrong checkpoint 0,64,128: errors and work counters must match. Total 9 history calls. No new actor/controller/optimizer call occurs.

Frozen actual temporary-file sequence, separately for original/memo: first content; different path same content; wrong expected digest on a cached content; same path changed bytes with old reference; new correct reference; restoring original bytes; appended byte; truncated byte; symlink refusal. These files are created only in new RUN_ONCE/literal-*; originals are never changed. Full admission/refusal/returned-hash/IO records must match. Six digest attempts per mode, memo 2 computations/4 hits. This is trusted-local byte-change detection, not an adversarial filesystem/TOCTOU security claim.

Fixed capacity literal:17 distinct 4096-byte strings, repeat overflow 17th (must hash), repeat retained first (hit), same 4097-byte string twice (must hash twice). Exactly 21 calls/20 SHA computations/81,922 hashed bytes/one hit/16 entries/65,536 retained payload bytes. Reject one bytearray without counters changing. It is a cap test, not a resource benchmark. All numbers were set before the sole run. No outcome-based tuning, cache-size sweep, timing winner selection or retry.

Source/input hashes are checked before and after:392 original saved files 2,406,239 bytes, same existing saved 128 provenance. Fresh payload SHA reads occur on old NPZ as opaque bytes, not array/model loads. CPU costs of input barriers and tests retained in full wait 4. No per-case timing screen is performed; receipt CPU is cost only. On a caught failure, the exception and previously completed test records are retained; an in-progress history group or local file_sequence observations may not yet be appended. A hard kill may leave no RESULT, which the outer receipt records as missing rather than success. Source reviewer and parent admission required before execution.
