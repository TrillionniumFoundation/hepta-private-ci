# Synchronized training on the desktop RTX 4060

Independent of the single-core host and the short requested Colab qualification, repeat the registered seven-arm, three-seed SHD panel on an actual processor with GPU timings. Use a 30/180/720/1800 synchronized fit-wall-seconds ladder per arm and seed (10.5 aggregate device fit-hours), all real original trainings and validations. Maximum GPU allocation is limited to 40% of memory, and model construction and CPU→GPU transfers, checkpoint durability, cold forward and validation have separate timestamps. Record machine GPU utilization and available VRAM, and whole-device power only as shared-host measurements. A changing co-tenant load precludes reporting dedicated-device energy. Execute each rung in a durable job with an atomic optimizer/model/RNG checkpoint at least every thirty fit seconds. Run verification and scientific scores when all members of a rung have been sealed; use fixed choices from the CPU registration. The timing clocks, optimizer update counts and input preparation differ across hosts and are reported independently.

Prepared event counts are derived from Cramer, Stradmann, Schemmel and Zenke (2022), The Heidelberg Spiking Data Sets for the Systematic Evaluation of Spiking Neural Networks, IEEE Transactions on Neural Networks and Learning Systems, doi:10.1109/TNNLS.2020.3044364. Authors' distribution and CC BY 4.0 terms: https://zenkelab.org/resources/spiking-heidelberg-datasets-shd/ and https://creativecommons.org/licenses/by/4.0/. Modifications are fixed 50 ms bins, 25 consecutive cochlear channels per band, and separately identified time rescalings. No source authors endorse this experiment.
