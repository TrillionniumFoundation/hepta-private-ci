# 关系能力五臂：独立冷进程成本复核

本复核针对原 `programs-v1` 中一个具体计费问题：五种方法共用进程，BP 首先建立 PyTorch 优化器，承担首次初始化开销；后续 HYBRID 已处于热状态。原记录保留，但不能把该方法顺序产生的微步骤差异解释为算法加速。

新增 `cost_replay.py` 在固定三个 N8 父模型上分别启动 KEEP、BP、ANALYTIC、STRICT_WSP、HYBRID，共 15 个新进程。每个方法独立支付解释器与库初始化、原候选全量预检、父模型加载、训练/开发数据生成、两路父模型特征计算、程序生成或监督更新、开发验证、证据写盘与重新读取校验成本。进程间不共享特征缓存或优化器初始化。

父模型固定为 `n8-s17011`、`n8-s27011`、`n8-s37011`，没有按效果挑选。复用原冻结目标、数据生成器、每 source 数量、最多 96 次实际 closure、10 CPU 秒更新预算和梯度早停条件。原 BP 候选来自 KEEP 初始化，HYBRID 来自严格公式初始化；监督岭回归仍明确标为 ANALYTIC。

## 实际结果

15/15 独立 worker 正常退出；15 份 RESULT、15 份 WORKER_COST、15 份 LAUNCH_COST 和总 TERMINAL 均已核验。所有重算训练/开发特征逐元素完全相同；所有候选 tensor、开发分数和优化计数均与原封存候选完全相同。没有因为成本复核产生新的模型选择。

15 个冷子进程的实际 CPU 总计 170.1054 秒，逐子进程 wall 之和 171.0194 秒；协调器 CPU 0.4118 秒，整个冷复核 campaign wall 171.0330 秒。安装与协议冻结回执另外保留。

冷复核后，HYBRID 不再具有原共享进程中因初始化先后造成的巨大微步骤时间优势。严格程序的生成阶段短于常规计时分辨率时，记录中可能出现 CPU 增量为零；这只反映计时分辨率，不表示程序生成没有成本。完整 worker 费用仍为非零。

## 能说明和不能说明的范围

本表关闭了本次实际执行的共享进程顺序计费缺口。每个父只进行一次相应冷测，三个不同父的计时差异不构成延迟置信区间。完整子进程时间受特征计算和启动成本影响，不能用矩阵求解或公式写入的微秒数代替端到端费用。

质量需在原冻结测试结果上单独判定。严格 WSP 正确编译给定关系规则，也仍会继承父分类错误；不能自动假定它和 BP、岭回归或 HYBRID 达到相同真实标签准确率或校准。即使某个已知关系规则可以不读取训练标签安装，也不证明未知规则发现、表示学习或全模型预训练可由该程序替代。

人工/agent 编写规则与字典的发现成本没有完整计量，保持 unknown。能源和完整机器成本同样没有测得。原任务迁移、测试及复核属于可追溯的额外验证工作；本表不把它们隐藏为零，也不将单个环节的速度差包装为基础模型训练加速。
