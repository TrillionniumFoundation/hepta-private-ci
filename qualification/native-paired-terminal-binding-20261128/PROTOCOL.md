## Typed boundary and ordering

The only intake is the private owned `OriginalPairedTrainingDelivery` from the
required original owner. Public record metadata is not original-delivery proof.
`prepare_paired_original_v1` checks the fixed Root plan, full raw and canonical
record pins, current Memory Replay permission, exact current signed Dataset and
exactly two existing authenticated Decision/Outcome pairs. It retains the bytes
and returns a private Prepared object and a domain-separated signing payload.
Preparation performs no fit and creates no ledger or event.

The fresh turn/delivery do not exist at startup. The existing authorized Evaluator
must sign the observed payload after preparation; fixed startup pins cannot stand
in for this signature. `consume_paired_original_v1` requires that signature,
the same Dataset producer and actual owner, and current source/dataset checks
before calling the unchanged owner.train. Its returned receipt retains both
original byte records, the separate binding and the native fit receipt.

The payload binds original registration/study/enrollment/principal/generation,
turn/delivery/operation, raw hashes and lengths, full canonical pins, exact native
job/profile/budget/deadline, Dataset, Memory owner/policy/revision/support/purpose,
and the four complete Ledger event digests. A valid signature authenticates this
association; it does not independently establish its semantic truth or provenance.
The native fitter derives actions, propensities and values solely from existing
authenticated events. No text/success flag becomes a label. Outcome.support_digest
keeps its original meaning. Extra active episodes are refused even if a valid
current-cut Dataset signature is supplied; no subsetting, reset or new ledger.

The supervised absolute end is inherited and can only shorten. Waiting for a late
signature does not reset it. Timeout after entering the fit is CommitUncertain;
the existing owner retains its native job. Post-fit changes prevent result release.
This stage has no new signing authority, production Evaluator factory, implicit
CLI owner, durable paired-result store, adoption, payment or general text training.
Actual deployment lacking the existing owners or late signature remains blocked.
