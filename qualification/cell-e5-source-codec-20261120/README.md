# E5 source-unit action and visible-input freeze

This isolated prototype adds an executable, hash-bound source action codec and a before/task-only context selector for the **existing ordered sixteen E5 materials**. It does not start a model, native regression replay, or optimizer. The earlier E1/E2 56-call NoUpdate result and both frozen 32-update arms remain separate historical evidence.

The fixed source-prefix commit is `9dade6e90f6227dded45afa1c8462758a511a699`; the material package is #6783 at `63f494553a735bd55a3fef7cfe2e76604cd6db7d`. The first four sources remain **Delgan/loguru, SethMMorton/natsort, Textualize/rich, coady/multimethod**. A source that fits the codec is not moved into an earlier prefix. The original two 32-unit budget curves are unchanged; optimizer-unit, compute, native-candidate/verifier and independent future-panel bindings remain unfrozen.

## What the codec actually does

`source_units.py` inventories original Python functions, methods with decorators, module/class statements and class structural headers using byte slices. It never unparses an AST. A class header is a structural prefix, not a complete class; the selector separately retains required constructors, ancestors and referenced methods/state writers. The Cython path preserves complete lexical source boundaries, and Python/Cython twins remain a coupled correction. Lexical acceptance of a Cython candidate is not native compilation or correctness evidence.

`source_actions.py` binds all retained before runtime files and stable source units. One strict UTF-8 JSON payload contains original-line replacements and adjacent complete-helper insertions. The raw answer is bounded by 32,768 bytes and 128 action entries. Duplicate keys, stale roots, overlapping edits, changed before bytes, edits outside the trusted visible-unit set, unsupported file creation/deletion and omitted Python/Cython counterparts are rejected. Unchanged bytes remain exact. Empty edits is an explicit no-change action and makes no improvement claim.

Structural roundtrip and visible-task admission are deliberately separate checks. A full-material reference action may reconstruct the maintainer's source exactly while targeting a unit that the frozen task input never exposed. Such a target fails visible-task admission; its location is not added to the input afterward.

## Input boundary

The source map comes from every runtime `.py`/`.pyx` file inside the **retained before snapshot scope**, not the after-changed-file list. This does not claim that the archive contains every file of the upstream repository. `visible_material.py` validates the original material hashes, complete fixed test files, original before execution bindings and all selected testcase identities. The selector itself receives only sanitized byte maps and before diagnostics; it has no material-store handle, patch, target or after-runtime argument.

Some original test and fixture bytes are from the upstream after revision. They were already the fixed task inputs used in the retained before run. They remain legitimate task information here; this freeze does **not** claim that every input byte predates the repair. Runtime after bytes, changed-node/compatibility matrices and future B/C data remain excluded from input selection.

All selected parameter cases retain their complete original test function and decorators, including passing and skipped cases. Named fixtures, applicable setup/autouse fixtures, helpers and literal constants are retained. The bounded path resolver can propagate fixed literal parameter strings through named helpers without executing code. For loguru it resolves all eighteen original parameter choices to all thirty-six complete script/output fixtures; it does not select only the failing case. Rebinding, late binding, unknown values, missing paths and unsupported path operations cause a specific refusal. No fixture or parameter is dropped to fit a token limit.

## Static scope and limits

`v1_static_context_closed` is a statement about this implemented static graph. It is **not a proof of arbitrary Python semantic completeness**. The graph records Python and external-object API contracts and rejects unresolved globals/project receivers, unsupported dynamic loaders/namespaces, class construction behavior and module initialization effects. This conservative implementation can reject a source that a more capable prospective selector could represent. A rejection does not show that the upstream task or decentralized learning is intrinsically impossible.

Complete prompts and complete actions will be measured with the already frozen parent tokenizer only: Qwen/Qwen2.5-Coder-1.5B-Instruct revision `2e1fd397ee46e1388853d2af2c993145b0f1098a`, exact native template and special IDs. Limits stay at 4,096 input tokens, 3,584 full SFT positions, 384 generation positions, 65,536 bytes per native chat message and 32,768 answer bytes. No prompt/target truncation, extra turn, action splitting into more updates, or hidden budget expansion is allowed.

`count_tokens.py` uses the exact native serialization rule: independently encode the inference prefix, then independently encode the complete assistant continuation. All prefix labels would be masked and every target token retained. It only counts tokens; it does not allocate or train a model. A representation that fits these bounds is still not an admitted E5 training run while the external execution bindings remain null.

## Freeze and continuation

The source and complete sixteen-context digests in `SOURCE_FREEZE.json` are published before `run_targets.py` may read actual runtime after bytes. The latter requires the frozen code and context hashes, uses the original prompt verbatim, constructs the entire historical maintainer correction, checks deterministic byte-for-byte roundtrip, and tests stale-binding/source rejection. After values have no input-selection or rerendering role.

The Python modules live under `scripts/cell_experiments/e5_source_codec_v1/`. They can run directly by path; no upstream package import, model service or weight download is required for the static stages. Material unpacking and original native provenance remain in the #6783 package. This Draft introduces no production integration or change to the original hardbound four-source runners.

Earlier prototype diagnostics, including the failed synthetic test invocation with two missing-test-import errors, are retained as actual attempts. Only the final prospective freeze describes the continuation source. The original repository formatter ran in a new detached clone, with the original `just fmt` and `--check` commands and pinned existing offline Ruff. Formatting preserved every source AST, and the twenty-four synthetic boundary/tampering tests passed there. That synthetic test execution is not a new upstream native replay.

This package is an integrity and representability check inside trusted historical evidence. It is not an unforgeable contribution proof, a measured learning improvement, a multi-teacher result or a proof-of-useful-work result. All new model loads, forwards, generations, optimizer updates and upstream native task replays remain zero.
