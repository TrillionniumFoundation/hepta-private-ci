# E5: what this frozen codec result establishes

The current single-turn, complete static-context representation does not admit any of the original ordered 1-, 4- or 16-source prefixes within the unchanged 4,096 input-token, 3,584 full-SFT-position and 384 output-position limits. Only attrs at **ordinal 11, the twelfth source**, fits this limited representation contract, with 1,277 input tokens, 138 complete target tokens and 1,415 total positions. It stays in that position and does not establish an executable growth curve.

The new edit transport removes the requirement to copy a whole replacement function. All sixteen historical maintainer corrections reconstruct exactly from stable, source-bound edits; their complete payloads are 266–2,931 bytes. Eleven also fit the independently frozen visible-unit set. That is concrete codec progress. It is not a student success rate: these actions were constructed from historical maintainer targets after the complete source/input freeze was published. Five targets require units absent from the frozen visible set, fifteen full inputs exceed the input/SFT bounds, and five complete outputs exceed 384 positions. The input representation is the main measured bottleneck.

This result does not license dropping cases or fixtures, shortening complete code units, increasing limits, splitting one intended update into uncounted extra calls, or moving attrs into the beginning of the prefix. It also does not establish that these upstream tasks are impossible. The 2,841-line static resolver is a new conservative implementation with explicit unresolved-behavior blockers; its limited closure flag and 24 synthetic controls do not prove arbitrary Python semantics. The original retained native provenance and all 290 selected case identities remain intact.

A distinct future study can investigate bounded interaction with a source environment: inspect a complete function or fixture on demand, retain an explicit source-root identity, and use typed results for dependencies whose implementation is outside the current view. The information-selection policy, external contracts, task order and total retrieval/action/token/optimizer/verifier budgets must be frozen prospectively. Each additional tool step must be charged to that budget. This would test a different execution protocol; it cannot repair the current result retroactively. A fresh evaluation panel and explicit optimizer-unit mapping are still required before any learning claim.

No additional model load, forward, generation, optimizer update or upstream native replay occurred. The historical E1/E2 56-call NoUpdate decision and both original 32-update arms are unchanged.
