# Maintained YAML parser with bounded consumer compatibility

## Status

**DRAFT / production HOLD.** The real hosted qualification must finish for all four consumer crates, the complete Cargo dependency graph, and the generated Bazel lock. The original required CI remains unchanged. The new workflow runs complete package tests with the repository's original `just test --locked -p PACKAGE` command; it does not select a small subset or relax existing guards.

## Scope

Six source files in four workspace crates use YAML: `codex-skills`, `codex-skills-extension`, `codex-core-plugins`, and `codex-external-agent-migration`. The shared `codex-utils-yaml` crate preserves their string/option handling, dynamic Value key equivalence and local tags, unsigned port/version rules, and the Product unit enum representation. All consumers now select the same adapter. This is not a claim of complete serde_yaml API compatibility.

The parser is the official serde-saphyr 2.1.0 source with a bounded compatibility fork. `VENDOR_PROVENANCE.json` records the official package/VCS identity, every retained file's original and final SHA256, and the exact pre-format research source. The source tree and upstream license notices are included. Pure scalar resolution helpers adapted from serde_yaml retain its MIT/Apache notices; no unsafe-libyaml or legacy parser runtime is used. The actual Cargo lock generated by Cargo removes both old packages and pins granit-parser 2.1.0. Hosted all-feature metadata still must verify the complete resolved graph.

## Why compatibility code is needed

A direct maintained-parser substitution changed real metadata behavior. Quoted numeric values, numeric-looking strings, global/local tags, Option null handling, duplicate keys, large integer rejection, and Product enum representations differed. The exact official baseline and intermediate failures were preserved. The final bounded probe has zero differences across the original 1,574 matrix and 28 examples, the 13,063 extended observations, and 2,918 actual skills-extension type observations; the original expanded consumer harness passes 14 tests.

The old Tagged wrapper added recursive frames at every dynamic node and caused a default 2 MiB stack abort at depth 64. The final adapter uses direct Serde visitors, emits EnumAccess only for real local tags, and keeps the large scalar-dispatch frame outside tag recursion. All 160 depth-isolation processes complete under both the default 2 MiB and repository's existing 8 MiB thread settings. The independent full-profile resource tests pass 9/9. The original aborts and each intermediate failure remain in the research history.

All official new-parser resource budgets remain intact. In particular the structural depth cap stays 64, while the old parser's recursion budget was 128; deeper documents are explicitly outside this compatibility profile and are rejected. No input, event, scalar, alias or depth cap is increased.

## Actual local validation

The production utility's original `just test --locked -p codex-utils-yaml` completed with **10 passed, 0 skipped**, with all command inputs unchanged. The depth regression itself uses a 2 MiB thread so the repository's 8 MiB test setting cannot hide the prior failure. Original `just fix -p codex-utils-yaml` also passed and changed no source. Complete command argv, input SHA256 and outputs are under `local/`. The first unlocked native run legitimately generated the updated Cargo.lock; the subsequent locked run verified it. No large consumer build is claimed locally.

Repository formatting is applied to all new source. Its formatting of upstream imports is recorded separately from substantive compatibility changes in the vendor manifest.

## Hosted qualification

`yaml-consumer-qualification.yml` runs five complete native packages (the utility and four consumers), resolves the full Cargo graph, and runs original `just bazel-lock-update` / `just bazel-lock-check` plus the utility's actual Bazel test. Each job checks exact source identity, preserves every command exit status, and uploads receipts even when qualification fails. The generated MODULE.bazel.lock is an artifact until its exact bytes are committed and the original lock check passes on that committed head.
