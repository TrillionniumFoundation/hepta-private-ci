## 2. Public operations and contract details

`compose_runtime(supervisor_snapshot, ports, configuration) -> AgentHost`; `start_run(authenticated_request, objective_snapshot, body_snapshot, artifact_set, authority_epoch, deadline) -> RunHandle`; `attach_context(run_id, expected_revision, complete_frozen_tuple, compilation_receipt) -> AttachmentObservation`; `mark_dispatched(run_id, expected_revision) -> RunReceipt`; `cancel_run(run_id, expected_revision, reason) -> CancellationDisposition`; `observe_terminal(run_id, expected_revision, owner_observation) -> RunReceipt`; `recover_indeterminate(external_recovery) -> RunReceipt`; `release_closed(run_id, expected_revision) -> RunReceipt`. These are design signatures. The local control socket advertises `run.lifecycle/1.1` for start/attach/dispatch-marker/cancel/observe/status/release; component-only recovery has no daemon method or typed client. Signed admission uses the separate `ObjectiveStart` method. Local lifecycle operations record boundaries and do not themselves invoke physical turn start/interrupt. Product composition uses the existing Codex session spine and typed owner ports; Agentd cannot create a second memory/learning store.

## 3. State records and transaction design

Own only the canonical runtime-health observation surface and ephemeral composition state. The daemon owns one bounded `AgentRunCoordinator` inside `AgentdState`; its run map stores handles, revisions, immutable snapshot references, cancellation reason and terminality, not authoritative objective, memory, prompt or artifact bytes. Context attachment binds request/objective/body/artifact digests together with the original authority epoch and deadline. The recovery component validates the supplied prior tuple/revision/context identities and rehydrates only `Indeterminate`; it does not authenticate an external execution owner or compose that owner into daemon startup. A product caller must supply that authentication and exact durable dispatch identity before using this seam. Recovery never authorizes redispatch.

## 4. Deterministic algorithm and scheduling

Bootstrap auth and revocation readers, stores/read ports, execution adapters and intelligence composition in explicit order. Freeze run snapshots; validate every attached receipt against the complete tuple; re-check the run deadline before attachment and dispatch; route effects to the sole execution spine; observe cancellation at defined boundaries. Shutdown first closes admission, converts pre-dispatch work to local cancellation, moves dispatched work to cancelling, keeps the control path alive for bounded terminal reconciliation, and marks unresolved post-dispatch work `Indeterminate` before process teardown. A dependency failure takes a declared deterministic/read-only fallback or rejects the run. Shutdown never turns an unknown external effect into success/failure or silently redispatches it.

## 5. Capacity and performance profile

Active daemon runs are bounded by the owning Fleet `ResourceBudget.max_concurrent_turns` (currently 1..=32); the reusable component supports up to 256. The coordinator retains at most 1024 records until closed runs are explicitly released; `Indeterminate` remains unresolved and consumes active capacity. Control ingress has 32 concurrent connections, 65,536-byte frames, a 2-second exchange timeout and a 50-millisecond overload-write timeout. Run IDs are at most 128 bytes and cancellation reasons at most 512 bytes. Per-run deadlines are caller-supplied and checked by the 50-millisecond monitor; post-dispatch cancellation uses a 3-second acknowledgement window before becoming `Indeterminate`. Shutdown allows a 5-second drain and a later 2-second reconciliation window, followed by bounded 3-second task acknowledgement. These are source constants, not measured host capacity. Track queue age and dependency/readiness latency.

Pilot ceilings are design targets, not measurements. Stricter canonical limits prevail. Bind actual schema/migration, host and measurements before composition; stateless modules prove absence rather than inventing state.

## 8. Current native implementation

The explicit `AgentdConfig::with_cognitive_ranker` host connects existing artifact-owner loading and the tabular operator to the real SQLite control-read projection before truncation. Current views and memory deletion are rechecked; source tests are `cognitive_ranker_tests.rs`. This is not the App Server automatic memory path or complete C1; the ordinary CLI has no implicit selection.

- **Implemented entrypoints:** `AgentRunCoordinator` in [codex-rs/hepta-agentd/src/lane_b_runtime.rs](../../../codex-rs/hepta-agentd/src/lane_b_runtime.rs) is owned by `AgentdState` and reached through the real control dispatch in [codex-rs/hepta-agentd/src/state_control.rs](../../../codex-rs/hepta-agentd/src/state_control.rs); typed clients are in [codex-rs/hepta-agentd/src/client.rs](../../../codex-rs/hepta-agentd/src/client.rs). `AgentdProductionWriterHost` remains an explicit host seam in [codex-rs/hepta-agentd/src/production_writer_host.rs](../../../codex-rs/hepta-agentd/src/production_writer_host.rs); cognitive `read` remains in [codex-rs/hepta-agentd/src/cognitive_context.rs](../../../codex-rs/hepta-agentd/src/cognitive_context.rs).
- **State and recovery:** Agentd owns one bounded in-memory run/revision coordinator per process. Its active-run ceiling is bound to the Fleet `ResourceBudget.max_concurrent_turns`; closed records remain retained until an exact-revision `RunReleaseClosed` acknowledgement releases them. Admission, complete-tuple attachment, dispatch marker, reasoned cancellation, continuous deadline transitions, the 3-second cancellation-ack timeout, terminal observation and closed-record release use the daemon control path. Component-only `recover_indeterminate` has no daemon ingress or independent durable-owner authentication. On shutdown, admission closes before task teardown and the control socket remains available during bounded drain/reconciliation. Agentd does not persist or fabricate external effect results and component recovery cannot redispatch. Durable cognitive facts stay in hepta-memory SQLite; `AgentdProductionWriterHost` requires an externally verified lease and explicit target attachment and is not enabled automatically by startup.
- **Control saturation:** the bounded UDS server returns a small typed overload frame with retry guidance instead of silently dropping a saturated connection. `run.lifecycle/1.1` also exposes the pending cancellation-ack deadline in receipts so clients can distinguish active cancellation from indeterminate recovery. This is backpressure signaling, not target-host capacity qualification.

- **Readiness and helper bootstrap:** final run admission checks all required stores, revocation, ports, App Server readiness, open admission and current lifecycle under runtime-to-run lock ordering; local drain cannot be bypassed by an earlier copied readiness snapshot. - **Synchronous effect bridge:** the existing provider/authority owner bridge runs in at most four blocking workers, preserving permit/dispatch guard and durable uncertainty if its control caller is cancelled.
