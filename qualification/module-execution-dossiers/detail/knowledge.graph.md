Parent: `docs/modules/knowledge.graph/TECHNICAL.md`. Lane: `LANE-C-MEMORY`.

## 1. Source and work envelope

Roots: `codex-rs/hepta-kg`.
Packages: `MEM-4-KG`.

Operation signatures below describe the target contract. Section 8 identifies the implemented native subset and remaining integration; names in section 2 are not automatically native API symbols. Preserve existing stores and APIs; do not create another authority or execution spine.

## 2. Public operations and contract details

`consume_source_batch(source_frontier, facts, corrections, tombstones) -> ProjectionCandidate`; `build_generation(candidate, graph_profile) -> GraphGeneration`; `publish_generation(expected_predecessor, validated_generation) -> ProjectionReceipt`; `query_relations(snapshot, seeds, bounds) -> RelationResult`. Supported relation kinds include supports, contradicts, temporal, causal, procedural and prompt-factor interaction, each with explicit source support and validity.

## 3. State records and transaction design

`knowledge_graph_projection` and `prompt_factor_graph_projection` are rebuildable, never source truth. Nodes key entity/fact/factor identity and generation; edges key endpoints+relation+support revision, with confidence, validity, tombstone cutoff and producer profile. Source frontier and complete-generation manifest are published atomically. A partial builder cannot update the selected graph pointer.

## 4. Deterministic algorithm and scheduling

Consume exact source/correction order; remove revoked support; rebuild affected adjacency within the declared bound; retain contradictory alternatives with separate supports; validate no unsupported edge; publish one complete generation. Incremental and full rebuild paths must be observationally equivalent for the same source cut. Prompt-factor complements/substitutes/conflicts are projections of registered facts, not new instruction authority.

## 5. Capacity and performance profile

The pilot/target profile uses <=4096 nodes and <=32768 edges, output <=512 references and builder batches <=10000 source records. These are design and measurement profiles, not implemented kernel traversal/batch limits. The native V2 kernel admits <=65536 nodes, <=262144 edges and <=50000 supports per node or edge and <=327680 supports per generation; `query_relations` performs bidirectional one-hop adjacency selection with an explicit edge bound and copies only visible supports for temporal results. The cognitive SQLite owner admits <=10000 heads, <=10000 node occurrences and <=50000 edge occurrences per scope; each cognitive retrieval channel retains <=32 candidates. `optimize_with_factor_graph` admits <=4096 candidates/128 selected, requests the full kernel edge ceiling and rejects truncation. Canonical `select_portfolio_v1` admits <=128 candidates/16 selected/512 interaction edges and also rejects truncation. Persistent growth is constrained by support retention. Measure incremental rebuild, complete rebuild, generation publication, tombstone propagation and query p99.

The repository PERF-LIBRARY probe drives 256 real product mutations to 4,096 physical node-support occurrences and 32,768 physical edge-support occurrences, then samples product retrieval/GraphOneHop and ordinary reopen while reporting p50/p95/p99, throughput, DB/WAL size, RSS and Linux CPU ticks when the full run completes. Those supports project to 16 canonical nodes and 128 canonical edges: this support-dense fixture does not prove query capacity at 4,096 unique canonical nodes. A measurement receipt does not establish target-host latency acceptance. Full-generation rebuild remains the selected runtime writer until a concrete target-host budget justifies promoting the independently checked incremental path.

## 6. Concrete verification cases

- KG-01: incremental versus full rebuild produces equal semantic graph digests.
- KG-02: deleting the last non-revoked support removes/invalidates the derived edge.
- KG-03: partial generation or mismatched source frontier cannot be selected for reads.
- KG-04: supports and contradicts edges remain distinct and cannot be collapsed into an unsupported high-confidence centroid.

These are required product test designs, not executed-test receipts. Each implementation supplies native test identity, exact input/output and independent oracle evidence.

## 7. Integration, rollback and capability ceiling

World-model consumers must distinguish symbolic evidence relations from learned dynamics. `knowledge.graph` owns semantic projection/query rules; `cognitive.store` / `hepta-memory` owns the physical SQLite schema and transaction; cognitive facts and prompt-registry facts remain owned by their source modules. KG reads compose with cognitive snapshots and cannot construct mutation authority. Agentd is the named product host that selects the scoped cognitive mutation feature; ordinary Codex stays default-off. Rollback selects a rebuildable compatible projection after current deletion filtering. Test-only crash rendezvous exercise process death before semantic receipt and after semantic receipt but before current-pointer CAS; reopen must recover the exact predecessor. Current publication reconstruction checks the current generation plus its exact predecessor; full historical publication-chain replay is reserved for qualification/forensic audit. Ordinary startup rejects source/memory owner IDs above 128 UTF-8 bytes with a scalar preflight before row materialization, then verifies all retained revision-fact digests with 128-record keyset pages and streams live entity shapes. This bounds Rust-owned KG row/identifier materialization on the checked cut, not SQLite internal page/sort work; total verification work grows with retained history. Migration `0014` stores compact revision-fact generation witnesses instead of copying historical projection rows.

Use all eighteen dossier receipt fields. Immediate revocation/stop remains effective across frozen snapshots. Preserve every applicable external gate; no generator self-acceptance, self-merge or self-release.

Source coverage is explicit: cognitive stored labels produce stable `Custom` relation identities consumed by the owner-mapped typed channels; the sealed prompt registry source produces only complements/substitutes/conflicts. Requires/dominates/redundant/supersedes remain private algorithm fixtures without a sealed owner source. Generic kernel enum coverage is not product source composition or external source authentication. Historical node/edge fact intervals must exactly equal their memory revision's validity interval; narrower subsets and wider windows both fail closed.

## 8. Current native implementation

- **Canonical deterministic core:** `build_complete_generation`, `apply_incremental_delta`, `publish_generation` and `query_relations` are implemented in [codex-rs/hepta-kg/src/generation.rs](../../../codex-rs/hepta-kg/src/generation.rs). V2 preserves canonical/custom relation identity, explicit support lineage, validity windows, exact predecessor publication and generation-bound queries. Query results bind a canonical request digest covering exact seeds, relation filters, temporal cut and edge bound, so a result receipt cannot be replayed as evidence for a different request that happens to return the same edges.
- **Immutable query admission:** [codex-rs/hepta-kg/src/validated_generation.rs](../../../codex-rs/hepta-kg/src/validated_generation.rs) owns `ValidatedKnowledgeGenerationV2`. `new` consumes and semantically validates one generation; a shared getter exposes no mutation. Repeated queries use the same core as the validating free function and still check generation digest, identities and bounds while binding the same request/result receipts. This avoids repeated full semantic validation, without authenticating an external source or adapter.
- **Cognitive source adapter and durable owner:** [codex-rs/hepta-memory/src/cognitive_kg_store.rs](../../../codex-rs/hepta-memory/src/cognitive_kg_store.rs) derives V2 nodes/edges/supports from the existing cognitive SQLite facts. Pure source-cut-local memo maps reuse kind/checked-shape hashes and historical node occurrence endpoint IDs without sharing state across transactions or dropping per-occurrence source/revision supports. `refresh_scope_projection_tx` builds the complete V2 candidate, reconstructs the predecessor, validates `publish_generation`, persists physical projection rows and immutable semantic receipts, and CAS-advances the selected generation inside the same SQLite transaction. It does not create a second fact store.
- **Persisted semantic identity and recovery:** [0013_kg_generation_semantics.sql](../../../codex-rs/hepta-memory/migrations/0013_kg_generation_semantics.sql) stores source-snapshot, generation-vector, graph-profile, generation and publication digests. Reopen recomputes physical input/output truth, reconstructs canonical V2 semantics, and replays predecessor-bound publication; tampered or partial current receipts fail closed. Legacy pre-0011 history cannot drive digest-bound graph expansion without a V2 receipt.
- **Product query consumer:** the GraphOneHop path in [cognitive_retrieval.rs](../../../codex-rs/hepta-memory/src/cognitive_retrieval.rs) uses `load_generation_query_cut_tx` to reconstruct the persisted V2 generation and, for compact storage, its support-to-memory index together in the same read transaction. Legacy storage retains the physical `kg_edges` lookup fallback. The shared loader reuses occurrence IDs from loaded edge rows instead of a third source-cut scan; its generation-only mode allocates no query index. Retrieval retains the owned immutable validated generation plus relation-kind inventory in that transaction. Each processed seed remains fenced by its persisted `generation_sha256` before an absent typed relation skips an empty query. Remaining queries use the shared KG core. Relation selection, temporal visibility and truncation retain one semantic owner; ordering, ranking and admission bounds are unchanged, and SQL only resolves the selected support identities back to physical memory occurrences.
- **Prompt-factor owner source and projection:** [codex-rs/hepta-prompt-registry/src/lib.rs](../../../codex-rs/hepta-prompt-registry/src/lib.rs) owns governed complements/substitutes/conflicts and is the only constructor of the sealed `PromptFactorGraphSourceV1`. [codex-rs/hepta-kg/src/prompt_factor.rs](../../../codex-rs/hepta-kg/src/prompt_factor.rs) rebuilds that exact source into `KnowledgeGenerationV2` with registry-revision support lineage and the registry source digest as the generation source snapshot. The existing durable registry admits relations through an operation-bound final-use grant and persists them with its metadata; legacy metadata without relations retains an empty relation set. `revoke_factor_relation_final_use` binds a durable immutable withdrawal to the current owner cut, original relation, actor, scope and reason. A withdrawn identity cannot be reused, but replacement evidence can use a fresh identity. Reopen verifies withdrawal lineage; the next source/projection excludes withdrawn relations even when both endpoints remain admitted. Factor revocation also removes non-admitted endpoints/relations on the next rebuild.
- **Prompt-factor real consumer:** [codex-rs/hepta-prompt-optimizer/src/graph.rs](../../../codex-rs/hepta-prompt-optimizer/src/graph.rs) requires every candidate factor to exist in the complete V2 generation and queries the exact generation for complements/substitutes/conflicts. `PromptConflicts` are hard co-selection exclusions and `PromptSubstitutes` are hard redundancy exclusions. `PromptComplements` are counted and request/result-bound but do not add unsupported numeric gain; calibrated complement marginal utility must come from causal interaction evidence. The graph-bound portfolio receipt binds the exact query request digest, query result digest and typed relation counts. Its private original-binding seal plus inner portfolio validation reject valid standalone portfolio substitution or rewritten graph/query digests even if the public digest is recomputed. These typed output seals are not external authentication credentials. The optimizer remains read-only and authority-free.
- **Canonical candidate source cut:** [codex-rs/hepta-prompt-optimizer/src/canonical.rs](../../../codex-rs/hepta-prompt-optimizer/src/canonical.rs) and [canonical_input_binding.rs](../../../codex-rs/hepta-prompt-optimizer/src/canonical_input_binding.rs) seal the complete original enumeration and verified pricing result separately. `select_portfolio_v1` validates both inputs and accepts only a sealed `PromptFactorProjectionV1` with the exact owner revision/snapshot/source cut and generation vector; arbitrary bare graphs cannot omit owner relations or be relabeled into this boundary. A complete private selected-output seal covers bindings, actual realizations and accounting; `exercise_v1` validates it before checking current owner state. Canonical complements/substitutes require graph/state/edge-bound signed evaluator pair utility, unlike the graph wrapper's hard substitute exclusion and observation-only complements. The additional four relation kinds remain private algorithm fixtures until a sealed owner can emit them. Generic KG validation still proves semantics, not authentication of external facts.
- **Versioned utility evidence:** [canonical_evidence.rs](../../../codex-rs/hepta-prompt-optimizer/src/canonical_evidence.rs) defines `PromptPricingEvidenceV2`, binding the complete enumeration receipt and the factor's actual realization digest, and `PromptPairUtilityEvidenceV2`, binding model-tuple and both oriented realization digests alongside graph/state/edge identity. Formal pricing/selection use the V2 signing domains; unchanged V1 types and payloads remain available for historical interpretation. Raw confidence bounds receive the same deterministic debit as net utility, using checked Q32 arithmetic/range conversion. The existing confidence admission rules are preserved.
- **Canonical evidence lifetime:** pricing and selection require the enumeration objective to equal the current verifier objective. Priced inputs privately retain at most 129 completeness/pricing signed proofs with canonical payloads, admission time and trust digest. Selection rejects time before pricing admission and re-verifies the proofs at its current time, rejecting expiry, trust rotation and effective scheduled revocation. Its lifetime is capped by the requested deadline and the shortest completeness/pricing/pair/selected-realization deadline; verification at the exclusive upper bound minus one millisecond rejects crossing a scheduled revocation already known to the same trust snapshot. `exercise_v1` checks the selected seal, current registry owner and expiry and emits typed `DENY_ALL` proposals; for a nonempty selection it rejects clock rollback before the privately sealed `selected_at_unix_ms`. It cannot detect an unknown later ledger trust rotation; final effects still require fresh trust and final-use authorization.
- **Oracle/product tests:** [cognitive_kg_oracle_tests.rs](../../../codex-rs/hepta-memory/src/cognitive_kg_oracle_tests.rs) compares full and incremental V2 generation with SQLite materialization, reopen, correction/tombstone and query visibility, including physical output, generation and publication digests; it also reconstructs the full persisted predecessor-bound publication chain and verifies fail-closed live entity shape conflicts plus legal shape evolution after correction. [cognitive_store_tests.rs](../../../codex-rs/hepta-memory/src/cognitive_store_tests.rs) adds the ignored child-kill crash-window matrix. [cognitive_kg_benchmark_tests.rs](../../../codex-rs/hepta-memory/src/cognitive_kg_benchmark_tests.rs) emits the PERF-LIBRARY pilot receipt. [cognitive_product_e2e.rs](../../../codex-rs/hepta-agentd/tests/cognitive_product_e2e.rs) exercises the real Agentd/App Server path and checks persisted receipts across restart/correction/forget plus fail-closed startup when the writer store is unavailable. Prompt-stack tests in [prompt registry](../../../codex-rs/hepta-prompt-registry/src/lib_tests.rs), [prompt factor projection](../../../codex-rs/hepta-kg/src/prompt_factor_tests.rs) and [optimizer graph consumer](../../../codex-rs/hepta-prompt-optimizer/src/graph_tests.rs) cover governed relation admission, sealed source production, revocation/rebuild, V2 query and hard-conflict selection.
