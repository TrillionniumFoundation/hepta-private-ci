# learning.operator: implementation design

Parent: `docs/modules/learning.operator/TECHNICAL.md`. Lane:
`LANE-E-LEARNING`. Canonical mutable status is
[`docs/modules/learning.operator/STATUS.json`](../../../docs/modules/learning.operator/STATUS.json).
This dossier explains implemented mechanics and acceptance boundaries; exact
candidate identities are generated by qualification rather than copied here.

The deterministic reference, simplest-sufficient tabular learner,
action-conditioned world model, owner-bound final-use path, V2 read-only loader
and the generic Agentd shadow coordinator are implemented source candidates.
The evaluated ranker is a real read-only consumer. A real artifact persistence
adapter, qualified V3 read-only loader and named ProductRunner persistence API
are implemented. Remaining coordinator owner stages, one configured default
runtime lifecycle, distinct-process shadow and exact durable rollback remain
repository-controlled integration work.
Scientific efficacy, target-host capacity, production writer authority,
operator acceptance, canary, promotion, activation and release remain external;
activation remains false.

## 2. Public operations and API boundary

Default public operations include canonical profile construction, opaque
single-use final-use capability issue/consumption, semantic sensor-core
qualification, V2 pinned loading and the read-only shadow coordination contract. The
owner-authenticated V3 verification and fitting primitives remain crate-internal
on the default path so an external caller cannot bypass the final-use capability
fence.

The crate root uses an explicit allowlist. Raw structural fitters, direct V3
owner-bound verify/fit functions, generic V2 caller-authored verification inputs
and raw prediction helpers are unavailable to default consumers; they are
feature-gated under `qualification-unverified-input` and grouped in
`compatibility`. Independent consumer compile-pass/compile-fail tests enforce
this boundary.

The original `build_targets` remains a deterministic target builder, not a
neural trainer or authority boundary. The historical `train` alias is
compatibility-only.

## 3. Owner-authenticated training and state

There is no production source writer. Training reads immutable ledger-bound
datasets and emits immutable candidates for the artifact owner. Sensor cores are
fixed versioned designs, not replay caches. Artifacts bind axis partition,
conditioning snapshot, model and dataset lineage, units, runtime/device,
applicability, error budget and predecessor.

The tabular learner requires a complete canonical sensor-by-action grid and a
minimum sample count for every cell. Per-cell mean, minimum, maximum, count and
evidence digest are retained. Missing/underfilled cells and relabelled duplicate
evidence reject. Inside the final-use implementation,
`verify_tabular_operator_plan_v3` binds the durable `LedgerWriter`, independently
verifies `DatasetSnapshotReceiptV3`, objective, dataset and exact signed source
records, then issues an opaque input consumed by the internal fit. Current-owner
verification repeats immediately before and after work. Unsupported predictions
abstain rather than extrapolate.

The action-conditioned world model groups immutable observed rows by
state/action, rejects relabelled evidence, publishes exact Q32 branch
distributions and rejects unsupported pairs. The bounded V2 profile uses exact
integer moments for variance/confidence, accounts for owned input text/capacity
before allocation, and retains private statistic/metadata integrity commitments. Model-generated trajectories remain
synthetic and cannot satisfy independent outcome evidence. Legacy fitted world
models retain a private inference seal so mutations of public fitted fields reject;
the V2 commitments bind complete training rows. Raw, indexed and persisted tabular
inference share bounded rectangular-support, identity, cell-evidence and attainable
summary-statistic validation.

The reference consumes supplied reward/continuation cells, not diffusion
simulation. V2 dataset wrappers establish structural membership only; internal V3
training binds current durable-owner facts and signed row semantics. The
owner-derived terminal profile derives its labels directly from authenticated
decisions/outcomes, rejects future observation/finality times and a fit clock
before freeze, and revalidates correction/withdrawal at fit.

## 4. Deterministic sensor construction

Applicability admission checks the declared smooth/jump/hard profile separately.
The sensor builder constructs deterministic farthest-point sensors and records
finite-design fill distance, separation radius and mesh ratio. Fill and mesh
round upward, separation rounds downward, and the manifest commits the complete
candidate design. `hull_digest` is a selected-point commitment, not a geometric
hull or continuous-domain coverage proof; tabular OOD is exact fitted identity
membership.

`build_sensor_core_qualified_v1` emits a public receipt containing:

- `selection_mode=exact|reduced`;
- stable reduction-algorithm identity;
- exact and maximum working-set limits;
- input/working candidate counts;
- operation, elapsed and estimated-memory work receipt;
- aggregate qualification digest.

The reduced path uses deterministic fingerprint-stratified candidate reduction
before exact FPS on the bounded working set. Tests compare exact and reduced
modes on tractable inputs, cover adversarial duplicate handling, enforce
determinism and bound geometry degradation. This is bounded engineering
evidence, not a universal covering-optimality proof.

## 5. Final-use and product composition

Canonical `TrainingProfileV1` and `WorldModelProfileV1` derive profile and
runtime identities internally and bind sensor representation, objective,
dataset frontier, support/error budgets and runtime limits.

Opaque non-`Clone` final-use capabilities borrow the durable owner and bind
ledger head, dataset generation, candidate generation, authority epoch, stop
epoch, issuance time and exclusive deadline. Owner/currentness is checked at
issue, immediately before fit, after fit and at selected/pinned use. Time before
issuance is a clock regression; equality with the deadline fails closed. The
retained monotonic fit context also checks actual elapsed work and cancellation
at the final publication boundary. World-model request trust must match its
current owner verifier.

The implemented Agentd coordinator contract has this sequence:

```text
freeze training → final-use fit → freeze independent future window
→ independent evaluation → independent selection → create-only persistence
→ fresh-process LoadedTabularOperatorV2 load → read-only shadow
→ currentness/revocation → exact predecessor rollback
```

The coordinator has no publish, canary or activation port. Its state-machine
tests implement fixture ports. Separately, signed ledger/evaluation/selection/
ranker E2E uses fixture keys and a virtual clock to exercise component identity,
ordering, revocation and rollback. That test does not invoke the coordinator or
prove longitudinal product benefit. Real owner-port adapters and the default
runtime caller must be composed before `defaultLoopWired` becomes true;
`productExecutionProved` remains false.

`LoadedTabularOperatorV2` verifies immutable bytes and pins once.
`SelectedTabularOperatorV1` and the opaque selected world model additionally
check their retained selection window at each prediction. Static selection tokens
do not observe later revocation, registry changes or stop events; actual host
owner witnesses must be refreshed at every final use. Tabular selection binds the
trust digest retained when training.

Current native structs do not implement the canonical-JSON protocol adapters.
Three untrusted registered transport codecs have strict bounds and canonical
round-trip tests. Bellman canonical schema definition and context/semantic
native bridges remain repository-controlled work. V2
sensor/reference/target/tabular commitments require new independent admission;
correctly pinned existing `HEPTTB01` payload bytes remain readable. The raw world
model has no persisted wire format to migrate.

## 6. Capacity and performance

Canonical smooth dimensions are bounded by 32, sensors by 4096 and actions by
128. The compatibility tabular grid is bounded by 262144 cells and 1000000
represented samples; owner-authenticated signing has a separately smaller row
bound of 4096 signed rows. World-model limits are profile-specific.

GitHub-hosted performance is a regression gate only. Shipping capacity requires
a target-host profile with fixed runner/device identity, warm-up, a statistically
meaningful measured sample, cold/warm separation, actual RSS/cgroup or allocator
observations and independent acceptance. Structural maxima and three-sample tail
percentiles are not accepted as target-host capacity facts.

## 7. Failure, recovery and rollback

Failure classes preserve identity conflict, stale owner, revoked authority,
source withdrawal, resource exhaustion, cancellation, deadline, clock
regression, payload mismatch, load failure, shadow rejection, currentness
failure and rollback failure. Failure to reopen the exact predecessor is
terminal. Unknown persistence and unverified cleanup retain stable recovery
identity and cannot become terminal success or a safe blind retry. Actual host
clock and receipt expiry are checked around each port; verified persistence is
cleaned up after work expiry. Terminal audit binds storage, selection reason and
rollback evidence.

Every qualification stage emits `passed`, `failed` or `not_run`. Independent
stages continue after a documentation or API-contract failure so diagnostics are
not hidden. Any non-passing, cancelled, skipped or missing required stage forces
`mergeReady=false`; repository evidence never sets `productionQualified=true`.

## 8. Concrete verification cases

- OP-01: analytic Bellman table reproduces canonical Q32 goldens.
- OP-02: unsupported diffusion, mesh ratio or reconstruction gain disables the learned path.
- OP-03: high in-sample fit with poor future calibration or retention fails evaluation.
- OP-04: synthetic rollouts remain synthetic; unsupported pairs abstain; duplicate world-model evidence rejects.
- OP-05: tabular fitting is deterministic and complete-grid; duplicate evidence rejects.
- OP-06: the internal V3 path consumes the exact owner-authenticated frozen dataset and signed rows only through final-use or the explicit compatibility feature.

Additional authoritative qualification scenarios retain their own test/script
identities rather than redefining the OP case registry:

- Semantic sensor receipts report exact/reduced modes and a stable algorithm identity.
- Independent API consumers cannot import raw fitters, direct V3 verify/fit, compatibility, publish or activation ports by default.
- Component V2 load, revocation and predecessor rollback execute through Agentd; separate-process payload tests and fixture-port coordinator tests cover their respective boundaries. A unified coordinator E2E remains work.
- Exclusive-deadline and issuance-clock mutations are killed by named final-use tests.

## 9. Qualification identity and readiness

The authoritative workflow runs exact source and ordered-parent deterministic
merge lanes. It records source head, frozen source, observation head, base,
deterministic merge, GitHub merge, workflow blob, workflow run/attempt, runner,
target, lockfile, toolchain, test-set, implementation-map, documentation, source
tree and all artifact hashes in one readiness manifest.

Results from different attempts cannot be combined. The real post-merge `main`
SHA reruns qualification. Independent scientific review, future-window efficacy,
target-host capacity, operator acceptance, canary, promotion, activation and
release remain unissued external gates.

Repository closure also requires canonical wire adapters and a named runtime
caller with actual owner ports for the coordinator. Source-map validation reports
these gaps separately from source/test inventory success; no empty-gap projection
may replace the missing composition evidence.
