# learning.plasticity: implementation design

Parent: `docs/modules/learning.plasticity/TECHNICAL.md`. Lane: `LANE-F-ADAPTIVE-POLICY`.
Status: parameter V2 remains compatibility-stable; governed V3 candidate generation enforces an authority-free typed parameter mutation policy, and the real Agentd runtime bootstrap now creates the bounded owner/producer pair and retains the producer handle in Agentd state. `AgentdState` now retains the named non-test `AgentdLearningPlasticityProducerV1`, which holds only the bounded runtime handle. `AgentdState::submit_parameter_plasticity_v1` routes through that producer while the long-lived owner exclusively retains writers, owner stores, trust verification and anchor/fence state. Dataset/Policy plus NDU modulator, broadcast-policy, neuron eligibility and exact ParameterSignal owner adapters are implemented with live-frontier/value binding. Parameter/topology registries retain external-anchor/fence recovery. The external `hepta-runtime` owner implements FinalUse-authorized live CNS topology replacement plus a separate recovery transition: healthy replacement requires every predecessor organ Ready, while recovery accepts only Stopped/Quarantined predecessors and uses a distinct FinalUse destination. Repository qualification now exercises a real cutover → forced live-host stop/fault → separately authorized recovery generation → Observer-signed canary receipt. Target-host execution evidence, physical rollback-domain independence, independent/operator acceptance, activation and release remain external gates. Common requirements: `../EXECUTION_SEMANTICS.md` and `../TECHNICAL.md`. Canonical ownership and package predecessors are unchanged.

## 1. Source and work envelope

Roots: `codex-rs/hepta-plasticity`.
Packages: `PLS-1-PARAMETER-PLASTICITY`, `PLS-2-TOPOLOGY-PROPOSAL`, `PLS-3-BOUNDED-STRUCTURAL-CANARY`.

Operation signatures below describe the target contract. Section 8 identifies the implemented native subset and current product adapter. Preserve existing stores and APIs; do not create another authority or execution spine.

## 2. Public operations and contract details

Target operations remain `propose_parameter_delta(selected_artifact, eligibility, modulator, trust_region) -> PlasticityProposalV1`; `propose_topology(body_graph, typed_operation, unmet_capability) -> TopologyProposalV1`; `validate_candidate(candidate, constraints, rollback_design) -> CandidateDisposition`. The module can produce candidates, not apply them to its current runtime or select itself.

The source implementation uses versioned internal records instead of relabeling those target JSON contracts. Parameter V2 remains compatibility-stable. Parameter V3 defines a bounded deterministic generator whose output can be regenerated exactly. Topology V2 creates typed structural candidates but deliberately has no apply path.

## 3. State records and transaction design

`plasticity_proposal_registry` is append-only: candidate/content ID, exact predecessor, source/objective/body, generator, supported dataset and update-rule digests, parameter/topology delta, bounds, test/evaluation references, rollback and state. Generated candidate state never doubles as selected production state. Current selected weights and graph are read-only.

The parameter writer uses an explicit `Healthy -> AppendPendingAnchor -> Healthy/Poisoned` state machine. Bootstrap emptiness is checked only after the durable registry has acquired its exclusive file lock. Agentd owns a source implementation of the independent anchor/fence store and recomputes owner frontiers before admission. Governed topology proposals use a separate checksum-chained anchored registry and Agentd topology anchor/fence store. Deployment still owns physical rollback-domain separation and target-host execution evidence.

## 4. Deterministic algorithm and scheduling

Parameter V3 starts with no-change and evaluates every declared positive scale over explicit parameter signals. A `ParameterMutationPolicyV1` is mandatory: each signal must match the exact artifact/window-bound parameter allowlist and layer mapping, stay within policy bounds and be marked `LearnableParameter`; authority, evaluator, deletion, runtime-topology and credential surfaces fail closed. This Rust policy is not the canonical readiness `MutationGrammarManifestV1`; that protocol remains owned by `control.engineering`, and plasticity is only its declared consumer. Each signal maps eligibility, modulator and learning rate to one parameter, uses checked Q32 arithmetic, clamps to explicit bounds, rejects unknown norm layers and duplicate parameter identities, applies the canonical per-layer/global trust regions, removes duplicate semantic candidates, and derives update candidate IDs from the selected artifact, exact window and canonical content. The source therefore proves generator-relative completeness for the declared bounded V3 profile rather than accepting an arbitrary caller candidate list as complete.

For authenticated adapter composition, the generator signs the generated-set digest. A trusted Observer signs the selected artifact, current artifact/evidence frontiers, window, generation, dataset/update/modulator/eligibility lineage and generator digest. Every update candidate must then carry a signed independent evaluation under the existing host-owned learning-evidence trust snapshot. If deterministic generation produces only no-change, a distinct Evaluator signs the exact no-admissible-update terminal payload and that disposition is durably recorded instead of being collapsed into an ordinary error. Proposer and evaluator IDs are derived from verified principals, not caller-supplied role labels.

Topology V2 starts with no-change and one candidate per typed operation. Add/remove/replace/split/merge/rewire/retire changes carry migration, rollback, writer-handoff and evidence digests. `admit_governed_topology_v1` requires one exact typed writer-handoff plan per update, distinct source/destination owners, an advancing writer fence and matching migration/rollback bindings. Authenticated Generator/Observer/Evaluator roles are verified before durable append. `StructuralCanaryControllerV1` observes bounded canary evidence but has no apply path. The composed path uses `observe_authenticated_structural_canary_v1`, so the plan and every health/evidence/regression/safety/lineage/rollback assertion must be signed by a trusted Observer before entering the state machine. Application remains outside this module.

## 5. Capacity and performance profile

Canonical parameter bounds remain <=32 candidates, <=4,096 total deltas, <=256 norm layers, per-layer relative parameter delta<=0.5%, global<=0.25%, and one proposal per artifact/window. V3 admits at most 31 update scales and caps signal/scale work at 4,096 deterministic evaluations. Initial structural candidates contain one operation and are capped at 31 updates plus no-change.

Operational thresholds and recovery are concrete in `docs/modules/learning.plasticity/OPERATIONS.md`; they remain host targets until exact deployment measurements exist.

## 6. Concrete verification cases

- PLS-01: parameter deltas beyond any trust region reject even when visible reward improves.
- PLS-02: split/merge cannot duplicate writers or erase supported lineage.
- PLS-03: topology candidate cannot self-activate or alter its evaluator/hidden tests.
- PLS-04: canary abort fences new work and verifies a compatible non-revoked predecessor after reconciling outstanding effects.
- PLS-05: regenerated V3 candidate set must exactly match the generator digest and artifact/window-bound content IDs.
- PLS-06: authenticated adapter rejects unsigned/expired/revoked generator or Observer evidence, generator/evaluator controller collision, missing candidate evaluation and stale/frontier mismatch.
- PLS-07: any acknowledged proposal-history reopen requires the externally retained registry anchor; failed external anchor persistence poisons the adapter writer, and a retained acknowledgement rejects a rolled-back registry prefix.
- PLS-08: a generator-relative no-admissible-update outcome is independently attested and durably recorded as no-change rather than returned as an ambiguous error.
- PLS-09: changing any structural-canary observation fact after Observer signing invalidates admission before the controller transition.

These are required product test designs unless a named exact-candidate receipt is attached. Source test identity is not an execution receipt.

## 7. Integration, rollback and capability ceiling

The product-workspace parameter and topology adapters live in `codex-rs/hepta-intelligence`. `codex-rs/hepta-agentd` now supervises a long-lived `PlasticityRuntimeOwnerV1` that exclusively holds the writers, trust verifier, current ArtifactRegistry/DurableLedger handles, owner-evidence resolver and independent anchor/fence seams behind a bounded typed channel. The host recomputes current artifact/ledger frontiers immediately before admission. Dataset receipts and immutable Policy artifacts have concrete live-frontier adapters. NDU projection state supplies the current modulator, the immutable broadcast-policy artifact binds the projection map, neuron.runtime supplies the anchored eligibility checkpoint, and ParameterSignal evidence recomputes the exact eligibility/modulator/learning-rate/bounds consumed by the generator. These adapters reject stale, rolled-back, unavailable, wrong-owner and value-substituted state. The bounded Agentd submission boundary is now driven through the state-held non-test `AgentdLearningPlasticityProducerV1`; the lifetime E2E exercises that route while final owner/frontier/evaluator/anchor validation remains inside the long-lived owner. This source composition is not evidence that a deployed target host has executed or accepted the path. Rollback of selected model/topology state remains an authorized transition outside this proposal engine.

- **Governed topology composition:** `admit_governed_topology_v1`, `DurableTopologyProposalRegistryV1` and `StructuralCanaryControllerV1` in the plasticity core; `propose_authenticated_topology_plasticity_v1` in `codex-rs/hepta-intelligence/src/topology_product.rs`; `observe_authenticated_structural_canary_v1` in `codex-rs/hepta-intelligence/src/topology_canary_product.rs`; and `propose_agentd_topology_plasticity_v1` plus the topology anchor/fence store in Agentd.
- **State and recovery:** `DurableProposalRegistry` owns bounded, locked, generation/fence-scoped checksum-chain frames. The adapter writer allows unanchored open only for a brand-new zero-length registry; acknowledged history reopens through an external anchor and a failed external anchor commit poisons the writer. Agentd parameter/topology host anchors use the shared append-only `AdaptiveAnchorJournalV1`: complete corrupt frames fail closed, only incomplete crash tails are repaired, and explicit rollover/resume preserves monotonic generation fences. Registry resume is separately restricted to zero complete frames; header-only/incomplete-first-frame state may recover, while any complete unacknowledged proposal frame is preserved and rejected for explicit reconciliation.
- **Evidence boundary:** the adapter uses the existing `LearningEvidenceVerifierV1` and signed evaluation path for trust-root, signature, expiry, revocation, role and controller-separation checks. Agentd owner-evidence queries bind the live ArtifactRegistry/DurableLedger heads and exact per-signal numeric values. `ConcretePlasticityOwnerEvidenceResolverV1` verifies DatasetSnapshotReceiptV3 and eligible Policy artifacts against those live heads. `PlasticityDynamicOwnerEvidenceResolverV1` verifies the NDU modulator projection, immutable broadcast-policy binding, anchored neuron eligibility and exact per-parameter numeric signal values; stale/unavailable/rolled-back/wrong-owner inputs fail closed rather than falling back to opaque digests.
