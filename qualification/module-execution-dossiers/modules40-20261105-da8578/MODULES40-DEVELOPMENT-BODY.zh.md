# 40 个模块的源码能力、组合层级与开放门槛

当前 40 个模块均有登记的源码根，371 条操作映射构成了实现导航；全部模块的 productionImplementation 仍为 false。源码实现、命名 caller/writer 的组合、固定候选执行、部署资格和独立验收属于不同层级，不能互相替代。

本节固定描述源码 `8658210499706130788c216ff14fd342809b45a4`（tree `6bc86196d10cf83b010f9917e5e9cb471b5f6b68`）中的 Map 事实。模块名链接到该提交的对应 Map；原生和平台 CI 的实际结果由执行总览按各自 commit/tree 单独记录。完整源码根、owner、caller/writer 原值、371 条操作、全部 gate 以及历史 source pins 均保存在同目录 `MODULES40-SOURCE-FACTS.json`。

源码事实以显式传入的 40 张 Map blob 清单、登记表和 canonical Git 对象绑定；3 份 source-navigation history ledger 的原始文档也完整保留在 facts JSON 中。sourceBase 和历史执行观察保持各自身份，新增导航只更新对应源码定位。

“尚未组合”指命名产品调用与 owner 的组合资格未闭合，不能理解为没有源码。只读、无状态或组合 facade 的模块也不应为了填满 writer 字段而新增持久 owner。

## 读表时保留的边界

- 表内能力依据当前 Map 的 operation、caller/writer 与 owner 边界概括；完整原字段没有被中文摘要替换或升级。
- 各模块共同需要当前固定源码和有序合并候选的相应资格回执，表中优先列出更具体的产品或外部门槛。
- 历史 sourceBase、observedAtHead、currentSourceEvidence 和源码审阅 addendum 保留原身份。导航重绑不搬运历史执行证据。
- 某些 Map 的内部 gate 列表为空，仍不能据此宣称生产完成；例如 TaskFlow、Servo 和 UI 的实际宿主、二进制、认证与终态验收仍在外部 gate 中。
- 实现操作数不等于模块通过数。局部恢复/取消/撤销回归不代替默认 daemon 完整路径、真实 provider 或独立部署验收。
