# Original checkpoint retention on two hosts

The ongoing sustained CREMA-D trainer preserves every immutable development checkpoint locally. Its deployed collector checks the hashes of all history entries, then archives the selected best weight for each cell. The alternative collector in [#7264](https://github.com/TrillionniumFoundation/hepta-private-ci/pull/7264) also retains original per-clip scores for each gate. The live original process predates that collector.

This independent finite mirror protects the historical weight bytes used by all quality gates. On ai395, `capture_history.py` fixes the live trainer source SHA-256 and validates a checkpoint against its original history entry before creating a content-addressed hard link on the same filesystem. These links provide a stable incremental transfer source. The desktop pulls missing blobs with its existing strict SSH identity for ai395. It checks its own and the source machine identities, verifies each destination blob's size and SHA-256, and retains the exact source inventory. The two hosts have physically independent source and destination disks. The worker uses a single writer lock; a checkpoint mismatch fails the run. It exits when all 12 cells' six registered history milestones and the final original selection seal are present, or errors after the finite observation window. The earlier independent gate replay remains available.

The first successful second-host receipt contains all 60 then-existing original history weights (193,806,920 bytes). Compare [first receipt](first_receipt.json) with [the exact source inventory](first_manifest.json). The source inventory's SHA-256 is 0e5220e3ae393dbce8b67432f266f598336268783a0e759cb7ac54339985a18f. The original trainer, timing and scoring paths continue on the original host. The mirror only handles weights, development history, and the eventual selection seal. Original cold arrays and later recomputed arrays retain their separately identifiable provenance.
