# Replay every historical CREMA-D checkpoint against its original input

The live study evaluates six observed budgets (16 and 128 updates, and 20, 240, 1,000 and 3,150 optimization seconds), four encoders and three seeds. Its original `study.py` SHA-256 is `69e8cf12bcfcd414175250405ac08286901457377d76c1ad28f08d33a775dbc1`. That program retains raw held arrays only for the single development-best candidate and saves aggregate metrics for its other development-selected quality gates. An independently archived selected gate and a complete chronological series answer different questions.

The historical replay verifies the source and original data hashes, loads each immutable chronological weight by its original SHA, reproduces the production scorer, independently recomputes NLL using float64 log-sum-exp and rechecks development top-1. It saves each original 72-way gallery score array together with row IDs and truth. At the captured development snapshot, 62 unique checkpoints reconstructed all 1,147 development examples, producing **5,120,208 original gallery logit values**. The receipts bind all 62 per-checkpoint array hashes and original weight identities. The physical arrays on the ai395 host are under `/home/qq/.local/share/hepta-research/hcsn-9de7-cold-history/dev`. At the same stage the immutable weights were preserved on a separate host, 62 distinct weights and 200,391,774 bytes.

A single finite worker is listening to the original result directory with Linux filesystem notifications. It opens the held scoring pass after the original study publishes its complete `terminal.json`. It then reconstructs development and held outputs for all observed chronological gates, verifies every development-selected best held array bitwise and every published selected-gate aggregate numerically, then computes paired actor-cluster differences independently at each prespecified gate. The snapshot here is development-only. Secondary comparisons across fixed checkpoints are explicitly post-training validation and are not used for development selection.
