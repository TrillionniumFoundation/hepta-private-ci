# Native-decoder qualification after the large executable hit the worker file limit

The managed T4 worker for request `hcsn-public-rematerialize-1140569-20261128` retrieved the exact public wheel and verified its bundled binary hash. Writing the binary raised Linux `EFBIG` before any media files were fetched. The provider-level execution succeeded and the data experiment qualified zero inputs. This new request preserves that first result and its source.

The recovery studies decoders already present on the new private Colab VM. It never installs a large executable. It records the SHA, version and size of each available candidate and the process's file-size ceiling. A requested candidate must match both 12-frame image and audio SHA-256 references on each of six predeclared pilot clips, taken at the beginning, midpoint and end of the sealed 48-clip reference in training and held-out folds. Candidates are tested in fixed order, with duplicate executable content omitted. The first qualifying executable gets the original full 48/168/672/1776/7442 sequence. There is no relaxed equality tolerance. The primary deliverable is byte-level data equivalence, independently qualified for every completed tier. Any decoder/version differences and failed pilot counts remain part of the result. All other source identities, time budgets, splits and four-arm training endpoints follow the frozen parent protocol.
