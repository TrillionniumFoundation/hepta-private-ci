# Hepta PR #1494 — latest-SHA CI convergence observer

This is a **read-only, non-authorizing** operator diagnostic. It is **not** a
GitHub commit or a production promotion receipt. The repository's ongoing
large CI run should complete for one fixed HEAD before another source change;
this tool intentionally does not push a commit or restart CI.

## Provenance and usage

This folder includes a narrowed GitHub REST field projection from the Oct 13,
2026 audit for HEAD `8ca848b86290d004ac838357f55b2ed3f506acbd`: `pr.json`,
`ref.json`, and `runs.json`. The projection is **not signed**; it is merely a
record of the observed REST values, not a host-attested source of truth.

For a NEW capture, use a GitHub-authenticated `gh` CLI on a trusted machine,
then independently verify its response origin. Do not substitute a previously
saved snapshot for the latest HEAD:

```sh
gh api repos/TrillionniumFoundation/hepta-private-ci/pulls/1494 > pr.json
gh api repos/TrillionniumFoundation/hepta-private-ci/git/ref/heads/codex/neuron-external-model-trials-20261011 > ref.json
sha="$(gh api repos/TrillionniumFoundation/hepta-private-ci/pulls/1494 --jq '.head.sha')"
gh api "repos/TrillionniumFoundation/hepta-private-ci/actions/runs?head_sha=$sha&per_page=100" > runs.json
python3 hepta_ci_convergence.py --pr pr.json --ref ref.json --runs runs.json \
  --repo TrillionniumFoundation/hepta-private-ci --number 1494 \
  --branch codex/neuron-external-model-trials-20261011 \
  --expected-sha "$sha" --output observation.json
# Re-read PR + ref AFTER collecting workflows. If HEAD changed, reject report.
```

CLI exit 0 only if all nine required workflow runs were completed `success` on
that exact observed SHA. Incomplete/queued/missing/failed/older-SHA reports
return exit 1. Malformed observations or preexisting output file return 2.
A newer failed or queued run supersedes an earlier success of the same name and
SHA. Workflow-dispatch/manual runs never stand in for the corresponding PR
check. Stale CI status is **never** accepted as a new HEAD success.

The observed Matrix advisory probe remains **non-accepting**. Even an all-green
CI workflow snapshot cannot by itself prove patched Matrix dependencies,
actual CNS/Cell selected state, trusted physical model load or real future
NDU returns. The report ALWAYS sets
`matrix_production_upgrade_verified=false`,
`production_no_change_selection_verified=false`,
`real_future_window_ndu_verified=false`, and `promotion_authorized=false`.

This is not an independent GitHub signature verifier and cannot securely
resolve a network race by itself. Run it from trusted GitHub API captures,
re-read HEAD afterwards, and use the real GitHub run URLs and logs for final
human review. Do **not** disable cargo-deny or ignore RustSec advisories to
make this output green.
