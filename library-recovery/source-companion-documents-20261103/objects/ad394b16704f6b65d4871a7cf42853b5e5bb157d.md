# Hepta P0 — 本地、无网络、Fail-closed 修复与审计工具

**本包由助手的隔离本地工作目录创建并运行 Python 单元测试。它不是你的 dot 电脑，也不是 Hepta 仓库克隆。** 没有 Rust 工具链，因此不能声称 Cargo、Clippy、Bazel、目标主机或生产 NDU 已通过。

## 使用步骤（dot / 已授权的本地工作树）

确保 Python 3.11+；只需要标准库，无账号/联网依赖。解压本包后：

```bash
# 1. 先基于你 dot 电脑上的真实仓库路径审计（阻断时退出码 2）
python3 hepta_p0_local.py --repo /你的路径/hepta-private-ci audit --out /tmp/hepta-p0-local-audit.json

# 2. 查看精确的六处 Rust 测试改动，不修改任何文件
python3 hepta_p0_local.py --repo /你的路径/hepta-private-ci fix-core-tests

# 3. 在本地确认 git status 与当前分支，然后明确执行此修复
python3 hepta_p0_local.py --repo /你的路径/hepta-private-ci fix-core-tests --apply

# 4. 本地 Rust 工具链与实际复现；不能用审计脚本代替
cd /你的路径/hepta-private-ci/codex-rs
cargo +1.95.0 fmt --all -- --check
cargo +1.95.0 test --locked -p codex-core --lib client_provider_policy_tests -- --nocapture
cargo +1.95.0 clippy --locked -p codex-core --all-targets -- -D warnings

# 5. 完整依赖审计——需要真实 cargo-deny 和全部 lockfile
cargo deny --locked check
```

如果仓库代码不是六个精确的旧调用、函数签名不对、文件缺失或被并发改动，工具以退出码 3 **拒绝修改**。补丁原地原子更新，不在仓库里留下 `.bak` 或无关文件。

## 已经在本地执行的测试

python3 -m unittest discover -s . -p 'test_*.py' -v

## 安全边界

工具**不做**以下行为：部署、推送 GitHub、更新 production Cell、绕过 Final-use、改 Cargo.lock、添加 advisory ignore、下载或执行模型权重。`audit` 不可能证明生产晋升：即使静态检查全部通过，输出 `production_qualified=false`、`rust_compiler_ran=false`。

在拿到实际 dot 机器工作树及权限前，不应声称此工具已在 dot 电脑运行。任何核心变更都必须真实 Rust Test/Clippy/Windows Bazel 验证，并且独立的 Artifact CAS、NDU、异常恢复及 64–4096 Cell 目标主机测量仍属独立生产门禁。
