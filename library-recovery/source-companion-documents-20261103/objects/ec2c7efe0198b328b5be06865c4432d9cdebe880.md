## Actual diagnosis

At the repository GitHub Actions API, two sequential observations showed **1,457–1,515 queued workflow runs** and approximately **7 in progress**. Those numbers are workflow runs, not failed jobs or evidence that each one is runnable. The queue includes `blocking-ci`, Architecture, Neuron, Stem and MemoryCell work. Listing through the GitHub API becomes partial at the 1,000-run pagination boundary; **the entire oldest-to-newest queue has not been exhaustively enumerated**.

At the exact PR #2366 source SHA, the queued campaign included Granite `38736123539`, Router CPU `38736123597`, A–F `38736123461`, and global `blocking-ci` `38736123624`. Architecture source-head and base-merge jobs in run `38736123403` completed successfully; aggregate required check remained queued on inspection. Historical #2239 CPU/A–F/Granite **offline** gates succeeded, but its real 97M model child remained queued, so there is no new 224-case five-arm real Granite outcome receipt.

The public [GitHub Status](https://www.githubstatus.com/) page listed Actions operational and no reported incident for Oct 15 at the time checked. That does **not** prove a repo- or organization-specific runner/billing/concurrency problem, and does not rule out an undetected service issue.

### What was actually changed

This package adds a **strictly read-only** workflow inventory script, with a fixture-based safety suite. It cannot cancel, dispatch, rerun, merge or grant runtime/model permission. It identifies older research-only queued runs as **manual review candidates** only when the same PR has a **current source SHA** run for the exact same allowlisted research workflow. It never suggests review of `blocking-ci`, Architecture, A–F safety, external-owner jobs, runs belonging to another PR, manual dispatches, retried runs, or already-running jobs.

### Commands

On a machine with network access (optional read-only GitHub token from `GITHUB_TOKEN` or `GH_TOKEN`):

```bash
python3 tools/hepta_actions_queue_audit.py \
  --repo TrillionniumFoundation/hepta-private-ci \
  --pr 2366 \
  --head-sha f019280f1c1fe77b13b847901ad69098b1e1a2ba \
  --pages 10 \
  --output ./hepta-queue-readonly-report.json
```

Test without network:

```bash
cd tools
python3 -m unittest -v test_hepta_actions_queue_audit
python3 -m compileall -q .
```

The tool's output is create-only. It always declares `any_mutation_performed=false`, `cancelled_runs=[]`, `production_admission=BLOCKED`, and `authority_posture=DENY_ALL`.

### P0 ops handoff (manual / authorized Actions owner)

1. Verify runner capacity, organization billing and quotas, concurrency and queue age independently. Do not call the cause identified from queue counts alone.
2. Inventory every queued run by **owner / PR / exact SHA / workflow / run ID**, preserving historical failure receipts and independently owned work.
3. Confirm which already-queued **research-only** runs have been superseded by a current exact-SHA campaign. Cancel only after explicit owner authorization and with an immutable run-ID log. Never turn canceled/queued into success; never cancel safety, original-owner recovery or production jobs indiscriminately.
4. Prioritize **one latest-source pinned Granite research campaign**: offline test → 224 real Encoder forwards / shared features → five arms × three seeds → independent FP32, source, pair, cost checks → native/security gates. `DENY_ALL` still applies.
5. Consider PR-number scoped concurrency only where historical CI receipts are safely supersedable. Current Granite workflow uses a **per-head-SHA** group with `cancel-in-progress: false`, which cannot deduplicate superseded commits across the same PR. In contrast, the repository `v8-canary` workflow already uses a PR-number concurrency key with cancellation on non-main events; this is a design reference, not authorization to cancel research evidence. Do not automatically change policy for signers, independent future windows or durable owner tests.
