# V10: physical-pair handoff after **both** public Encoder executions

Research only; **NO-GO for training claims, model selection and production**.
This change closes one concrete execution-chain gap: the V8 hosted job could
obtain two physical results without ever connecting their rehashed model directories
and matched input census to the V5 candidate profiles.

The single `public_stem_pair_handoff_v10.py` CLI consumes the two original V8
output directories (one for mmBERT-small, one for Granite 97M R2). It requires:

1. The exact V8 pinned plan and canonical physical/material receipts for each.
2. Full rehash of **every** locally retained weight/tokenizer file through the
   existing V9 handoff owner. Unknown, missing or symlinked bytes reject.
3. Identical versioned probe-input SHA-256 and count on **both** physical receipts.
   The V9 single-candidate handoff now rejects old receipts lacking these fields.
4. Exact candidate/model/revision/pooling/normalization identity and non-promoting
   receipt statuses. Failure of **either** candidate blocks the combined handoff.
5. Atomic creation of a five-JSON research-only handoff directory. No model
   weights or tokenizer bytes are copied into the GitHub Actions evidence artifact.

The V8 physical workflow calls V10 **only after both real forwards report
success**, then copies the resulting JSONs into its weight-excluding artifact.
Its offline job tests both old and new contract paths. CI queuing, network/model
load failure, or a missing result must never be summarized as a passing run.

```bash
PYTHONPATH=experiments/shared_stem_cell python3 \
  experiments/shared_stem_cell/public_stem_pair_handoff_v10.py \
  --mmbert-root /tmp/hepta-public-v8/mmbert-small \
  --granite-root /tmp/hepta-public-v8/granite-97m-r2 \
  --output /tmp/hepta-public-v8/paired-handoff
```

**What it does not prove:** a self-consistent Hub artifact and self-reported
physical receipt are not independently authenticated publisher/execution evidence.
This stage does not train a Head, run the no-change baseline, compare held-out
accuracy, calculate NDU, revalidate authorization for production, or run on the
target host. It does not change Rust, Q24 replay or the deployed selected model.
`authority=DENY_ALL` and `production_accepted=false` are unconditional.
