# Hepta P0–P6 local closure aid — 2026-10-22

**Source-only, fail-closed; not a deployed/merged Hepta change.** This standalone bundle never touches live services. Independently, the source-only P0 and P6 subsets have been published to isolated GitHub draft PRs #3269 and #3273; no production branch was merged. Its patch is intended for review on a local *development worktree*, not direct promotion to production.

## What is implemented

- `qa/meta-network-scale/p6_fallback_gate.py`: Ed25519-signed P6 fallback **advisory**, rejecting stale/mismatched FinalUse, wrong tool/host/generation/owner epoch/idempotency, replayable signer roles, unknown/indeterminate effects and unverified Codex/native parity. No tool execution or effect-owner code is included.
- `qa/meta-network-scale/test_p6_fallback_gate.py`: 22 offline negative, tamper, non-repeat and matched-parity regression tests, including non-finite JSON exponent rejection. Keys generated in-memory by the tests are **not** project trust keys.
- `scripts/run_hepta_local_closeout.py`: Git-worktree-aware, dirty-tree-rejecting, source-drift-detecting local P0–P6 source/test runner with SHA-pinned Git source inventory, private per-command logs, bounded execution, Cargo/fmt/Clippy/unit test commands and **unconditionally false** production qualification. Does not create/deploy any runtime job or modify Git refs. `--execute-checks` opts into running existing repository tests, which may write build/test artifacts. Do not execute such tests on a production host.
- `scripts/test_run_hepta_local_closeout.py`: 15 tests of the runner's linked-worktree support, dirty-tree rejection, no-repo, tool-absence, test failure, timeout and no-false-closure behavior.
- `.github/workflows/hepta-p6-codex-native-parity.yml`: isolated source-head Python contract CI. Uses pinned Python 3.12 and `cryptography==46.0.4`, **not** an independent external host qualification.

**Important:** the P6 verifier checks explicitly configured public-key signatures and equality of records. It cannot prove that the underlying host, observer or measurement was honest. The existing Hepta FinalUse authority, durable outbox, target-host readback and operator acceptance must *still* verify reality and consume grants. `ADVISORY_FALLBACK` is deliberately **not** a dispatch permission. Never give each Cell an independent tool effect owner.

## Review and apply on your actual local machine

From an **isolated, reviewable Hepta worktree** rooted at `hepta-private-ci`:

```sh
git status --short
git apply --check /path/to/hepta-p0-p6-local.patch
git apply /path/to/hepta-p0-p6-local.patch
python3 -m unittest -q qa/meta-network-scale/test_p6_fallback_gate.py scripts/test_run_hepta_local_closeout.py
```

Use a branch that already includes the *unmerged* P0 pure-contract extraction (PR #3218), dependency-origin isolation (PR #3242 or equivalent), and related P0–P5 integration. Do not combine sibling PRs by arbitrarily overwriting files. The patch adds five new paths and does not edit existing owner or permission code.

To run the **local source and test** gate, supply local worktree paths (not GitHub URLs):

```sh
python3 scripts/run_hepta_local_closeout.py \
  --hepta /path/to/hepta-private-ci \
  --runtime /path/to/hepta-runtime \
  --report-dir /path/to/private/logs \
  --execute-checks
```

The local Rust test/build commands are intentionally substantial. Run only on a controlled *non-production* development host with proper Rust 1.95+ (or exact pinned repository toolchains) and complete locked dependencies. The tool writes log files mode `0600` and captures source HEAD/tree, checks and file presence. It performs **no checkout, merge, commit, model promotion, release, systemd mutation or tool dispatch**. Its exit codes are fail-closed: `2` = missing/failed code checks, `3` = all local code checks passed but independent physical evidence remains open. It never returns `0` for production qualification.

`source_tree_digest` used by the P6 signed offline parity example is a **SHA-256 digest of the raw Git tree content**, not the ordinary 40-character Git SHA-1 tree identity. The separate local runner records the normal Git SHA identities. Freeze and attest both under the external evidence protocol before using this to evaluate actual model runs.
