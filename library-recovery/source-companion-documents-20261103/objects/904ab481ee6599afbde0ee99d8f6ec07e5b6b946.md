# Hepta 本机剩余 Blocker 验收工具

检查时间：2026-10-23（UTC）；目标仓库：`TrillionniumFoundation/hepta-private-ci`。

## 如何在真正的 Hepta 工作树运行

在有 Rust、Cargo、Python、Git 的本机执行（脚本存放位置不必在仓库内）：

```bash
python3 hepta_local_blocker_sweep.py --repo /absolute/path/to/hepta-private-ci --profile full
```

可选：`--profile smoke` 仅执行核心 Python 身份/范围门禁、Rustfmt 与四个 Cell 相关 crate 的 Rust 测试、Clippy。`full` 在此基础上执行 workspace 的 `cargo test --locked` 和 `cargo clippy --all-targets`。工具**从不自动修改、提交、推送或合并源码**。报告默认落盘于系统临时目录，终端输出实际 JSON 回执位置。允许使用 `--out /path/outside/worktree` 指定独立证据目录。

出于 fail-closed 原则，脚本即使本机步骤全部 PASS 仍退出非零；只有完整跨平台 GitHub CI、生产权限、独立 FinalUse 和模型性能验收的真实证据才能闭合全局 Blocker。`BLOCKED_ENV`、`TIMEOUT`、`FAIL` 不能算通过。注意：运行所检出的仓库测试代码通常具有本机执行权限，使用适当隔离账户/沙箱，不要在保存生产密钥的环境运行未经审核的代码。

脚本自身回归测试：

```bash
python3 -m unittest -v test_hepta_local_blocker_sweep.py
```
