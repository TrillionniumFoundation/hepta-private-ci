## Provenance and the discovered validation problem

The immutable pre-existing V18 negative-evidence file `STEM_V18_SOURCE_FIRST_20261016.json` has exact SHA-256 `5c9cf67e1d91ca8ebc5adafd9963357a91ddb45361f43d0311c276150e29edb4`; its actual missing-new-source HOLD file has exact SHA-256 `1cd975d0ab51fbe90ee161df1a30c8a7dc66b06bd39e46eb19229b699b544372`. Those original bytes must **never** be rewritten or rehashed to make verification pass.

The V18 original public gate correctly rejects altered historical evidence, but naively applying its fixed original-receipt SHA rule to an independently rerun producer would also reject legitimate floating-point recompilation differences. In the present distinct original-data execution, V18 replay SHA `b39cada32b071c323f6a03d77a283e191589594b0ada8e24d44a8e69382c30e9` differs from the untouched published V18 SHA. The independent exact saved-tensor/original-source reviewer still validates all 82 model/normalizer files, original input binding and all 32 calibration rows, and all historical arm effects agree to below `2.38e-8` absolute metric difference. The new V17 sealed-prediction JSON SHA also differs from archived history, while model/tensor identities are source-bound and verified.

V19 therefore uses **two distinct assertions**:

1. **Historical authority and custody:** original historical V18 JSON and original actual HOLD must exactly match their published hardcoded SHA. The original V18 producer source itself is SHA-pinned; the new results must be generated by actually running its full original V15–V17 independent tensor/source auditor. The consumer does not accept an arbitrary claim of "82 verified models" or a user-supplied new JSON as independent physical proof.
2. **Numerical replay:** after source and actual saved-tensor rechecking, compare the whole strict JSON tree; keys, arrays, seeds, case counts, publication decisions, no-change baseline, source and owner digests, historical loss direction, null fields and all authorization flags must match exactly. Only finite floating metric values may differ, by at most `5e-7` absolute for each field. The complete V17 prediction-record digest may differ as a byproduct of the independently checked replay; it must still be a canonical lowercase 64-hex digest. Any tampered original data, injected held label, missing/extra arm, changed source ID, changed vote, fake prospective result, enlarged/forged cost or unauthorized promotion is rejected.

This is a **bounded numerical consistency acceptance**, not equivalent evidence of bitwise-identical floating kernels across hosts or model publisher signatures. No numerical tolerance applies to provenance or authority. The result never selects a model.
