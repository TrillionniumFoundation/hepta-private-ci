# RR-SNN v3 joint replay contract

This directory adds an offline, single-neuron research profile around the actual
marked-event runtime. It does not register a Hepta production checkpoint profile,
run a production owner, or activate a candidate.

## Run

Run `node research/rr_snn_v3/validate_replay.cjs`.
The command loads the checked-in event, continuation, and adapter modules, hashes
their actual source bytes, runs the fixture, and emits the full result as JSON to stdout.
Save stdout as replay_results.json in a CI artifact directory.
A successful report contains all assertions' results; source hashes must match the
revision under review. The report is generated by execution, not hand-authored.

## Checkpoint scope

rrsnn.joint-checkpoint.v1 binds the source digests, declared model, configuration,
initial RNG seed, complete initial input plan, physical checkpoint, commit sequence,
predecessor digest, clock, consumed-input cursor, and next input sequence. It retains
the actual runtime's RNG word and draw count, hazard anchor and remaining exponential
threshold, physical index, refractory expiry, trace anchor, held-rate regimes and
exposures/counts, obligations, resource ledger, utility, event log, and emitted pulses.

This profile accepts a fixed external input queue. It rejects a modified future
queue even when a checksum is recomputed. Dynamically enqueued recurrent deliveries
need a separate explicit profile that also binds network state and pending work.
The single-neuron results cannot establish network journal recovery.

Unknown fields, nonfinite values, negative-zero values, invalid identities, sparse
or accessor-backed JSON, and inconsistent runtime states are rejected. SHA-256 and
sorted-key canonical JSON identify content; they do not authenticate an untrusted
caller. A direct restore should supply a separately retained expected digest.
Source hashes must be computed from the loaded code by the embedding application.

Hooks must be deterministic, pure functions of current observations, supplied data,
and the frozen declared model. Arbitrary hidden mutable closures are not serialized.
The same source/model and hooks must be supplied at restore. Model metadata or
training weights alone are never represented as complete execution state.

## Journal and crash contract

MemoryJournal and MemoryWitness are explicit reference stores. Their JSON images
can be serialized independently. A writer first claims a monotonically increasing
fence generation. A commit checks its expected head and sequence, computes the
complete next physical state on a restored copy, appends a checksummed frame,
advances the witness by compare-and-swap, and then publishes the new checkpoint.

Reopening replays every complete frame from the bound genesis and compares the
entire resulting checkpoint. It discards only a declared incomplete tail, rejects
corrupt complete frames and fabricated physical history, and reconciles a lagging
witness after replay. A separately retained minimum acknowledged anchor is required
to detect removal of acknowledged history. Rolling back every store and every
independent anchor together is outside this reference threat model.

An exact retry returns the original checkpoint without another append. Changed old
requests, stale heads, old fenced writers, witness rollback, and capacity overflow
are rejected. Time is nondecreasing; repeated time with a new sequence is a permitted
no-op physical advance. Errors after an injected crash poison that writer until it
is reopened. The public sequence bound is enforced before publishing a new envelope.

## Evidence and limits

The fixture has two evidence states and three transition channels, with a physical
pulse debit, refractory period, deadlines, input changes, a resource shock, and a
refill. Six interruption points compare complete final state and path statistics
with one uninterrupted run. Four reference faults cover before append, an incomplete
tail, complete append before witness, and witness advance before publication.
Thirty-two negative cases include resealed future-input changes, source/model/config/
input identity changes, tampered budgets, sequence overflow, and false residual
hazard history. A separate legal boundary accepts maxRecords+1 statistical regimes.

The reference tests establish deterministic offline continuation and the in-memory
journal/CAS/witness state machine. They do not establish filesystem durability,
multi-writer operating-system locking, cross-runtime floating-point identity,
production owner registration, target-machine cost, independent future utility,
or real 64/256/1024/4096 Cell receipts. Physical pulse debits here are explicit model
resource units; they are not measurements of CPU time, energy, or production cost.

## Optional actual process evidence

validate_replay_fs.cjs uses temporary Linux files, append and fsync, atomic witness
rename and directory fsync. It SIGKILLs separate Node child processes at the four
named fault points and checks exact recovery from disk. It also checks stale heads,
an exclusive wx lock, corrupt complete records and acknowledged history rollback.
Only the supervising process that observed the exact child exit removes its dead
lock file. Results must come from actual execution. Even a passing report does
not establish power-loss durability, arbitrary multiple-writer coordination or a
registered production owner. This profile still concerns one neuron with fixed
external inputs.
