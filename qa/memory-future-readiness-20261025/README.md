# Future-task comparison: capability audit before a new method freeze

This is a readiness review and an unimplemented candidate design. It does not freeze a confirmatory method, launch a study, amend old experiments or supply future outcomes. `ready_to_run_confirmatory_comparison=false`; the effective method freeze is null and admitted independent future families remain zero.

[review.json](review.json) binds nineteen existing source/evidence files and records the complete resource/statistical proposal. The source review read no new failure logs, repair answers or GitHub data and ran no model, training, product test or automation. All numerical cost ceilings and hypothetical power calculations are design values, not observed future performance or provider prices.

## Concrete capability gaps

| Reusable component | Missing capability |
| --- | --- |
| Frozen cohort hashes and exposure records | A genuinely prospective failure/repair chronology and independent family curation |
| BM25/code/path retrieval over authorized documents | A pinned capable repair solver and common bounded read/edit/test tool loop |
| Source-bound LoRA, rank expansion and split checkpoints | A shared global training exposure schedule and general repair-memory corpus |
| One actual Ruff failure with 76 semantic checks | A common immutable original-gate executor across real task families |
| Resource reservation and settlement ledger | Complete dependency/process-tree/transient-storage accounting and post-report inventory |

The known-case procedural experiment now passes an actual repair gate in three seeds, and its typed tool retrieval baseline also passes. The older raw workflow-command proposer is still not a strong general retrieval repair agent. Seventy-five workflow documents are not a diagnosis/action/outcome corpus. Adding numeric fields to that older runner does not create a valid future comparison.

## Proposed comparison, once implemented and qualified

| Arm | Fixed-capacity view | Priced-growth view |
| --- | --- | --- |
| Continue | rank-8 parent plus continuation | rank-4 parent plus continuation |
| Expand | same rank-4 parent, function-preserving expansion to rank 8 | Reuse the same execution |
| Retrieval | common source retrieval, solver and tool loop | Reuse the same execution |
| Data split | same rank-4 parent, two rank-4 children | Reuse the same execution |
| Random split | same parent, two rank-4 children | Reuse the same execution |

The four neural arms in the fixed-capacity view end with 460,800 adapter values; retrieval is a resource comparator, not a parameter-count match. Split-versus-expand and split-versus-random comparisons share an identical parent. Rank-8-from-start continuation supports a strategy-level comparison only. Freeze the same 128-record exposure sequence and route its final 96 records to the assigned child; do not resample child schedules to create a hidden data advantage.

There are six unique configurations across both views. With three neural seeds and deterministic retrieval physically reused once, sixty independent families would produce at most 960 task trajectories. The proposed caps permit about 69.33 CPU-hours for standalone preparation and task execution before extra shared-curation accounting. This is an upper bound, not an estimate of actual cost or work already performed. Every method gets the same resource opportunity; unused budget is retained. Strict no-more-cost superiority also requires complete measured cost no greater than retrieval, not merely equal ceilings.

## Prospective and statistical boundary

Preserve the published October 25–November 1 intake window. Only failures first visible after the complete implemented method freeze can be future candidates; earlier observed failures remain development or metadata candidates. Enroll by the fixed creation order and deadline, never by current success. Do not turn repeated jobs, renamed branches, seeds or common dependency regressions into independent families.

The candidate primary comparison is preselected data split versus qualified retrieval at one fixed seed; two further seeds assess robustness. The proposed rule requires at least thirty independent paired families, an observed ten-point success gain, and a one-sided exact paired test at 0.025. This does not prove that the true gain is at least ten points. The report includes a more conservative interval and declared secondary comparisons. Correlated families block ordinary independent-pair inference.

A sixty-family pilot can still be inconclusive: under the report's hypothetical paired discordance probabilities 0.20 versus 0.10, the proposed primary rule has only 22.07% power. This is exact design arithmetic, not a model result, and is not a justification to extend a window after seeing its outcomes.

## Next concrete work

First build a separate development catalogue and common original-gate executor for twelve real historical incidents across at least four causal families. Pin an actually available capable repair solver and qualify both retrieval and memory paths on that development set. Then complete the global exposure schedule, whole-system cost meter and shared five-arm launcher. Only their exact implemented bytes, corpus, solver, tools, prices and analysis program can establish the new method freeze. Until then, the future-superiority and fully matched-budget split blockers remain open.
