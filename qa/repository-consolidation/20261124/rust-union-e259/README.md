# Rust 分支整合审计检查点

本检查点记录 `TrillionniumFoundation/hepta-private-ci` 的全量分支盘点、保护关系、已审阅的合并和实际验证结果。目标是将普通 Rust 分支收敛到 `main`，同时保留 HIA 分支及其别名和后代。

**全仓整合尚未完成，本候选尚不具备合入 main 的资格。** 分支盘点完整不等于全部待合并源码已经完成语义审查。这里保留失败、环境限制、未审范围和历史保护记录缺口，不以局部通过代替仓库的必需 CI。

## 仍阻止 main 的问题

原 `24abd` 的 blocking CI 未通过：确定性合并空白检查、Intel macOS supervisor/fleet 健康观测、Windows shard 2 与 shard 4 失败；Architecture required 通过。这些是原头的结果，不能转用为新头通过的证明。

Windows elevated admission 当前明确拒绝未经资格验证的 `FILE_DELETE_CHILD` 隔离机制。原功能性正向操作必须继续执行并真正通过，不能将期望成功替换成期望拒绝、删除保护拒绝、过滤测试或扩大超时来关闭问题。

最大待合历史 `ca77c88d01b5dc800bdba7cfdc673c7d8d89101a` 含 399 个默认合并冲突。直接采用旧文件会删除当前的符号链接防护、截止时间与所有权检查，或退化 Windows ACL 策略；同时它也有需保留的 UTF-8 文件名等新逻辑。报告明确区分已逐段审阅和仅完成分类的路径，没有采用 `ours` 空合并，也没有将尚未执行的建议记为修复。

32 个最初单提交前沿均已计算完整 Git 路径和默认三方合并结果；API 的前 100 项文件列表未被当成完整 diff。其中一项实际有 1,183 个改动路径。冲突清单和未审范围都在证据包内。

## 使用证据包

`EVIDENCE-MANIFEST.json` 记录全部原始成员、分片和完整压缩归档的大小与 SHA-256。`restore_evidence.py` 只校验并恢复数据，不运行归档中的脚本、测试或历史任务。将数据恢复到一个新的外部目录后，可按原相对路径阅读所有记录。恢复命令以该脚本的 `--help` 为准。

此归档与状态文件是在草稿 PR 发布前制作的不可变检查点。GitHub 原始 CI 与原主机验证并行，Rust 最终收口结果将以新的跟进记录追加，原失败和本包保持不变。最终发布提交、精确旧头租约读回、之后的原始 CI 结果见 [PR #6799](https://github.com/TrillionniumFoundation/hepta-private-ci/pull/6799)。不得把这份发布前快照当作后续分支删除许可。
