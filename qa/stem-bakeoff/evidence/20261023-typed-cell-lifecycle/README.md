# Typed semantic-cell lifecycle: complete and interrupted development evidence

This package retains both real pretrained-model attempts. The second completed
the registered lifecycle with 19 engineering gates and 6 parameter-control gates
passing. The first was killed with exit 137 and remains an incomplete attempt.
Neither is a prospective general-memory, capacity, compression or multi-host
qualification result. Every production-acceptance claim remains false.

The workload uses eight synthetic entity/color facts, a ninth event arriving
during training, a conflicting report, correction, source withdrawal, migration,
worker restart and authority outage. The exercised memory role is `semantic`.
Other role names in the service schema are not evidence that their learned
behavior was validated here. Natural CI incident memory and procedural repair
replay are separate experiments and are not counted in this package.

## What the engineering gates establish

The original receipts and the post-run audit preserve the following chain:

1. Source changes atomically create versioned source records and training jobs.
   Immediate overlay reads see the new event while its earlier trainer runs.
2. A source change makes the old background candidate superseded. Complete
   replay starts from the frozen base and uses the current unconflicted facts.
   Immutable source payloads, snapshot digests, training facts, catalog entries,
   checkpoint manifests and source epochs are checked against saved bytes.
3. A real checkpoint is transferred to two independent worker processes over
   authenticated loopback HTTP/TCP. Saved checkpoint files match byte for byte.
   Migration retries preserve the current placement and reject the stale owner.
4. Unknown, conflicting, withdrawn and stale-epoch requests are rejected before
   decoder callbacks. Authority outage also prevents a callback. These checks
   use trusted registered entity/relation keys and external source authority.
5. Clean replay after withdrawal excludes withdrawn roots. Worker restart and
   authority recovery preserve raw text, generated token IDs and prompt hashes.

The successful run has three clean 256-update publications and one superseded
32-update background attempt, for 800 decoder optimizer updates. This is fresh
base replay, not certified selective unlearning. Old source history and old
checkpoint files remain in the audit archive; revocation blocks authorized use
and does not physically erase every prior copy.

## Runtime failure verification and its limits

`runtime-verification/` retains the focused seven-test result, its earlier
two-test subset, the separate one-test observation repeat, raw logs, authenticated
nonzero/timeout receipts, missing-model decoder failure, parent-death observations
and restart outputs. The two-test subset is already included in the seven; the
one-test repeat is not another independent capability or task cohort.

The preliminary parent-death harness failed before its assertion because the
process PID namespace did not match mounted procfs. Its exit-1 observation and
original harness are preserved. The subsequent observation resolves the procfs
PID through a pidfd. It records a killed child that ceased execution and remained
an adopted zombie, not a child reaped by the test. The process's recorded
`child_returncode` stays null where the observer was not its parent.

Linux `PR_SET_PDEATHSIG` is bound to the creating parent thread. The retained
evidence supports the exercised Linux behavior and restart paths. It does not
qualify other platforms, arbitrary host reapers, power loss, distributed
consensus, partitions between physical machines or production authorization.
The local source owner is a research authority, not an authenticated bridge to
the production HNMF ledger. Hashes alone do not attest an untrusted trainer.

## Published archive distribution

The unchanged archive is distributed as four ordered binary parts. The logical
archive remains 21,339,733 bytes with SHA-256
`acd7835de3b37b1768a7dca60f1b02b5d2175099c1c4650ce132ca28625b3aa2`.
`archive-parts.json` records each part's byte count, SHA-256 and Git blob identity.
The complete member manifest and both auditor modules are inside that archive.
`SHA256SUMS` covers the files actually distributed in this directory.

After downloading this directory, reconstruct to a new local file. This command
checks every part and the full archive before reporting success:

```bash
python3 - <<'PY_REASSEMBLE'
from pathlib import Path
import hashlib
import json
manifest = json.loads(Path("archive-parts.json").read_text())
whole = hashlib.sha256()
with Path(manifest["archive_name"]).open("xb") as target:
    for part in manifest["parts"]:
        payload = Path(part["name"]).read_bytes()
        assert len(payload) == part["bytes"]
        assert hashlib.sha256(payload).hexdigest() == part["sha256"]
        whole.update(payload)
        target.write(payload)
assert whole.hexdigest() == manifest["archive_sha256"]
print(manifest["archive_name"], whole.hexdigest())
PY_REASSEMBLE
```

This distribution changes no run, source, checkpoint, audit or compressed byte.
