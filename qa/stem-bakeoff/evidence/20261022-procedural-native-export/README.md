# Dedicated Procedural replay export for the native linear Head

This directory contains three **real trained** Procedural-selection Head bundles
and the real 64-row heldout Granite feature batch. It uses the existing native
linear Head binary format. The new weights have **not yet been executed by the
native runtime** as part of this export; no artifact-owner admission, source
authority, Procedure execution permission or activation is created here.

All input evidence comes from the separately frozen
[Procedural replay experiment](../20261022-procedural-memory-replay/README.md).
The exporter does not fabricate the P37 news experiment's report schema, retrain
a Head, rerun an Encoder or change any original evidence bytes.

## Exact inputs and preserved semantics

The exporter requires independently retained input pins:

- Plan SHA-256: `7c4fc2bb251d1c6f897e336dcc82adad3780511b6f353e7b672dc9fca8f471bf`.
- Result SHA-256: `84e12378b548dd8f105d8f94881ec3b4ffc1d69bef1155b8398e2413f3caf56b`.

It verifies the frozen 20-file source snapshot, the query/goal specification,
all input-file bytes, all actual Encoder/source bindings, retained replay bytes
and observed labels, and all three original Head/owner manifests. It independently
reconstructs the complete **526-member** learning-source closure and requires
each original owner manifest to equal that exact sorted set. The observed label
digests use the trainer's actual little-endian int64 representation.

Each seed directory contains:

- `head.bundle`: the existing `HEPTA-CELL-HEAD-BUNDLE-V1` framing.
- `manifest.json`: a new, explicitly derived export manifest.
- `original_manifest.json`: the original training manifest, byte for byte.
- `weights.npz`: the original trained weights, byte for byte.
- `original_replay_owner.json`: the original research owner manifest, byte for byte.
- `pins.json`: new bundle identity, original identities, tensor evidence, and the native owner-manifest requirements.

The derived manifest preserves every original JSON value and adds the independent
`procedure_replay_provenance_v1` field. That field binds the original manifest,
plan, result, replay, source snapshot, complete ancestor list, actual query-source
records, feature-byte pins and ordered class contracts. The export manifest's
digest intentionally differs from the original training manifest's digest.

The class order is exactly:

| Index | Procedure contract |
| ---: | --- |
| 0 | Last input occurrence per id, ordered by id |
| 1 | Sum scores by group, ordered by group |
| 2 | Inclusive threshold filter preserving input order and duplicates |
| 3 | Stable ascending score sort retaining all records |

These are the four fixed file programs in the original artificial experiment.
The logits do not represent news classes, memory-retrieval relevance, action-head
values or execution authorization. Forced heldout success was 64/64 for each
seed, tying nearest neighbor and centroid. At confidence 0.7 the Head executed
only 21/64, 20/64 and 21/64 tasks, versus 57/64 and 59/64 for those baselines.
The export preserves that unsuccessful strong-baseline qualification result.

## Native compatibility and the remaining host obligation

The original NPZs each have 12 tensors, 7,315 parameters and 32,426 file bytes.
They use STORED ZIP entries, exact NPY-v1 little-endian float32 layouts and finite
values. `up.weight` is exactly zero. The supported profile is width 384, state
width 8, adapter rank 4 and four task classes, with zero-state linear task-only
inference. Temperature is 0.25 and confidence threshold is 0.7. Auxiliary action,
value and uncertainty heads remain untrained.

The new top-level provenance field fits within the existing manifest size bound;
no Rust parser or binary framing was changed. Once a valid artifact owner admits
and reads the bundle, native readback checks the complete manifest digest,
including the added field's bytes. **It does not interpret the added field as a
source-withdrawal check, validated procedure contract or authorization receipt.**

The native owner-manifest profile still expects exactly the training and
calibration dataset digests. Those two digests do not automatically expand into
the 526 learning ancestors or current query sources. Consequently every export
states `requires_external_current_source_validation=true`, with native contract,
closure-expansion and current-query authorization checks explicitly marked false.
A future host must independently retain the new pins, establish the actual unique
owner and current source frontier, and perform those checks around advisory use.
No owner key or authority is generated by this exporter.

The root-level input files are:

- `heldout.features.f32le`: 64×384 row-major little-endian float32 features copied from actual frozen Granite outputs; 98,304 bytes.
- `heldout.batch.json`: exact native feature identity, ordered source-record digests, query ids, feature-byte/source-list pins and a 98,304 multiply-add cap.
- `heldout.scorer.json`: observed class labels for **post-inference scoring only**. It is separate from the native input and must never enter model features or routing.

The 64-row batch is below the native 128-row maximum. Its source-list digest uses
the exact native domain, row-count u64 little-endian and ordered raw digests.
The byte and source pins must be independently retained by the host, not copied
from a request immediately before claiming independent verification. This is an
archived feature batch; a live Agentd cue producer for this exact Granite profile
is still absent. The original offline observer is separate reference code, not a
current signed runtime Outcome, and cannot replace the Procedure ledger owner.

## Validation and identities

The dedicated exporter tests passed **10/10** using real frozen artifacts. They
check native framing and preservation of original bytes; source/feature order;
independent pins; input tampering; an omitted ancestor even after attacker-style
owner/result hash rebinding; nonzero adapter weights; finite tensor tampering;
NaN; compressed NPZ rejection; and exclusive output creation. Tests execute no
training and make no native-success claim. An initial development setup check
identified the trainer's binary int64 label-digest representation; the exporter

## Reproduce this export

Run from the research repository root. Only Python standard-library modules are
needed; no model download, NumPy, PyTorch or network access is required. Choose a
new output directory; the exporter refuses to overwrite one that already exists.

```bash
python3 qa/stem-bakeoff/procedure_native_export.py \
  --evidence qa/stem-bakeoff/evidence/20261022-procedural-memory-replay \
  --output /tmp/hepta-procedural-native-export-reproduction \
  --expected-plan-sha256 7c4fc2bb251d1c6f897e336dcc82adad3780511b6f353e7b672dc9fca8f471bf \
  --expected-result-sha256 84e12378b548dd8f105d8f94881ec3b4ffc1d69bef1155b8398e2413f3caf56b

python3 -m unittest discover -s qa/stem-bakeoff \
  -p test_procedure_native_export.py -v
```

The original frozen source snapshot remains at
[source_snapshot.jsonl.gz](../20261022-procedural-memory-replay/source_snapshot.jsonl.gz).
Export validation reads that snapshot rather than importing potentially formatted
current experiment code. `freeze_manifest.json` binds the new exporter sources,
test log and all export files; the original plan/result/weights are unchanged.
