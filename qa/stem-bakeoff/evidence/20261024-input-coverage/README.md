### 与简单控制的次要比较

下列 95% 配对区间未作多重比较调整，仅作描述；没有任何一个排除零。

| 128 样本 Head-tail Linear 减去控制 | 平衡准确率差值，百分点 | 95% 配对区间 |
|---|---:|---:|
| prototype | -0.795 | [-3.442, +1.932] |
| dense_topk | +0.232 | [-2.397, +2.861] |
| bm25_topk | +2.516 | [-0.477, +5.672] |

Prototype 的平衡准确率点估计 55.711% 高于训练 Head 的 54.916%。当前结果没有确认 Head 对这些简单控制的净收益。

Head 的 NLL 为 0.7127，高于等概率控制 0.6931、BM25 的 0.6799 和类别先验控制的 0.6459。
固定置信阈值 0.7 时，Head coverage 为 19.92%，把拒答计为未成功后的 overall success 为 11.82%。
类别先验已有 61.04% forced accuracy，但平衡准确率只有 50%；只报普通 accuracy 会掩盖类别不平衡。

训练后的 Head 比未更新状态有更好的均值，增加训练预算也出现均值增长；这些现象
与实际权重更新、保存和重载相符，不能概括成“完全没有学习”。不过，相对强控制
的优势仍未确认，概率质量和绝对区分能力也不足以支持实际 agent 任务收益。

## 来源与真正相同的计算预算

新样本来自固定 revision 的 SWE-bench 官方 train；官方 test/dev 仅用于排除来源、
归一化 issue 和补丁连通组。按时间与源组分开后，标签无关地选出 512/128/256 个
训练池、校准和评价来源。四个目标为多文件、多 hunk、至少二十行修改、净增加行。
它们是同一补丁形态任务族的替代指标，不是根因、工具动作或修复成功。

32/128 是每个 Head 与检索索引实际拟合的来源数，不是总标注预算。平衡抽样
需要查看 512 个训练池标签，所有方法还共享 128 个校准标签；原始数据准备
也读取补丁来去重和派生机械标签。没有把这些额外访问隐去并声称 few-shot 标注效率。

排除连接旧 test/dev 的 train 记录 0 条；跨新时间边界的重复组 17 个。
准备阶段记录 476 条无效输入/不适用 patch 记录，保留完整原因，不以模型表现决定排除；详情见来源清单。

固定缓存 LFM2.5-Encoder-230M，FP32、两 CPU 线程，冻结共享模型。使用明确声明的
非 padding token 均值与 L2 池化；这不是上游优化过的 sentence-embedding pooler。
不能将结果归因于之前研究的 Granite/EG2，也不能当作端到端 Encoder 微调结果。

- head_tail：112 次前向，146851 有效 token，172032 padding 后 token；wall 529.246s，CPU 1032.928s。
- prefix：112 次前向，146851 有效 token，172032 padding 后 token；wall 526.801s，CPU 1028.944s。

两策略的 token、padding、前向次数和批次 attention 长度平方总量完全相同。
另有明确单列的两次 warmup。头尾策略仍丢弃中间内容；它没有增加保留 token 总量。
评价组仍有 209/256 个源输入超过保留上限（81.64%）。
不发生截断的 297 个输入，两策略输出逐位一致。

实际训练 48 个 Linear Head 状态（四目标 × 两预算 × 三种子 × 两输入策略），每个 2050 个私有 float64 参数；全部 48 个在独立评分进程中重载并逐位复现预测。这不是 48 种独立能力。
Head 优化器合计 wall 6.463s；完整拟合/检索/校准流程 wall 30.326s。

独立 Python 环境冷启动安装另耗时 986.102s，原始回执和日志已归档；该成本没有摊入单次 Head 优化时间。
数据准备、独立 checkpoint 校验、完整编码、拟合与评分的进程阶段耗时见 `cost-components.json`。模型权重复用了固定缓存，不能据此声称首次模型获取没有成本。

BM25 使用相同的 32/128 个有标签训练来源，但可读取完整 issue。文本存储、检索与
校准成本保留，不把它冒充 192-token 输入，也不把 Head 小参数量直接称为净收益。

BM25 的预测本身不需要 Encoder。原始 `control_memory` 是 dense、prototype 与
BM25 共用 wrapper 的可达状态开销，不能冒充独立 BM25 的最小驻留内存。两输入
策略的主比较具有相同实际 Encoder 工作量；Head 对 BM25 的次要比较不是完整硬件
预算相同的证明。

### 独立 BM25 成本回放

原评分完成后另行测量：仅加载已冻结的倒排表、训练标签、来源 ID、k 与温度；
不加载特征矩阵或 Encoder，不读取评价标签，不重新选择设置。24 个逻辑索引
逐项复现两输入策略原先保存的全部 48 组 BM25 概率，逐位一致。

| 索引训练来源数 | 可达独立索引状态范围 | 256 查询 batch wall p50 / p95 | batch CPU p50 |
|---|---:|---:|---:|
| 32 | 431.3–870.9 KiB | 149.255 / 180.241 ms | 149.260 ms |
| 128 | 1407.5–1874.1 KiB | 179.082 / 225.131 ms | 179.084 ms |

纯词法回放进程整体峰值 RSS 45.71 MiB；包含 Python、NumPy、全部 predictor 文本、已保存概率与临时查询矩阵，不等于索引独占 RSS。
每个索引先执行一次校验回放，再执行五次完整 batch 计时。batch 百分位不是单条查询的
尾延迟。原始从文本建立索引的时间没有从共享 wrapper 中独立拆出，因此不虚构为零。
详细样本、状态字节、预测 hash 与分析源码见 `bm25-replay.json` 和 `source/`。

## 真实失败、修复与证据

首次执行在任何 Encoder 前向、Head 拟合或评价标签解析前被完整性检查拒绝：
直接裸 body 加载期待不带前缀的键，而 checkpoint 使用 `lfm2.` 前缀。原始失败
目录、执行计划、journal 和固定来源清单均未改写。

修复采用官方完整 MaskedLM 加载入口，再提取 `.lfm2`。单独进程与实际编码进程
都把每个 body tensor 的名称、形状、dtype 和全部原始字节与 checkpoint 对照。
核验 132 个张量、918772736 字节，全部相等；没有忽略缺失参数或使用随机初始化。

本地完整数据/拟合态归档：`/data/hepta-cell-input-20261024/evidence/coverage-evidence-v2.tar.gz`，146515469 字节，SHA-256 `61f561df4792f45cd388113914357e7860d6ccced5d64bd55c8a67a9bd7ff9b7`。
重新读取归档并逐项校验 362 个文件；索引见 `archive-index.json`。公开模型权重和安装环境未重复打包。
