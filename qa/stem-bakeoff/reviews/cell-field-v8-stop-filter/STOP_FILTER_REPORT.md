# V8 原停止点：双修复诊断与固定顺序反事实核验

## 结论与适用范围

全 98 个原 V7b 停止点、196 个成对修复槽位已经执行并通过独立证据审计。旧 single-ray 修复安全完成 43/98；新 joint actual-old 修复安全完成 72/98。新修复在 26 个 H8 原点上失败，而同一新意图经旧修复成功，因此新修复没有独立覆盖所有停止点。

固定“旧修复整个块先试；证书失败后，从相同原点与相同意图调用新修复整个块”的反事实组合覆盖 98/98。43 个原点选旧路径、55 个原点选新路径。组合只在已封存的成对结果上计算，没有执行新的组合控制器；没有拼接两条路径，没有更换风险规划器，没有放宽动作盒或旧损失阈值。

本报告是开发机制诊断。`scientific_acceptance=false`；不声称完整 32 步闭环完成、独立旧任务保留、外部未来任务改善或 CPU≤3 门槛通过。所有来源和标签均来自已经披露的 V5/V6 开发资料；没有抽取、编码或读取新的确认数据。

## 预先冻结的比较

- 原点：原 V7b 全 864 行中的全部 98 停止点；54 个实际 repair reject、37 个 tangent infeasible、7 个 unresolved。18 个 H1、80 个 H8，保留全部原 method/config/status/source 标签。
- 原完整参数、Adam 一阶/二阶矩、时钟、上下文、四个原 old anchors 由 2,150 条原始已提交动作与凭据精确重放恢复。
- 原失败 intended actions 未保存。本诊断统一生成新的 risk+effort、box-quadratic proposal，并将同一个数组交给两种修复。不能把结果描述为复现原失败意图。
- 保留原 dt=.02、effort price=.03、action bound=4、old weight 与 current dispersion。原 relinearizations 标签仍保留，但本轮实际固定为 0；没有实际终点风险回溯或预测 old 硬约束。
- 旧修复每步最多 16 组四面板查询；新修复最多 64 个不同试探加至多一次选中重放。查询预算不同，结果不能单独归因于搜索方向几何。
- 全块原子接受；失败块不安装已经试探成功的前缀。每个接受状态都须满足全部四个原 old anchors，零松弛。
- 新执行明确设置 `OPENBLAS_NUM_THREADS=1`、`OMP_NUM_THREADS=1`。历史 V7/V7b 的线程配置仍未知，未追认成单线程。

## 独立验证范围

执行内的透明观察器保留全部真实 old 损失/梯度查询、完整 prospective optimizer 状态与动作凭据；执行内审计独立重算每个查询、梯度与物理更新。其额外费用被单独计时，不归入规划器的假想低成本。

后置独立审计另外校验精确 98/196 census、111 个冻结源文件、同一 proposal 数组、全部原始账本与计费恒等式，并独立重算 3,960 个返回路径的真实 old 损失。0 个实际执行异常，0 个证据不一致。原封存全部成员在审计前后按 SHA256 复核。

固定组合进一步核对全部 98 条选中整块路径的 658 条凭据，绑定原实际观察过的 before/after 完整状态与实际 dt×action；独立重算 3,024 个选中初态和未来态 old 损失，所有值均≤原 anchors。最接近约束边界的未来 old excess 为 −5.828226790072222e−12。这里使用实际浮点值的原严格比较，没有事后放宽容差。后置两项检查没有调用新的 solver 或 optimizer。

## 实际费用与查询账

| 修复器 | 安全块 | 观察器包含在内的整调用 CPU 秒 | old 面板查询数 | prospective optimizer 调用数 | 安全块返回更新数 |
|---|---:|---:|---:|---:|---:|
| `single_ray_v7` | 43/98 | 8.015030571 | 26,568 | 1,539 | 344 |
| `joint_actual_old_v8` | 72/98 | 30.006594797 | 104,412 | 1,745 | 450 |

共享 proposal 实际只计算一次，总 CPU 3.808128436 秒。两修复合计 130,980 个 old 查询；加 proposal 查询为 134,004。两个修复合计 3,284 个 prospective optimizer 调用。

完整 retry 的 producer 记录 CPU 为 89.169156268 秒，wall 为 89.296787732 秒，其中执行内独立重放 CPU 33.637090225 秒。这是 producer 已记录的计时区间，截止于最终 report/seal 写入之前；不是包括最后封存写入的完整进程时间。后置独立全196审计另耗 CPU 4.472187893 秒；固定组合核验另耗 CPU 3.501558328 秒。

固定旧优先组合的**带观察器反事实费用**按每原点 proposal 一次、旧修复全部费用、仅旧证书失败时追加新修复整调用费用求和：

| 反事实费用项 | CPU 秒 |
|---|---:|
| 共享 proposal 一次 | 3.808128436 |
| 所有 98 个旧修复调用 | 8.015030571 |
| 需要的 55 个新修复调用 | 12.105277937 |
| 合计 | 23.928436944 |

反事实 filter 查询数为 68,808、prospective optimizer 调用数为 2,431。它包括失败旧尝试的全部已记录费用，不包括新组合调度的额外开销。两支原执行采用交替顺序，真实旧优先顺序下的 cache/时序效应没有重新测量，因此该数值不能替代真实组合控制器的成本测量，也不能据此宣称 CPU 门槛已通过。

## 第一次磁盘中断及完整重试

第一次执行完整保存了 9 个原点、18 个修复槽位，第 10 个 case 写入遇 `OSError [Errno 28] No space left on device`，退出码 1。所有原字节保留；其中两个“旧安全、新失败”的负结果也完整保留。中断清单记录 68 个文件、4,740,527 字节，第 10 个 0 字节 case 和部分 proposal 未冒充完整结果。

重试声明在 r2 启动前写入，明确原因是基础设施磁盘耗尽；同一 111 源、同协议、同 98 原点、同顺序完整重跑，没有只重跑有利案例。r2 为唯一完整封存的执行；attempt1 并未被替换或隐藏。

第一次可恢复的互不重叠 CPU 下界：proposal 0.410111270 秒，旧修复 0.824004363 秒，新修复 3.660282276 秒，执行内独立重放 3.788123484 秒，合计 8.682521393 秒。第一次完整 CPU 未记录，第 10 个部分执行、准备与 I/O 的遗漏成本未知。两次 producer 记录成本合计仅能给下界 97.851677661 秒；该值未加后置审计开销，不应称为精确全部成本。

## 不可混淆的下一步

原点上的安全路径补集覆盖只支持下一轮测试固定公共组合规则。新完整闭环仍必须在同源、同预算、同规则的所有注册槽位实际执行，保留每次失败尝试、全部约束查询、真实 CPU 与完整控制器状态；后续遇到的状态可能不同于本次 98 原点。规划代理的经验四面板安全约束也不能代替独立旧任务最终评价。
