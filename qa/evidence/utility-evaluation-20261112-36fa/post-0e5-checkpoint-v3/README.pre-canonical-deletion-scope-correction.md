## Outcome semantics and external acceptance

**Adopt** requires the complete deployable combination to pass benefit and hard gates, followed by original-owner authorization and actual new-consumer use. **NoUpdate / Ineligible** requires enough evidence for a complete negative comparison. **InsufficientEvidence / Unknown** covers absent results, costs, provenance, independence, authority or unresolved effects. **Objective Fraud** requires reproducible deterministic evidence and the explicit challenge process.

Base, Cell/adapter, router/selector, runtime, tools and real task distribution must be evaluated together against the strongest deployable control. Training, failed/cancelled work, search, evaluation, download, activation, serving and maintenance belong in their frozen cost contracts. Privacy, authorization and mandatory tasks cannot be offset by average quality gains. Task origin, training lineage, evaluation models and operational control remain independent-evidence obligations; fixture labels or separate keys do not settle them.

The required real chain remains: authorized A → original Training owner → independent B → Adopt or evidence-complete NoUpdate → actual new C → daemon and Root cold recovery. None of the source maps, static reviews, checksums or restored build dependencies is reported as that chain.
