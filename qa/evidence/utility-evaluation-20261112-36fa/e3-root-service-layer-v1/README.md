# E3 Root resident candidate service: first source unit

Status: local source proposal, not formatted, compiled, tested, collected, activated, or qualified. No H action and no source Git write occurred. The exact b608 inputs remain unchanged. This unit has an actual authority-host CLI caller; daemon late enrollment and the remaining owner-host deployment are separate obligations below.

## What this unit connects

Two explicit commands, `serve-resident-learning` and `recover-resident-learning`, consume original inherited descriptors before any file open or Tokio runtime creation. They load independently supplied Root0600 host trust and deployment inputs, parse the actual baseline through `LoadedCellQ24ModelV1::open_files`, reconstruct the original exact empty stage cut and frozen scope, verify the complete original freeze signature and payload, bind the complete pre-training B/retention panel, receive the existing 21-right ten-role handoff, register or recover the original V3 custody, and call the existing candidate service and runtime. No parallel checkpoint or delivery loop is introduced.

The deployment file is supplied only after the real ordinary A completion exists. It cannot supply completed E/D/T/S/C receipts: the original snapshot must equal a newly validated empty coordinator cut. Its completed-A/request binding is subsequently checked by the original Material owner and the daemon's original outbox; loading the file is not evidence that A was independently re-executed or authenticated by this loader.

The separate host trust file is trusted operational configuration opened by the original Root0600 reader. It contains complete pre-enrolled public principals, controlling identities, keys, roles, epoch, scope and revocation fields. It is not accepted from the stage handoff, the deployment file, a model, or an ordinary consumer. `LearningEvidenceVerifierV1::new` validates this original host input. This code does not generate keys, sign evidence, activate a new grantor, or claim that file ownership proves scientific independence. The real operator must supply the actual trusted configuration.

The freeze payload is preserved and cryptographically verified as originally signed. The loader does not open a LedgerWriter or reconstruct the signed payload from an invented ledger. The actual Material pair retains its original ledger/source checks and must verify that same freeze against its actual current ledger before an E/D effect.

## Actual typed API and CLI

The only new public input container is `RootResidentCandidateProcessInputsV3`: a stage handoff datagram, one original consumer stream, its original consumer pidfd, and original `CellQ24ModelFilesV1`. It owns all descriptors by value and has no Clone implementation.

`prepare_host_resident_candidate_v3(config_file, deployment_file, trusted_evidence_file, original)` returns the original `RootResidentCandidateServiceV1`. `recover_host_resident_candidate_v3` additionally requires a separate current readback file. The readback file must construct the existing `RootResidentLearningReadbackAuthorizationV3`; no command or packet can turn recovered registration into fresh channels. Calls execute inside the resident Tokio runtime, as required by the existing original stage factories.

Both commands require `--config`, `--resident-deployment`, `--learning-trust`, `--candidate-stage-handoff-fd`, `--resident-consumer-fd`, `--resident-consumer-pidfd`, `--baseline-base-fd`, `--baseline-encoder-fd`, and `--baseline-heads-fd`. Optional original model adapters use `--baseline-organ-fd` and `--baseline-cell-fd`. Recovery alone also requires `--resident-readback`. The old stdin pidfd mode and unknown options are rejected for these commands. The old command branches and original descriptor parser remain unchanged.

All supplied connected endpoints must already have the actual accepted peer credentials and pidfd binding. Inheriting or forwarding a descriptor does not retarget SO_PEERCRED. The original ten-role handoff validates its actual resident recipient, distinct sockets, actor identities, Root sender, and absolute CLOCK_MONOTONIC deadlines. A supervisor must establish each endpoint for the actual process before exec or transfer, following those original checks.

SIGINT/SIGTERM requests cancel only the original Root service and await its existing owned work. A daemon/consumer EOF does not trigger a parallel cancellation path. The original service deadline and uncertainty semantics remain unchanged. A remote effect already sent can outlive an await; no new rollback claim is made. A failure after original registration may leave the original registered record; the caller must use the separate original readback path and must not retry fresh creation as though no effect occurred.

## Bounds retained

Root JSON files retain the original 65,536-byte bound, Root0600 regular single-link requirement, Root-owned directory validation, O_NOFOLLOW, O_CLOEXEC and O_NONBLOCK. Initial snapshots retain the original 8,192-byte bound and exact original codec re-encoding. Model files retain the original Q24 parser/shape/file bounds. Trust uses the original maximum 64 signers; panel retention uses the original maximum 16 tasks. Signature and scope validation use the existing original factories.

The handoff and ordinary command timeout remain at most 30 seconds, the service lifetime at most 300 seconds, and completion readiness retains its original 500 ms lane check. Original role semaphores, request counters, same-UID/same-PID refusal, pidfd/SO_PEERCRED checks, dispatch gates and all old runtime limits are untouched. The service cannot increase the absolute handoff deadline.
