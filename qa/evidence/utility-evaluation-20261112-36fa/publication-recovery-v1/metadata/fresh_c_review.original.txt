## A concrete fixture loss to avoid

`circuit_retained_version_task_support_tests.rs::retained_version_task_inputs` destructures `Admission.request` as `_original_run_start` and does not return it. That helper deliberately builds C inputs without creating RunStart. A complete C fixture therefore must preserve the actual C ingress before consuming the Admission. Do not silently synthesize a different request after publication.

The existing `circuit_q24_task_test_support.rs::start` shows how the fixture issuer binds the request body to the actual Cell runtime digest, Cell semantic digest and bundle digest, then signs `authbus_objective_claims` for the actual runtime identity. These are explicit test credentials. Reusing that signing pattern is a test mechanism, never evidence of a real user's grant.

`OriginalCircuitRetainedTaskInputsV1::require_completed_a` compares the original A publication twice and enforces a separate C session. `install_original` uses the existing `AgentdConfig::with_q24_circuit_task_profile` factory once, observes its actual installed Source/Cell, checks original A again and preserves the original freshness gate. Do not call `support::start` afterward to create a second replacement factory or substitute Source/Cell files.

## Ordinary bootstrap and the full daemon have different evidence

The existing `support::start` extracts the task bootstrap and attaches it to a fixture's already held `RuntimeFixture.state`. The ordinary Q24 test's `execute` calls that state's real `response(..., AgentdMethod::ObjectiveStart)` and reads real Source/Cell receipts. This is meaningful ordinary bootstrap/ingress integration, with explicit fixture credentials.

The actual Version `run_original_c` path instead calls `crate::run`. `runtime.rs::run_with_shutdown` creates a new `AgentdState`, attaches the consumed original bootstrap, opens original AuthBus/Objective owners, binds the control socket, starts the real App Server and observes actual App Server readiness. The old Admission's in-memory state is not this new daemon state. Marking the old fixture state ready does not prove that the new daemon became ready.

For actual daemon ingress, the existing public API is:

```rust
let client = AgentdClient::new(
    identity.control_socket.clone(),
    identity.agent_id.clone(),
    identity.spawn_generation,
)?;
let outcome = client.objective_start(original_c_request).await?;
```

`AgentdClient` already checks bounded framing, request identity, agent identity and spawn generation. Its original two-second per-transport timeout remains unchanged. The fixture must verify the applicable admission/completion outcome and actual Source/Cell readback. A timeout does not prove non-admission; `objective_admission` is the existing exact-request historical read path, not permission to replay another task.

`run_original_c` uses the existing daemon signal-driven stop entry. If a mechanism test chooses the explicit `run_with_shutdown` embedded entry, it must say so and preserve real startup, generation fences and drain; it cannot claim to have exercised the exact Version entry simply by calling a different path. No change to either entry is proposed by this review.

## Scheduling and limits

Version's ordinary server uses `try_join!` for command service, the actual C runtime and FinalUse issuance. C startup performs another original current read. This can overlap an externally issued S/C predecessor read. The proposed sealed same-channel sharing must retain original Unavailable/Unknown behavior; there is no new queue, retry, reset, extra permit or implied guarantee that every schedule succeeds.

A complete fixture should observe the actual startup/readiness boundary before dispatching later S/C work, retain any actual collision, and measure all original public sessions and aggregate reads. The planned T=4 and E=3 arrangement is still an engineering design; this source review does not measure it or prove the 128-request / absolute-lifetime budget sufficient.
