# Declared runtime artifacts for a paired loop

The existing loop remains v1 when no artifact options are supplied. The new v2
identity commits actual declared runtime bytes, as well as the existing source,
interpreter, model, router, evaluation and consent commitments. It does not turn
an engineering fixture into a human adoption or authorize a Chain payment.

## Prepare and retain the inventory

With `PYTHONPATH=scripts`, create a fresh inventory using:

```sh
python -m cell_experiments.runtime_artifacts MATERIAL_ROOT MANIFEST.json ROOT...
```

Each `ROOT` is a relative file or directory under `MATERIAL_ROOT`. Roots must not
overlap. Directory roots include every regular file below them; symlinks and
special files are refused. Traversal uses descriptor-relative `O_NOFOLLOW` opens;
platforms without these safe filesystem operations refuse v2 material verification.
Paths, directory depth (128), and counts are bounded. The command writes a
new manifest and prints its canonical SHA-256. Retain that commitment separately.
The manifest must live outside the declared roots so that creating it does not
change the inventory it describes.

For v2 operations, all recorded files of the actually installed `torch`,
`transformers`, `peft`, `tokenizers` and `safetensors` distributions must be inside
the verified inventory. Include their metadata, native files and recorded entry
scripts. A copied package elsewhere cannot stand in for the installed package.
This check reads distribution metadata without importing dependency code.

Pass all three options to every `paired_loop` command:

```text
--runtime-artifacts MANIFEST.json
--runtime-artifacts-root MATERIAL_ROOT
--expected-runtime-artifacts SEPARATELY_RETAINED_SHA256
```

Run `identity` first and retain its `loop_sha256`; supply it as `--expected-loop`
on subsequent commands. Missing artifact options, changed contents, extra files,
removed files and changed manifest commitments are refused. The wrapper rechecks
the implementation after an action; a detected change retains a failed stage
without publishing a successful bound-loop result. The underlying consumer may
already have retained its own original result. Started actions remain non-replayable.

## Wire contract and limits

The manifest schema is `hepta.paired-learning.runtime-artifacts.v1`, with exactly
`schema`, `roots`, `files`, `inventory_sha256` and `total_bytes`. Each sorted file
entry contains exactly `path`, `size` and `sha256`; `inventory_sha256` hashes the
canonical file list. Limits are 256 roots, 65,536 files, 16 GiB of declared bytes
and 32 MiB of manifest JSON. File paths and absolute material locations are
separate: only portable relative paths enter the identity.

The implementation adds `runtime_artifacts` and sets `dependency_identity_kind`
to `verified_runtime_artifacts_v1`. Identity and readback schemas become
`hepta.paired-learning.loop-identity.v2` and
`hepta.paired-learning.loop-readback.v2`. Existing v1 records keep their schema.
Chain uses a new request/delivery version rather than silently changing a v2
request that has already been commissioned.

## Remaining qualification boundaries

`runtime_closure_complete` remains false. Declared files and installed RECORD
coverage do not establish every transitive dependency, import hook, loaded
shared library, driver or host state. Before/after file and directory checks
detect observed races; they do not make mutable files immutable or prevent an
adversary from changing them after verification. Use owner-controlled immutable
runtime material for execution. Import-generated bytecode or other writes under
declared roots also invalidate the inventory.

Whole-file hashing incurs real I/O and CPU cost. Post-action checking is inside
the measured action; initial identity/admission preflight remains a declared
missing cost scope. No end-to-end cost advantage is established by these tests.
Original authorization, independent B arrival, repeated use, FinalUse, service
confirmation and scientific improvement retain their separate acceptance gates.

Engineering checks use temporary installed distribution metadata and the retained
original engineering archive. They do not run training, cold model inference,
native adoption, payment, or the frozen E1–E6 experiments.
