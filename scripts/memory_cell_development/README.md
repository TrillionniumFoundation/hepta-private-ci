# Executable procedural memory development

This Linux-only development assay trains the existing source-bound decoder on
actual Ruff repair observations and executes its proposed operation against a
pinned historical project fixture. It does not change the old frozen budget or
longitudinal experiments, their quality gates, or their results.

`procedural_trial.py prepare` requires `--repo`, `--output`, `--ruff`, `--python`
and `--model`. It verifies the existing budget archive, its 17 original fixture
files and exact Ruff executable, produces two teaching observations through real
tool execution, and freezes the source-only recipe and evaluation contract.
Use a fresh output directory; no existing run is overwritten.

Run `procedural_trial.py run` with the same arguments and the exact
`--protocol-sha256` printed by preparation. Each fit/read runs in a fresh child.
The trainer receives only the separate training spec, and the existing reader
receives no fact text, retrieval results or answer lexicon. The common executor
accepts only the two frozen operations and binds their target to the pinned
fixture; arbitrary generated shell commands are refused.

The study uses three fixed seeds and one previously exposed project task, not
three independent tasks. Its typed retrieval control also executes the full
lint/76-test gate but is not a complete strong RAG repair agent. It is a narrow
action-capability development test, not a future-utility or fission benchmark.

See [the detailed report](../../qa/memory-development-20261025/README.md), frozen
protocol and measured summary. Only these small reports and source are published;
raw checkpoints remain local. Production acceptance and all complete research
gates remain false.
