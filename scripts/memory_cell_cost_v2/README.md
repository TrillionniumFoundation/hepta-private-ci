# Declared storage and bounded warm-load cost, v2

This is a new development accounting layer. It does not modify older protocols,
models, checkpoints, task gates or evidence. It imports no model packages for
inventory, normalization, proposal freezing or its pure tests.

## What is measured

`historical_inventory.py` reads the retained two-rule Ruff development run. Its
source observations are real local tool outcomes on two authored teaching cases;
the original project fixture is one previously exposed incident. Three trained
seeds are three cells, not three independent tasks. The report validates the
historical source, fixture, six-file base and adapter pins before reporting costs.

`storage_ledger.py` distinguishes logical file-entry bytes, unique device/inode
payload and allocated blocks, and content-unique bytes. Hard links remove repeated
physical ownership only. Identical copies on different inodes still consume
storage. The content-unique result is a hypothetical dedup bound; no data is
removed or compressed. Directory metadata, filesystem extents/reflinks and all
OS costs are outside this measurement. Membership and file metadata are checked
again at the cutoff; this is not an atomic filesystem snapshot.

Deployment projections explicitly assign dependencies to hosts and consumers.
Only real dependencies are shared. The source-only retrieval consumer does not
retain the memory base or model packages. Separate hosts pay their own copies.
These are storage projections from real files, not measurements of remote hosts.
Source observations, retained original fixture, adapter lineage, tools and audit
artifacts remain visible as separate components. A production source event
journal and a persisted router/index were not implemented by the old two-rule
experiment; zero persisted index bytes does not mean zero resident retrieval
memory. The full current model environment is counted, including later relay
packages, and is labelled an observed overinclusive snapshot, not a minimal
runtime or the original historical environment.

`receipt_reader.py` checks raw process streams, includes failed attempts and
normalizes explicit known receipt formats. Unknown CPU/token/whole-host/energy/
billing dimensions remain null; known subtotals are separate. Nested attribution
cannot be added again to a charged outer process. Compression requires an
explicit paired quality gate with sufficient independent groups and complete
cost closure. The present future group count is zero, so gain is null.

## Unexecuted warm-load proposal

`warm_trial.py freeze` writes an immutable proposal and pins implementation,
inventory, runtime, checkpoint and source bytes. `execute` is a separate command
for a later controller decision. No training path exists in the worker. Each arm
would start once, run two warmups and eighteen measured queries, and stop after
the first error. The total decoder ceiling is twenty, including warmups. The
same three exposed question forms repeat six times; they do not create new tasks.

The source comparator verifies the two original observation records, then takes
the first operation whose recorded action, lint and semantic outcomes all pass
for every requested diagnostic code. This is a strong source comparator for that
closed typed contract, not a general RAG repair agent. The decoder receives no
source values, retrieval answers or expected output in its request. The process
is trusted; this separation is not a hostile-code filesystem sandbox.

The future report retains raw samples, source reads, actual decoder entry/finish
markers, startup, warmup, process failure and unattempted counts. p50/p95 use
nearest rank over all completed measured attempts. Completion throughput and
correct-operation throughput are separate. Startup/import/load time and charged
whole-process wait4 costs are separate from sample attribution. Token counts from
finished generation remain available even if a later validation fails. A killed
query with no sample has unknown latency; it is not inserted as a successful
sample. Eighteen queries cannot establish scale, statistical superiority or a
latency SLA. The old 76-test success is retained evidence, not a new task run.

The generation wrapper directly enforces twenty total attempts, complete prompt
length at most 192, exactly sixteen allowed new tokens and at most sixteen
returned tokens. Its limits are pinned in both protocol and worker request;
entered failed calls are spent. A separate controller receipt measures its own
CPU and the complete execute wall interval, including admission hashes, child
waiting, post-execution hashes and result serialization. It adds wait4 child CPU
only once. Serialization of that final meter receipt itself is outside its cutoff.

The selected worker supervisor enforces single-CPU affinity, CPU/wall, virtual
address-space and output-file limits while its parent is alive. Virtual address
space is not RSS. There is no whole-host/energy/billing meter, hard RSS quota,
parent-death containment or model-throughput result in this implementation stage.
Every immutable source change, including publication formatting, requires an
explicit new protocol or audited publication binding before later execution.
