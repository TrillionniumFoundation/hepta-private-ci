# Hepta Memory A–I Frozen Acceptance Protocol v1

**Status:** `RESEARCH / SHADOW_ONLY / DENY_ALL / HOLD_NO_GO`.
**Implementation:** `qa/stem-bakeoff/memory_ai_acceptance.py`.
**Important:** This is an **adjudicator and negative-control gate**, *not* nine trained/retrieved benchmark runs. The synthetic tests prove only contract behavior. No experiment, model forward, score, cryptographic signature, or promotion may be inferred from passing this test suite.

## Exact pre-registered nine arms

| Arm | Required method identity | Scientific contribution under test |
| --- | --- | --- |
| A | `bm25` | Strong lexical baseline |
| B | `hybrid_dense_rerank` | Dense + BM25 + real reranker; must actually run all components |
| C | `source_graph` | Source-bounded Graph-RAG/HippoRAG-style graph traversal |
| D | `typed_static` | Typed Memory *without* local training |
| E | `shared_one_head` | Same frozen Encoder + one genuinely trained Head |
| F | `shared_typed_heads` | Multiple typed trained Heads sharing that Encoder |
| G | `learned_router` | F + learned sparse route **before** Head execution |
| H | `learned_meta_graph` | G + learned source-bounded Meta-Graph |
| I | `split_merge_evolution` | H + executed split/merge/rollback, matched to an unsplit continuation |

`COMPARISONS` are frozen in source: B–A, C–B, D–B, E–D, F–E, G–F, H–G, I–H, I–B, I–C. Positive I–B and I–C are **necessary**, not sufficient, to assert general Memory superiority. Each incremental arm must also pass its own contribution gate to support a *full A–I superiority* claim.

## Freeze boundary and input contracts

The independent planner must **persist and externally authenticate** the `plan.json` bytes *before* anyone generates or scores evaluation outputs. The CLI requires the expected SHA-256 of all three input files from a separate trusted registry or independent reviewer. A SHA-256 string copied from a file generated by the same experiment **is not a signature or an effective time-of-freeze witness**.

The plan uses schema version 1, exact `arms` and `comparisons`, `status=SHADOW_ONLY`, `evaluation_frozen_before_outputs=true`, pinned source/Reader/Encoder/scorer SHA-256, global `limits`, frozen `acceptance`, all nine `arm_manifests`, and a canonical `tasks` census with source-family identities, timestamps/window assignments, source closure and allowed original source IDs.

Each arm manifest must carry:
- `method`, `artifact_sha256`, `source_closure_sha256`, `reader_sha256`, `encoder_sha256` (E–I);
- actual `resident_bytes`, `training_work_units`, and complete `learned_from_families` (A–D must have none; E–I must use training-only families);
- `route_before_head=true` for G–I, actual `router_artifact_sha256` for G–I;
- `graph_artifact_sha256` for C/H/I; `evaluated_split_merge=true` and `topology_receipt_sha256` for I.

All arms use the **same** `reader_sha256`, source snapshot, task census, common resource ceilings, and generation-safe original evidence IDs. E–I must use the **same frozen Encoder identity** and exactly one Encoder forward per scored task. H and I must match both resident tensor bytes and training work units, or the static-vs-evolution comparison is invalid. Cross-arm training sources must be auditable as complete descendant closures, not merely direct training rows.

The separately sealed `gold.json` contains only evaluation task IDs, `answerable` flags, independent accepted exact answers and required original support IDs. No answer/gold/support labels may reach any Retriever, Head, Router or topology-selection process before prediction sealing. Gold support sets are not automatically sufficient semantic evidence; that must be independently adjudicated.

`predictions.json` contains exactly **one row per (A–I arm, evaluation task)**, including:
- `task_id`, `arm`, original selected and cited source IDs, `answer_text`, `abstained`, `confidence_ppm`;
- bound `artifact_sha256`, `source_closure_sha256`, `source_snapshot_sha256`, `reader_sha256`, and graph/router digest when applicable;
- `invocation_receipt_sha256` pointing to the independently retained real execution journal;
- `measured`: **all** `context_tokens`, `reader_output_tokens`, `reader_calls`, `encoder_calls`, `head_calls`, `router_calls`, `graph_hops`, `wall_ns`, `cpu_ns`, `peak_rss_bytes`, `io_bytes` as nonnegative *measured* integers, not estimates.

Missing, duplicated or extra rows, impossible all-zero execution resources, missing measurements, wrong generations, unauthorized references, nonexistent citations, swapped Reader/Head/Router/Graph digests, exceeded ceilings, mislabeled training families, absent Split/Graph executions, and wrong invocation counts reject **before scoring**. Failed/unavailable executions remain in the census and block the run; **never** silently drop difficult tasks or produce missing Head predictions from another arm. A task abstention is not equivalent to missing execution.

## Scoring and prospective gates

The pure verifier recomputes conservative `grounded_success` after joining the sealed evaluation gold. An answerable task succeeds only if the normalized final answer matches an independently accepted exact answer **and all registered required original source IDs appear in the delivered citation set**. An unanswerable case succeeds only on explicit abstention. No producer-supplied correctness field is read. This deterministic measure is deliberately stricter/narrower than semantic correctness, which must be evaluated independently with the **same Reader**.

The primary measure is **whole-source-family macro** grounded success, not question-micro accuracy. Paired bootstraps sample entire source families at once; the lower confidence bound is one-sided, with **Bonferroni correction for all ten frozen comparisons**. The default prospective production-quality plan should freeze at least 200 *independent, nonoverlapping* evaluation source families across at least two genuinely later collection windows, plus multi-hop, OOD and adversarial slices. The implementation enforces a minimum of 30 clusters, two future windows, and nonempty critical slices even for a research-scoring candidate. An original source ID cannot be shared across allegedly independent families, and one family cannot appear in multiple future windows. Physical independence and chronology still cannot be established purely from labels.

For each frozen comparison: corrected lower bound must exceed frozen `min_effect`; **both** mean CPU and wall-time ratios must be within frozen `max_cost_ratio`; and no multi-hop, OOD, or negative-answerability slice may regress more than frozen `max_slice_regression`; every future window must show a positive paired family-macro difference. All ceilings apply *before* computing gains. Training, calibration, graph/index construction, Reader calls, checkpoint storage, retraining after withdrawal, and host/worker RSS must be accounted for by the independent execution owner. Resource receipts merely supplied as JSON have no trusted physical provenance.

The verifier *always* returns `qualification=HOLD_NO_GO`, `production_activation_allowed=false`, and `independent_evaluator_authenticated=false`. `scientific_matrix_candidate=true` only means the **declared** frozen-input research arithmetic passes; it never certifies external source/evaluator attestation, truthful measured compute, temporal independence, semantic citation entailment, durable erasure, or production FinalUse. Those require separate trust-owner receipts and sign-off.

## Current independent blockers (must not be waived)

1. **A–I physical execution incomplete:** no nine-arm common original-source forward/journal; B's actual dense+rerank and C's real source graph are not the same as old BM25/session proxies; H needs actual learned graph, not fixed edges.
2. **Reader quality:** same actual Reader per arm; independent answer/citation sufficiency and semantic exactness. LoCoMo support-retrieval scores are not task success.
3. **Model and routing gains:** existing Procedural Head, learned Router and split-merge trials did not beat their predeclared strong/equal-budget controls consistently.
4. **External validity:** 200 independent future source families, two genuine future windows, calibrated abstention and OOD/multi-hop nonregression are not provided by retrospective ten-conversation LoCoMo or 2014 news categories.
5. **Full lifecycle cost:** real hardware CPU/GPU, total RSS, indexing, training, latency, worker, storage, replay, retraining, deletion and rollout cost needed; proxy work units not physical total cost.
6. **Trust and deletion:** independently authenticated source membership, tombstone/withdrawal closures, evaluated Reader and outcome journals, replay/adapter lineage, production owner permissions, rollback and cross-host final-use validation.
7. **Exact-head CI:** required Cargo/Bazel/Linux/macOS/Windows/security/Architecture/V8 workflows must terminate successful on the correct composed source commit. Contract smoke checks alone do not close them.
