## Adversarial cycles

1. **Legacy wire accounting.** A receipt could claim zero tokens for selected
   items, nonzero tokens for an empty selection or a count above the native
   ceiling. The #1295 regression fails against this V3 candidate. Forward the
   same encode/decode invariant without changing wire fields or granting trust.
2. **Public archive parser bound.** A valid preparation archive padded beyond
   64 KiB was accepted; both public decoders parsed before enforcing a byte
   ceiling. Apply the existing runtime limit before decoding. Boundary tests
   preserve valid exactly-at-limit input and reject one extra byte for both
   preparation and terminal-recovery archives. Canonical schema and hash domains
   remain unchanged. Checksums do not authenticate an adversarial archive.
3. **Ambiguity-scan amplification.** The 32 MiB request ceiling still allowed
   retention of every one-byte match as a machine-word offset. Stop at the second
   match instead of collecting all offsets; keep overlapping-match rejection.
   A separate native-process observation of the same maximum-size fixture changed
   peak RSS from 297,512 to 35,428 KiB and wall time from 1.420 to 0.0134 seconds.
   These are one-host development observations of the first short-circuit stage,
   not model-token accuracy, selected-host qualification or product latency
   evidence. A second review identified the naive byte-window search's
   pathological repeated-prefix cost. Reuse the existing workspace memmem
   dependency with its documented linear-time/constant-space bound; search again
   from the first start plus one byte so overlapping occurrences remain rejected.
   Differential arbitrary-byte tests and repeated-prefix absent/unique cases
   preserve the exact segment and rejection semantics.
4. **Recovery index/archive disagreement.** Production terminal-state validation
   accepted independently changed preparation digest, snapshot digest, observation
   time, thread, turn and coherently renamed outer attempt key while preserving
   the original recovery archive. The exact production validator and extracted
   production stored types reproduced all six acceptances using a real compiler
   recovery archive. The corrected validator rejects each mismatch and retains
   the coherent positive control. A registered real Agentd pre-send regression
   exercises the same cases, and immutable CI requires its exact native name.
   The isolated validator harness is not the full Agentd owner or a product run.
5. **Actual diagnostic caller failed to compile.** Current-head hosted execution
   reached `prompt_runtime.rs:697` and failed E0631: the old variant constructor
   expected the new public wrapper while the owner returned its internal error.
   Use the already-defined `From` conversion. Preserve raw-free reason codes;
   do not expose the internal error or dynamic strings to make it compile.

The reviewed proof path retains exact source/content/tokenizer/profile bindings,
mandatory floors, scope/domain checks even for empty selection, cumulative
revocation frontiers and exclusive expiry. Attachment/preparation do not treat a
cached digest or earlier snapshot as current authority. The normal existing
runtime stage clamps request lifetime to portfolio/selected-realization expiry;
final send checks follow tokenizer work and durable I/O. No additional deadline
bypass is claimed solely from an internally constructed request mutation.

## Follow-up: aggregate test evidence must not count nested output

The exact `e7dad716204ccba1d5a7a3c71b1b67dea25def97` qualification artifact exposed an evidence-recorder defect: `observed_tests` added each libtest result printed by nextest's immediate success output to nextest's final aggregate. The lifecycle, metrics and capacity receipts reported 20/8/6 passes while their actual nextest summaries contained 10/4/3. These counts feed `minimumTests`, so this was a gate defect, not only a presentation error. One executed test plus its nested output could meet a minimum of two. Independent required-name sets prevented those three named inventories from accepting missing required tests; count-only command gates did not have that protection.

The recorder now binds the expected runner from the command contract (`just test` invokes nextest), streams the complete log using the existing bounded-line reader, and requires exactly one complete nextest summary. It counts only passes, validates aggregate totals, and rejects missing, malformed or ambiguous summaries. A truncated tail cannot conceal an earlier summary. Explicit non-nextest libtest parsing retains multiple-suite pass counts while excluding failures and ignored tests. Command exit status, all minimums, test selections and required-name sets remain enforced independently.

Parser regressions cover immediate-output duplication, insufficient unique execution for the threshold, malformed/ambiguous summaries, failure/ignored counts, ANSI output, invalid UTF-8 and line limits, and summaries separated by more than the former one-MiB tail window. The prior artifact is retained solely as a parser fixture, not execution evidence for the recorder repair's source revision: [run 36980052695 artifact 11216783951](https://github.com/TrillionniumFoundation/hepta-private-ci/actions/runs/36980052695/artifacts/11216783951), ZIP SHA-256 `d24544c31824779699abec2187e04eb91b9d7dbf676ea10e050ad5ee4c174000`. Replaying its 16 count-gated logs corrects only those three counts, and every genuine minimum remains satisfied. Historical receipts are not rewritten.

That prior source-head run executed all 24 commands: 17 passed and seven failed. All new compiler/recovery named regressions, the full 257-turn lifecycle fixture, composed-product compilation and the hosted Bazel context-compiler target passed. Four broad suites failed on the unchanged cognitive-store recovery test's indeterminate immutable file identity; core provider policy finished 55/57, strict lint failed in unchanged hepta-operations, and advisories reported imbl-sized-chunks RUSTSEC-2026-0292 and matrix-sdk-crypto RUSTSEC-2026-0318. The five source feature profiles passed. All synthetic-merge profiles stopped before compilation on the same 11 conflicts reproduced on both the pre-audit baseline and the audited head against main `c6f90d48c40f7b5267db587bb3c3f4934f1414a8`. These results do not establish independent acceptance, activation or release, and fresh checks are required after this recorder repair.

## Follow-up: qualification must not update the checked lockfile

The resumed audit verified that PR #1157 still contained final source `69e1f50929bbcf6f287948262168384f7ce0be67` and main remained `c6f90d48c40f7b5267db587bb3c3f4934f1414a8`. Its source receipt recorded a `ValueError` after the successful Bazel command, without identifying the verification boundary or reason; source/document readiness therefore remained unexecuted. The unavailable full job log prevents proving the exact cause of that historical exception.

A separate concrete contract mismatch was found in the checked command: bare `bazel test` permits the default lockfile-update behavior while the executor claims to perform no write-back. [Bazel documents](https://bazel.build/versions/7.6.0/external/lockfile) that update is the default and error mode rejects missing/outdated lock data. The repository's existing lockfile verification script already uses `--lockfile_mode=error`. Context qualification now explicitly uses the same error mode. This is a plausible mechanism for the historical post-Bazel dirty-candidate failure, not a retroactive attribution of that incident.

Receipts now retain a bounded, source-defined failure context: verification/execution phase, current registered command, and a stable reason code. Dirty worktrees, changed commit/tree/parents, other candidate rejection and generic interruption remain failures; exception text and subprocess output are not copied into this context. The original immutable candidate checks remain before and after every command. A command's ordinary nonzero exit is still recorded and permits later independent checks when the source remains clean; candidate mutation stops immediately.

Real-Git recorder tests model only Bazel's lock update/error behavior with a small subprocess fixture. They verify that lock refusal leaves committed bytes intact and does not suppress subsequent readiness checks, while an actual fixture write is rejected at the post-command boundary without repairing the checkout. Unknown verifier errors do not expose their raw strings. These are orchestration tests, not native Bazel execution or proof of the old exception's cause. The existing count regressions and these boundary tests are now required together in hosted qualification. A subprocess stdout handle exposed by these tests is closed explicitly; no command, native test minimum, named inventory, advisory or security check is removed.
