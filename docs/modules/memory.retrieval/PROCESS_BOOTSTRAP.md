# Signed retrieval bootstrap for the ordinary Agentd process

Status: source implementation, not native execution or deployment qualification. This document specifies the loader added to the ordinary `codex-hepta-agentd` binary. It does not declare an independently deployed frontier service, vector encoder/index, calibrated policy, approved canary or measured product SLO. See `API.md`, `OPERATIONS.md`, `THREAT_MODEL.md`, `ROLLOUT_POLICY.md`, `CANARY_AND_ROLLBACK.md` and `E2E_MEASUREMENT.md`.

## Entry point and startup

The ordinary daemon accepts the paired arguments `--retrieval-bootstrap-descriptor PATH` and `--retrieval-bootstrap-descriptor-digest SHA256`. Duplicate flags, an incomplete pair, a malformed digest, a wrong descriptor identity or failed signature/currentness checks reject startup. Helper re-executions still reach the existing arg0 dispatcher before daemon-only argument parsing. Existing daemon arguments are unchanged.

The launcher must independently select `HEPTA_COGNITIVE_RETRIEVAL_MODE`. Absence or `compatibility` does not enable HNMF; compatibility forbids attaching an HNMF provider. `hnmf-shadow`, `hnmf-canary` and `hnmf-required` require a configured current provider. Adding the descriptor does not grant activation or override the host's mode wrapper.

A protected launcher can pass its already approved descriptor and digest as follows. These environment values name operator-provisioned inputs; they are not generated by Agentd and are not credentials created by this example.

```sh
codex-hepta-agentd \
  --retrieval-bootstrap-descriptor "$RETRIEVAL_DESCRIPTOR" \
  --retrieval-bootstrap-descriptor-digest "$APPROVED_DESCRIPTOR_SHA256"
```

The library entry is `LeasedMemoryRetrievalProviderV1::load_process_bootstrap(path, expected_digest, identity)`. Loading performs a real signed publication installation and a freshly challenged frontier acquisition. `AgentdConfig::with_cognitive_retrieval_context` also checks current identity. Parsing a descriptor alone is not successful startup qualification.

## Protected descriptor

The descriptor is a strict UTF-8 JSON object, at most 16384 bytes. The pin is SHA-256 of the original file bytes, not reserialized JSON. Every version has these common fields:

| Field | Required value or representation |
| --- | --- |
| `schema` | Exact supported schema string described below |
| `owner_id` | Exact Agent UUID string from the launched identity |
| `body_generation` | Exact nonzero launched body generation, unsigned integer |
| `context_public_key_hex` | 64 lowercase hexadecimal characters for the publication verifying key |
| `frontier_public_key_hex` | 64 lowercase hexadecimal characters for the independent frontier verifying key |
| `frontier_endpoint` | Explicit loopback IP address and nonzero port, parsed as a socket address |
| `request_timeout_ms` | Total frontier request deadline, 10 through 5000 milliseconds |
| `maximum_lease_ms` | Maximum publication/frontier lease, 1 through 300000 milliseconds |
| `publication_path` | Absolute canonical path to the signed publication file |

### Descriptor v1

`hepta.agentd.retrieval-bootstrap.v1` preserves the original fixed approximately five-percent canary cohort and the product structural ceilings. It must omit every v2 rollout/budget field. Supplying a v2 field under v1 is rejected rather than ignored, so old schema identity cannot silently acquire new rollout semantics.

### Descriptor v2

`hepta.agentd.retrieval-bootstrap.v2` requires all of the following fields in addition to the common fields. There is no field-by-field fallback to v1.

| Field | Meaning and bound |
| --- | --- |
| `canary_threshold_ppm` | Deterministic owner cohort fraction, `0..=1000000` |
| `canary_cohort_salt_hex` | Nonzero 32-byte policy-generation salt, 64 lowercase hex characters |
| `shadow_maximum_channel_candidates` | Maximum declared candidates for any channel in non-delivery evaluation, `1..=512` |
| `shadow_maximum_nodes` | Maximum HNMF nodes in non-delivery evaluation, `1..=4096` |
| `shadow_maximum_synapses` | Maximum HNMF synapses in non-delivery evaluation, `1..=32768` |
| `shadow_maximum_settling_steps` | Maximum settling steps in non-delivery evaluation, `1..=4` |

The v2 policy is captured once when the host composes the provider. Mode, policy version, threshold, salt and all four structural ceilings are included in the routed lifecycle binding used at final revalidation. An in-place descriptor mutation fails its byte pin. A legitimate rollout transition requires approved new bytes/pin and a new process launch.

The structural ceilings are checked before optional HNMF work for shadow and canary owners outside the delivery cohort. Exceeding a ceiling skips the optional work and preserves compatibility delivery without treatment exposure. These fields do not isolate CPU, RSS, allocations, wall time or cancellation; those remain separate qualification blockers.

Key pins, endpoint and rollout policy are startup configuration, not request parameters. No private signing key is read, generated or sent by this loader. The publisher and frontier owner must have separately governed keys and recovery policies. Merely supplying two public-key fields does not establish independent administration of those owners.

Descriptor and publication paths must be outside the Agent home, absolute, canonical and non-symlink. Files must be regular and bounded. Their immediate directory must not be group/world writable; shared writable ancestors are permitted only when sticky, such as a private directory under `/tmp`. The loader fails closed on non-Unix hosts until a separate host implementation is qualified.

These checks assume the publisher-owned directory is protected against the Agent and untrusted callers by the host sandbox and ownership configuration. They are not an atomic descriptor-relative `openat` path walk and are not a defense against a malicious trusted publisher racing file types or directories. Do not expose this loader as an arbitrary agent-selected file reader. A same-UID Agent without filesystem isolation is outside this threat model. Qualify the actual launcher/sandbox ownership boundary before activation.

## Signed publication file

The outer file is a strict JSON object, at most 33554432 bytes, with exactly the following fields:

| Field | Representation |
| --- | --- |
| `schema` | `hepta.agentd.retrieval-publication-file.v1` |
| `owner_id`, `body_generation` | Exact owner and launched body |
| `sequence` | Nonzero monotonically advancing publication sequence |
| `not_before_unix_ms`, `expires_unix_ms` | Signed bounded validity interval |
| `context_json` | A JSON **string** containing the original strict context document described below |
| `signature_hex` | 128 lowercase hexadecimal characters, Ed25519 signature |

`context_json` is deliberately not decoded through an intermediate generic JSON object: that would erase duplicate keys before strict context validation. The signature is over the existing `SignedMemoryRetrievalContextV1::signing_bytes()`, not JSON bytes. Those bytes bind owner/body, authority epoch, sequence, validity interval and the complete native execution-context digest. A syntactically valid signature string is not a verified signature.

Every acquisition rereads the bounded publication, validates the native context, checks the publication signature and observes the independent signed frontier. Identical installation is idempotent and cannot renew the existing monotonic lease. Errors do not reuse an old cached publication. The source implementation currently decodes the file on every acquisition; its CPU/allocation cost must be included in target-host measurements rather than assumed negligible.

## Context JSON v1

The inner document is at most 16777216 bytes and has schema `hepta.agentd.retrieval-context-json.v1`. All nested structures reject unknown fields and duplicate fields. Integer fields reject Booleans, fractional values and overflow. Digests use exactly 64 lowercase hexadecimal characters. Fixed-point values are raw Q32 integers; one is 4294967296.

The `generation_vector` object contains `scope_id`, `purpose_id`, `memory_ledger_frontier`, `knowledge_fact_frontier`, `tombstone_frontier`, `source_ledger_frontier`, `knowledge_graph_generation`, `compact_checkpoint_generation`, `prompt_registry_revision`, `retrieval_profile_digest`, `encoder_preprocessor_digest`, `authority_epoch`, `model_digest`, `tokenizer_digest`, `template_digest` and `tool_schema_digest`. Native generation/revision constructors and vector validation remain authoritative. The descriptor does not manufacture values for missing generation owners.

The other top-level fields are `objective_digest`, `approved_context_digest`, `cue_profile_digest`, `retrieval_policy`, `dynamics_policy` and `engram`.

`retrieval_policy` contains `policy_id`, `channel_weights`, `maximum_results`, `minimum_total_score_q32`, `maximum_ood_q32`, `minimum_distinct_channels` and `abstain_on_contradiction`. Each channel row contains `channel`, `weight_q32` and `maximum_candidates`. At most eight rows are accepted. Channel codes are 0 lexical, 1 vector, 2 entity, 3 temporal, 4 causal, 5 procedural, 6 contradiction support and 7 generic graph. Unknown codes are rejected. The native policy digest must equal the vector's retrieval-profile digest. The existence of code 1 does not enable a vector producer; enabling it without a real generation-bound owner remains invalid product composition.

`dynamics_policy` contains `policy_id`, `maximum_nodes`, `maximum_synapses`, `maximum_active_per_population`, `maximum_active_nodes`, `maximum_settling_steps`, `maximum_graph_hops`, `maximum_activation_paths`, `leak_q32`, `lateral_inhibition_q32`, `minimum_activation_q32` and `contradiction_forces_abstention`. Native dynamics validation enforces the existing hard ceilings and semantic rules; the decoder does not weaken them.

`engram` contains `generation_digest`, `nodes` and `synapses`. A node contains `node_id`, `population`, `support`, `threshold_q32` and `confidence_q32`. Each support contains `record_id` and `record_revision`. Population codes are 0 sensory trace, 1 episodic binding, 2 semantic concept, 3 procedural skill, 4 predictive world, 5 utility salience and 6 meta-memory.

A synapse contains `source_node_id`, `target_node_id`, `relation`, `weight_q32` and `support_digest`. Relation codes are 0 associative, 1 temporal, 2 causal, 3 procedural, 4 predictive, 5 supports, 6 inhibitory and 7 contradicts. Node/edge generation digests are derived from the same validated vector; mixed per-entry generations cannot be supplied in this wire format. Native snapshot construction enforces canonical collections, endpoints and `DENY_ALL` authority. Wire limits are 4096 nodes, 32768 synapses and 1 through 512 support entries per node, in addition to the byte bound.

## Publication lifecycle and recovery

A separately managed publisher assembles real owner/model/encoder/tokenizer/policy/engram identities, signs the native publication bytes, and atomically replaces the protected publication file. Its independent frontier owner publishes the same publication digest with a strictly advancing epoch/sequence. Either ordering may create a short fail-closed mismatch window; no mixed generation is delivered. A same-payload renewal is still a new signed lifecycle and invalidates old final-use receipts.

Revocation advances the independent frontier sequence and publishes a null publication digest. A stale local file cannot override revocation. Restart begins with an empty in-memory provider; it must observe the live challenged frontier again. A replayed Agent-home backup or local publication file is not an independently current frontier. Key rotation requires new approved descriptor bytes/pin and a new authorized host launch, not a request field.

The frontier RPC framing, signature domain and total-deadline behavior remain specified in `OPERATIONS.md`. Deployment and durable recovery of that owner are still required; the loopback client is not itself the owner. The ordinary CLI bootstrap also does not create a learned ranker, durable learning sink or vector index. Bootstrap v2 supplies the rollout-policy seam but not independent operator approval or resource isolation. Full-chain composition and the nine-stage measurement producer remain separate implementation and qualification work.

## Tests and acceptance

The candidate includes strict schema/path regressions for bounded decoding, duplicate/unknown keys, integer confusion/overflow, policy drift, generation binding, duplicate node support, canonical hex and private regular-file paths. It also includes v1 compatibility and v2 completeness/range tests plus routing tests for exact legacy cohort behavior, zero/full ppm limits, policy identity and each structural budget. They are authored source tests until exact-head CI records their execution.

Require locked Agentd build/tests, all-target Clippy, repository formatting, dependency/Bazel lock validation, real startup/rotation/revocation/recovery fault injection, protected-path sandbox qualification and independently reviewed target-host evidence before activation. See `E2E_MEASUREMENT.md` for the exact-source SLO contract; a JSON validator pass is not a measured product result.
