## 2. Repository-controlled runtime semantics

The parent candidate already contains the full endpoint/session/view/payload/final-use binding, monotone display epoch, pre-refresh invalidation, durable `Prepared`/`Invoking`/`Indeterminate` transitions, restart reconciliation, bounded journal capacity, and evidence-gated retirement with an append-only hash-chained audit sink.

This closure changes the remaining path-resource boundary. The system adapter no longer dispatches `OpenPath` or `RevealPath` through `open`, `explorer.exe`, or `xdg-open`. Those launchers consume a mutable path string rather than the verified file object. Retaining a file descriptor while launching a path does not make the launcher consume that descriptor and therefore does not close the replacement race.

`SystemPlatformAdapter::confirmation_resource` now rejects path effects before the runtime writes `Prepared`. The permission adapter also returns a negative decision, and effect entry independently fails closed. A configured allowlist is therefore necessary but not sufficient: path effects remain unavailable until a platform-specific adapter consumes an already-verified resource capability without reopening a mutable name.

Clipboard and notification effects retain their existing local-policy, signed final-use, dispatch fencing, observation, and indeterminate-retirement semantics. A launcher exit code is not treated as proof that a user-visible notification occurred.

## 3. User-visible operation lifecycle

The UI and operator tooling must preserve these distinct states:

- **rejected before dispatch** — the operation was not sent to the OS; this includes path effects rejected for lack of capability handoff;
- **possibly dispatched / observation pending** — replay is prohibited and reconciliation may continue;
- **observation closed** — automated observation has ended, but this does not manufacture success or failure;
- **retired with evidence** — the active record was moved out of the bounded live journal under the retirement policy and remains represented in the append-only audit chain;
- **terminal succeeded, rejected, failed, or quarantined** — only a typed terminal observation may create the corresponding receipt.

A normal “retry” control must never mint a new operation identity for an indeterminate effect. The product should expose reconciliation, evidence attachment, observation close, and policy-governed retirement as separate actions. Clearing the journal is not a recovery procedure.

## 5. Installed-artifact and release gates

Repository CI can prepare evidence, but it cannot self-issue the following results:

- macOS Developer ID custody and notarization;
- Windows Authenticode, packaged AppUserModelID, and WinRT notification integration;
- Linux distribution signing or repository ownership;
- physical screen-reader, keyboard-only, Chinese IME, focus restoration, and multi-monitor DPI acceptance;
- installed update, crash-boundary, restart, rollback, key-rotation, and revocation drills;
- long-running installed-artifact startup, latency, memory, file-descriptor, journal, and recovery measurements;
- independent release-channel selection, promotion, and approval.

These gates must remain `not_claimed` until evidence from the actual installed binary and target host is retained. Source self-tests and release approval stay independent.

## 6. Performance measurement

Measure the fixed candidate binary and package, not constants in source. At minimum retain host identity, OS/build, package digest, binary digest, configuration digest, endpoint/gateway identity, sample count, warm-up policy, raw observations, percentile method, and pass/fail threshold for:

- cold and warm startup to coherent view;
- UI input-to-paint latency during idle, refresh, reconciliation, update staging, and journal compaction;
- refresh and restart recovery with the live journal at 50%, 90%, and policy limit;
- active and retired journal growth across repeated restarts;
- resident memory, CPU, thread count, handle/file-descriptor count, and private-state disk growth during long runs;
- update activation and rollback recovery time from installed artifacts.

The launcher concurrency bound and observation timeout are safety/capacity settings. They are not performance evidence.

## 7. Re-enable criteria for path effects

A future change may re-enable `OpenPath` or `RevealPath` only when all of the following are true:

1. authorization binds endpoint manifest, session incarnation, view generation/digest/revision, payload digest, action, operation identity, and a canonical resource identity;
2. the adapter passes the already-verified capability to the OS rather than resolving the original path again;
3. target and parent replacement, symlink substitution, mount/volume change, delete/recreate, rename, and in-place mutation tests fail closed at every boundary;
4. revocation between permission and effect entry prevents dispatch;
5. a crash after OS acceptance but before receipt persistence never causes replay;
6. the installed package is exercised on each supported platform;
7. documentation and the implementation map are rebound to the tested source anchor.

Until then, unavailable path effects are an explicit security posture, not a silent fallback.
