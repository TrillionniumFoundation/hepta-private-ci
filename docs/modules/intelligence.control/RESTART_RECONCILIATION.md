# intelligence.control restart reconciliation security contract

This document narrows the product-learning restart boundary for `intelligence.control`. It does not grant deployment, promotion, release, model, tool, or physical-effect authority. Exact candidate identity and execution status remain generated by `scripts/hepta-intelligence-control-status.py` and the independent qualification workflow.

## Durable objects

A Decision or Outcome append is represented by:

- one immutable, digest-addressed payload sidecar;
- one `kernel.operations` intent binding scope, operation ID, destination, payload digest, predecessor operation, and owner generation;
- one canonical `learning.ledger::LedgerWriter` destination;
- one final-use binding derived from the durable operation intent.

Recovery must not synthesize a replacement logical event, change the original ledger predecessor, or infer success from a process-local return value.

## Restart algorithm

For each unsettled operation, the current Agentd generation:

1. adopts the durable operation generation when necessary;
2. loads and digest-validates the immutable payload;
3. validates payload identity against the durable operation intent;
4. observes the authoritative learning ledger before requesting authority;
5. if the exact event is already present, records an idempotent acknowledgement without consuming a new grant;
6. otherwise requests a fresh, host-owned signed final-use grant for the adopted binding;
7. claims that binding through `FinalUseAuthority`;
8. dispatches the exact payload and original predecessor through `dispatch_final_use`;
9. maps only an authoritative destination observation into a terminal operation outcome.

The ordering in steps 4–8 is normative. In particular, a grant retained by the failed process is never reusable recovery authority.

## Terminal semantics

- Exact destination event observed or exact append acknowledged: `Acknowledged` / `ReconciliationOutcome::Applied`.
- Deterministic malformed, conflicting, or policy-rejected append: `Rejected` / `ReconciliationOutcome::NotApplied`.
- Revoked, expired, epoch-mismatched, or stale-revocation authority: `Revoked` / `ReconciliationOutcome::Quarantined`.
- Authority unavailable, capacity exhausted, dispatch already in progress, state lock contention, ambiguous I/O, or writer poisoning: `Indeterminate`; no terminal receipt is fabricated.

An `Indeterminate` record remains reconcile-only. It does not authorize automatic creation of a new operation ID or a new logical Decision/Outcome.

## Qualification requirements

The default product profile and deterministic synthetic merge must prove:

- already-applied recovery completes without requesting fresh authority;
- not-applied recovery requests and consumes a fresh grant before mutation;
- revoked fresh authority quarantines the operation without ledger mutation;
- unavailable authority leaves the operation indeterminate;
- exact replay remains idempotent across Agentd restart;
- tracked implementation and traceability artifacts are generated from the exact executed commit.

## Daemon scheduling profile

A product embedding may attach `AgentdIntelligenceLearningRuntimeConfigV1` only after the canonical runner and host-owned invocation provider are installed. The config must carry a learning host for the exact Running generation (`spawn + 1`), a 10 ms to one hour cadence, and a batch bound of 1 to 256. Agentd then starts one required `intelligence-learning-reconciler` task. Each iteration waits for the live Running admission fence, observes/reconciles unsettled rows first, drains only the remaining bounded batch from the prepared outbox, and rechecks generation after destination work. A generation mismatch fences the daemon; the successor adopts the unsettled operation and replays only the exact immutable payload.

The ordinary CLI installs no learning host, writer, grant provider, or scheduler. Absence therefore means no product-learning mutation authority, not an implicit compatibility writer.

## Exact authenticated destination observation

Version 2 learning outbox payloads freeze the already verified principal, controller, credential-chain digest, signing-key digest, scope, authority epoch and signature-derived authentication digest. Restart observation reconstructs the complete `AuthenticatedDecisionRecordV2` or `AuthenticatedOutcomeRecordV2` and acknowledges only exact event equality. A changed signature, principal, controller, credential chain, key, scope or epoch cannot be mistaken for an already applied event; replay also re-verifies current evidence and rejects binding drift.
