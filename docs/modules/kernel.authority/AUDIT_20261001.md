## Position and documentation

This module is the non-learnable authority boundary beneath execution and
adaptive proposal modules. It owns the durable general lease/revocation store
and signed single-use FinalUse owner. Callers must retain exact subject,
destination, scope, payload, epoch/revision and live-time binding at effect
entry. Evidence witnesses are serializable audit facts, not bearer authority.

Detailed development documentation exists: `TECHNICAL.md`, the V1 lease ADR,
`LINEARIZATION.md`, `PRODUCTION_TRUST_PROFILE.md`, `PRODUCTION_CLOSURE.md`,
`CAPACITY_QUALIFICATION.md`, `HOT_PATH_DECISION.md`, the generated traceability
and port matrices, plus `hepta-contracts/FINAL_USE.md` and `FINAL_USE_CONTROL.md`.
It covers APIs, ownership, state layouts, concurrency, rejection, recovery,
trust-provider requirements and named tests. The audit found contradictory
recovery/schema/performance prose; those statements are corrected in this patch.

## Confirmed defects and corrections

| Finding | Trigger and consequence | Correction / regression |
|---|---|---|
| FIFO input blocks before file-type validation | An owner store's snapshot or claim journal is replaced by an owner-only FIFO. `openat(RDONLY)` waits for a writer before the regular-file check, so fail-closed admission hangs. | Both storage helpers use `O_NONBLOCK` alongside `O_NOFOLLOW`; descriptor ownership, links, mode and regular-file checks remain mandatory. Bounded tests cover lease snapshots and FinalUse snapshots/journals without a writer. |
| Revocation retry accepts a wrong predecessor at revision exhaustion | Stored revocation revision is `u64::MAX`; a retry supplies `u64::MAX` as its expected predecessor. Saturating addition matches and returns a receipt with a predecessor that never committed. | Checked successor comparison. The durable near-exhaustion regression preserves the real `MAX-1` retry and rejects `MAX` after owner reopen without changing the frontier. |
| Pending-revocation documentation conflicts with storage | Existing prose calls pending state process-local, while schema V4 stores the pending head and includes it in the external frontier digest. | Document the durable head and process-local active-dispatch counter separately; recovery must preserve pending admission denial and authenticate the live feed. |
| Constant-time claim statement omits external trust work | Journal append is fixed-size, but `frontier_for_state` hashes retained nonces during protected claim CAS. | Limit the constant-size claim to journal bytes; require history-sensitive measurements of the full frontier path. No nonce eviction, cached authorization or unmeasured algorithm replacement. |
| Candidate source anchors drifted | Hosted run `36661311428` rejected tracked changes to the target workflow and convergence regression after `be80239…`. | Rebind convergence/status manifests to an immutable commit containing all current source fixes; regenerate projections instead of weakening the drift validator. |
