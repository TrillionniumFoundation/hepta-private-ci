# HNMF bounded migration plan

## 1. Migration rule

The existing immutable source ledger, memory revisions, citations, KG generations, FTS channels, reciprocal-rank fusion, and pre-send revalidation remain valid inputs. HNMF is introduced as a rebuildable qualification projection first. No existing source fact is rewritten and no current production path is replaced in place.

## 2. Phase M0 — evidence freeze

Bind the exact source snapshot, SQLite schema, active memory heads, KG generation, retrieval fixtures, and deletion fixtures. Record a baseline for citation precision, stale rejection, contradiction detection, latency, resident memory, and source-scope enforcement.

## 3. Phase M1 — multimodal event envelope

Wrap existing text memories as `MemoryEventV1` with `text` modality spans and exact source digests. New image, audio, video, code-AST, GUI-state, tool-trajectory, structured-data, and sensor observations enter only after their exact asset digest, byte range, preprocessor identity, privacy scope, and redaction manifest are available.

## 4. Phase M2 — projection build

Build HNMF event, temporal, causal, contradiction, procedure, and engram projections from immutable source facts. FTS, vector, KG, temporal, causal, procedure, predictive, recency, explicit-memory, and contradiction-support indexes are candidate generators only. Every projection generation is atomically published and can be rebuilt from authoritative ledgers.

## 5. Phase M3 — shadow recall parity

Run the existing retrieval result and HNMF `RecallPacketV1` side by side. HNMF may emit references, activation paths, contradictions, confidence, OOD, and abstention, but may not attach content to a production model request. Any source, scope, lifecycle, validity, citation, asset, or generation drift invalidates the packet.

## 6. Phase M4 — consolidation qualification

Record replay candidates, activation observations, eligibility traces, outcome signals, credit, and candidate-only plasticity. Generate immutable next-snapshot artifacts. Current-run mutation, production writer construction, online topology activation, self-selection, and self-promotion remain forbidden.

## 7. Phase M5 — bounded canary prerequisite

Canary eligibility requires future-time evaluation, old-task retention, OOD and subgroup floors, deletion non-resurrection, crash/reopen, backup/restore, exact rollback, resource bounds, and independent acceptance. A successful reference or shadow run is not canary authority.

## 8. Rollback

Rollback selects the exact predecessor event/engram/synapse snapshot and rebuilds all derived indexes. It never edits historical source events. External effects are outside HNMF and cannot be declared rolled back by this migration.
