# neuron.runtime adversarial audit, 2026-10-01

Baseline: `TrillionniumFoundation/hepta-private-ci` main
`997e7beef8151160065df36b024bc8da5c989e93`. This audit evaluates the
native source and its project boundaries. It does not attest deployment,
independent acceptance or real-model efficacy.

## Documentation and completion

Detailed development documentation exists: the module `TECHNICAL.md`,
`IMPLEMENTATION_MAP.json`, readiness execution specification, implementation
dossier, and crate `EXECUTION.md`, `JOURNAL.md` and `RECOVERY_ANCHOR.md`.
Together they describe algorithms, numeric budgets, ports, transaction ordering,
recovery, threats and acceptance requirements. This revision corrects stale
segment-rotation, work-package and DecisionCell status statements.

| Layer | Supported conclusion |
| --- | --- |
| V1 mechanism | Bounded Q24 recurrence, inhibition, competition, homeostasis and eligibility are implemented. |
| V1 durable owner | Journal replay/CAS, independent witness, acknowledged publication, full-segment rollover and deletion-generation bootstrap are implemented. |
| Model boundary | The inference-control adapter validates exact feature receipts and the selected tuple; the host must authenticate its actual driver. |
| Project composition | Agentd has a long-lived owner wrapper and intelligence has a typed caller. The daemon startup/run lifecycle does not install them. |
| V2 mechanism | Separate temporal/activation dimensions and population-first/global competition are implemented as a pure mechanism. |
| V2 durable owner | Versioned journal migration, recovery and owner composition are not implemented. |
| DecisionCell | Cell/organ/bundle admission, candidate/deadline semantics and state transformation remain planned extensions. |
| External qualification | Selected real-model execution, target-host budgets, future-window efficacy and independent acceptance remain outstanding. |

A percentage would conflate these distinct obligations. Source presence and
passing fixtures do not establish production completion.

## Findings and changes

| Finding | Concrete failure | Resolution |
| --- | --- | --- |
| V2 config ambiguity | Moving an identically encoded edge between projection and inhibition preserved the config digest while changing the mechanism. | Length-frame all three collections and reject inherited checkpoints with a different config digest. |
| Incomplete recovery binding | The same native sparse config could recover under a changed encoder, weights, tokenizer or calibration tuple. | Bind the complete runtime config in an independent HPTNWA02 witness and reject unbound canonical owners. |
| Witness context mismatch | A witness with the right config digest but a different subject, objective or generation could enroll the owner. | Verify retained context before journal initialization or repair and during owner use. |
| Unacknowledged publication | Pending or intermediate-chain state could be exported as a canonical checkpoint or eligibility sample. | Require journal/witness frontier agreement before publication or advancement. |
| Successor reconciliation | A recovered complete suffix could remain ahead of the witness, causing the next tick to conflict. | Reconcile the final recovered segment before installing it. |
| Early owner rollover | Rotating a non-full root could create a chain that owner recovery could not locate. | Require a full current segment before owner rollover, before touching the successor file. |
| Indeterminate acknowledgement | A witness could have committed while reporting uncertainty; retry needlessly attempted the same CAS. | Read and accept the exact retained next anchor without invoking the model again. |
| Checkpoint forgery | Caller summaries could substitute predecessor, config metadata or saturation count. | Validate native config and derive/check summaries against replay-produced checkpoint metadata. |
| Late rejection | Invalid context/sequence/clock/body or known store capacity failure could occur after model execution. | Check these owner invariants and both store capacities before inference. |
| Incomplete latency | Witness acknowledgement and reported model latency were omitted from the final latency gate. | Measure through acknowledgement, including same-process retry wait, and take the greater reported model latency. |
| Resource ordering | Equal timestamp/latency samples with different remaining fields produced order-dependent sample digests. | Canonically order all bound resource fields. |
| Invalid resource admission | Invalid envelopes, zero checkpoint sizes or an understated ratio could produce a passing sample summary. | Validate the envelope, denominator and exact wide-integer byte ratio before qualification. |
| Zero projection policy | A valid zero-projection runtime policy could not roundtrip through its registered u32 protocol field. | Permit and test the zero saturation budget. |
| Witness count narrowing | A 32-bit record-count conversion could turn an oversized file into an empty history. | Check quota at full u64 width before conversion. |
| Plasticity ingress | No public constructor admitted an independent modulator; invalid projections were deep-copied before validation. | Add checked host-admitted construction and sort bounded references. |
| Documentation/platform drift | Implemented segments were described as absent; a segment test read a Windows-locked file through another handle. | Correct operating documentation and read through the owned handle. |

## Compatibility and operating limits

V1 HPTNSJ01/HPTNSJ02 journal bytes and checkpoint digest semantics remain
unchanged. Third-iteration calibration admission is stricter at fractional
confidence, OOD and activity boundaries without changing those bytes. Keep
historical receipts and qualification samples bound to their actual source
version; repeat affected qualification for the updated candidate. Protocol
validation rejects malformed previously accepted DTO values without adding or
renaming registered fields. HPTNWA02 adds a complete-config commitment; legacy HPTNWA01 remains
available for low-level mechanisms but cannot compose a canonical runtime.
Never retroactively bind suspect history to a caller's current config. Existing
owners require independently authenticated migration or a fresh generation.
Custom witness implementations must supply a retained config commitment and
context verification; the trait defaults fail closed.

The pure V2 config framing correction changes its previous digests. Restart
affected qualification chains at sequence 1 and rerun their evidence. No old
checkpoint may be relabelled or silently inherited.

Witness history remains bounded to 4096 acknowledgements. Capacity preflight
avoids known impossible commits but is not a reservation or durability promise.
Journal rotation does not extend witness lifetime. Authenticated witness rotation
or compaction requires its own migration design.

`execution_micros` measures model-call-to-witness acknowledgement latency;
`transient_allocation_bytes` remains driver-reported, and
`journal_bytes_written`/write amplification describe the tick journal frame.
These are not measurements of all owner allocations, headers, witness writes or
whole-device I/O. Pure eligibility samples and modulator digests do not themselves
authenticate owner provenance or independent observation.

`checkpoint_bytes` bounds the mechanism's binary payload, including the domain
tag, seven digests, sequence/time, projection metadata and five framed numeric
vectors. It does not measure JSON encoding, heap use or a checkpoint disk write.
The continued-audit correction changes this reported bound and resource budget
disposition, but not V1 journal bytes, checkpoint digest preimages, registered
wire fields or the HPTNWA02 witness format. Consumers of historical resource
samples must retain the source/measurement-profile identity rather than relabel
old samples as corrected measurements.

`runtime_recovery.rs` separates first-acknowledgement reopen, root-chain traversal
and successor recovery. The host must authenticate the existing witness and its
empty frontier before first-acknowledgement reopen; a newly fabricated empty
witness cannot erase an earlier acknowledgement. The host supplies the declared
segment order and quotas. Intermediate acknowledged segments must be sealed;
they are never repaired into a shorter prefix. Recovery and canonical rollover
are distinct operations, and neither grants deployment or effect authority.
