## What scales and what remains fixed

Only the shared 4->width->2 tanh feedback subnetwork is widened. Widths
4/16/64/256 give 78/162/498/1842 actual parameters including the six layer/regime
matrices. There are no dummy parameters or frozen pretrained features. Width4
matches R7's initial bytes, forward values and population gradients. Output
initialization scales as sqrt(4/width); different widths do not have identical
initial functions. Within each width/seed all four methods have identical initial
tensors, full objective, CC5 nodes/weights and continuous parent population.

The plant and preference law remain known and affine/Markov; the learned
feedback is nonlinear. The state dimension, three-step horizon, task target,
entropic recursion and quartic terminal cost are not scaled. This is parameter-
width scaling on one small numerical problem, NOT larger world-model/state,
sequence-length, data-volume or LLM scaling. No global neural optimum is known.

## Fixed double gate and first-observed time

The protocol requires max(J_CC5,J_CC9)<=0.04850 AND
abs(J_CC9-J_CC5)<=1e-6. Both rules target the same continuous law. The second
condition is a numerical integration-consistency test, not a certified uniform
integration bound. Monitors are part of stopping on a known population, not
independent held-out evaluation. They are fully charged in wall/CPU time.

Every run is allowed 12 wall seconds from entry to fit, including initialization,
rule construction, optimizer setup, all gradient/HVP/cache/trial work and quality
checks. Checks occur initially and at optimizer callbacks/updates after a
0.5-second cadence, plus a terminal check. Trust callbacks may repeat the last
accepted weights after rejection; the code counts distinct changes separately.
No trial point is adopted. Thus the protocol's update wording is operationally
implemented as callbacks on the latest accepted point, not necessarily distinct
changes. All such redundant check work is paid.

A qualifying monitor must FINISH within the cap. First-observed completion time
is not an exact first hitting time: intermittent checks can miss transient
crossings, and nonmonotone trajectories do not support inferred crossing-time
intervals. Misses remain null/censored, not successes assigned twelve seconds.

## Cost-only progress versus integration consistency

28 runs had an in-budget monitor meeting the COST conditions;
only 8 met both conditions simultaneously. Consequently 20 cost-qualified runs
still missed the joint gate. This is a disclosed descriptive decomposition,
NOT a retrospective replacement of the primary with an easier target.

At 498 parameters all three HVP-explicit, all three HVP-AD and all three L-BFGS
runs reached the cost condition, but none passed the integration condition at
the same in-budget check. Adam did not reach the cost condition there. At 1842
parameters no method reached even the cost condition in the observed window.
The intermediate-width bottleneck therefore differs from the largest-width
bottleneck; a blanket optimization-failure story would be incorrect.

## Resource scaling and the cost of measuring quality

At 1842 parameters mean fit-plus-monitor peak process RSS is 453.1 MB (Adam),
654.0 MB (explicit HVP), 512.0 MB (AD HVP), and 468.2 MB (L-BFGS). At 78
parameters corresponding means are 384.0,362.9,360.6,329.2 MB. These include
runtime/allocator/monitor memory, NOT model-only memory. Matrix-free avoids
explicit full-Hessian construction but does not eliminate widening the retained
forward/backward graph. No dense-Hessian large-width experiment was run here.

At 1842 parameters monitoring alone averages 5.003s for Adam, 2.765s for explicit
HVP, 3.047s for AD HVP, and 5.034s for L-BFGS. Monitoring frequency depends on
when iterations/callbacks complete; it is not free and not identical in count.
The result measures end-to-end observed numerical qualification, not pure
optimizer throughput. The common cached gradient engine also retains a graph
for L-BFGS; this is the measured baseline, not a claim of a maximally optimized
L-BFGS implementation. All matrix-free fits construct zero full Hessians.

Capped runs can overshoot through a nonpreemptible operation/final monitor;
maximum actual fit-plus-monitor elapsed time was 12.666676s. After-cap checks
cannot count as successes. No exact FLOP/time equivalence, energy improvement,
or asymptotic complexity law is inferred from this four-width study.

## Next discriminating target

This round does not establish a scalable fixed-quality advantage for explicit
NDU adjoints. It locates two concrete next questions: integration inconsistency
can block otherwise low-cost candidates, while the largest width additionally
fails to optimize enough under the measured monitoring cost. A subsequent
controlled study should vary integration refinement and monitoring allocation
without relaxing the original target, with the same AD/L-BFGS controls and
explicit paid work. It is NOT reported as executed here. The result does not
rule out better native NDU structures or solvers; it limits the claim supported
by this particular implementation and budget.
