## Reproduction, repair and re-review

### 1. Signed authority crossed objective scope

After a valid root-signed successor distribution changes objective, the original
`append_credit_batch` accepted a newly signed allocation for an old-objective
Decision/Outcome. `freeze_dataset` likewise accepted a new-objective evaluator's
signature over an old-objective freeze plan. Signature validity did not imply
that the referenced causal objective matched the signer distribution.

Two regressions fail on the original implementation. Credit admission now checks
the canonical active Decision objective against the current verifier; freeze
checks its plan objective. These match the existing `append_outcome` boundary.
Failure leaves both ledger history and witness unchanged. The allocator/controller
independence and exact conserved terminal value remain enforced by canonical
ledger admission; no alternate credit owner or settlement path was introduced.

### 2. Dataset final use outlived root distribution

A receipt whose producer metadata remained time-valid passed final-use
revalidation after the root-signed distribution expired. The third original-source
regression demonstrates this independently of credential expiry. Final-use now
requires current owner trust and the current objective. An objective change denies
current use while retaining the immutable historical receipt and its integrity.
This is not a rule invalidating all historical receipts on ordinary key rotation.

### 3. Crash-cut data escaped the independent acknowledgement boundary

An explicitly constructed crash fixture synchronizes Decision and Outcome to the
canonical ledger while retaining a witness only through Decision. Reopening this
one-event-lag state is legitimate for exact retry. Previously signed dataset freeze
and metadata-only final use both succeeded using the unwitnessed Outcome. Two
regressions failed before repair.

Freeze now requires matching ledger/witness frontiers. Final use verifies, with
constant-time sequence indexing, that the claimed eligible frontier identifies
its actual canonical chain digest and lies within the witnessed prefix. Existing
indexed source lookup additionally rejects any source after that prefix. A
self-consistent rehash cannot invent a prefix or smuggle newer source rows.
No history replay/copy was added to final-use revalidation.

Positive regressions preserve an older witnessed dataset when a later unrelated
Decision is one event ahead of the witness. Exact retry of the unwitnessed Outcome
advances the independent witness without another journal row; only then does the
new signed freeze succeed. Existing correction and unlearning invalidation remain.

### 4. Durable qualification did not bind manual invocation

The deep ledger workflow now runs only as `workflow_call`/`workflow_dispatch`, but
its source environment read only `pull_request.head.sha` and unconditionally
created a synthetic-merge lane. On a non-PR event the exact-head assertion compared
HEAD to an empty value. Source binding now falls back to `github.sha`, and the
matrix follows the repository's established pattern: source-head for non-PR events,
source-head plus ordered-parent synthetic merge for PR events. Required tests,
limits and PR merge checks are unchanged; manual source-only execution does not
claim merge evidence. The actual bind shell was exercised with temporary local
Git fixtures for dispatch, non-PR call, PR source and PR synthetic merge.

Parent re-review found that the concurrency key also used only the PR number,
leaving unrelated manual branches in one empty-suffix cancellation group. It now
falls back to the full `github.ref`: repeated runs of the same branch still
supersede one another, different branch or tag refs remain separate, and PR
revisions retain their PR-number group. The regression reads the actual workflow
and evaluates its bounded context-fallback expression: two cancellation-isolation
cases failed before repair; all three cases pass afterward. This is local expression
model evidence, not a hosted cancellation experiment. Read-only permissions and
PR source/synthetic-merge lanes remain unchanged.

## Receipt authentication and actual consumers

`DatasetSnapshotReceiptV3` is a public, self-describing metadata envelope with
`DENY_ALL`, not an opaque issuer capability or retained signed proof. Its producer
identity and self-hash alone do not authenticate issuance, prove that its source
set is a complete historical freeze, or authorize training. The new prefix checks
prove only the stated canonical/witness/current-membership conditions.

The Bellman `dataset_bound::OwnerAdmission::revalidate` path retains signed freeze
and row evidence, invokes the current owner's signed `freeze_dataset`, compares
the entire receipt, and re-verifies role evidence. The terminal V3 preparation
path similarly calls `terminal_v3::verify_freeze` before returning a fit-capable
opaque value and repeats checks at final use. These are explicit APIs with source
and regression coverage; they are not proof that every default product caller
uses them.

In this integration source, `owner_terminal::freeze_terminal_cell_from_owner_v1`
and Agentd `shared_terminal_cell::train` still accept metadata V3 plus owner
membership checks without the signed V3 preparation contract. They must not be
presented as equivalent issuer-authenticated dataset admission. No ad hoc full
history replay, retroactive signer revocation, new receipt version, or invented
production closure was added to conceal that composition boundary.

resetting a witness, nor merging both enum meanings under one tag is a repair.
The publication branch also differs in root-expiry/recovery support; it is not a
strict newer superset. Its historical hosted test results do not transfer here.
