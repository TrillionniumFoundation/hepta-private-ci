# Original fixed training material owner

This component adds an explicit native path for one bounded failure/correction
read. It is disabled unless trusted startup installs the existing Root service,
its exact enrollment and effect records, the original physical-login and UI
descriptors, two original read-only files, and one pinned consumer connection.
The five existing service lanes retain their existing purpose. Generic paired
`FinalUse` remains rejected, and the Python engineering intake remains rejected.

## Exact ownership and order

`AgentdConfig::with_original_paired_training` requires the already installed
required turn owner and original preparation journal. It refuses any registered
paired effect dispatcher. The private training lane keeps the same writer `Arc`
and metadata; it does not open another journal. Its queue has capacity one, in
addition to a possible in-flight request, and uses the original ten-second
request deadline and required-task cancellation token.

The runtime verifies the original Core item, AuthBus delivery, Root owner and
current adapter lifetime through the existing verifier. Only a fresh, non-replayed
commit on the actual writer produces the private continuation. That continuation
owns the real queued receipt and borrows the original verified human source.
It consumes both while asking the same writer for its current exact operation
binding. A retained row, cancellation, restart or public observation cannot
construct another continuation. The original preparation API continues to
discard the private owner and return historical metadata only.

Wire fields correlate the original signed ingress, canonical payload, stable
delivery operation, route, principal, purpose, material commitment and current
writer binding. They are not a serialized permission or independent proof that
a journal commit occurred. The Root independently checks the original peer,
issuer, writer, effect, enrollment and human. No wire field can select a file,
callback, reconnect endpoint, trust key or new policy.

On the Root, the order is:

1. Validate the already installed fixed manifest and the exact registered wire
   correlation. Borrow the original channel and its absolute deadline.
2. Enter the existing four-record Registry boundary, using tokens from that
   same Registry `Arc`, then take the original issuer request lock. No asynchronous
   wait or complete human verifier runs while these locks are held.
3. Check the retained issuer state, writer proof and exact policy. Recheck the
   original signed human input against that loaded state, both held UI/login
   descriptors, all four lease expirations, the original peer and the clock.
4. Commit `Entered` in the actual protected issuer CAS before any material
   content read. The key is the original delivery alone; conflicting metadata
   cannot obtain another slot.
5. Read only the two already held regular descriptors. Immediately before every
   actual positional read, run the same private synchronous authorization check
   with a nondecreasing clock floor and the same channel deadline. Validate both
   original file identities, lengths and content hashes before returning bytes.
6. Commit the local `ReadCommitted` state, encode the complete bounded response,
   and keep the Registry and request locks through the actual socket writes.
   After each writable poll and before each prefix/body write, recheck the same
   authority and human. Recheck again after the last byte.

The response writer is borrowed from that original frame. It rejects a missing,
repeated or incomplete send and cannot reconnect. A channel error permanently
closes that channel. The dedicated service also rejects EOF before a request.
The original generic peer exchange retains its existing half-close behavior;
only the fixed paired handler opts into rejecting extra input or peer EOF at
the current exchange boundary.

## Persistence, limits and uncertainty

Both materials together are at most 32 KiB. Each must be a distinct original
regular file with a read-only descriptor, exact owner, private mode and one
link. Capture examines descriptor metadata without reading content. Reads use
at most 4 KiB per positional operation and verify device, inode, length, owner,
mode, links, modification time and change time against the captured descriptor.
Installation does not discover or reopen material paths.

The original peer framing is at most 64 KiB; the preparation payload is at most
16 KiB. The trusted paired connection permits at most one second for its frame,
also bounded by the original pinned process lifetime. Client cancellation shuts
down the exact original socket while an in-flight blocking request owns the
channel. The returned native value exposes bytes only after complete framing,
delivery, manifest, length and hash checks, followed by the original adapter
lifetime check in the required runtime.

The issuer retains at most 64 delivery entries, also subject to its existing
record size limit. Each entry has an explicit schema, exact semantic commitment
and issuer sequence. A stale CAS, different semantic commitment, corrupt version
or regressed sequence is refused. The entries use the same protected issuer
store and monotonic sequence as existing state. Nonempty entries are serialized
as a new versioned field: the old `deny_unknown_fields` decoder cannot load that
state and silently write it back without the consumed identities. This does not
claim an additional rollback defense beyond the existing protected store.

`Entered` survives a failed hash check, expiry, crash or missing response.
`ReadCommitted` proves only that the local original read and its durable state
transition completed. It does not prove that the consumer received the frame,
trained successfully, used the candidate, received `FinalUse`, or earned a Chain
settlement. Partial delivery and lost replies remain uncertain; neither state
permits another read. A later matching request can only receive retained
metadata, and a native retained journal never rebuilds the private continuation.

The deadlines are checked at actual read/write boundaries. Ordinary filesystem,
store and mutex operations are not forcibly cancelled mid-system-call; this
component does not claim a hard wall-clock bound for stalled storage. No lock
is held across an asynchronous Rust wait, and the only socket wait uses the
original absolute frame deadline.

## Source-bound engineering controls

The existing architecture lane selects 33 exact ordinary test names: 16 original
Root/lease/human controls and 17 new controls. It uses the repository `just test`
entry, no retries and one test thread. The new names cover eight material and
issuer controls, four original-response transport controls, three client
cancellation/complete-response controls and two required-owner cancellation
controls. The original ten turn controls and twelve preparation controls retain
their separate command records. The isolated Root gate retains its eight Python
controls and its one explicitly executed ignored native refusal test; that Root
test is not included in the 33 ordinary names or counted as an ordinary pass.

The material controls use synthetic content and human metadata with actual
temporary Registry/issuer CAS, restart, signatures, original descriptors,
pidfds, socket backpressure and Linux content-access observations. The client
transport controls explicitly use a test-local peer rather than claim a real
Root or fabricate a private journal receipt. The required-owner controls prove
future release and uncertainty reporting; they do not fabricate a successful
training operation. All new controls are source-defined and remain unexecuted
until their exact source is compiled and run by the owning CI lane.

Real participant enrollment, original A/B inputs, installation of the trusted
production composition, useful learning, candidate reuse, adoption and Chain
settlement remain separate evidence. This native component does not create or
substitute those inputs and leaves production installation absent by default.
