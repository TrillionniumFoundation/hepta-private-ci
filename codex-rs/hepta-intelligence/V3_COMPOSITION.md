# intelligence.control V3 composition

Status: source implementation on the feature candidate; no activation, promotion or release authority.

This document describes the converged composition surface in
`codex-rs/hepta-intelligence/src/composition_v3.rs`,
`native_v3.rs`, and `learning_v3.rs`. V1 read-only vertical and V1/V2 shadow
entrypoints remain compatibility surfaces. V3 is the only new integration path;
it is not a fourth independent facade.

## 1. Boundary

V3 is an authority-free composition library. It may validate, sequence, digest,
abstain, request slow-path handling, and prepare an `IntelligenceHostEnvelopeV1`.
It does not invoke Codex/model providers, tools, network effects, or physical
effects. `runtime.agentd` consumes the final envelope and remains responsible
for the existing Codex execution lifecycle.

The frozen `CapabilitySnapshotV2` binds objective identity, authority epoch,
body generation, configuration and revocation frontier plus exact owner,
contract, implementation and generation bindings. Required V3 capabilities are:

| Capability | Owner | V3 stage |
| --- | --- | --- |
| `objective.validation` | `objective.compiler` | `ObjectiveValidated` |
| `legal.actions` | `intelligence.control` | `LegalSetBuilt` |
| `utility.evaluation` | `utility.ndu` | `UtilityEvaluated` |
| `intuition.decision` | `intuition.policy` | `IntuitionDecided` |
| `context.compilation` | `context.compiler` | `ContextCompiled` |
| `evaluation.admission` | `learning.eval` | `EvaluationAdmitted` |
| `learning.record` | `learning.ledger` | `DecisionRecorded` |
| `dispatch.proposal` | `runtime.agentd` | final host-envelope consumer |

`neural.signal` / `neuron.runtime` and
`prompt.portfolio` / `prompt.optimizer` are optional. Absence is represented
as a typed `Unavailable` fallback bound into the predecessor chain; no fake
owner receipt is created.

## 2. Stage graph and predecessor chain

The selected path is:

```text
ObjectiveValidated
 -> LegalSetBuilt
 -> UtilityEvaluated
 -> NeuralSignalCollected
 -> PromptPortfolioBuilt
 -> IntuitionDecided
 -> ContextCompiled
 -> EvaluationAdmitted
 -> DecisionRecorded
 -> IntelligenceHostEnvelopeV1
 -> runtime.agentd
 -> existing Codex execution spine
```

Each owner receipt must match the exact stage, registered producer, frozen
snapshot digest and predecessor digest. Output and evidence digests must be
non-zero and authority must remain `DENY_ALL`. The next stage receives the
previous output digest. The final trace digest commits stage order, producer,
predecessor/output/evidence, disposition and observed timing.

The objective owner's output digest must equal the objective digest frozen into
the capability snapshot. The legal candidate set is generated by the facade and
must be bound to the same snapshot. Every typed stage also receives the frozen
implementation identity and generation for its capability. Native NDU input must
contain exactly the legal candidates plus the intrinsic `abstain` candidate;
NDU, neuron and intuition generation-bearing inputs must match their frozen
capability generation. Native intuition candidates must consume the scalar NDU
utility for the same candidate IDs rather than an unrelated caller score.

## 3. Native contracts

`LegalActionCandidateSetV1` is a bounded, canonical set with at most 126
caller-supplied action candidates. The durable Decision adds the reserved
`abstain` and `slow-path` identities, so the complete ledger candidate set
remains within its 128-entry bound. It binds candidate-set identity, state digest, generator, grammar,
candidate support and support floor. Input order does not change its digest.

`IntelligenceHostEnvelopeV1` is produced only after the selected path reaches
a successful durable `DecisionRecorded` stage. It binds the request and frozen
snapshot, objective/body/artifact set, legal candidate set, utility, optional
neural/prompt stage results, intuition, context plus context receipt,
independent evaluation, durable decision record, complete V3 trace, authority
epoch and absolute deadline. Its envelope digest excludes itself from the digest
scope. The canonical JSON field shape is registered in
`docs/contracts/PROTOCOL_SCHEMAS.json`.

No envelope is produced for abstain, slow path, terminal owner failure,
cancellation or deadline exhaustion. Abstain and slow-path decisions still skip
context/evaluation/dispatch and append a durable `DecisionRecorded` entry with
their reserved identity and positive logged propensity before the run returns.

## 4. Native owner adapters

`NativeCompositionPortsV3` invokes the current native owner libraries rather
than a simulation port:

- `objective.compiler`: `compile`, with compiled legal-action validation;
- `utility.ndu`: `evaluate_candidates_with_policy`, with exact legal-set plus
  abstain binding;
- `neuron.runtime`: bounded local `step`;
- `prompt.optimizer`: bounded `optimize`;
- `intuition.policy`: `decide_calibrated_v2`, with exact candidate IDs;
- `context.compiler`: `compile`;
- `learning.eval`: independent `evaluate`; only
  `EligibleForFurtherReview` continues;
- `learning.ledger`: actual `LedgerEvent::Decision` append through the sealed
  `DurableLearningJournal` interface, including reserved `abstain` and
  `shadow:slow-path` decisions when no dispatch envelope is produced.

The adapter retains concrete owner receipts for qualification inspection. It
does not turn evaluation eligibility into promotion and does not turn context
preparation into dispatch success.

## 5. Deadline and cancellation

`CompositionBudgetV3` reserves explicit evidence and recovery floors before
stage budgets. The total committed budget must fit the run horizon. Every stage
receives an absolute stage deadline and the coordinator checks a monotonic
`CompositionControlV3` before and after the owner call.

Cancellation and deadline exhaustion are traceable terminal dispositions, not
generic success/failure. Synchronous local owner calls cannot be forcefully
preempted inside Rust; therefore V3 permits only bounded local/proposal owner
calls before handoff. An overrun is detected immediately after the call and no
later stage or host envelope is admitted. Blocking durable sync remains a
learning-owner boundary and must be reconciled before retry. External model,
tool and effect I/O remains outside this synchronous facade and uses the
existing Agentd/Codex cancellation lifecycle.

## 6. Agentd handoff

`codex-rs/hepta-agentd/src/intelligence_facade.rs` is the named product caller.
It validates the exact V1 envelope, maps the frozen run/objective/body/artifact
tuple into `AgentRunCoordinator::start_run`, attaches the exact context and
context receipt, and does not mark dispatch until the existing runtime reports
that transition. A changed or stale envelope cannot silently rebind an existing
run.

This source composition is not activation evidence. The daemon must still
exercise the caller in an admitted product request and pass target-host
qualification before `productionImplementation` can become true.

## 7. Decision, Outcome and Credit

Every completed V3 intuition decision is durably recorded. The selected path
records the actual Decision before dispatch; abstain and slow path jump directly
from intuition to `DecisionRecorded` and produce no context/evaluation/dispatch
envelope. Outcome and Credit are deliberately separated from preparation and
dispatch.

`append_outcome_and_credit_v3` accepts only a caller-supplied terminal
`OutcomeObservation` and a linked `CreditAssignment`. It appends Outcome then
Credit through the existing durable journal. Exact retries retain the original
predecessor: the ledger replays identical records idempotently. The facade never
creates an Outcome from queue acceptance, dispatch, model completion, or its own
decision. If Credit append fails after Outcome is durable, retry replays Outcome
and continues from its committed chain digest; the partial durable state is not
rolled back or hidden.

## 8. Failure matrix

| Stage | Missing/failed owner | Result |
| --- | --- | --- |
| objective | required | terminal failure |
| legal set | local invariant | terminal error/cancel/deadline |
| utility/NDU | required | terminal failure |
| neuron | optional | bounded fallback |
| prompt | optional | bounded fallback |
| intuition | required | selected, abstain, slow path, or terminal failure |
| context | selected path required | terminal failure |
| evaluation | selected path required | terminal failure |
| decision ledger | required after selected/abstain/slow decision | terminal failure/indeterminate |
| Agentd/Codex | outside facade | existing runtime lifecycle; never inferred by facade |

Unknown producer, mixed snapshot, predecessor drift, authority widening, empty
evidence, candidate-set mismatch and objective-snapshot mismatch fail closed.

## 9. Qualification

Focused source tests cover:

- canonical candidate-set digest and exact V3 stage order;
- optional capability add/remove without fabricated receipts;
- utility/evaluation placement in one predecessor chain;
- cancellation, deadline, mixed snapshot and authority widening;
- native traversal through actual objective/NDU/neuron/prompt/intuition/context/
  evaluation libraries plus a real file-backed durable Decision append;
- Agentd admission and dispatch transition from a validated V1 envelope without
  changing the legacy public `RunSnapshot` shape;
- durable abstain/slow-path Decision recording without context/evaluation/dispatch;
- terminal Outcome/Credit append, exact retry and invalid linkage.

The applicable exact candidate must pass the existing Lane F, Agentd, workspace,
format, lint, documentation and deterministic merge-candidate gates. Passing
source CI establishes source qualification only. Independent semantic review,
target-host product execution, operator acceptance, canary, promotion and
release remain separate external gates.
