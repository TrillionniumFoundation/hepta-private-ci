# Observed procedures before another reader update

This continuation inherits source `9c1dcf37e7798cfd23b40a6098b4905c2c1aa16e`.
It reuses the evidence bundle, persistent FTS5/dense retrieval, frozen shared
reader, source validation and complete-census reporters. No production writer,
signing authority, serving default, LoRA trainer or acceptance gate changes.

## Why an executable control

The previous reader diagnostic retains whole publisher-marked sessions. Some do
not fit the model budget; those unavailable rows cannot establish a reader ceiling.
The minimal-evidence review importer remains the route for actual externally
reviewed natural tasks. This control does not invent such a review. Instead it
creates a small configuration problem whose answer is checked by executing Rust
compilations, with both necessary constraints supplied in separate source records.
It tests whether a reader can compose short complete evidence BEFORE more training.

`procedural_observations.capture` writes its protocol before 64 compiler calls:
four authored recipes, two revisions, two candidates for each of two component
checks, and all four joint configurations. The compiler inputs, fixed argv, exit
status, stdout, stderr, tool identity and observed times are retained. A complete
2x2 outcome grid must agree with both separately observed constraints; missing
runs, process timeouts or signals cannot become negative training labels.

The programs are deliberately controlled and small, not production incidents.
Natural-language source records are deterministic projections of actual component
exit codes, not LLM-written facts. Reopening the corpus recomputes the projections
and checks them against recorded source bytes and process results. Revision A
remains in the history when B is queried. Both constraints change, so knowing one
old setting or selecting only one necessary component is not sufficient.

The experience corpus is synced before planning constructs queries. Observation
clock values are not independent timestamps; this does not create a prospective
calendar window, trained snapshot, consent or independent source family. All four
cases share ONE authored program template family. There is no optimizer here.
The existing `FrozenMemorySession` remains available for read-only learned-state
experiments; this control does not pretend a parameter snapshot has been trained.

## Same-reader experiments

Ordinary conditions use the existing persistent hybrid index, never oracle IDs or
outcome labels. They include one window, ranked and coverage sets of 2/4/8,
bounded supplemental retrieval, a larger-context control with identical evidence,
and empty evidence. Three extra diagnostic conditions contain both CURRENT
compiler-verified component records or remove either one. Removing a premise does
not relabel the world's answer as unanswerable. Older constraints remain original
historical observations and are not deleted to make retrieval easier.

The 13 conditions on four tasks are frozen once before generation. 135M, 360M and
1.7B use the same registered prompt/decoder and the existing exact model revisions.
52 answers per reader are planned; changing reader size is a capacity diagnostic,
not a learned-memory gain. All failures and unavailable cases retain their place.
Raw answers are synced before labels are opened. No model output is executed.

Reported metrics separate token F1, strict registered configuration syntax,
complete-current-constraint coverage, false refusals with complete evidence, and
actual tokens. A predicted registered configuration is compared with the already
executed grid; the diagnostic parser accepts only the two values (optionally with
field labels and protocol citations), not arbitrary narrative or executable shell.
Failure to parse is not an independent semantic verdict. A valid E-label is not
an entailment certificate; semantic citation precision stays null.

## Execution

The read-only workflow runs only on `codex/memory-procedural-*` pushes or explicit
dispatch, rather than launching additional model runs on every PR synchronize.
It executes the full Python regressions and repository formatter, captures actual
compiler outcomes, then runs three isolated readers and a complete matrix merge.
A formatter failure retains a patch for review and blocks execution; it cannot
self-push or waive any required check. Model tensors are pinned, not reuploaded.

```sh
python -m unittest discover -s scripts/memory_cell -p 'test_procedural*.py' -v
python scripts/memory_cell/procedural_bundle_trial.py capture OUT --count 4
HEPTA_MEMORY_TESTED_COMMIT="$(git rev-parse HEAD)" \
  python scripts/memory_cell/procedural_bundle_trial.py plan \
  OUT STAGED PLAN --corpus-sha EXTERNAL_CORPUS_SHA256
```

Run the resulting plan with the EXISTING `bundle_trial.py run` and independent
plan/label pins, then `procedural_bundle_trial.py audit`. The ordinary supervised
memory/reader parameters stay unchanged. Only a reader that demonstrates useful
capability on reviewed natural evidence and held-out tasks should be frozen for
learning policies. Success on these controls is necessary diagnostic information,
not sufficient evidence of general memory, task superiority or production safety.
