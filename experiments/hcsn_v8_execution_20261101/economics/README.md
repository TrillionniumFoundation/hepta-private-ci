# 执行成本：实际任务、进程后代与输出边界

本组件可以包住真实模型命令，不依赖模型采用特定框架。已执行正常父／子／孙进程、父提前退出后的收养后代、超时失败和真实调度器探针。探针是测量工具验证，不是模型收益或新 AV 确认。

## 使用

从仓库根目录运行，输出目录必须尚不存在：

```bash
python3 -m experiments.hcsn_v8_execution_20261101.economics.worker_cost \
  --out /absolute/new/result-directory --timeout 1800 --sample-interval 0.5 \
  -- /absolute/python -m your.model.command --your-arguments
```

也可调用 `worker_cost.run(argv, out, timeout=1800, sample_interval=0.5)`。调用方 Python 与实际模型 Python 可以不同。命令作为参数数组传递，不经过 shell 插值。

`CONFIG.json` 保留命令；`stdout.log`、`stderr.log` 保留任务输出；`SUPERVISION.json` 保留内部观察；`RECEIPT.json` 是外层完整 supervisor 的 wait4 凭证。源文件开跑哈希及结束时是否保持一致写入凭证。长任务每类最多保留 2,048 条原始内存样本；超限后仍继续更新计数和峰值，且显式标记原始样本截断。

## CPU 与等待后的回收

专用 Linux supervisor 先设置并回读 child-subreaper，再启动实际任务。任务等待过的后代已经计入任务的 wait4；父进程提前退出后的普通 fork/exec 后代由 supervisor 收养并分别等待。内部收集的是互不重叠的子树。

对外费用使用**整个 supervisor 从启动到退出的外层 wait4 一次**，包括 Python 启动、task exec、后代、采样、输出排空、关闭和内部证据写入。内部 task／child／grandchild 的时间仅用于解释，不能再加到外层数值上。外层启动器的参数解析、CONFIG 写入和最终 RECEIPT 写入明确位于这个边界之外；本组件没有把这些未知开销冒称为零。

`complete_task_cpu_coverage` 要求 subreaper 已确认且全部可等待后代已收集。它只限定普通受控 fork/exec 任务，不证明恶意 clone/reparent 程序也不可逃逸。超时只杀死尚未回收的直接任务；若后代或继承的输出管道仍未结束，费用保留但覆盖失败。没有声称任意整棵进程树故障恢复完成。

## 内存与能量

继续使用原 v7 身份绑定 observer；执行前的专用小入口发出 proc/PID 身份，随后 exec 为真实命令。枚举的进程族和已登记集合分开报告。RSS 求和可能重复计算共享页，不是物理独占内存；采样峰值也不是连续原子峰值。

本轮环境依然缺少每线程 children 元数据，完整进程族内存保持 **null**。已有已登记集合读数不能替代这个结果。可观察 powercap、hwmon、drm 计数器目录均不存在；设备能量保持 **null**。同一机器的共享 cgroup 数值没有被用作任务专属内存或能量。

## 时延

工作进程先序列化并 flush 真实任务输出，然后读取单调时钟，再发出 `episode_output` 测量消息。消息含 `episode_id`、`source_monotonic_ns`、`output_flush_monotonic_ns`。supervisor 验证时间戳落在本次执行边界内，并保留自己的消息接收时刻。

因此 source-to-flush 是受信工作进程报告的输出时延，source-to-receive 是父进程直接观察的上界，两者明确区分。若消息在输出后还等待晚到工作排空，父接收时刻可明显较晚。没有这种合作式标记的模型命令仍有完整进程费用，但 episode 时延不可用，不能用进程壁钟替代。`task_success` 只表示任务进程成功并收集完毕；每个时延消息还须单独检查 `bounds_valid`，不能因任务成功就接受无效时钟。

## 已执行的证据

| 运行 | 外层 CPU 秒 | 外层壁钟秒 | 结论 |
| --- | ---: | ---: | --- |
| 最终 5 项行为检查 | 1.313090 | 2.434924 | 正常后代、收养后代、超时费用、时钟拒绝、缺失成本全部通过 |
| 正常父／子／孙 | 0.511664 | 1.268679 | 内部一次 wait4 含三进程，未重复相加 |
| 父提前退出后的后代 | 0.535916 | 1.242044 | 内部两次不重叠 wait4，全部后代回收 |
| 调度器实际双 episode | 0.585029 | 4.027416 | 正常与晚到路径均保留输出及排空成本 |

正常树三个进程各自报告 CPU 总和为 0.382183 秒，任务子树 wait4 为 0.407436 秒，外层为 0.511664 秒。收养树对应 0.402533／0.437228／0.535916 秒。进程初始化、测量与证据处理使外层更大，不能把三列相加。

调度器正常 episode 的 source-to-flush 为 2.233204 秒；晚到 episode 在 0.200857 秒输出，而其测量消息于 1.232704 秒被父观察到。晚到输出略超该夹具的 0.2 秒截止线，故 `timely=false` 且实际支付截止惩罚，不能称为按时完成。整个批次仍包含晚到工作的排空和关闭，不能只按 0.200857 秒记完整执行费用。精确动作与缓存归因见调度器探针本身。

`EVIDENCE_AUDIT.json` 重算了费用包含关系及费用边界。首轮源码和测试凭证保留在 `validation/source001`、`tests001`。独立审阅发现摊销输入中的保留键 `execution` 可能遮蔽未知成本；修复后，针对该边界的回归通过，外层费用为 0.150116 CPU 秒。审阅前源码已按冻结哈希逐一重建核对并保存在 `validation/source002`，最终源码见 `SOURCE_FREEZE.json`。重复测试只用于本次修复核查，不是新增模型样本。所有探针、两轮测试及针对性回归的 4.577549 CPU 秒是已计量开发执行小计，尚未计量的文件检查／审阅不属于这个数值，不能称整个项目的总费用。

## 实际模型运行与独立结果复核

最终冻结的计量器随后包住了两个实际模型批次，均成功收集全部普通可等待后代：

| 批次 | 外层 CPU 秒 | 外层壁钟秒 | 已测范围 |
| --- | ---: | ---: | --- |
| 历史 AV 共享头调度 | 16.068374 | 81.925233439 | 经验适配拟合、48 个逻辑重放和 8 个实时 episode，以及启动、记录、排空 |
| 合成机制开发 | 447.582388 | 1023.519430844 | 5 次 GRU／SSM 成对拟合、48 个世界上的 1,728 次运行及汇总 |

历史 AV 批次的 8 个输出时钟边界有效，source-to-flush 为 3.007787–3.045726 秒；这是恢复出的历史数据／共享头验证，没有新独立 AV 确认。该批次混合拟合、逻辑评估和实时输出，不能除以 8 作为部署每次推理费用。完整记录在 `../scheduler/validation/historical_cost001/` 和 `../scheduler/validation/historical001/`。

机制开发的七个阶段 CPU 小计为 427.898262 秒，已包含在外层 447.582388 秒内，不能再相加。单个阶段、拟合小计和外层费用的身份／包含关系已独立核对。该批次没有物理 episode 输出时钟标记；仿真逻辑截止时间不代表实机时延。两批次的完整部署进程族 RSS 和可归因设备能量仍为 null。

独立标准库审计从原始记录重建了 6,912 个输出、实际 READ 费用和全部选中参照对照；133,975 项原始检查及 532 项补充检查通过。两个条件的主口径 D−B 分别为 −0.008250 与 −0.001667，本次没有观察到正的解析核心增量。五次普通拟合复用每条件 24 个世界，不能扩成 120 个独立解析核心世界。详细解释、干预效应、成本凭证路径和 H 分摊见 [独立复核](review/MECHANISM_REVIEW.md) 与 [机器报告](review/REPORT.json)。这两次复核另计 0.905915 和 0.791645 CPU 秒，处于模型批次之外。

## H=20 与 H=10,000

`amortized_cpu` 接受明确列出的准备／训练／校准成本以及测得的执行批次成本。对每个 H 计算准备费用除 H，加实际每 episode 执行费用。任何必需项为 null，完整摊销结果仍为 null，同时给出已知项和缺失项；不会将缺失的训练、预处理或预训练成本替换为零。主口径 H=20 与敏感性 H=10,000 均保留。

尚未用本组件通过实际模型的质量约束经济性守门。新 AV、完整部署内存和直接设备能量仍需可用资产与测量环境。
