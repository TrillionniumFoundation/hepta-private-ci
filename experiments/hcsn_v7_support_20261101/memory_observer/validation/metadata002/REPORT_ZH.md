# HCSN v7：进程身份与内存观测修复

## 已执行结论

**当前环境已经验证正确的 PID 映射和自有父／子／孙三进程集合测量；完整进程族覆盖仍不可用。** 本模块没有运行候选模型，也没有修改或重算 v6 结果。不能将本次受控集合探针的成功写成生产进程族峰值守门通过。

最终 12 项安全测试通过。两次真实探针均验证了自有父／子／孙进程的合作握手、完整 starttime 身份和已触页内存。最终探针三次已登记集合 RSS 为 87,158,784–87,179,264 字节；完整自动族测量三次均为 unavailable，RSS 为 null。

## 修复了什么

`os.getpid()` / `Popen.pid` 是调用方 PID namespace 内的标识，不能直接拼接到当前挂载的 `/proc`。本轮从当前进程自身 `/proc/self` 得到挂载视图中的数字 PID，并验证 `NSpid`、`stat` 起始 tick、PPid 与直接路径一致。子进程必须通过调用方自己的 spawn 管道报告自身身份，再与真实 Popen 返回值及已知父身份绑定；孙进程沿同一方式逐边核验。没有全系统扫描、读取命令行/环境变量或检查无关进程内容。

每次 RSS 读取前后都重新验证 starttime、NSpid、父进程和 PID 一致；退出、复用、重新归属、缺权限或缺映射均返回 unavailable/null。重复进程不得重复加总。自动枚举在所有父线程的 children 文件上取并集，前后检查进程成员身份，支持孙及更深的子树并有数量上界。

## 实际触页验证

| 自有进程 | 申请并触页字节 | 观察到的 RSS 增量字节 | 触及页数 |
| --- | ---: | ---: | ---: |
| parent | 8,388,608 | 8,392,704 | 2,048 |
| child | 16,777,216 | 16,785,408 | 4,096 |
| grandchild | 25,165,824 | 25,169,920 | 6,144 |

三次采样的进程读取窗口为 0.688–1.069 毫秒。RSS 是顺序读取求和，不能称为原子快照；进程之间共享页面可能重复计入，不能作为 PSS 或物理唯一内存。短时峰值仍可能落在采样间隔之外。

原始记录同时保存了各进程的 `/proc` RSS 与自身 `getrusage` 高水位，以及对子/孙的 `wait4` 结果。不同计量器存在小幅数值差异，本报告不强制它们相等。父 `wait4` 的最大 RSS 是其等待子树中的最大单进程高水位，不能把它叫作同时进程族 RSS，也不能将各进程高水位相加。

## 尚未关闭的观测条件

当前环境虽然能读取自有 `/proc/<正确外层PID>/stat/status/statm`，却对真实 task ID 下的 `children` 文件返回 ENOENT。因此自动完整进程族枚举无法建立，模块诚实返回 null。

`sample_registered_set` 的范围始终标为 `registered_owned_process_set`，`full_descendant_coverage=false`。它适合调试已明确登记的受控进程集合；它无法发现未登记子进程，不能自动替代完整部署族峰值。

要验收完整族峰值，需要运行环境提供可读的自有子树枚举，或另行建立并审核覆盖全部实际 spawn 路径的受控进程注册合同。若采用注册合同，结果仍应明确声明该合同与可能逃逸的范围；未实现这一条件前，部署报告的完整族峰值继续保持 unavailable。专属 cgroup 若由运行环境正式提供，可另行验证其计量范围；本轮没有假定该能力存在。

## 测试与费用

最终 12 项测试覆盖 namespace 映射、括号进程名解析、PID 复用、NSpid 缺失、RSS 元数据缺失、PermissionError、僵尸进程、错误 spawn 边、重复成员、多线程 children 去重、数量上界、已登记集合不得被提升为完整族覆盖。

第一次版本的源码与凭证保存在 `validation/source001/` 和 `tests001/probe001`。随后补齐所有失败路径的覆盖标记，并增加缺权限与僵尸进程案例；第二次版本对应最终源码、`tests002/probe002` 和 `PROBE_REPORT_002.json`。旧探针没有被覆盖。

四个完整 worker 总 CPU 为 0.540920 秒，worker 壁钟之和为 0.897130 秒；包装器已测区间 CPU 单列为 0.002111605 秒。完整 worker 的 wait4 CPU 只计一次，内部父/子/孙 CPU 不再叠加。初始只读 shell 检查、源码编写、报告及打包不在这一费用总额内，不将它们记作零。

## 文件入口

- `process_memory.py`：独立标准库实现，无额外包或外网依赖。
- `probe_memory.py`：真实自有父／子／孙触页探针。
- `test_process_memory.py`：12 项故障与身份测试。
- `run_validation.py`：新进程完整费用凭证，拒绝覆盖已有输出目录。
- `PROBE_REPORT_002.json`、`HANDOFF.json`：最终结果及边界。
- `INITIAL_INSPECTION.json`：最初 children 路径读取失败与未包裹成本边界。

这是 Linux `/proc` 观测组件。本轮只在当前 CPU 环境完成上述验证，不声称已经接入尚未恢复的 HCSN v6 仓库或证明模型经济性改善。
