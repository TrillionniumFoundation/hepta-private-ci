# HCSN v7：进程身份与内存观测修复（003）

## 已执行结论

**当前环境已验证正确 PID 映射、已知存活成员守门和自有父／子／孙集合测量；完整进程族覆盖仍不可用。** 本组件没有运行候选模型，没有修改或重算 v6 结果，不能写成生产进程族峰值守门通过。

最终 19 项安全测试通过。三次版本的真实探针均完成；最终版本三次已登记集合 RSS 为 88,035,328–88,055,808 字节。完整自动族测量三次均为 unavailable，RSS 为 null。

## 003 修复的独立审查问题

前后两次枚举相等，仍可能稳定漏掉已知存活子进程。因此 `sample_family(root, required_members=...)` 现在先核验已登记 live Identity，并要求**第一次和第二次枚举都包含这些完整身份**，不仅检查 PID。空 children 列表不能掩盖实际仍存活的已知子／孙。

受控探针把父／子／孙三个身份全部传入 required_members；枚举结果还必须与这一受控集合精确一致。缺成员、身份错配或者多出非预期进程都会拒绝，不能设 `full_family_measurement_available=true`。原始失败仍保留，不把局部集合成功提升为完整族覆盖。

自有握手采用 `select` 与非阻塞、带缓冲的有界分行，每行最多 131,072 字节、最多等 10 秒；没有换成“select 后仍调用可能无限阻塞的 readline”。部分行不带换行也会超时。退出用有时限 wait4；必要清理只向自身尚未回收的直接 Popen 子进程发信号，子探针会尝试清理其自己的子进程。没有全系统扫描或 process-group kill。

### 清理与异常费用的边界

本轮实测的是正常父／子／孙退出与有界的直接子进程清理，**没有保证任意故障下完整子树都能回收**。每层清理的宽限时间有限；祖先可能在子层完成孙进程清理前发出 SIGKILL，极端内核阻塞也可能造成未回收。因此源码只作有界清理尝试，不能把有限等待写成强回收保证。

若异常探针在写出 JSON 前退出，外层 worker receipt 与日志会保留可观测的失败。该失败条件的内存以及完整后代成本必须标为不可得；在未完整回收后代时，不能把 wait4 记录提升为所有后代的完整费用。本次六个验证 worker 均正常完成，正常探针的子／孙 wait4 记录在原始报告内。

## 身份绑定与失败处理

`os.getpid()` / `Popen.pid` 不能直接拼接当前挂载的 `/proc`。模块从 `/proc/self` 得到挂载视图中的 PID，验证 NSpid、stat 起始 tick、PPid 和直接路径一致。子进程通过自有 spawn 管道报告身份，绑定真实 Popen 返回值、父身份和 namespace 链；孙进程逐边核验。

RSS 读取前后重新检查身份。退出、PID 复用、重新归属、缺权限、缺映射、僵尸、缺元数据均返回 unavailable/null。重复成员不重复计数。自动枚举合并全部自有线程的 children 列表，并有进程数上界。

## 最终实际触页验证

| 自有进程 | 申请并触页字节 | 观察 RSS 增量字节 | 触及页数 |
| --- | ---: | ---: | ---: |
| parent | 8,388,608 | 8,392,704 | 2,048 |
| child | 16,777,216 | 16,789,504 | 4,096 |
| grandchild | 25,165,824 | 25,174,016 | 6,144 |

三次顺序读取窗口为 0.860–1.055 毫秒。原始结果保留各进程 RSS、自身 getrusage 高水位、对子／孙 wait4 结果。不同计量器存在小幅数值差异，不强制它们相等。

RSS 和可能重复计入共享页，不能称 PSS 或物理唯一内存；多进程读数不是原子快照。wait4 子树高水位是最大单进程高水位，不能替代同时族 RSS，也不能将各进程高水位相加。

## 尚未关闭的完整覆盖条件

当前环境能读取自有 `/proc/<正确外层PID>/stat/status/statm`，但真实 task ID 的 children 文件返回 ENOENT，因此完整枚举无法建立。`sample_registered_set` 始终标为 `registered_owned_process_set` 且 `full_descendant_coverage=false`。

**两次枚举相等与 required_members 通过，仅说明采样窗口中已知存活成员和枚举一致。它们不能排除枚举之间出现又退出的短命后代，也不能证明未登记后代从不存在。** 即使在支持枚举的环境中得到一个有效样本，也不能把它称为持续完整物理峰值。

完整部署观测需要可读、自有子树枚举，或另行证明全部实际 spawn 路径都受控并已登记；后一方式必须明确注册合同与逃逸范围。当前完整族指标继续 unavailable。专属 cgroup 如由运行环境提供可另行核验，本轮没有假定该能力存在。

## 测试与费用

最终 19 项测试覆盖原 namespace／starttime／权限／僵尸／去重／边界条件，并新增稳定空枚举漏已知子进程、漏孙进程、必需身份错配、第二次枚举漏孙、受控集合额外成员、部分握手超时、自有阻塞子进程有界清理。

第一次源码留在 `validation/source001/`，第二次留在 `validation/source002/`；旧报告／交接／清单留在 `validation/metadata002/`。所有 001、002 凭证、原始探针与旧 ZIP 均未覆盖。最终凭证为 `validation/tests003/` 与 `validation/probe003/`，最终原始探针为 `PROBE_REPORT_003.json`。

六个完整 worker CPU 合计 **0.898548 秒**，worker 壁钟之和 **1.409140 秒**；包装器已测区间 CPU **0.003037708 秒**单列。内部父／子／孙 CPU 不再加到完整 worker。初始 shell 检查、写源、报告与打包不在这项总额内，不记作零。

## 文件入口

- `process_memory.py`：Linux /proc 标准库观测模块。
- `probe_memory.py`：有界自有父／子／孙触页探针与精确集合守门。
- `test_process_memory.py`：最终 19 项测试。
- `run_validation.py`：新进程完整费用凭证，拒绝覆盖已有目录。
- `PROBE_REPORT_003.json`、`HANDOFF.json`：当前结果与覆盖限制。
- `INITIAL_INSPECTION.json`：最初 children 读取失败及未包裹费用边界。

本轮未接入尚未恢复的 HCSN v6 仓库，也没有证明模型经济性改善。代码已在 003 验证后冻结，供主代理独立审阅、组装与持久保存。
