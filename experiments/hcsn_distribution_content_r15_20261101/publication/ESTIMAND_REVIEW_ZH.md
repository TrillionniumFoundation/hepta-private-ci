# 四格效应与共享控制器的源码口径复核

## 结论

本次注册的“独立训练四格总效应”成立的具体含义是：**在固定的六模型联合训练方案、共同训练数据、组级验证选择和既定执行规则下，比较 core × value 程序的四个单元格。** light 与 value 分别运行独立优化器、保存独立训练组 checkpoint；组内六个架构共同参与优化与梯度裁剪，并在同一个选中 step 保存。value 组还共同训练一个控制器。

因此，这些差值适用于这套已登记程序。它们不能扩张为“每个架构分别独自训练完整系统”的普适因果总效应，也不能据此预测移除或替换联合训练组中其他成员后会得到相同差值。

**D−B 仍然是在同一 task/seed 的同一控制器参数下，对两个分别训练出的内容系统所作的配对比较。** 这一控制器参数相同的事实，不要求两个模型产生相同的特征、Q 值、读取次数或停止动作。

本复核只阅读源码，没有读取正式训练结果、确认数组或测试集，也没有改动冻结科学源码。

## 1. 训练组的实际构成

[campaign.py](../campaign.py) 的 `train()` 在每个 task/seed/train_mode 调用中创建六个模型对象和一个 `ValueController`。内容参数按模型对象分别持有；每个模型拥有自己的 encoder、core 和 readout。

该调用把六个模型的参数拼入一个 `parameters` 列表。value 模式再把唯一控制器的参数加入这个列表，随后创建一个 `torch.optim.Adam`。light 模式不把控制器参数加入优化器。每次更新对六个模型使用同一批对象，平均六项模型损失，执行一次反向传播，再对完整参数列表调用一次 `clip_grad_norm_`。

light 与 value 的独立性体现在两个不同的 `train()` 调用、不同的优化器对象、独立的参数演化及不同的 checkpoint 文件。配对的 family/seed 从相同初始化出发，批次抽样规则和预算相同。这一独立性描述训练程序的分离，不能解释成四个单元格在统计上彼此独立。

同一 Adam 对不同参数维护各自的优化状态。这里实际使架构之间产生组内依赖的机制包括：

- **全组梯度裁剪。** 裁剪系数由所有模型的梯度共同决定；value 模式还包括控制器梯度。一个成员的梯度范数可以影响其他成员的更新缩放。
- **共同训练控制器。** value 模式下，六个模型产生的 Q 损失都更新同一控制器；该控制器又参与各内容模型的当前 Q 预测分支。
- **组级选择 checkpoint。** `validate()` 使用六个模型在相应执行模式下的平均验证效用。选择某个 step 时，一并选择该 step 的全部模型及控制器；没有为每个架构单独选择自己的最佳 step。

这些因素已经属于冻结程序。它们不需要事后修正或从对比中扣除，但必须保留在结果的适用范围中。

## 2. 当前 Q 预测有梯度，目标与贪心后继分支断梯度

实际调用的是继承的 [engine.py](../../hcsn_validation_r14_20261101/content/engine.py) 中 `ValueController.forward()`、`policy_values()` 与 `realized_returns()`。当前路径里没有把 policy features 统一 detach 的辅助函数。

| 分支 | 源码行为 | 解释 |
| --- | --- | --- |
| 当前 Q 预测 | `policy_values(controller, logits, dt)` 直接把 logits 传给控制器；控制器由 softmax 概率、熵、前两类概率差和公开时间／价格特征构成输入 | 当前 Q 预测保留通向 logits 的 autograd 路径 |
| 目标策略副本 | `target_q = q.detach().clone()` | 构造目标后继动作时，不通过当前 Q 副本反传 |
| 目标 STOP 正确性 | `logits.detach().argmax(...) == labels` | 样本路径正确性作为目标，不通过 argmax 分支反传 |
| 目标贪心后继 | `values.detach()[..., 1] > values.detach()[..., 0]` | 后续 READ/STOP 的离散目标选择不反传 |
| Q 损失 | 当前 `q` 与上述目标比较，加入模型损失 | Q-MSE 同时能够更新控制器和当前内容模型的 encoder/core/readout |

因此，不应写成“特征已 detach，所以价值损失只训练控制器”。准确说法是：**目标及离散后继选择断梯度，当前 Q 预测分支保留梯度。**

light 训练使用末端交叉熵。value 训练增加前缀交叉熵和合法动作 Q-MSE，二者登记系数均为 0.2，并启用控制器执行。前 128 次更新的目标后继采用 read-all warmup，随后采用当前贪心控制器。因此，B−A 和 D−C 包含这套训练目标、共同控制器、组内裁剪、组级选择和执行方式的程序变化，不能单独归因于“仅增加一个停止控制器”。

标签和后续观察用于训练损失与样本路径目标。运行时控制器的输入仍是当前已取得前缀产生的预测特征，以及协议公开的完整时间表、剩余预算和价格。保留 Q 分支的梯度与运行时是否读到标签是两个不同问题。

## 3. D−B 的共享控制器事实

[evaluate.py](../evaluate.py) 的 `evaluate_group()` 从 value 组的选中 checkpoint 加载一次控制器，在遍历所有 family 时复用这一对象，并对 value 执行记录同一个 `controller_hash`。

全对象实际执行附加程序 [online_confirm.py](../online_confirm.py) 同样从同一训练组 checkpoint 加载控制器，将其 hash 与训练摘要及每个原评估条件核对，再用于各 family 的实际执行。该过程没有针对不同架构重训或替换控制器。

所以 D−B 的可核验表述是：

> 在同一 task/seed 的 value 联合训练组内，两个内容系统使用同一组选中控制器参数、同一任务对象和同一费用规则执行，其效用差构成配对系统比较。两个内容系统及其 encoder/readout 是各自训练所得；控制器接收的预测特征和实际动作可以不同。

“同控制器”限于该 task/seed 配对；不同 task 或不同 fit seed 各有自己的控制器。此事实不证明解析传播机制在任意控制器、单独训练环境或其他训练预算下都具有相同收益。

## 4. 保留原注册 contrast 名称，紧邻解释范围

| 原注册单元格／contrast | 本次程序内的含义 |
| --- | --- |
| A | ordinary_distribution：light 训练、完整读取执行 |
| B | ordinary_distribution：value 训练、价值控制执行 |
| C | analytic_distribution：light 训练、完整读取执行 |
| D | analytic_distribution：value 训练、价值控制执行 |
| `B-A` | 普通核心在两套已登记训练与执行程序之间的差 |
| `D-C` | 解析核心在两套已登记训练与执行程序之间的差 |
| `C-A` | light 联合训练程序内，两个已训练内容系统的差 |
| `D-B` | value 联合训练程序内，同控制器参数下两个已训练内容系统的差 |
| `interaction` | `(D-C)-(B-A)`，即当前联合训练方案中的交互差 |

冻结分析中的 `independent_training_total_effect` 及附加实际执行中的 `actual_online_independent_training_total_effect` 名称均保持原样。建议在每个相关表格或结果段紧邻加入：

> **适用范围：** 本表的“独立训练总效应”指已登记六模型联合训练方案内的 core × value 程序单元格差。light 与 value 分别拟合独立优化器和整组 checkpoint；每组使用全参数梯度裁剪和六模型平均验证效用共同选择 step，value 组还共同训练并使用同一控制器。D−B 是同一 task/seed、同一控制器参数下的配对系统差。本表不建立各架构独自训练完整系统的普适因果效应。

同权重执行对照继续单列：其中用于完整读取的 A、C 来自 value 训练后的同一组权重，只改变执行方式。它不替代上述独立 light/value 程序差，也不能用来填补独立训练单元格。

## 5. 对区间和推广的影响

八个 fit seed 的对比使用同一 task/domain 中配对的单元格差；不能把六个联合训练成员当成六个独立训练重复。配对 t95 描述这套既定训练方案在这些 fit seed 下的变化，不消除联合训练依赖，也不把有限任务、固定成员集合和固定预算上的差值提升为跨架构或跨任务的普遍结论。

本复核只限定估计量的含义，不改变任何注册 contrast、统计公式、确认数据、checkpoint 或验收阈值。
