# V14 独立审查终态

## 工程验收

同一组源码在普通 Python 和 `python -O` 下各通过 **23/23** 项测试。四个源码文件的运行前后 SHA256 一致，两次运行使用的版本也一致。普通模式耗时 79.349 秒，优化模式耗时 81.018 秒；该耗时包含持久化测试，不属于神经网络或目标硬件性能结论。

测试源码已按可独立审阅阶段拆分：`test_boundary.py` 和 `test_runtime.py`。原始日志、命令、退出码、源码散列及耗时在 `FINAL_TEST_NORMAL.json`、`FINAL_TEST_OPTIMIZED.json` 与对应 stderr 日志中。

- 拒绝超出获取窗口、倒序、重复时间点、非有限特征及失败输入夹带内容。
- 检查冻结来源、编码器、时钟、特征维度、录制群体与跨会话隔离。
- 验证调用者修改原始文档、暴露的来源字典或 receipt 不会改变冻结输入及执行限额。
- 拒绝相同 READ ID 下不同窗口、模态、费用或结果；重试保持费用和核心状态不变。
- 验证保守来源释放时间、RESET 后延迟结果拒绝、内容保留与 RESET 幂等。
- 在独立子进程中，写入新的接受快照后、SQLite 执行 COMMIT 前立即退出。重启恢复为已签发待处理 READ、一次收费、零已接受内容和初始核心；重新完成后再次重启状态一致。
- 首条内容经过 **1,024 次**后续读取仍能按地址输出原文本和完整引用，并通过进程重开恢复。全部 1,025 个包均明确为合成工程样例。
- 内容容量和操作数量耗尽、持久化快照损坏、输入／模型／预算变更均拒绝。
- 实际文件读取检查散列、大小与路径边界；修改冻结文件后拒绝。

## 本轮审查发现与修复

已检查来源字典的深拷贝、跨 world 对齐、返回 receipt 的身份隔离、严格 Packet 类型、显式来源到到达时钟映射、构造失败关闭 SQLite 等修复。审查还发现工程重放原来仅使用可变 PLAN.json 约束 TRAIN 数据的问题；现已将 PLAN 固定到已认证候选与 roster，按同一份内存字节核验和解析 TRAIN。

针对 PLAN 的复核使用实际候选核验函数和实际 context 函数 AST 的依赖隔离执行：原候选通过；修改合法 JSON 的 PLAN 字节被拒绝；原 PLAN 下修改 TRAIN 在 NPZ 解析前被拒绝。该复核没有运行神经前向，详情见 `V14_PLAN_ANCHOR_PROBE.json`。

原 V13 的 `freeze()` 使用 assert。独立探针证明优化模式会跳过五类校验；历史源码和结果保留，新路径直接核验已发布 roster、PLAN、源码、模型及归一化字节，所有新边界测试也在优化模式通过。

## 保留的资格限制

实际 V13Core 仍仅消费音频／视频 row55；文本和图像目前完成通用输入与精确内容存储机制覆盖。地址读取并未建立语义检索或学习式实体绑定能力。声明的来源身份、时钟和 SHA 不能自行证明真实新录制、完整历史排除或预训练无污染。

本次审查没有执行真实 Encoder、神经数值前向或目标 GPU 性能；没有证明外部 I/O 恰好执行一次、跨机器接管或完整设备成本。完整快照持久化的时延和资源占用也需单独测量。`all_blockers_closed=false`、`production_activation=false`。
