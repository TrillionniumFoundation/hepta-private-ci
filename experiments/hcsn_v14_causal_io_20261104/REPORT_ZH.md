## 3. 统一输入与可恢复内容状态

`boundary.py` 为 text／audio／video／image 定义共同 Packet。每个包携带实际采样窗口、严格递增采样时间、来源与 Encoder 标识、特征维数，以及 `ok / missing / corrupt / unsupported / ood / denied / unknown / timeout` 状态。非有限特征、越过接受窗口的采样、错误来源、错误维度、失败状态夹带内容均被拒绝。来源配置采用深拷贝，实际文件读取检查大小、散列和路径边界。

可见性使用 `release_offset_ns + end_ns + sync_uncertainty_ns` 的保守释放界。它依赖可信的时钟标定；软件没有通过 Packet 声明自行测量物理同步。`aligned` 检查的是声明的来源／会话／世界和时间兼容性，不是模型学会了说话人、物体或语义实体身份。来源 ID 不应进入学习策略的特征。

`runtime.py` 用 SQLite 将纯核心转移、获得的内容和完成凭据一起提交。READ 在签发时收费一次；相同 ID 重试必须保留相同请求和结果。接受提交前崩溃会保留待处理 READ，恢复后不重复收费。外部 I/O 必须复用同一 read ID；该机制未证明跨系统调用本身恰好执行一次。

RESET 清除递归核心、递增 epoch、取消待处理 READ，并拒绝旧 epoch 的迟到结果；保留已接受内容、来源前沿与各来源 watermark。后续 `dt` 从保留的来源前沿计算。这是明确的外部控制语义，不是连续物理时间 RESET 定理，也不等同于原 HX 内部阈值／不应期转移。

按地址查询返回已获取的原文本及来源、时间、内容散列引用，未获取则返回 unknown。**这还不是从真实音频／视频识别内容后回答语义问题。** 目前文本／图像只完成通用 Packet 和内容存储机制覆盖；实际 `V13Core` 仍仅接受原音视频 55 维行，并拒绝不兼容的文本、图像或 1536 维描述符，没有通过任意 reshape 冒充接入。

原模型六行读出窗口保持为六行；更长回放时持续保存真实隐藏状态／膜状态／冷却状态。地址存储与递归状态是两个显式机制，不能把地址表的长期保留计入核心的长程记忆优势。完整快照式持久化还会随历史增长产生高累计成本，本实现没有生产吞吐或压缩率声明。

## 4. 实际测试与原始证据

### 4.1 对抗性工程检查

独立测试在普通 Python 与 `python -O` 下均 **23/23 通过**，运行前后源码 SHA256 完全一致。普通模式 79.349 秒，优化模式 81.018 秒；这些是持久化工程测试耗时，不是神经推理性能。

测试包含四种模态、缺测／失败状态、时钟与未来数据拒绝、调用者修改输入／凭据、幂等收费、容量耗尽、损坏快照和身份变化。真实子进程在 SQLite 接受 COMMIT 前立即退出，恢复后待处理状态和费用保持一致。首条合成文本在 **1,024 次后续 READ** 后及重新打开数据库后仍可精确查回。1,025 个包都明确为合成工程样例，不能计入独立世界或真实长程问答样本量。

审查还复现了原 V13 `freeze()` 的 assert 校验在优化模式下被跳过的五类情形。新路径显式核验冻结候选 roster、PLAN、源码、权重和归一化字节；测试也覆盖优化模式。这是历史验证器的风险证据，不足以断言历史运行实际遭受污染。

### 4.2 三种真实旧检查点回放

按执行前协议使用原第一声明种子 13301、原 `async_av-TRAIN.npz` 第 0 条序列、CPU 单线程、FP64、确定性算法。没有新增训练，没有从本轮结果中选种子或模型。

| 家族 | 模型参数总数（张量元素计数） | 六个前缀与原直接 forward 的最大绝对差 | 新进程恢复待处理 READ | RESET 迟到拒绝／新状态一致 | 连续执行 |
|---|---:|---:|---|---|---:|
| HX | 31,430 | 0.0 | 通过 | 通过／通过 | 128 步 |
| GRU | 32,550 | 0.0 | 通过 | 通过／通过 | 128 步 |
| SSM | 29,382 | 0.0 | 通过 | 通过／通过 | 128 步 |

128 步由相同六行历史特征按每轮 3 秒平移重复形成，是合成时间变换。它检验可运行状态持续性、存储和执行边界，不是 128 步新世界准确率。三模型都保持六行读出窗口，各产生 128 次收费、128 项内容，内容负载各为 166,273 字节；这些数字不是进程内存峰值。回放中的 AV Packet.content 为空，模型输出是六类概率，没有输出音视频转写或语义答案。六前缀零差是与同一原实现的兼容性结果，不是独立数学实现的验证。

实际恢复测试在接受三个 READ 后留下第四个 pending，再由新 Python 进程加载并完成；RESET 的新状态还与相同来源时间间隔下的全新核心比较。运行后没有改动执行源码。
