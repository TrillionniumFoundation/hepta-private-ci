# First-passage clock learning: frozen confirmation, 2026-10-30

This research package fixes numerically unstable first-passage formulas, learns
the physical clock from explicit event observations, and evaluates the fitted
models in a continuing control task. It preserves the earlier adaptive studies
and their results. It does not activate a production DecisionCell.

**Outcome:** the declared numerical and observation-contract checks pass. The
new likelihood training succeeds without selected FPT parameters hitting their
bounds. The frozen confirmation does **not** establish a utility advantage over
both strong hazard baselines. Out-of-distribution confirmation does not establish
that advantage either. These are completed negative/inconclusive comparisons,
not a reason to retune on the same confirmation seeds.

## Frozen experiment and result

The source, protocol, and complete trained bundle were published in commit
`0878c82563e2b2a5b483fe9d3777c2e75964d6a1` before either confirmation split was
generated. `RUN_METADATA.json` records their execution times and environment.
The executable gate checks byte equality of the four critical files and the
trained bundle against the named Git commit before generating data.

There are five independent training seeds. Each model uses 256 labelled training
contracts per class, two classes, six fitted parameters, three neutral starts per
class, and the same maximum optimizer iterations. All 90 optimizer runs report
convergence; all ten selected FPT class fits lie strictly inside their declared
parameter bounds. This is optimizer and finite-sample evidence, not a global
optimization theorem.

The baselines are cured Weibull and cured log-logistic distributions. Each has an
estimated eventual-event probability, shape, and scale for each class, including
proper no-hit mass. They receive the same observed information, training data,
context, and decision controller. Actual compute differs and is recorded.

Each confirmation split contains 512 paired episodes per training seed: 2,560
distinct episodes and 7,680 model rollouts. Five training replications, not 2,560
episodes, determine the reported uncertainty across learned models. The intervals
are Bonferroni simultaneous 95% intervals for the two contrasts within a split.

FPT has lower mean held-out event NLL in these synthetic runs, but this does not
translate into an established utility advantage. It also consumes more of the
declared task resources than either baseline on average; no energy-saving claim
follows. The IID data are generated by an FPT model and therefore favor its
correct specification. OOD introduces a hidden per-contract clock mixture and
tighter time costs/deadline. Neither split establishes external-task or SNN
generalization. All controllers improve on immediate STOP in the observed mean;
that alone does not establish a special benefit of the FPT family.

## Observation and continuing-task contract

The active process is `dX = mu dt + sigma dW`, with a fixed upper barrier at
distance `d > 0` and independent cancellation rate `lambda`. Every WAIT explicitly
starts a new independent reset contract. A hit returns its exact time if it occurs
before cancellation and the chosen horizon. Otherwise the observer returns
`no_hit` at the horizon. Hidden cancellation never releases the task early and
never becomes a policy input.

The observation likelihood is:

- `hit` at time `t`: `exp(-lambda*t) * f(t)`, a density.
- `no_hit` at horizon `T`: `1 - H_lambda(T)`, including hidden cancellation.
- An observer that actually sees both event channels instead uses `survive` with
  mass `exp(-lambda*T) * S(T)` and `cancel` with density
  `lambda * exp(-lambda*t) * S(t)`.

The simulator uses independent Wald and exponential draws, not the candidate CDF.
The common controller compares STOP with several WAIT horizons using one-step
expected terminal utility, then updates its posterior and replans. Costs include
queries, actual elapsed task time, and observed hits. There is a hard deadline
and maximum query count. This is a real continuing decision loop with a limited
lookahead policy, not a globally optimal Bellman solution.

## What the mathematical checks establish

`NUMERICS_AND_STABILITY.md` gives the stable formulas, finite-time parameter
scores, and conditional projected-gradient/SGD bounds. The numerical gate uses
an independent 100-digit Decimal implementation with guard digits, original
positive density integrals, and exact-law physical draws.

- 67 parameter cases and 946 checks pass.
- 12 kernel regressions and six task-contract tests pass.
- Twelve independent positive-integral cases and three physical sampler cases
  with 120,000 draws each pass their declared tests.
- The seven first-run failures remain in `INITIAL_NUMERICAL_FAILURES.json.gz`.
  The corrected run is `NUMERICAL_VALIDATION.json.gz`.

The tests include `sigma = 1e-8`, the sub-ULP shift in the tilted drift near exact
arrival, rare cancellation boundary layers, log survival near -4909.94, and the
zero-rate and initial-boundary cases. Tiny-cancellation mass uses a documented,
bounded approximation; it is not falsely labelled an exact expression.

`IDENTIFIABILITY.md` proves that known-distance, calibrated-time unconditional
hit densities together with no-hit counts identify the three physical parameters.
Conditioning on hits loses an exact parameter direction; an unknown voltage scale
also leaves a symmetry. In this design, multiple finite horizons with binary
hit/no-hit already supply local full-rank information. Exact hit times add
information; they are not the sole source of identifiability.

The log-coordinate Fisher eigenvalues at the declared reference point are:

| Observation | Eigenvalues | Rank |
|---|---|---:|
| Hit times and no-hit, per started contract | 0.034841, 0.349751, 1.359554 | 3 |
| Binary outcomes at four finite horizons | 0.007602, 0.150627, 0.631146 | 3 |
| Times conditional on hits | approximately 0, 0.179389, 2.994925 | 2 |

These deterministic diagnostics use the candidate kernel and are distinct from
the independent numerical oracle. Structural identifiability and a local
stationarity/strong-convexity argument do not prove global SNN convergence.

## Relation to the original proposal and native Hepta owner

A stationary exponential shape is an occupation measure, not a transition
kernel or a finite-horizon hit density. Killing, discounting, renewal/reset, and
a resource shadow price are different operators. Increasing a killing rate
reduces this contract's hit probability; increasing a reset rate can increase
long-run firing. The package retains those distinctions.

The connection to [He and Xiong's rollover model](https://www.princeton.edu/~wxiong/papers/rollover.pdf)
is a constant-coefficient/resolvent analogy, not an exact transformation of OU
leakage into Poisson loss. The regularity results in
[Qi's Hölder Q-learning paper](https://proceedings.mlr.press/v336/qi26a.html) do not
by themselves prove convergence of a hard-spike network or smooth fit at a fixed
one-touch barrier. A later Spiking Q experiment must supply its own generator,
boundary/renewal law, loss, meta-gradient, and validation.

The separate `../first_passage_owner_v2/` package links the unchanged native
`NeuronRuntime` and adds explicit state-adoption, atomic result/credit settlement,
price admission, and fail-closed recovery. Its process evidence is separate from
this synthetic task study. This study does not execute its entire policy inside
the native owner and does not claim signed NDU/organ-credit or production CNS
activation. The owner contract documents its lower-barrier coordinate convention;
the kernel here uses distance to an upper barrier.

## Reproduction and evidence

Python requires NumPy and SciPy. The recorded versions are in `RUN_METADATA.json`.
From the repository root:

```bash
python -m unittest experiments.first_passage_clock_v1.kernel_tests experiments.first_passage_clock_v1.task_tests
python -m experiments.first_passage_clock_v1.validation --output /tmp/fpt-numerical-reproduction.json
python -m experiments.first_passage_clock_v1.identifiability
python -m experiments.first_passage_clock_v1.verify_evidence
python -m experiments.first_passage_clock_v1.report_results
```

The report command only reads existing results; it never draws new data. Full
per-episode results are losslessly compressed with deterministic gzip. The
uncompressed and archive SHA-256 hashes are in `EVIDENCE_MANIFEST.json`.
`RESULTS_SUMMARY.json` is the compact machine-readable result.

To reproduce the existing confirmation, use the committed bundle and explicit
freeze SHA with the `task_study --phase confirm` or `--phase ood` command in
`RUN_METADATA.json`, writing to a fresh output path. That reproduces the same
holdout; it is not a new independent confirmation. A change to the critical
source, protocol, or trained bundle requires a new protocol and fresh seed
namespaces before making a new scientific comparison.
