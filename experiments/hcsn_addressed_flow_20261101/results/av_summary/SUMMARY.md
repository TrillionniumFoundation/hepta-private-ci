这里的句子识别只有DFA/IOM两种已知句子。句子身份是训练时额外提供的辅助监督，所有核心共享同一前端，不能将提升归因于解析动力学。基分类器按演员交叉拟合；校准器使用全部训练交叉预测与标签，校准步骤本身没有再次嵌套交叉拟合。
句子识别率与最终一致性任务准确率是不同指标。最终一致性任务中，三个单模态头都为50%；独立训练的音频＋视频头为50%／50%，视频＋文字头为52.431%／50%（八演员／1019）。乘积规则使用条件独立假设构造，并不是共享演员、情绪等干扰下已证明正确的联合后验。
视频识别仍接近机会水平，未达到90%门槛。完整学习关系头在两组上的分类准确率都与去掉视频后的独立关系头相同。八演员的乘积规则仅增加0.174个百分点；1019为0。1019的完整学习头Brier比去视频头低约0.0027，但这是一个演员上的描述性概率评分差，不能证明稳定视频收益。
冻结规则还要求音频识别至少90%、完整乘积规则的演员bootstrap 95%下界超过5/6；八演员音频81.25%也未达标，两组完整点估计本身都未超过5/6。1019只作单演员点估计，不能用旧引擎的退化区间建立总体合格结论。
该加权组合任务的任意两模态信息上界为5/6=83.333%；目前完整三模态结果没有超过这一界限，不能以“高于50%”代替三模态绑定验收。全部八种模态子集结果保留在原始确认文件中。

开发负结果也保留：初轮宽视野时序视频与最终嘴部运动候选的验证识别率均为56.944%；固定DTW候选为45.833%。最终只冻结预定候选集内的训练／验证选择结果，没有依据上述确认结果再改模型。

## 4. 成本、驻留与时延

相同编码器参数由全部核心共享；共享编码器驻留数组共**1,423,056字节**，其中视频RBF含257个支持向量、每个684维。该数字不包括Python/库运行时、解码器和临时矩阵。核心参数量依次为Flow10,770、diagonal10,845、GRU23,938、Transformer15,386、MLP290。

逐个验证15份冻结state_dict的SHA和dtype后，Flow／diagonal／GRU／Transformer／MLP参数张量分别为43,080／43,380／95,752／61,544／1,160字节；这不是运行时进程驻留增量。完整确认子进程的峰值RSS分别为292,421,632字节和293,072,896字节，包含框架和工作缓冲，不能当成单个核心的增量内存。Transformer报告的384个状态标量只是概念KV规模，本实现仍重算前缀。

| 核心 | 八演员 batch1 / batch24 核心时延(ms) | 1019 batch1 / batch24 核心时延(ms) |
|---|---:|---:|
| flow | 3.639 / 4.955 | 2.709 / 3.369 |
| diagonal | 0.501 / 0.669 | 0.511 / 0.639 |
| gru | 0.538 / 0.760 | 0.449 / 0.702 |
| transformer | 0.555 / 0.854 | 0.501 / 0.810 |
| mlp | 0.414 / 0.394 | 0.332 / 0.341 |

表中核心时延为每个种子9次重复的中位数，再对三个种子平均。前端另作31次重复：八演员已提取特征上的batch1中位数为0.125ms，batch384为6.040ms（约63,576 episodes/s）；1019的batch1为0.125ms，batch48为0.594ms（约80,816 episodes/s）。这些微基准不包含媒体获取／解码／特征提取，也不能与不同batch的数字直接相加。
**完整一秒接受前缀是所有输入的前提。** 三个模态token的零时间顺序只是计算次序；离线解码读取完整文件。本实验没有测量流式采集到输出的端到端实时延迟。

15个核心训练的完整子进程CPU为**53.529秒**；其内部阶段计时51.203秒已包含在内，不重复相加。原20次探针、41次初轮与52次最终候选开发、两轮特征准备和子集关系头的已记录开发主体CPU合计**160.549秒**。两组下载共35,477,081字节，下载主体CPU合计0.557秒，分别耗时8.491和1.274秒。

完整子进程训练＋确认计时合计154.887CPU秒；再加明确分列的开发主体和下载主体计时，已记录、互不重叠的CPU合计315.994秒。开发早期导入/失败路径开销与继承特征缓存的历史创建成本未完全重测，不能把这一已观测合计称为全系统完整经济成本。能耗仍为null，没有GPU结果，也没有将CPU秒换算成焦耳。
