# 缺测训练、概率校准与拒答：新确认结果

本轮保留 PR #4548 的两类 typed addressed 架构，完成 **18 个全新最终检查点**，并与18个历史 base-only 最终检查点在相同新世界上比较。两个核心都在本轮全部已知答案查询上达到100%，基础及128步干扰条件的四查询全对率也全部100%。缺测下的概率评分得到稳定改善，但**可靠拒答的准确率与覆盖率联合门未通过**，不能宣布缺测问题全部闭合或解析核心胜出。

## 拒答联合门仍然失败

预注册要求接收答案准确率至少95%，并且已知答案接收覆盖率至少80%。**72条新模型条件记录中有27条未同时满足这两项。** 拒答全部查询没有被计为通过。

- Flow 的 MQAR 缺测条件，种子17/43接收答案准确率分别93.9904%/94.5995%，虽然已知答案覆盖均100%，仍未通过95%门。种子17的缺测加128干扰也未通过。
- Selective 的 Flow 三个种子在所有条件都拒答全部查询，已知答案覆盖为0。
- Selective 的 Diagonal 种子17/29全部拒答；种子43在缺测条件的已知答案覆盖仅42.9499%，接收答案准确率93.8144%；基础覆盖39.5508%，长干扰条件也全部拒答。
- MQAR 的 Diagonal，以及 Binding 的两核心，本轮登记条件内满足相应准确率与覆盖要求。这不抵消其余失败记录。

开发期 Wilson 下界仅用于扫描固定阈值的启发式选择。同一episode内四查询相关，且开发标签重复用于阈值选择，**该下界不是95%总体可靠性证明**。本报告只给确认期实际点估计和三个拟合的可见差异。

## 成本与当前结论

训练阶段已测下界为 **508.724287 CPU秒**，包括父进程阶段计时和已等待的三个worker；初始父进程导入未外层计量，完整训练成本仍为null。校准与确认分别由外层wait4完整子进程计量，得到 **20.068745 / 127.874395 CPU秒**，包括启动、导入与写入。三阶段合计已测下界 **656.667427 CPU秒**，没有重复相加嵌套fit计时。开发、历史准备、环境安装、恢复和发布仍有未计量项；能耗保持null。

历史参照的训练流与本轮新训练流不同，运行时也由原PyTorch2.9变为当前2.6，因此这是候选修订对历史基线的比较，不能把所有变化严格归因为缺测监督这一单独因素。显式WRITE/BRIDGE类型、四地址、八值和符号跨模态关系仍在；没有未知生成器、开放域内容或真实视频增量资格。本轮也没有价值控制完整四格、等质量完整成本前沿或解析核心独立净收益证据。

下一项实质问题是Selective中的过期内容与隐含缺失地址：单一全局温度和阈值不能在该任务同时保住可靠性与覆盖。当前保存改进与失败原样，`all_blockers_closed=false`、`production_activation=false`。

开发因果检查中，两核心首查询与仅前缀执行、合法未来后缀替换的logits完全一致。一次使用非法Gaussian事件类型的夹具先被输入契约拒绝，失败和修正记在 `DEVELOPMENT_CHECK_FAILURE001.json`；没有修改科学源、模型或确认结果。
