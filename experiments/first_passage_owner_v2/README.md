# First-passage owner adoption V2

This is an **unactivated Linux research executable**, composed with the repository's
real `codex-hepta-neuron::NeuronRuntime`. It closes the research bridge's concurrent
owner, partial-publication, immutable-configuration, duplicate-settlement, and
observation/credit atomicity gaps. It does not activate production DecisionCells,
TaskFlow, authenticated Organ Credit, or an NDU parameter-selection service.
Every response retains `authority: DENY_ALL` and `production_activation: false`.

## Verified result

The final revision passes **10 Rust contract tests through `just test` and 21
separate-process integration tests**. The latter execute actual native ticks and
bounded local-file reads, including **9 real SIGKILLs**, a live competing process,
cold-process replay, cancellation in refractory holding, corrupted records,
dangling links, FIFO rejection, and immutable model/clock checks. Tests also cover
zero-time WAIT, fractional accounting, idle-time partitioning, and identical read
admission with or without an explicit WAIT at the same physical endpoint.

`evidence/BUILD_REPORT.json` binds all compiled owner sources, the Cargo lock,
65 unchanged native source/manifest/toolchain files, compiler version, command
outputs, and binary SHA-256. `evidence/PROCESS_QUALIFICATION.json` contains the
individual subprocess requests, exit statuses, outputs, and signals against that
same binary. `MANIFEST.json` additionally binds the deliverable files. Final
formatting is checked against the compiled source digests; it did not change them.

Earlier counterexamples are retained. `INITIAL_FAILURE.json` records the genuine
first-bootstrap/prepared recovery failure. `COUNTEREXAMPLES_BEFORE_FIX.json`
records the initial credit projection/admission ordering bug and a hit accepted
at the exact refractory-release instant. Their outcomes are superseded by the
final tests; earlier passing test counts are not final qualification.

## What owns which state

| Layer | Responsibility |
| --- | --- |
| Trusted observation producer | Supply the physical FPT checkpoint, event times, sampled cancellation clock, numeric features, model artifact and NDU receipt identities. |
| `contract.rs` | Validate full typed state, phase continuation, clocks, event order, immutable run configuration and parameter identity. |
| Original `NeuronRuntime` | Own sparse neural state, native journal and witness; execute the real numeric model port. |
| `engine.rs` and `store.rs` | Hold one OS file lock across adoption, native tick, read, and atomic settlement publication. |
| `settlement.rs` | Store the request, native anchor, observation, attempts, budget, and all resource-price fields in one immutable record; validate them together on restart. |

The coordinator stores an adoption history, not a second sparse-neuron model. The
entire typed request is hashed into the native tick's `ndu_snapshot_digest`;
the supplied external NDU receipt digest is a field within that request. This is
a research binding, not verification that an external NDU service authenticated
the receipt. The original numerical identity model and research calibration
configuration are retained byte-for-byte in `native.rs`; they are not a trained
new backbone or a production calibration result.

The owner **does not resimulate the diffusion or verify its stochastic law**.
It rejects inconsistent checkpoints and freezes their identities, while the
producer remains responsible for valid Brownian/FPT observations and first-hit
evidence between checkpoints. `Read` is an explicitly proposed local action
subject to phase and resource guards; it is not automatically generated by a
reported spike. See [CONTRACT.md](CONTRACT.md) for the coordinate and time contract.

## Physical cancellation and resource price

`model.cancel_rate` is the physical killing rate in inverse seconds. It is frozen
with drift, volatility, reset, refractory duration, model identity and the sampled
cancellation clock for the run. It never receives an execution-cost update.

Resource price is a separate state variable. On arrival at physical time `t`,
the owner first decays and projects the previous price over the elapsed time,
uses that **current admission price** to guard a read, and then charges the
attempt observed at the endpoint. A nonnegative idle interval cannot prepay a
future read. Fractional residues are persisted, so subdividing a WAIT cannot
erase rounding debt. The request binds the previous settled price and residue;
the output records prior, admission, and resulting prices. The hard read budget
remains independent. This establishes an implemented research admission loop;
it does not establish optimal control, task utility improvement, or a hardware
power measurement.

## Crash contract

The ordinary sequence is: private owner lock; validate prior history; publish
prepared request; publish dispatch fence; open/tick the native runtime; perform
the guarded read; publish one observation-and-credit record.

| Process stops at | Next invocation |
| --- | --- |
| Lock or prepared, before dispatch | Can proceed; no native bootstrap or read has started. |
| Dispatch through synced but unpublished settlement temporary | `Indeterminate`; no automatic native recovery, read retry, price update or historical replay. |
| Published settlement | Return the same settled record, with zero new attempts. |

The dispatch fence precedes even native bootstrap, because bootstrap itself
writes a native journal header. This avoids the observed prepared-retry failure
without modifying the existing runtime's bootstrap/recovery implementation.

**Indeterminate is permanent local quarantine in this profile, not automatic
business completion.** Recovery of a real external effect needs an independently
idempotent/reconcilable effect adapter and authoritative evidence. No command in
this executable removes a fence, guesses an outcome, or reruns an unknown effect.
Even a historical replay is refused while a later dispatch remains unresolved.

## Reproduce

Use Linux, Rust 1.96, `just`, `cargo-nextest`, Python 3.11+, and the locked crates
in an existing offline Cargo cache. The builder checks native files against
`eb5a1cc503e1ea6592d68e73c95b94d24564352a`, creates an explicit standalone workspace
in the requested build directory, and does not edit repository Cargo/Bazel files.

```sh
python experiments/first_passage_owner_v2/build.py \
  --build-dir /tmp/fpt-owner-v2-build \
  --report /tmp/fpt-owner-v2-new-build.json --test
python experiments/first_passage_owner_v2/verify.py \
  --binary /tmp/fpt-owner-v2-build/target/debug/codex-fpt-owner-v2 \
  --output /tmp/fpt-owner-v2-new-process-run
```

Reports and process-run directories must be new; the tools refuse to overwrite
them. The build used approximately 74 MiB of target artifacts. Only this profile
and its declared tests were built. The standalone nextest profile inherits
bounded defaults with zero retries; it does not alter repository-wide gates.

The CLI consumes `fixture.json`-shaped JSON on standard input and takes
`--store PATH --data-root PATH`. A successful first read returns a record digest
and next price pair. The next request must use that predecessor and exact price
pair, increase its logical sequence and owner monotonic clock, and preserve the
run configuration. All examples and tests read ordinary UTF-8 files below the
explicit task root; no source paths confer production authority.

## Qualification boundary

The evidence covers cooperative independent Linux processes, ordinary trusted
local directories, bounded input/record/source bytes, and process death. It does
not certify storage power-loss behavior, malicious rollback or same-user file
replacement, network filesystems, or a hard I/O latency bound. Hashes detect
accidental damage; this is not an authenticated or signed credit journal.
No shared `/tmp` research checkout, frozen V1 package, native crate, or production
TaskFlow caller was modified by this implementation.

The implementation and independent review are organized in
[REVIEW_STAGES.md](REVIEW_STAGES.md).
