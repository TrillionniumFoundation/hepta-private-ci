本轮把正式研究生命周期分成互斥的 prepare、data、train、execute、validation、audit 进程阶段，各阶段只将唯一外层 wait4 CPU 加入账户；所有失败尝试保留并计费。外层覆盖子计量器的解释器启动、导入、能力检查、研究命令、普通可等待后代、采样和内部收据序列化。内部任务、观察器与模型分项计时都已包含，只作分解，不再相加。源码编辑、工具传输、早期读取与最外层账户生成仍在边界外。

这里不作整个开发历史成本完备的声明。此前的 Library 下载、ZIP 提取、manifest/远端树比较、843 个历史 v3 文件恢复及首次初始化失败未被这套正式阶段计量，继续分别为 null；正式 audio prepare 不覆盖它们。v5/v6 准备和训练成本也未恢复。LIFECYCLE_SCOPE.json 固定了正式阶段范围和这些未知项。

硬件核验已经给出外部阻塞：独立子 cgroup 的实际创建返回 EROFS，cgroup2 挂载只读；没有 powercap、hwmon、drm、GPU 设备或 Docker socket；当前没有暴露的外部运行器或配置身份清单。没有改动宿主限制，也没有推断旧会话的运行器仍可用。精确独立进程族同时内存峰值与可归因设备能量无法在此环境闭合，继续为 null。重复提高采样密度不能替代这些能力。

根代理另按插件管理流程搜索 cloud environment remote terminal GPU execution 和 Cloud Environment SSH Tailscale；这两次搜索只返回未连接的部署及其他服务，没有获得可为本任务提供精确能量或独立 cgroup 的现成执行器。这个结果限定于实际搜索范围，不是对整个插件目录不存在其他服务的证明，也没有把连接一个通用部署服务当成硬件资格。

对两个完整受控进程树，新增逐进程最终 wait4 清单与数学上正确的保守上界：sup_t ΣRSS_i(t) ≤ Σsup_t RSS_i(t) ≤ ΣH_i。父、子、孙、短命任务、收养、共享 32 MiB 页面都在同一闭合清单中；短命任务另触碰 48 MiB，其驻留内存采样缺失仍有最终 HWM。两个上界分别为 317,775,872 与 270,446,592 bytes。共享页和已等待后代最大值的重复使上界更松，不使它成为同时峰值。该资格仅属于完整控制夹具；没有对任意研究命令声称完整高水位清单或生产内存上界。MEMORY_BOUND_SCOPE.md 给出公式、范围和主来源。
