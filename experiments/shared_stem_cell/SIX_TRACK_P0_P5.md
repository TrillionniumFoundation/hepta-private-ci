# P0–P5 prospective paired experiment review (research-only)

This is an additive, **non-authorizing** independent observational scorer stacked on the existing E1–E5 shared-Stem experimental lineage. It does not replace `e1e5_causal_gate.py`, original Reader/model/NDUs, the native Worker, authorization, Evidence WAL, original CellSplit owners, or any downstream experiment. Its positive fixtures are deliberately synthetic and must never be cited as model efficacy.

## Six disconfirmable arms

| Track | Required paired arms | Primary prospective question |
| --- | --- | --- |
| P0 | Granite/mmBERT/Gemma/Laya, frozen and trained, identical task and source group | Does a smaller Stem deliver at least the task quality of the current 421M reference for less *total* cost? Four Reader interventions (no evidence, retrieved, independently sufficient, removed premise) must be label-consistent. |
| P1 | Frozen/learned shared vs frozen/learned replicated Encoder | Do trained Heads actually change while shared residency, compute, exposure, retention and OOD are counted? |
| P2 | Parent, split, equal-parameter unsplit, separately identified more-data parent | Does genuinely trained fission beat matched unsplit and survive future/old-task retention after migration/validation cost? |
| P3 | Text, image/text, audio/text, temporal video, shuffled media, generated outputs | Are modality and time relations causal, and are actual generated bytes judged independently? |
| P4 | No search, cheap Bellman, Critic, tree search, ordinary optimizer, NDU/FBSDE candidate | Does NDU beat cheaper alternatives on paired future observed utility **after actual compute**? |
| P5 | Typed, MCP steps, batched MCP, native CPU, native GPU | Do identical validated physical effects have better end-to-end latency, completion and recovery? |

## Executable review

```sh
python -m unittest discover -s experiments/shared_stem_cell -p 'test_six_track_v1.py' -v
python -O -m unittest discover -s experiments/shared_stem_cell -p 'test_six_track_v1.py' -v
python experiments/shared_stem_cell/six_track_v1.py --observations /approved/sealed-six-track.json --output /new/write-once-review.json
```

The last command expects an **externally supplied, independently sealed** JSON document with `hepta.six-track-paired-observation.v3` (prior v1/v2 observations require a fresh freeze and evaluation; no relabeling). It never fetches weights, performs model calls, trains, actuates a device or emits authorization. Source, plan, dataset and evaluator digest fields are exact 64-character SHA256 identifiers **claimed by the submitter**, not cryptographic authentication. Provide one common canonical case registry (task, source family, split, time, modality, Reader condition, input digest, independent binary label, expected operation digest) with train/calibration/test/future1/future2/future3/OOD cohorts. Every evaluation task has all four Reader interventions while keeping the **same modality, source family, answer and intended physical effect**; intervention-specific input bytes may differ. Family and source do not cross partitions and times remain ordered. Train and calibration must both exist; OOD examples cannot precede the training/calibration freeze, although their timestamps need not follow the ordered future1–future3 windows.

Each P0–P5 track must include all specified arms with **one complete case-level prediction and utility/latency record per canonical case**, prelabel sealed prediction claim, a complete per-component `one_time_in_e2e` boolean map (exactly `load_ms`, `training_ms`, `jit_ms`, `evaluation_ms`, `migration_ms`) to prevent both double counting and silently omitted one-off costs, and measured lifecycle columns (model load, Encoder, Reader, Head, decoder, routing, NDU, JIT, external effect, checkpoint, retries, training, evaluation, migration, CPU, GPU, RSS, VRAM, energy). Each P3 result carries an output-artifact digest; each P4 result records actual measured solver time under the equal declared **per-request** compute ceiling. For NDU the arm-level `costs.ndu_ms` must cover the sum of its measured per-request solver time: it may legitimately exceed one request's ceiling. An aggregate-vs-per-request comparison would incorrectly reject valid long cohorts. Each P5 completed result must exactly match the same expected physical effect, with a recovery disposition. Missing, duplicated, mismatched, future-leaking, nonfinite or impossible observations reject.

The reviewer computes distinct **prediction accuracy** (including execution-failed cases), **completed-and-correct fraction**, Brier, signed net observed utility (including failure penalties in the closed range [-1,1]), negative-return count, completion, and **request-level** p50/p95/p99 using nearest rank only when the relevant split has at least **3/20/100** request observations respectively. Unsupported percentile values are explicit `null` rather than pretending that the maximum of 16 correlated requests is an empirical p99. The output also reports the number of distinct tasks and source families, not a claim that requests are independent. It reports paired **source-family mean** utility differences, and descriptive evaluation-request-plus-amortized-once work (each one-off component is charged once only if not already present in the measured request stream). Train/calibration rows may have model forwards, but do not inflate the cost amortization denominator for the **observed test/future/OOD request cohort**; no unsupported lifetime request count is imputed. A single legacy all-or-nothing `e2e_includes_one_time` flag is now rejected because, for example, observed load latency cannot erase unobserved training or migration time. CPU/GPU work and internal duration components are reported, not incorrectly summed into overlapping measured end-to-end latency. P2 more-data is a separate confounded diagnostic, never an equal-exposure competitor. The scorer never promotes a winner and marks small cohorts (<30 independent families per partition) underpowered. Even large self-reported cohorts receive **no independent attestation**.

## Additional v3 integrity gates

- **Task-instance lineage (v3):** `task_id` denotes one concrete answer-bearing task instance, not a reusable task-family label. The four Reader-condition views of that task may share its identity **within** a single cohort. The same `task_id` may not appear in train, calibration, test, future1, future2, future3 or OOD across different cohorts, even if changed input bytes and relabeled source-group fields would evade ordinary hash overlap checks. Source types/objective classes should use separate metadata, not repurpose the instance key. This establishes only declared structural separation; independent source/task provenance, true future observation, and benchmark contamination checks remain unverified.
- **Input/source independence:** a byte-identical model input cannot be assigned to two different declared source families, even inside one evaluation partition. Otherwise nominal source counts and paired family analysis can be inflated by aliases. The output reports distinct input digests but expressly does **not** authenticate real-world source independence.
- **Reader intervention identity:** the `sufficient` and `premise_removed` conditions of the same evaluated task must have different model-input byte digests. Otherwise a cosmetic condition-label change can masquerade as evidence removal. Identical `none`/`retrieved` inputs are allowed as a no-op retrieval control, but this is **not** proof that retrieved context helped.
- **P0 identities and budget:** the four advertised model families must have four distinct base-model digests; frozen/learned within one family must agree on the same base. All four learned arms must use an identical declared training-data digest, example count, local optimizer step count and optimizer-configuration digest. Distinct declared digests do **not** independently prove model loading, actual parameter count, equal hardware work or uncontaminated source data.
- **P0/P1 frozen vs learned:** frozen Head controls must declare zero experimental optimizer steps and identical initial/final weights. Learned Heads must declare positive experimental steps and nonzero trainable tensors. Merely changing a digest never proves physical training.
- **P1 sharing:** shared-vs-replicated trained Head controls must use the same initial Head digest and private trainable-parameter count. This is a partial Head comparability check, not an Encoder execution or memory-deduplication receipt.
- **P2 more-data:** a parent trained on additional cases must have strictly larger exposure **and a different training-dataset digest**; distinct hashes are necessary but not sufficient to prove truly additional independent records.
- **P5 effect recovery:** a task reporting `completed=true` may not declare `recovery_status=blocked`; a blocked or uncertain effect requires separately reconciled evidence before any success claim.
- **Per-component total cost:** an exact five-key boolean map records which load, training, JIT, evaluation and migration costs were genuinely already present in end-to-end observations. Every unobserved component is separately amortized over all recorded requests, including failures, without double charging CPU/GPU and overlapping internal stages.

**Signed utility is not probability.** Predeclared net task return may be negative (including a failed action penalty). Only decision probabilities are restricted to [0,1]. A failed effect cannot acquire positive net utility, and prediction accuracy is never substituted for completed decision success. This v2 amendment corrects the original scorer's inadvertent zero-floor on negative outcomes. Scalar time/bytes/energy observations are also validated before finite float conversion and bounded to an intentionally generous 10^18 per value, so adversarial huge JSON integers cannot overflow conversion or poison aggregate cost accounting.

These are structural rejections inside the same independent reviewer, not a second model owner, training pipeline, NDU evaluator or authority path. Existing research-only v1/v2 inputs do not silently pass as v3, and all produced reviews keep `DENY_ALL` and every model-promotion/efficacy field false.

## Critical evidence not supplied by this patch

- No newly executed pretrained Granite/mmBERT/Gemma/Laya or production no-change policy; no independent human Reader sufficiency review.
- No real multimodal generation or third-party media quality judgement, true prospective future windows, OOD robustness, real NDU net benefit or certified generic FBSDE optimization.
- No complete target-host P5 computer-use benchmark, direct CPU/GPU machine code installation, authenticated energy/VRAM or cross-hardware confidence intervals.
- No qualified 4096-Cell signed Worker/Evidence/FinalUse link, real unclean power-loss reconciliation, original effect authority, main branch change or production model selection.

**Scientific acceptance and production authorization are separate.** All emitted reviews explicitly set `DENY_ALL`, `production_promotion_permitted=false`, and independently verified efficacy/authority flags to false. The experimental owners must supply real evidence to their original gates; never use this review as an authorization token or new acceptance owner.
