# E5 two-wave sparse safetensors + atomic CAS — actual 4096-Cell CPU study (2026-10-15)

**DRAFT / RESEARCH / DENY_ALL. Not a production Worker, WAL, FinalUse or power-cut certification.**

## Research question and prior work

The existing `e5_continual_sparse_checkpoint.py` trains real Torch FP32 tiny Heads on a **synthetic** Q24 feature and labels; its second safetensors snapshot contains **all cumulatively touched Cells**. The existing `e5_crash_atomic_store.py` has true SIGKILL/atomic HEAD semantics but stores the **entire 4096-Cell bank** as a huge JSON checkpoint. Neither demonstrates physically efficient, atomically published per-wave delta recovery of a resident 4096-Cell bank.

The additive `e5_delta_cas.py` combines the existing, unchanged wave-generating research owner and tested local CAS primitives:

- Two frozen, deterministic waves of sparse SGD (409 of 4096 active Cells per wave, with partial overlap); each saved delta includes **only that wave's 409 Cell weights, per-Cell momentum, selected indices and cumulative per-Cell step counts**, never a full Head bank.
- Safe bounded `safetensors` binary blobs (no pickle), SHA-256 content-addressed immutable objects, SHA-256 chained commit manifests, `fcntl`-locked exact-parent compare-and-swap, tiny temporary HEAD with atomic replace and directory fsync.
- Reader verifies **every** wave in the chain: source/SCOPE/epoch/fence bindings, expected wave-specific Cell IDs, exact +3 optimizer steps, finite FP32 shape/weight/momentum geometry, bytes, manifest SHA, full reconstituted bank hash, and uncommitted orphan exclusion. A caller cannot inject an arbitrary valid-looking next training state because the research writer recomputes deterministic next-wave SGD and requires its entire state hash to match.
- Every restored state is rebuilt from the same frozen synthetic initial parameter generator and the complete two-wave delta chain; recovery outcome is compared to uninterrupted **actual PyTorch SGD**, not just to a writer's asserted checksum.
- A separate `e5_delta_crash_matrix.py` kills a real child process at each defined injection point. Parent checks SIGKILL exit code -9 and independently reconstructs/replays the full bank.

**Limit:** SHA-256 verifies local bytes, not signed publisher/model origin; local `flock` is not a distributed CAS/consensus system. Crash tests cover process death with the OS page cache alive, **not actual loss of power**.

## Physical, independently re-readable local CPU evidence

Environment: single sandbox CPU with Torch 2.10.0+cpu and safetensors 0.7.0. Four thousand ninety-six actual Head weight rows resident (9,744 trainable parameters per logical Cell; **39,911,424 FP32 parameters**). 409 selected Cells trained in two consecutive three-step waves with independent Cell momentum state and exactly checked dormant indices.

| Measurement | Actual observed local reading |
| --- | ---: |
| Full 4096-Cell FP32 Head weight payload, excluding momentum | **159,645,696 bytes** |
| Wave 1 immutable safetensors delta | **31,890,144 bytes** |
| Wave 2 *incremental* safetensors delta | **31,890,144 bytes** |
| Old cumulative two-wave sparse snapshot after wave 2 | **47,873,592 bytes** |
| Saving of new wave-2 delta over the old cumulative wave-2 snapshot | **33.4% smaller** |
| Wave 1 standalone process end-to-end measured wall | **4,717 ms** |
| Wave 2 standalone process restore / update / commit wall | **5,931 ms** |
| Independent cold replay plus uninterrupted reference verification | **4,835 ms** |
| Full reconstituted Head/momentum state vs uninterrupted 2-wave SGD | **Bit-exact** |

The delta is ~20% of the weight-only 4096-Cell FP32 payload, **but this is not an apples-to-apples compression claim**: delta carries both weights and optimizer momentum for active Cells while the weight-only baseline excludes optimizer. The 2-wave delta chain physically stores **63,780,288 bytes of binary blobs**, plus small manifests and pointers. Baseline deterministic reconstruction also requires CPU time and a correct identical initial weight generator; full lifecycle cost remains an open acceptance gate.

**True process SIGKILL, not exception mocks:**
- 64 logical / 8 active: **10 independent child SIGKILL events**, all defined crash stages. Eight before HEAD replacement expose only fully published wave 1; the two stages after replacement expose fully published wave 2.
- 4096 logical / 409 active: **two independently executed child SIGKILL events**, one during initial delta Blob writing (wave 1 remains selected), one just after atomic HEAD replacement (wave 2 selected). Both recover and verify all FP32 Head weights plus Momentum bit-for-bit.
- **12/12 child-process fault observations match their preregistered expected publication stage**, and all 8 local source/CAS/integrity tests pass.

The first full 64-Cell all-stage invocation exceeded a tool execution time boundary. The remaining stages were then run as bounded 2/4/4 batches, preserving **all ten distinct stages**; the whole experiment is not counted as a single successful initial command. The 4096-Cell crash trials were run separately at each of the two selected critical cut points. Each raw report has its own SHA; only completed records enter the evidence summary.

### Local integration boundary

For the local CPU sandbox, the already-existing `e5_sparse_packed_sgd.py`, `e5_packed_head_fanout.py` and `e5_crash_atomic_store.py` were taken from source-checked prior Git blob artifacts. The `e5_continual_sparse_checkpoint.py` core wave/config/state-hash functions were reconstructed locally from the retrieved upstream source text for this pilot; **that local supporting module was not byte-identical to the entire current upstream source file**. The three **new** E5 delta/CAS source and test Git blobs do match the locally executed files exactly. Hence these measurements establish a genuinely executed local implementation and physical storage semantics, but do **not** constitute an exact-upstream-integrated GitHub result. The new exact-HEAD workflow must run with the actual current committed `e5_continual_sparse_checkpoint.py` to verify those conclusions independently. This is an open, non-waivable check.
