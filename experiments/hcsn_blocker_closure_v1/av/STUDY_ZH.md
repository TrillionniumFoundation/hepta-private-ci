# 新演员真实音视频编码实验：执行合同与交付

本目录提供可以执行的 90 个独立训练作业及完整分析程序。它尚未产生真实训练结果，也不构成 Hepta 相对 Transformer、LIF 或 Mamba 的优越性证据。新的真实数据由单独的数据构建任务完成，研究执行阶段只接受预先锁定的同一份数据。

## 数据与信息边界

数据包含 30 名未出现在旧实验中的 CREMA-D 演员，共 720 段片段。按演员划分 16 人训练、6 人验证、8 人测试，各有 384、144、192 个样本；每个演员均为 6 类、每类 4 段。输入为独立音频与视频低层特征，各为 32×128。使用数据保存的真实 `dt`，不改成全一时间步；原始全片段重采样是离线预处理，不能据此声称因果流式媒体处理。

数据证据提交固定为 `dca9febc8143c682077fe27d40dbeaa1137bcaa4`。注册器从 Git 对象读取该提交中的 `TRANSPORT.json`，同时校验确切 Git blob、获取程序的执行提交、数据清单 SHA256，以及每一个恢复后的原始文件的长度和 SHA256。文件清单必须完整且无额外文件。注册时可以复制和校验测试文件的字节，但不加载测试数组或计算模型结果。

## 模型、目标与公平比较

五个模型为 `value_jg`、`two_gates`、`transformer`、`lif_snn`、`mamba1`。每个模型均有两个独立的模态编码器和一个共享线性分类头；编码维度为 32，类别为 6。融合预测取两个分类 logit 的算术平均，目标为：

\[
L=\operatorname{CE}\!\left(\frac{z_a+z_v}{2},y\right)
+0.25[\operatorname{CE}(z_a,y)+\operatorname{CE}(z_v,y)]
+0.5\operatorname{InfoNCE}_{sym}(e_a,e_v;0.1).
\]

InfoNCE 使用 L2 归一化的编码，正样本是同一片段的两个模态。批大小为 16，有放回采样；重复片段可能形成对比学习假负样本，该规则对所有模型相同。两个模态的输入投影、输出投影以及共享头在相同正式种子下具有相同初始张量。不同模型的两个活动 backbone 合计参数分别为 35,872、35,540、35,908、35,772、35,652，最大相对差约 1.03%，没有用不参与计算的参数填充。

这里的融合结构是加性融合探针。打乱模态配对后性能下降表示对配对错误敏感，单凭它不能证明跨模态协同或一般内容理解。JG 通道仍然是内容目标的代理；独立的有限状态任务 QVI oracle 不能自动等同于这些编码器的内容 Bellman 最优边界。

## 90 个作业与选择规则

每个模型先比较两个学习率 0.001 与 0.003，各训练 96 次更新，在第 48 和 96 次更新以六名验证演员的融合交叉熵选检查点和学习率，共 10 个开发作业。全部学习率选择持久化为全局锁后，才开始正式训练。

正式实验有 8 个预先固定的种子。每个模型、每个种子分别运行 256 次更新以及 60 秒完整训练 CPU 的预算，共 80 个正式作业。固定预算在第 128、256 次更新验证；CPU 预算在第一个完整更新跨越 30 秒和 60 秒时验证。相同种子的批索引流相同；不同 CPU 预算模型的更新数可以不同。选中的权重及选择说明先 fsync 到磁盘，再加载测试数组。所有失败作业、全部训练轨迹和未选中的最终权重均保留，不静默重跑或筛除种子。

分析器独立重构每一个模型、种子、学习率和阶段组成的精确作业矩阵。它检查全部更新编号、损失分量、有限梯度、概率合同、第一次 CPU 跨越、验证时点、权重张量哈希、真正的开发集 argmin，以及全局选择锁与测试访问的时间关系。只有完整 90 作业且完整性检查全部通过，才允许比较研究门槛。

## 统计、原始证据与成本

主要终点是按演员平衡的融合测试准确率；JG 分别对四个对照，在两种预算下形成八个预声明比较。统计使用 8 个配对初始化种子与 8 个测试演员的交叉 bootstrap，保留同一演员的所有片段，不把 192 段片段冒充 192 名独立演员。报告普通 95% 区间和八比较单侧 Bonferroni 下界。单个优势门槛还要求平均准确率增加至少 0.02、Brier 不恶化超过 0.01、ECE 不恶化超过 0.02；八个比较全部满足才允许使用广泛净收益表述。只有八名测试演员，区间是近似群体推断。

每次验证和测试保存完整音频/视频编码、所有 logit、演员/片段身份、全候选池与同演员候选池的两个方向检索排名，以及全局和同演员配对打乱索引。排名完全相同时按冻结的行号打破平局。原始证据足以独立重算准确率、交叉熵、Brier、ECE、R@1、R@5、MRR 和排名中位数。

每个作业的 `wait4` 收据覆盖独立进程从导入、初始化、加载、训练、验证、测试、证据写盘到退出的 CPU 与墙钟成本，并记录峰值 RSS。训练、验证和内存内推理的时钟是该总成本的组成部分，不能再相加。媒体下载、解码、归一化、传输恢复、注册、调参、分析、打包有独立收据；嵌套的媒体解码收据也不能重复计费。GPU 和直接焦耳测量没有执行，不用 CPU 秒数编造能耗。

源代码一致的 `results/preflight002.json` 为 19/19 通过。它只使用合成音视频及正、非恒定时间步，覆盖五种模型、实际参数更新、匹配参数量、共同初始权重及时间传播。`results/contract_checks002.json` 为 17/17 通过，检查权重保存/读取哈希以及被篡改的排名、融合、标签、训练轨迹和预算证据；非有限值同时受 JSON 写入与分析器检查保护。独立审查者另完成 29 项检索、平局、配对打乱和交叉 bootstrap 数学检查，并确认四项来源与选择合同修复。

本地第一次预检查约 2.67 进程 CPU 秒；第二次在共享环境接近 8 GB 内存限制并发生大量缺页时耗时 35.61 CPU 秒。两次结果和日志均保留，第二次的源代码哈希作为执行准入依据。预检查计时包含冷启动且受到共享环境影响，不作为模型性能排名或正式托管运行时间的承诺。真正的质量和成本结论必须等待正式 90 作业完成。
