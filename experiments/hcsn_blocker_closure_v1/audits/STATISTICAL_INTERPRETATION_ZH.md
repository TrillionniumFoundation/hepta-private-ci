# 统计推断与成本结论的适用范围

本说明限定冻结研究的报告语言，不新增检验、阈值、样本、实验或结果选择规则。依据为[内容研究预注册](../content/DESIGN.json)、[内容分析实现](../content/analysis.py)、[AV 预注册](../av/AV_DESIGN.json)、[AV 分析实现](../av/analysis.py)和[硬件测量合同](../hardware/HARDWARE_DESIGN.json)。编写本说明时未读取当前正式实验结果。

## 1. 全枚举不等于无假设的精确推断

内容研究对八个配对种子的差值枚举全部 $2^8=256$ 种符号翻转，并计算预注册的单侧正收益 p 值；双侧值也保留。因此，枚举本身没有随机抽样的蒙特卡洛误差，其零假设校准仍需要**符号翻转不变性**：零假设下，差值向量的联合分布应在相应符号变换下保持不变。独立且关于零对称的种子差值、或有依据的配对标签可交换性，可以支持这一条件；仅有“均值差为零”不足以保证它。共同种子和相同批次序列减少比较噪声，不能自动证明两种不同架构在零假设下可交换。[Hemerik 与 Goeman（2018）](https://pmc.ncbi.nlm.nih.gov/articles/PMC6405018/)给出了基于变换不变性的检验条件。

最终宜写“**在符号对称／可交换性假设下，使用全枚举配对符号翻转 p 值**”。不得写“无任何分布假设的精确显著性”。离散性和并列值也意味着有限样本检验通常只保证不超过名义水平，而非恰好等于该水平。

## 2. 八种子的 t 区间只描述固定数据下的训练随机性

源码使用

$$
\bar d\;\pm\;t_{7,0.975}\frac{s_d}{\sqrt8}.
$$

这是以已固定的数据、划分、开发集选择和训练合同为条件，对配对种子差值均值构造的区间。经典精确覆盖依赖独立同分布正态差值模型；本研究的准确率差有界、离散且仅八个种子，实际使用应解释为近似抽样模型下的区间。它不能覆盖重新采样数据、换任务、换人群或另一次调参所引入的不确定性。八种子也不足以可靠确认尾部形状或对称性。

预注册的实际收益幅度是**点估计门槛**，区间下界要求大于零；通过二者不能改写为“已证明真实收益至少达到该幅度”。Brier/ECE 的平均差守门条件也不是额外完成的统计非劣效性检验。

## 3. 多重比较与跨任务平均的边界

机制比较在四个预注册族内分别实施 Holm 校正：冻结组件 5 项、边界 2 项、通道 5 项、边界与通道交互 2 项。在单项 p 值有效的前提下，Holm 控制的是指定族内的家族错误率。[Holm（1979）](https://www.jstor.org/stable/4615733)的保证不能直接延伸成这 **14 项合并后的全局 5% FWER**。独立的 12 项等训练 CPU 外部比较有自己的校正族；通过项数不是一个新的全局检验。

机制主比较先在每个种子内计算

$$
d_s=\tfrac12\bigl(\Delta_{s,\mathrm{Copy}}+\Delta_{s,\mathrm{MQAR}}\bigr),
$$

再用八个 $d_s$ 推断，不能把两个任务拼成 16 个独立种子。平均正收益可能掩盖某一任务的负收益；最终报告必须同时列出 Copy、MQAR 的任务级 ID/OOD 效果及方向。任务分解沿用预注册的次要／描述性地位，不能据结果改权重、选择任务或更换主比较。

## 4. AV 的交叉 bootstrap 是小样本近似

AV 在 **8 个种子 × 8 个测试演员**的配对效果矩阵上，分别重采样种子索引和演员索引，保留演员内部的片段集合。64 个矩阵单元及同一演员的多个片段均不能当成相互独立的人群样本。这种按两个交叉维度重采样的思路见 [Owen（2007）](https://arxiv.org/abs/0712.1111)；它不使当前八演员的百分位区间获得精确有限样本覆盖保证。

20,000 次重采样控制的是数值模拟精度，不会增加实际演员数。对八项比较采用预声明的 Bonferroni 分位数，仍依赖各近似区间的覆盖表现；它不能修复小样本偏差，也不能证明真实世界人群泛化。测试演员之外的数据采集、训练集构成与开发选择仍是条件。接近零的数值边界应透明保留，不得根据另一种浮点求和顺序悄悄改写已冻结判定。

## 5. 错配敏感性不能单独证明跨模态协同

当前 AV 使用两个编码器和共享线性头，融合 logits 为 $z_{av}=(z_a+z_v)/2$。打乱配对后的下降可以说明对输入配对有敏感性，也可能只是平均了彼此冲突的类别证据；它不能单独证明互补信息收益、推理时跨模态交互或时间对齐能力。同演员打乱控制了演员身份，仍可能改变情绪或语句。应同时报告音频、视频、融合、全局错配、同演员错配和检索结果，并保留“加性融合探针”的研究范围。

## 6. 成本范围与结论必须对应

| 已测范围 | 可支持的陈述与限制 |
| --- | --- |
| 等训练 CPU | 比较完整训练更新时钟内的质量；包括前向、反向、梯度／概率审计和优化器，排除验证、序列化等。最后一次完整更新的预算越界须保留。 |
| 完整 worker 的 `wait4` | 包含解释器导入、构造、加载、训练、验证／测试、保存和退出。开发搜索与失败尝试均须计入；内部训练时钟不能再加一遍。 |
| 流水线和运行器 | 区分采集／解码、注册、训练、分析、打包及平台阶段；只汇总互不重叠的成本。未测量的平台 CPU 成本不能由 wall 时间推造。 |
| 驻留／主机端完整推理 | 使用相同 batch、长度、输入和完整状态／复位合同；分别说明是否包含输入输出传输、模型加载和服务启动。并发环境内少量 wall 样本不是独立硬件复制。 |
| GPU 与能耗 | CUDA 同步计时和实际 NVML 能量计数器属于单独证据；设备总能量包括空闲及后台活动。不可由 CPU 时间、MAC 或一次内部实现加速推出整机焦耳收益；不可用时报告 `null`。 |

因此，等训练 CPU 下通过质量门槛，尚不能直接称为完整系统的净收益。最终应并列呈现质量、完整 worker 成本、推理延迟／吞吐及实际可获得的能耗范围；负结果、缺失能力和条件性结论均按原合同保留。
