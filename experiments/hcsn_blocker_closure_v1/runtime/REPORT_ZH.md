# 任务价值到真实 Hepta 执行的闭合结果

本轮完成了一个任务目标明确的原生执行验证：**32 个固定随机种子 × 5 个策略 × 4 个再生周期，共启动 160 个真实 Rust 子进程，执行 5,535 次原生决策、640 次 STOP，以及每个 STOP 后的不应期与新任务初始化。** 所有原生动作与预先定义的策略一致；事件重试没有重复执行，STOP 后和不应期内的读取被拒绝。完整指标、成本与限定见 [SUMMARY.json](SUMMARY.json)；该文件引用主结果和协议的 SHA-256。

本轮控制器使用精确有限状态 Bellman 策略。它没有训练内容编码器，因此这些结果不证明已训练 HCSN 的分类边界最优，也不证明新的网络架构优于普通门控、SNN 或 Transformer。

## 1. 目标、时间与动作合同

任务模型及其独立数学验证来自 [oracle 数学报告](../oracle/MATH_AND_STATUS_ZH.md)。本次执行使用 17 个后验网格点，$p=P(Y=1\mid\mathcal F_t)$，证据强度为 1，折现率 $\rho=0.2$。活动期付出连续模型时间成本 $0.04$；发放选择类别，立即获得 $1\{\widehat Y=Y\}-0.1$。随后等待均值为 0.5、两个指数阶段组成的 Erlang 不应期，期间不读取新证据。结束后将环境状态和正常控制器状态重新初始化为后验 0.5，并抽取独立的新标签。

每个种子执行四个完整周期。统计同时保留：

- 四个周期实际产生的折现奖励与活动时间成本；
- 在第四个不应期结束后加上该策略精确续期价值所得的无限时域估计。

第二项包含**模型计算的终端续期价值**，不能解释成全部来自实际运行的奖励。QVI 策略平均总估计为 5.109762，其中实际四周期贡献 1.899407，终端续期平均贡献 3.210355。主结论使用有限任务的精确策略价值，随机路径负责验证执行与状态合同。

隐藏标签只在动作完成后用于评分。动作输入是当前后验和任务模型，没有把标签发送到原生决策器。每次 KEEP 对应一次条件 CTMC 均匀化观察；自跳也被计为真实读取。等待时间、折现时间和不应期时间都是模型时间，程序不通过墙钟睡眠模拟它们。

## 2. 连续消息确实控制原生 KEEP/STOP

QVI 策略发送的连续消息为

$$
m=0.05+0.9\tanh\left(Q_{\mathrm{keep}}-\max_a Q_{\mathrm{fire},a}\right).
$$

Q 值包含发放后的不应期折现和复位续期。映射在执行前固定，不使用运行结果、标签或高低状态极值来重新选择阈值。消息被量化为原生 Q24；实现要求距原生比较阈值至少 16 个量化单位。普通阈值对照使用同一后验网格上的有符号阈值距离，执行相同的原生消息通道。

每个原生 profile 的 `objective_digest` 绑定本次折现再生分类目标，`source_model_digest` 绑定已保存的策略表。旧的 paid-prefix 目标元数据没有被沿用。可执行文件 SHA-256 为 `1dc702aea6a448ad84407aeb71dc8f23066205fab79fe7c6859fc02c55e6f7a5`，运行时身份、原生源版本与清单摘要均经过检查，权限始终为 **DENY_ALL**。

一个 STOP 终止一个原生 owner 的逻辑 episode。复位不复活已经终止的 episode；不应期结束后，为新的独立任务打开一个不同的、序号从零开始的 episode。同一子进程负责一个种子、一个策略的四次再生。原生 journal、事件记录、profile、拒绝记录和压缩轨迹均保留。

## 3. 与强阈值对照及复位消融比较

最强普通阈值通过穷举所有对称后验网格阈值，按已知任务的精确价值选择。它不使用随机评估结果。该任务的一维最优策略恰好可以用两个普通阈值表示，所以它与 QVI 策略完全相同。

| 策略 | 精确无限时域价值 | 32 个种子的随机路径估计均值 | 四周期实际贡献均值 | 分类正确率 | 实际观察数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 任务 QVI | 4.943256 | 5.109762 | 1.899407 | 67.19% | 546 |
| 最优普通对称阈值 | 4.943256 | 5.109762 | 1.899407 | 67.19% | 546 |
| 固定置信度 0.8 | 3.746985 | 3.880929 | 2.074473 | 83.59% | 3,643 |
| 立即发放 | 4.302439 | 4.188933 | 1.283658 | 47.66% | 0 |
| 省略控制器复位 | 4.369317 | 4.325892 | 1.440982 | 51.56% | 160 |

表中正确率汇总每个策略的 128 次分类；置信区间以 32 个种子为统计单元，保留同一种子内四个周期的相关性。固定 0.8 策略用更多观察取得更高正确率，但在本次声明的时间成本与折现目标下价值更低。目标价值不等于单独的正确率。

复位消融保持新任务的独立标签分布与环境复位不变，只保留控制器在上一周期发放时的后验状态。所有种子的第一周期控制器轨迹与 QVI 完全相同；之后正常控制器回到新任务先验，消融控制器停留在旧的发放状态。原生状态、后续读取与动作因此改变。省略复位策略的续期价值按照它自己的陈旧状态行为计算，没有错误地代入最优策略的终端价值。

正常复位的精确目标价值比省略复位高 **0.573939**。随机路径的种子配对差值为 **0.783869**，描述性 95% t 区间为 **[0.377829, 1.189910]**；只计算实际四周期奖励时，差值为 **0.458424**，区间 **[0.128348, 0.788500]**。这些区间描述这个已知有限任务，不承担架构优越性或跨任务泛化的验收功能。

**QVI 对最优普通阈值的收益为零。** 精确价值、每个种子的实际奖励、动作和读取数量都相同。由此可关闭“这条任务价值是否能驱动实际执行”的实现问题；该任务不能支持“价值边界天然优于普通可学阈值”的结论。

## 4. 完整执行成本与统计范围

从启动新的 Python worker 到 worker 退出，`wait4` 测得主运行：

| 成本项目 | 测量值 | 范围 |
| --- | ---: | --- |
| 完整 worker 与已回收子进程 CPU | **5.509892 秒** | 包含 Python 导入、oracle 求解、策略初始化、全部原生进程、IPC、持久化、轨迹保存和验收 |
| 完整 worker 墙钟时间 | **11.956020 秒** | 同一进程生命周期 |
| 原生子进程 CPU | 2.195851 秒 | 上一 CPU 总量的组成部分，不能重复相加 |
| 结果写入前的 Python 自身累计 CPU | 3.271051 秒 | 不含其子进程 CPU；最终写文件和退出还有开销 |
| worker 最大 RSS | 47,420 KiB | Linux 峰值统计，不能解释成并发进程内存之和 |
| 原生 RPC 数 | 10,335 | 包括初始化、状态、重试与终止拒绝探针 |
| 请求 / 响应字节 | 2,601,837 / 10,455,116 | 实际序列化 IPC 流量 |
| 真实原生 kernel / NDU 调用 | 5,535 / 5,535 | 包含每次决策，没有用期望发放数替代 |

640 个 `native_errors` 全部对应每个周期预先声明的 STOP 后违规读取探针；正常执行没有子进程失败。原生物理 RPC 微秒数与 Python 往返时间是嵌套的墙钟观测，不能作为 CPU 或能耗，也不能再次加进完整墙钟成本。

对照按固定顺序运行，单臂墙钟时间会受到共享执行环境影响。因此这里不报告 QVI 相对普通阈值的速度胜利。任务质量目标中的“活动时间成本”也不是 CPU 定价。部署前仍需要在同一硬件、相同质量门槛下，对完整内容模型进行训练和推理成本比较。

## 5. 失败保留与原生限制

第一次预检在 profile 加载阶段失败，尚未抽取任何任务路径。原因是新客户端请求 4,096 个 tick，而未修改的原生 `Profile.validate` 上限为 512。检查固定原生源文件后，将客户端配置改为遵守 512 上限。没有修改原生限制、工作流或安全权限。

预检一的完整 worker 计时为 1.067602 CPU 秒、2.881026 墙钟秒；失败发生在构造阶段，原生子进程没有得到独立的 `wait4` 收据，因此这个失败尝试的子进程分项仍不完整。随后补齐构造异常时的资源回收。预检二成功，耗用 0.404500 CPU 秒、0.526765 墙钟秒。这些预检不与主运行混合；相关协议、日志和成本文件保留在 `results/preflight001` 与 `results/preflight002`。

原生限额在主运行中始终保持 512。任何达到观察上限、量化分辨率不足或被原生硬限制强制终止的样本都会使运行失败，不能计为成功的 QVI 轨迹。主运行全部 160 个策略种子组合成功完成，源文件哈希在运行前后保持一致。

## 6. 仍未关闭的工程与科学验收

本机没有可见 NVIDIA 设备、`nvidia-smi`，也没有可读的 `/sys/class/powercap/**/energy_uj` 计数器。**GPU 实现、直接焦耳测量与硬件能效优势仍没有证据。** 数学 oracle 和特征计算在 Python/NumPy/SciPy 中进行，原生部分执行真实消息处理、稀疏决策、owner 状态和持久化；这不是把 HCSN 神经计算全部移入 Rust 的结果。

普通 PR CI 的最新核对见 [CI_DIAGNOSIS.json](CI_DIAGNOSIS.json)：固定提交 `1d959d8d82091e6014b13c2191f62bf74e778561` 的架构收敛和 canary 已成功；`blocking-ci` 第二次尝试最终失败。Linux Clippy、Windows 原生链接、macOS 资源/测试和 cargo-deny 的失败仍存在。四个已核对的代表性 Rust 失败文件在研究 base 与 head 中字节完全相同；这不代表每一个广泛矩阵失败都已查明。cargo-deny 日志连续三次读取失败，所以其具体原因保留为未知。没有通过关闭检查或添加 blanket allow 来制造 CI 通过。

目前可以确认的闭合项是：**明确任务目标的 Bellman 值进入了真实 Hepta 控制通道，复位对真实动作有可复查的因果作用，完整进程成本有明确边界。** 已训练内容网络采用该目标后的收益、价值边界相对最优普通阈值的净收益、全模态规模化和直接能耗比较仍需对应实验，不能由本次低维演示替代。

```bash
python -m experiments.hcsn_blocker_closure_v1.runtime.measure \
```


运行失败时日志与已完成记录会留下，不能把部分记录填充到另一次运行中。固定随机种子使数学路径可复现，CPU、墙钟时间和硬件观测不要求逐位相同。
