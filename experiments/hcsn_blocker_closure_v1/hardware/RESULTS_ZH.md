# 已选检查点的 CPU 硬件参考测量

**当前 HCSN J/G 参考实现没有表现出推理速度优势。** 预先登记的 30 个 CPU 场景全部完成，输出与对应检查点的 CPU 参考完全一致；另外 30 个 CUDA 场景因当前运行时不可用而保留为不可用。零执行失败，实际能耗为 `null`。这些结果不能用于宣称优化 GPU 性能或 Joules 收益。

本次只测量两个内容任务中、固定更新组的五种模型，全部使用预先指定的种子 `881101`。每个模型恢复已经由验证集选定的检查点；测量方案没有根据测试结果选择模型、种子或输入。注册于 2026-10-31 03:32:07 UTC 完成，随后开始测量。原始结果见 [RESULTS.json](results/attempt001/RESULTS.json)，输入与源码绑定见 [PROTOCOL.json](results/attempt001/PROTOCOL.json)。

## 1. 测量范围

运行时为 Python 3.12.14、PyTorch 2.8.0+cpu、NumPy 2.3.5，PyTorch 使用一个 CPU 线程。环境记录了 8 核 CPU 配额和 8 GiB 内存上限；这不代表独占物理机器。所有模型均为相同冻结源码的 FP32 参考实现，未使用编译、自动混合精度或 TF32。

输入长度为 32、输入维度为 64，批量分别为 1、16、32。同一任务和批量的所有模型使用相同验证集前缀及原始 `dt`，没有加载标签、测试或 OOD 数组。每次调用都重新初始化状态，执行完整序列、各步状态更新、相应的发放／复位／不应期动力学，并生成完整序列输出；没有跨调用缓存状态或输出。

每个场景分别测量输入驻留和含主机复制两种范围。每种范围预热三次，再计时 20 次。下表是这些重复计时的墙钟中位数，**不是 20 个独立训练种子或 20 台独立机器的估计**。每种架构只有一个检查点种子；本测量没有新增质量比较或统计显著性门槛。
