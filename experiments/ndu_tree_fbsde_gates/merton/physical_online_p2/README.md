# P4 — equal-generation-budget thinking vs non-thinking original Reader experiment

**DRAFT / RESEARCH_ONLY / SHADOW_ONLY / DENY_ALL. NO PRODUCTION PROMOTION.**

Additive research child of [P3 #2536](https://github.com/TrillionniumFoundation/hepta-private-ci/pull/2536). The original P2 no-thinking/prompt-style and P3 12-token-direct versus 96-token-thinking studies remain frozen in their own source branches. P4 retains seven independent P1 allocation policies **and** runs an extra, fully paid original-model 96-token thinking/non-thinking matched comparison on every held task, independently of any P1 selection. It uses a new receipt schema rather than reinterpreting P2 or P3 artifacts. It neither treats offline precomputed actions as free nor substitutes synthetic fixtures for real model results.

## Fixed public sources

- Pretrained `Qwen/Qwen3-0.6B` **revision `16706fc57485378d4ffaf54139b29ccc66ae08fa`**, explicit file hashes of the downloaded model and tokenizer stored in the frozen plan. Does not load `trust_remote_code`. No claim of the older Hepta 135M Reader, so results **must not** be attributed to that candidate.
- AG News publisher-derived `szhuggingface/ag_news` **revision `98c532231d96ae10e176a909192ecac548949288`**; exact SHA256 of the 1.5k training and official test Parquets are checked before use. Four training samples per bucket/parity (16) and two test samples per bucket/parity (8) selected by a frozen first-occurrence rule; `short` means Unicode length <= 180, not an oracle difficulty label. Parity shards are **not independent publisher families**. Original test has historical public labels and possible pretraining exposure; **zero genuine future windows**. No claim of unbiased prospective generalization or benchmark significance.
- Three action names `direct`, `reason`, `verify`. The direct and reason arms have the *same task instruction*, but distinct Qwen3 `enable_thinking=False/True` hard switches. The `verify` arm is still a **single-pass alternative checking prompt**, not an independent verifier or a second model call. Maximum generated tokens are 12/96/32 for direct/reason/verify; the additional diagnostic `reason_equalcap` has **the identical user instruction and maximum 96 generated tokens** as `reason` but sets `enable_thinking=False`. The diagnostic never enters or changes the P1 policy candidate set. All use pinned seeded top-k 20, top-p 0.95, temperature 0.6 sampling (per Qwen3 recommendations). Raw thoughts are never placed into the scored final answer or review CSV; the visible final span is decoded only after token ID `151668` (`</think>`). If the 96-token budget expires before `</think>`, the answer is empty and scores incorrect. Generated thinking-segment token counts include the closing marker; they are measured compute, not proof of improved reasoning quality. The token/latency reservations are **forecast ceilings**, not guaranteed physical upper bounds, and this pilot does not enforce production admission using them. No tool/network or privileged effect in model responses.
- Exact manifest is `p2_manifest.json`, fixed before any physical inference; tariff is an arbitrary preregistered utility unit/token, not dollars. Training/calibration physical work charged once to acquisition and separately from each on-policy serving arm. Full input+output tokens reported (not only incremental reserved effort), plus model loading, train/serve CPU, wall and p95/p99. No hidden free hardware/cache gain.

## Three-stage hosted causal-order experiment

`hepta-ndu-merton-p2-original-online.yml` executes:

1. **source owner** downloads and hashes public source data; exports TRAIN+label-blind held text in a separate artifact from test gold. Original data remain source-owned, no new dataset labels committed.
2. **Reader worker** downloads **only** the public artifact, physically performs **48** TRAIN `generate` calls to estimate the three action outcomes across 16 tasks, computes all seven P1 selections and fsyncs the frozen plan *before* doing any held generation. It then performs **56 independent held generation calls** (seven policies × eight original tasks), including fresh repeated `direct` calls, plus **16 additional original-model diagnostic calls**: one thinking and one non-thinking 96-token-cap run on each of eight held tasks. Thus the intended full completed study needs **120 real generate invocations**, not 104. The extra diagnostic calls are never reused as free P1 actions or omitted from the lifecycle cost. Their **precommitted task-wise Latin-rotation schedule** counterbalances arm position rather than always running one policy first. The independent reviewer recomputes this order from the frozen allocation and rejects substituted even-resealed schedules. Every original `generate` invocation, including all 16 paired diagnostic calls, gets fsynced start/done records and output digest. Create-only evidence files and newly created journal/output directory entries are also directory-fsynced on the Linux target before downstream physical execution; a directory-sync failure refuses rather than releasing a success record. Partial runs never publish a complete success seal. Training labels are permitted; held labels are rejected at input validation.
3. **review worker** obtains original test gold *after* the model outputs are sealed. It independently reconstructs original TRAIN label outcomes, exact P1 plan, complete generation census, journal, prompt bindings, task scores, actual reported input/output tokens and CPU/wall/p95/p99 for the seven policies. Outputs are a **descriptive** historical public-data comparison, not independent model-host hardware attestation or human semantic adjudication.

P1 `ndu_discrete` and `ordinary_same_profile` use exactly the same fixed objective and must choose identical actions. They are still physically **re-executed** as separate policy arms, not credited with free reused outputs. A difference in model results is stochastic/runtime drift, not an NDU advantage. A difference in internal utility profile vs another arm is not itself an external-task lift.

The GitHub Actions workflow has read-only repository permissions, uses independently run jobs, never writes Git sources or changes production NDU/Neuron/Worker/FinalUse/CNS/CAS. A passing source-only unit test is **not** a physical model result. Hosted CI success cannot by itself establish independent accuracy, causal benefit, hardware provenance, or model selection. Original unredacted traces are short-retention CI artifacts, not repo-published claims.

## P3 incremental scientific controls

This branch deliberately uses new version `hepta.ndu-merton.p3.true-thinking-on-policy.v1`; it must **not** deserialize older P2 no-thinking journals as equivalent. The reviewer checks an explicit immutable runtime profile, registered per-action thought-mode flags, generated-token ceilings, deterministic seed derived only from the frozen public prompt (never held gold), truncated-thought refusal and budget-based failure counts. Each policy still physically regenerates its own selected actions; identical-profile Bellman/NDU allocations do not magically become a capability improvement.

This protocol jointly changes thinking-mode switch and its output-token cap, so it is a **computational investment mechanism** experiment, not isolated causal proof that hidden reasoning alone improves quality. A later equal-cap non-thinking arm and genuine prospective tasks are needed to isolate the mode effect. This is also distinct from a real multi-pass verifier: the `verify` action remains single-pass. The local fake-Reader tests can intentionally forge a pinned model identity and are never external attestation. Real pretrained Reader calls, original publisher scoring and target-host token/cost metrics remain unestablished until exact-HEAD hosted jobs complete.


## P4 intervention: isolating additional output budget from thinking mode

A separate versioned protocol `hepta.ndu-merton.p4.equal-cap-thinking-control.v1` adds an **always-executed matched two-arm diagnostic** on the same eight held news texts after the seven policies are frozen. Both diagnostic arms have **the same task instruction**, original-model checkpoint/tokenizer, sampling profile, SHA-derived random seed, **96-token `max_new_tokens`**, and external answer scoring. The only intended decoding-mode intervention is `enable_thinking=True` (action `reason`) versus `enable_thinking=False` (diagnostic `reason_equalcap`). These arms may consume different *realized* generated-token counts because EOS/finish timing differs; both full original amounts are reported, along with total input tokens, CPU/wall, p95/p99, completed versus budget-truncated thinking, correct-answer scores, and taskwise wins/losses/ties. This contrast is **not** a causal guarantee for other tasks or a proof that the recursive NDU allocator adds value: fixed-bucket work and the same-objective Bellman remain independent negative controls.

The contrast is preregistered in the same fsynced **pre-held** original plan and **interleaved after each task's seven selected-policy calls**. For even task index, run thinking then nonthinking; for odd task index, reverse. Each of the 16 diagnostic starts/results is independently recorded and fsynced, and the postseal reviewer reconstructs order and task membership from the frozen public IDs. The reviewer **rejects** any missing, duplicate, re-ordered, mis-bound, re-sealed or mislabeled diagnostic, and independently computes a structured matched-pair outcome census *only after original source labels become available*. No private thinking text enters the review; the immutable test source is still historically public, not prospective, the task sample is small, and model/host metering is not independent external attestation.

**Disqualifying conditions remain:** the real original pretrained Qwen3 physical job has not completed and the independent postseal job has not published a valid audit. Synthetic 120-call fixture replay is *not* physical proof.
