## Why a frontier, not a new learned controller

The previous scientific guard correctly rejected the original archive's claim
of NDU task lift, but cross-objective comparisons require care: one controller
may legitimately cost more **and** complete more external tasks. "Must be
cheaper than all baselines" is not a general optimal-control criterion. A
specified cost-weighted *net* external task utility is the proper comparator;
without an independently predeclared value per solved task there is no unique
scalarization of model quality and resource use.

This new module reconstructs the full **nine-arm × three repeats × two
interpreter modes** archived output census: all **54 historical records** over
only **32 genuinely distinct holdout records**. It reads the original 128 source
records and all 54 per-arm original model-output records, verifies the original
feature archive SHA256 and completed trial ZIP SHA256, reopens the independently
held original labels, recovers every predicted class from original 4-class
probabilities, counts actual SGD steps, checks CPU/wall and phases, and requires
an exact match to the original blind seal. No heldout labels are passed to the
producer. Git/source-owner hash checks are integrity bindings, not independent
human or hardware attestations.

**Observed finite-result certificate:** fixed8 and NDU both solve **26/32** on
the original historical holdout; every paired final four-class probability is
**exactly identical**. NDU uses **128** actually executed SGD steps against
fixed8's **8**, and its measured cached-input CPU is larger in all **six**
paired runs. Thus, *on this historical panel, and conditional on these observed
resource dimensions*, NDU is Pareto dominated by fixed8: the same observable
output with strictly more updates and greater reported CPU.

Importantly, exact matching class correctness alone would NOT be sufficient
if model calibration changed, and CPU + SGD must NOT be charged as two
independent dollar costs: CPU includes SGD. The module requires identical
full probability outputs for the strict dominance certificate. The exact
rational sensitivity helper computes alternative hypothetical
`task_value*delta_completed - step_fee*delta_steps` without inventing a
dollar-to-token conversion. It is not itself an economic guarantee, future ROI
bound or cost attestation. The original production Encoder/Reader loading,
training/serving p95/p99, migration, memory, energy and external verification
costs remain not independently qualified. Repeats/modes never create 192
independent source cases or new calendar windows.

Negative transfers across real independent source families and genuine
prospective time cohorts remain **unobserved**, not zero. All model-promotion
and FinalUse authority remains external. The original #2319 trained Head,
shared policy and predictive guard are untouched.

## Reproduce and verify

Use Python 3.13 standard library; the test suite uses constructed adversarial
mechanics and does not attempt to fake an original score:

```sh
D=experiments/ndu_tree_fbsde_gates/merton/qualification/frontier
python -W error::ResourceWarning -m unittest discover -s "$D" -p 'test_roi_frontier.py' -v
python -O -W error::ResourceWarning -m unittest discover -s "$D" -p 'test_roi_frontier.py' -v
python "$D/roi_frontier.py" \
  --original-source /path/to/sha-pinned-hepta-public-pretrained-38511456555.zip \
  --original-trials /path/to/completed-hepta_ndu_merton_news_9f4bd1f_evidence.zip \
  --output /tmp/ndu-original-frontier.json
```

Only locally acquired and byte-verified complete original trial ZIPs permit
the full original-outcome replay; the remote read-only CI deliberately runs the
exact math and integrity tests and only independently downloads/checks the
public source ZIP. A missing GitHub-hosted complete original trial ZIP is
**not** silently manufactured or relabeled as an Actions pass. The source
binary and original unredacted outputs are not committed to the Git tree.
