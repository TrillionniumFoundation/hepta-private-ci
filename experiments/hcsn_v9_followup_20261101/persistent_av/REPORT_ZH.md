# 持续 AV 普通基线：开发接线与真实执行

本增量把普通 GRU/SSM 的 32 维状态跨多次真实历史 A/V 前缀保留，使用相同不可变缓存、相同历史拟合内容头、相同实际请求及共同价值控制器。直接缓存 MLP 无核心参考消费相同公开特征。原 v8 计数传播器每次预测时重置；本候选的 recurrent state 则由上一次真实接受状态继续更新。全局源时钟增量为零时，第二模态的新内容仍然更新状态。

本轮**没有定义解析 AV 观测律或解析 AV 核心**。因此解析/普通 × 轻量/价值完整四格没有完成，`D-B` 没有测得。普通参考也只执行固定配方，没有逐架构调参或最强参考资格。direct MLP 只读当前缓存的均值、头概率及前缀特征，没有使用完整原始历史读出器；GRU/SSM 可以保留此前已接受特征的轨迹。它只是可实施的普通无核心开发参考，不能称为完整信息下最强 direct-history 对手。

随后在**独立的 `history_reference.py`** 补齐了完整已接受特征轨迹的普通 MLP 参照；原候选源码、冻结及 `results002/` 保持不变。新增参照显式保存 6×41 个按接受顺序排列的公开观察特征及六个槽 mask，源时间增量也逐次保留。该信息与 GRU/SSM 每次实际获得的输入相同，未来槽始终为零，不包含未来载荷、对象身份或标签。它没有学习的递归隐藏状态，代价是保留完整轨迹；名义输入载荷为 2,016 bytes，Python 对象、模型和共享缓存另计。

v8 调度器只通过 `core.accept` 通知一次已提交多步计划中的每个接受事件，因此透明历史 holder 使用该回调接线，并把完整日志与当前内容指纹的 SHA256 放进 32 标量 snapshot。`BackendKind.CORE` 在这里仅是接受回调协议，不代表神经核心；MLP 的实际输入是完整日志，摘要绝不替代历史。所有多步中的中途观察均按因果接受时序 append，一次等待不会追加观测。

## 冻结与拟合

两任务、两拟合种子，每次保留 direct/GRU/SSM，共 12 个模型。每个训练录制展开强制首音频后的全部 10 个合法完整采集顺序；重复顺序不是独立样本。输入仅为当前两模态已接受内容的均值、共同头概率、模态前缀及实际源时间增量。GRU/SSM 状态额外传入未来正确率读出器，STOP 头从不消费核心状态。

监督目标是相同共同头在 16 个合法终点的实际正确/错误，推理时未来载荷和标签不传入读出器。时间增量只用于 observation update，训练和执行的 readout 都明确将其置零。每个模型运行 100 个完整更新，以旧验证集最低 BCE 选权重；最后权重和选定权重全部保留。每任务的完整选定权重在打开本次历史 test 回放前冻结。

所有数据都已被此前研究使用；验证集也曾选择历史头。本轮 test 只是历史回放名称，不能视为新的独立确认。原始五类情绪/语句绑定前端门与 v6 强音频参考仍未恢复。本轮六类情绪/同录制绑定不能替代原门。

## 真实结果

`results002/` 完成 432 次实际执行，所有结果与相同已接受前缀的独立共同头计算逐值一致。固定六读时，各核心、种子得到相同内容输出：情绪 5/12，绑定 13/24。

| 任务/控制 | direct cache | GRU | SSM |
| --- | ---: | ---: | ---: |
| 情绪，固定六读准确率 | 41.67% | 41.67% | 41.67% |
| 情绪，价值控制准确率 | 41.67% | 41.67% | 41.67% |
| 绑定，固定六读准确率 | 54.17% | 54.17% | 54.17% |
| 绑定，价值控制准确率 | 47.92% | 52.08% | 50.00% |
| 绑定，价值控制平均净效用 | 0.392283 | 0.419783 | 0.415199 |
| 绑定，价值控制平均请求数 | 3.8125 | 4.4583 | 3.7292 |

这是 36 个旧录制任务对象 × 重复种子/模型/策略形成的描述统计，不能把 432 次执行当成 432 个独立录制。价值控制可能通过少读节省费用，同时损失内容正确率；绑定质量没有达到原前端门。逻辑源时钟与声明的 1 ms/read 服务用于质量/费用回放，实际 CPU 由外层进程包络测量，不能把逻辑输出时延当实测设备时延。

独立审查见上层 `review/AV_AUDIT.json`：9,144 检查通过，重算 432 条执行、1,511 次真实持续状态更新、737 次零全局时间增量内容更新、12 个模型的验证选择与权重/源码身份。

完整轨迹参照以相同训练配方、相同目标、同一控制器、同一旧数据与两种子再拟合 4 个模型，完成 `history_results001/` 的 144 次实际执行。每个模型在历史回放前冻结，所有最后/选定权重均保留，并实际通过六项“任意修改未来槽不改变当前输出”的因果检查。该参照有 17,232 个参数，未作与 GRU/SSM 的参数量匹配，也未完成普通模型家族独立调优，不能称为所有最强参照已资格化。

| --- | ---: | ---: |
| 固定六读准确率 | 41.67% | 54.17% |

绑定控制减少请求但也降低正确率；不支持主前端质量准入。以上比较仍没有解析 AV 模型，且只是相同旧录制上的开发描述，不是新独立确认。

## 失败、费用与复现

首次 `results001/` 的权重输出名遗漏任务前缀，第二任务覆盖一个 `.pt` 后在排他写 JSON 时失败；该轮冻结表因此不再有效，不作研究通过证据。`source001/candidate.py` 与完整失败工件仍保留。修复后按任务建立独立目录，使用全新 `results002/` 和 `cost002/`；没有覆盖首次失败输出。

外层完整 worker CPU：首轮失败 **21.326506 s**；修复后成功 **38.228770 s**；完整轨迹参照新增 **16.681842 s**，三轮合计 **76.237118 s**。内部 fit 定时已经包含，不再相加。该账包含本候选的导入、数据加载、拟合、执行与写证据；不包含原始媒体采集、解码、原特征准备、原头训练、开发实现和未计量探索。完整进程族峰内存和可归因焦耳仍为 null。

运行环境：Python 3.12，NumPy 2.3.5、SciPy 1.17.0、Torch 2.15.0+cpu，一个 Torch 线程；本轮没有复用 v8 的 Torch 2.9.1 运行时，因此不作跨版本性能对比。源、输入数组、历史头、每次权重均写入 protocol/input/freeze 身份记录。复现需先按 v8 说明恢复 `recovered/v3`，且必须使用新输出目录：

```bash
PYTHONPATH=/tmp/hcsn-torch-runtime "$CODEX_PRIMARY_RUNTIME_PYTHON" \
  -m experiments.hcsn_v8_execution_20261101.economics.worker_cost \
  --out /tmp/v9-av-fresh-cost --timeout 1800 --sample-interval 0.1 -- \

  -m experiments.hcsn_v9_followup_20261101.persistent_av.candidate \

```

`PYTHONPATH` 是本次只读已有 Torch 的位置；另一个机器可使用已经安装相同版本依赖的解释器。CPU 容器回放不代表 GPU、能量、真实媒体输入或生产准入。

完整轨迹参照的独立入口为 `experiments.hcsn_v9_followup_20261101.persistent_av.history_reference`；可在相同 worker 包络后替换模块名，仍须选择新输出目录。
