# 正式研究独立复核

## 判定

168 个正式作业的执行、验证集选点、checkpoint 与成本记录通过本次独立复核；这项实现及其负结果可以作为可复查的研究交付。
现有证据尚不支持用它替代 Transformer、训练大规模全模态模型更经济、或获得硬件能耗优势。
存在范围明确的正结果：同训练 CPU 预算下 MQAR 对两门模型的准确率提升，以及一个内部冻结消融对照的完整 worker CPU 节约。
这些结果必须按具体条件呈现；长度 32/64/128 使用同一批已训练模型，不能作为三个独立训练发现计数。

## 复核对象与证据

- [冻结协议](results/study001/protocol.json)：168 jobs、三个 seed、至多三个并发 worker。
- [独立逐作业读取记录](results/independent_review001/DIRECT_READ_AUDIT.json)：读取全部 168 份 summary、trace、meter 及实际 selected.pt 元信息。
- [独立汇总交叉核对](results/independent_review001/AGGREGATE_CROSSCHECK.json)：从逐作业 summary 重新计算 159 个配对的准确率区间、CPU 比区间与资格标记。
- [正式汇总](results/study001/analysis/aggregate.json)：包含保存预测的独立数值重算、数据身份及完整性审计。
- [成本范围说明](ECONOMICS_SCOPE.md)：定义完整进程、训练子项、状态内存及硬件缺测边界。

协议 SHA256 为 `643320e6d8e081df54e0ef8362de95d1eebddbd5b026f4e2373cf33d97a183c1`。
正式 aggregate SHA256 为 `06939b5da956236db7e24296e6b4af8d58347ccd2773f3099c4f4e07a6222bc3`。

## 完整性与公平性检查

168/168 个 worker 正常退出；168 个 checkpoint 的文件哈希、登记 job、模型 config、所选 step 和该 step 的训练时钟均一致。
每个 checkpoint 都保存有限的模型张量、非空 optimizer state、Torch RNG 和 NumPy RNG；所选 step 是 trace 中首次达到最低验证交叉熵的位置。
所有登记 source/data 哈希未变，固定更新作业均完成登记更新数，五种冻结分支的对应参数在最后状态和所选 checkpoint 中均保持不变。
本次逐作业硬错误为 0；正式审计也为 168/168 通过、全局错误 0、作业提醒 0。
159 个配对的独立资格计算与正式汇总完全一致；没有发现质量非劣失败却标记为 CPU 优势的配对。

固定 256 更新的合成任务、固定 64 更新的 AV，只匹配更新数及数据流，不能称为同训练算力。
默认宽度 16 时，value_dual 相对 Transformer 的训练 CPU 均值比为：selective_copy 30.05、delayed_recall 18.84、MQAR 23.73、AV 76.97。
参数数量接近并未消除这种实际计算差异；默认合成模型参数为 value_dual 4,566、Transformer 4,536。
27 个 `equal_cpu` 作业都达到 15 秒训练 CPU；实际范围为 15.000017–15.066995 秒，最大超额 0.066995 秒且均不超过最后一个 minibatch。
这些作业实际更新数范围为 140–5,587，符合预算停止规则；同训练 CPU 不能改写成同更新数，也不是同完整 worker 成本。

## 内容任务：主要负结果和局部正结果

下表是 width=16、固定更新、正常输入的三个 seed 均值；合成任务长度为 32，AV 使用完整片段。它是描述性比较，不把所有均值差都称为显著差异。

| 任务 | value_dual 准确率 | Transformer 准确率 | value_dual 完整 CPU 秒 | Transformer 完整 CPU 秒 |
| --- | ---: | ---: | ---: | ---: |
| selective_copy | 25.52% | 41.21% | 29.905 | 3.296 |
| delayed_recall | 36.46% | 100.00% | 25.520 | 4.154 |
| MQAR | 25.52% | 85.16% | 29.298 | 3.959 |
| 异步 AV | 16.67% | 19.44% | 70.132 | 3.758 |

在 15 秒训练 CPU 条件下，value_dual 的 selective_copy / delayed_recall / MQAR 准确率均值为 23.57% / 32.29% / 21.22%；Transformer 为 49.80% / 100.00% / 99.93%。
这支持“当前实现尚不能替代该 Transformer 对照”的有限结论；它不比较优化后的所有架构、超参数搜索或大规模预训练。

正式汇总有 21 个名义正准确率配对，只有 3 个同时满足参数与训练 CPU 匹配；三者全部属于 **15 秒 MQAR、value_dual 对 two_gates** 的三个长度。
其准确率提升依次为 7.62、7.62、8.14 个百分点；配对名义 95% 区间依次为 [5.94,9.30]、[2.11,13.13]、[3.25,13.02] 个百分点。
这是同一任务与同一训练条件的长度迁移结果，不是三个独立任务的胜出，也不是对 Transformer 的胜出。
另一个局部信号是固定更新的 selective_copy、长度 128：value_dual 相对 Transformer 提升 8.27 个百分点，名义区间 [2.28,14.26]。
该条件的训练 CPU 未匹配，完整 worker CPU 几何均值比为 9.01，不能据此报告经济性优势或普遍长程记忆优势。

## “三个 CPU 优势”实际对应一个内部配对

54 个条件/case 满足登记质量非劣门槛，其中 3 个还满足完整 worker CPU 比区间上界 < 1。
三个 CPU 标记全部来自 **固定更新 selective_copy、value_dual 对 freeze_boundary**，分别检查长度 32/64/128；三个 case 重用同一成本记录。
其完整 CPU 几何均值比为 0.621，名义 95% 区间 [0.407,0.947]；相应训练 CPU 未达到 ±10% 匹配门槛。
该冻结对照的可训练参数数量与完整模型不同，不能把这条结果改写为对另一个同等训练架构的普遍胜出，也不能把运行差异直接归因于某个硬件机制。
**对外部 Transformer、two_gates 或 LIF-SNN 的合格 CPU 优势数为 0。**
正确表述是“一项内部消融配对在三个质量评测情形下通过成本资格”，而不是“三次独立成本突破”。

## 真实异步 AV：接口成立，识别与缺失鲁棒性尚未成立

前端确实使用固定原媒体、视频原始 PTS、音频窗口结束时间、训练集归一化和独立时钟，共 48 个 clip、13,723 个事件，48/48 前缀因果检查通过。
训练/验证/测试为 24/12/12 个 clip，演员数量为 4/2/2；六类平衡，因此随机等概率分类的期望准确率为 16.67%。
value_dual 正常输入准确率均值恰为 16.67%，三个 seed 分别为 8.33%、16.67%、25.00%（顺序按种子可核对原记录），CE 均值为 1.981。
缺失音频和缺失视频的准确率均值都为 13.89%，CE 分别为 2.052 和 1.991；均匀六类预测 CE 为 log(6)≈1.792。
因果接口与训练流程已得到验证，但这些数值没有显示有效的多模态情绪识别或已建立的缺失模态鲁棒性。
保持接近随机水平的准确率不能当作鲁棒性证据；三个初始化 seed 也不能替代新增独立演员。
此 cohort 曾被此前研究观察过，缺失模态是保留采集时间的合成干预，不能称为新盲测确认或真实传输故障实验。

## 内存、通信与能耗

本轮完整 worker CPU 合计为 3,641.947064 秒；meter supervisor CPU 另为 95.786096 秒；调度器 makespan 为 1,750.602421 秒。
内部 training 与 inference 已在完整 worker 中，不能再次相加。一次共享解码准备、环境工作、发布等待等不在这组 worker 总账中。
单个 worker 最大 RSS 为 408,141,824 bytes，全部 checkpoint 文件合计为 15,941,921 bytes；这两个量分别是进程峰值内存和磁盘恢复材料。

同一 width16 MQAR、batch=1、no_grad 接口在长度 32/64/128 返回的 logical/storage 状态字节如下：

| 模型 | 返回状态字节 | 解释 |
| --- | ---: | --- |
| value_dual | 340 / 340 | 三个长度一致；不含输入、输出、参数与 BPTT |
| two_gates | 84 / 84 | 同样为固定大小返回状态 |
| LIF-SNN | 264 / 264 | 同样为固定大小返回状态 |
| Transformer | 未提供 / 未提供 | 该接口没有在线 KV state，不能当作 0 |

因此固定大小状态是有依据的实现属性，但本轮 HCSN 的返回状态并不小于这些递归对照，且它不证明完整推理实现或训练的常量内存。
168 个作业的 GPU、physical joules、communication joules 和子进程 I/O bytes 都没有直接观测；CPU 时间、事件数量和状态字节均不能换算为能耗。
`network_bytes=0` 只描述本地单进程执行，不是分布式通信节约的实验结果；当前没有多设备或多机验收证据。

## 复核结论的适用边界

全部区间使用三个配对 seed，未作多重比较校正；它们衡量当前固定数据与实现下的初始化变化，不覆盖演员、数据集或硬件总体的不确定性。
本次没有发现需要修复冻结源码或作废正式矩阵的实质一致性错误。需要纠正的是可能的结论扩大：局部匹配收益、内部冻结收益、异步接口成立和硬件经济性是不同命题。
后续若继续研究，应以已暴露的内容寻址能力与 AV 随机水平问题为新的研究目标，另行登记新的数据、优化预算和硬件测量；本轮结果应完整保留。
