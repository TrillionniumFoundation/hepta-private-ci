# R22 一次READ控制器独立分支复核

本复核只使用人工有限联合信念和实际索引owner探针，不调用任何新的world generator，不把这些数值控制当成任务确认样本。

## 数学政策与概率报告

政策先由第一个归一化预测分布选择标签，决策置信度为有限模型集合中该标签概率的最小值。因为阈值严格大于一半，只要通过接受门，该标签必然是每个成员共同的唯一高概率标签。**报告的四维概率向量仍为第一个正常后验**；逐坐标下包络一般不归一，不能替代它来计算proper score。

对某次READ及其可能receipt z，所有成员先承诺相同的后续标签／接受规则。其候选价值为

\[
\min_m\left\{-c+\sum_z P_m(z)\,a(z)\left[2P_m(y(z)\mid z)-1\right]\right\}.
\]

最坏成员在求完整期望之后才选，不能在每个receipt分支分别更换最坏成员。`independent_controller_check.py` 采用Python标量、逐隐状态求和的不同计算路径，未使用候选分支计算来构造参照。

明确的非矩形见证：两个成员对两种receipt的概率分别为(.9,.1)和(.1,.9)，而每个receipt都完全确定同一个对应目标。READ费用.3时，固定成员下的最坏总价值为+.7；逐分支切换最坏成员错误地得到−.1。候选选择READ，矩形化参照选择STOP，符合登记语义。

## 实际检查

48个人工信念、4个地址、4个阈值和5种费用，共3,840个条件：

| 检查 | 结果 |
| --- | --- |
| 标量分支参照的动作 | 3,840项一致，其中1,807项READ |
| 单模型退化到R18普通一次READ控制 | 3,840项一致 |
| 交换歧义模型顺序后的决策 | 3,840项一致 |
| 实际正常receipt执行（NumPy／合法list） | 4项通过 |
| 两条独立政策各自获取owner | 共2次实际索引获取，未复用其他政策的receipt |
| None／坏shape／坏schema／支持外／owner抛异常 | 5项均失败关闭，保留已发出READ的index和费用，未读目标 |
| 空集合／不对齐／丢支持／非法费用和阈值 | 9项拒绝 |

每次有效政策只向owner索引获取一次，再将同一个规范化receipt分别用于自己的模型假设。更新不修改原信念；隐藏target只在动作、receipt和更新后的后验决定之后读取。无READ时owner不被访问，费用为零。正常停止例验证了预测概率(.96,.04,0,0)与决策下界.94分别保留，未把不归一的下包络当概率。

复核中发现的两项API边界在冻结前由实现者修复：发出READ但得到None不能视为免费无READ成功；合法list receipt先转成NumPy数组，避免在读target后才因缺少`.tolist()`失败。最终失败路径以`ReceiptFailure`显式保留已发出请求的费用；研究执行器仍需把这类尝试计为无有效质量估计，而非补零收益。

最终候选控制器SHA256：`218a2e5f2d54bca07bd80cd6ae8dca50be399f516e3519faae29cd54bb066561`。完整计数与审核器／依赖身份见`INDEPENDENT_CONTROLLER_CHECK.json`；内部process_time为6.028441秒，排除解释器／导入启动。
