## 1. 为什么必须记录恢复年龄

状态过程到达零边界时计数，经历固定不应期 `d` 后从距离 `r` 重新开始。
处于恢复阶段的质量还需要知道自触发以来的年龄 `a`，因为下一次恢复发生在 `d-a` 后。
只存“正在恢复的总质量”不能确定后续状态。

在固定漂移和噪声下，第 n 次触发时间等于从 `x+(n-1)r` 出发的首达时间，加上 `(n-1)d`。
因此在时刻 H、年龄 `0<=a<d` 的恢复密度为

\[
\rho_H(a)=\sum_{n\ge1} f_{x+(n-1)r}\!\left(H-(n-1)d-a\right),
\]

其中首达密度在非正时间处取零。本轮分别积分此密度的四个年龄分箱及 `1,a,a²`，
再与独立前向差分方程产生的吸收流量队列比较。前向方程没有使用解析事件数驱动复位。
队列使用年龄有限体积表示，每个时间步的触发质量在相应年龄区间内均匀重构；这是一项数值近似。

连续参考的年龄矩还与未修改的 R12 `regenerative_successor` 积分交叉核验，避免把新写的
前向队列同时作为自己的真值。解析年龄恒等式与具体浮点积分误差、网格误差分别处理。

## 3. 完整 checkpoint 与真实新进程恢复

每个 checkpoint 保存活动位置概率、完整恢复队列及其游标、当前物理时刻与整数步数、
累计事件数、累计上壁流失、参数与网格身份，以及序列化 payload 的 SHA256。
恢复时同时核对字段、数组形状、有限性、概率非负、质量、时钟、游标与调用方期望身份。

观察分段取总步数的 `.13/.37/.61/.89` 后向下取整，实际整数步和时刻均记录。
两组参数、三个网格共 24 次中途状态均实际写入 JSON 再读取，之后继续推进。
六组最终完整序列化状态与一次推进结果逐位相等。

另外，从两组最细网格的 `.37` 中途文件启动全新 Python 进程继续运行，最终活动分布、
恢复队列、计数、损失、时钟和完整序列化状态也全部逐位相等。子进程 stdout、stderr
和最终 checkpoint 分别保存在对应 `case_*_grid_2/` 目录。

**这里的逐位相等仅限同一个已固定的空间／时间网格。** 它证明在观察分段时不会清空或
重建物理状态。非对齐时间请求被明确拒绝；没有把任意重分格、插值或改变时间步说成精确一致。
对目标连续过程的准确性由上一节独立年龄参考及三网格细化另行支持，不能从实现自身一致直接推出。

## 6. 对下一轮模型工作的实际约束

本轮提供了一个可审计的完整再生状态表示和可恢复参考实现。后续内容训练、价值估计和原生
执行若要声称使用同一个过程，应保留等价的活动分布、恢复年龄与实际剩余时间，并在自己的
实现中重新通过相应跨层验证。

本结果没有将固定 `1-exp(-E[N])` 内容门变成完整概率状态；没有证明其训练收益、`D-B`
净优势或任意观察重分格一致性。零不应期、初始边界原子、随机／状态依赖／学习移动边界、
金融停止核与复位 QVI 的等价、完整循环内容训练及 GPU／物理能耗，均保持未验证范围。
这些限制是本次验收的明确边界，不应把数值线的通过结论借给其他模型。
