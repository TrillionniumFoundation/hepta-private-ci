This runner is a disclosed development procedure for the same fixed Qwen and
16 task episodes. The seven adapter-delivery files were copied byte for byte;
their original protocol, validation receipt and manifest remain intact. This
candidate adds `run.py`, `protocol.json`, `check_wiring.py`, this document and
`required-inputs.json`. No new model or tool execution is part of preparing it.

identifies the **old worker protocol**, while request-context protocol digests
and the new result identify the **new procedure protocol**. Both are recorded.

## Deterministic checks, without inference

From the repository root:

```bash
python -B -m experiments.multimodal_output_portfolio.joint_hepta_20261029.v3.ndu_json_transport_20261106.check_wiring \
  --runtime /workspace/scratch/3f6a885bb83c/round3_resources/followup_lm
```

This check requires that `freeze.json` does not yet exist. It verifies the exact
future input inventory, original worker/configuration, public task projection,
fixed 16-episode schedule and prompt hashes. Ten synthetic transport scenarios
cover qualification, SQL/source dispatch wiring, exact-verifier zero versus one,
format and parameter rejection, tool failure, deadline and budget refusal, and
the retained original `legal_payload` guard. The transport and host meter are
replaced by local stubs; `subprocess.Popen` raises if anything attempts to launch.
These are wiring checks, not observations of model or tool success.

The gate requires a successful qualification under the exact new procedure and
freeze, one real model response and unchanged artifacts. An old qualification
cannot satisfy it. Qualification remains outside task denominators. Failure
retains its receipt and lists 16 task episodes as not started; do not retry or
change prompts. A task run attempts the same fixed 16 episodes without selection.

## Failure, timing and cost semantics

Each decode records stage, schema, raw-text hash, body hash, envelope and original
value. On rejection the raw response remains in the model receipt; body/envelope
fields are null because no accepted decode exists, with the rejection code
recorded. Plan-schema or original parameter-guard failures are `parameter_failure`;
other JSON/envelope failures are `format_failure`. Answer-schema, model, tool,
verifier, deadline and budget failures remain distinct. Actual command dispatches
are separate from admitted request counts. Delivery and exact correctness are
separate summary fields; a verifier score of zero is never counted as correct.

Every admitted request retains the existing durable intent/terminal ledger.
The host meter includes decoder time; CPU and full wall time are retained even
on failure. Completion has its own monotonic timestamp and must precede the
episode/global deadline; later host-ledger cleanup remains part of measured
resource cost. Calls remain bounded by one qualification, 24 task model calls,
eight task-tool calls and 16 verifier calls. Request, tool, episode and global
deadlines retain their original values. Unknown monetary costs remain null.

This procedure does not alter prior failures, expose oracle data, search models,
or establish NDU gain, independent confirmation or positive net benefit.
