# C 子实验审查：有源时间戳的因果 AV 流恢复

## 结论与范围

**原登记的工程收益门通过；结论限于固定超时家族 `{80, 240}` 中由 fit 数据选择的 240 ms 比较策略。** 后续发现 240 ms 存在可改进的固定基线：按已冻结网络律，非永久丢弃 packet 的最大延迟为 220 ms。唯一新增的 **220 ms 事后诊断**保留了原 240 ms 的全部媒体选择并减少模拟等待，反馈相对它的描述性 NDU 差仍为正。原确认性比较与事后描述性比较的性质不同；两者均**没有证明反馈控制的必要性或全局最优性**。

本轮使用真实 GRID 音画、真实 FFV1/PCM MKV 文件及实际逐帧/PCM 回读，网络到达、丢包和交付时钟则是模拟的。它建立了这一传输控制子实验的工程证据，**没有建立独立唇音同步、延迟共享语义生成收益或原生音视频联合生成训练；不能视为完整科学实验 C 通过。**

## 设计与证据

原流程在 31 个独立 speaker 中分为 10 fit、5 calibration、16 evaluation，每人固定一个真实 clip。正式评价保留每个 evaluation speaker 的 4 个网络情境和 3 个策略，共 192 次实际媒体执行；推断的独立分组数是 **16**，不是 64 或 192。4,000 次 bootstrap 将每个 speaker 的全部情境和策略共同重采样。

控制器只接收已经到达的 headers、当前队列及观测到的历史延迟；source PTS 是公开且正确的。已提交内容不能重写。缺失 packet 使用预设 placeholder，但仍计入 source 交付损失；内容回读 fidelity 与 source 交付 coverage 分开评价。

正式执行的 192 个 MKV 全部完成并通过回读，0 个系统失败。产物复核确认 565,504,105 bytes 的实际 MKV、14,400 条提交记录（192 条逐序哈希链）、14,400 帧视频和每声道 25,214,976 个音频 samples；末尾短音频块没有截断。逐文件 SHA、真实 clock receipts、服务计时及完整原结果见 [CAUSAL_AV_EVALUATION.json](../../CAUSAL_AV_EVALUATION.json)。来源及资格链分别见 [TEMPORAL_SOURCE_RECEIPT.json](../../TEMPORAL_SOURCE_RECEIPT.json) 和 [CAUSAL_AV_READY.json](../../CAUSAL_AV_READY.json)。

## 原登记比较与事后比较

损失结合 source 交付、有效对齐覆盖和模拟等待，风险参数为 eta = 4。下表中的联合交付指标是每个 episode 的 `q_video × q_audio`，其中音频 coverage 按实际 source samples 加权；它不是“整个 clip 无丢包”的二值成功率。

| 指标 | 原登记固定 240 ms | 事后固定 220 ms | 原登记因果反馈 |
|---|---:|---:|---:|
| NDU，越高越好 | −0.172027 | −0.167215 | −0.160625 |
| 平均损失 | 0.155186 | 0.152030 | 0.150479 |
| P95 损失 | 0.329534 | 0.316812 | 0.265257 |
| 联合 source 交付 coverage | 93.7565% | 93.7565% | 92.5076% |
| 平均模拟交付延迟 | 126.017 ms | 122.229 ms | 108.500 ms |

**原登记比较：**反馈相对固定 240 ms 的 NDU 差为 **+0.0114011**，speaker bootstrap 95% CI **[0.00786523, 0.01521916]**。联合交付 coverage 实际下降 **1.2489 个百分点**，95% CI **[−1.4511, −1.0485] 个百分点**；该下降仍处于预注册 **−2 个百分点**非劣界内，因此工程收益门通过。该结果表示预定效用下的取舍改善，不能表述为交付无损或所有指标同时改善。

**事后描述性比较：**反馈相对固定 220 ms 的 NDU 差缩小为 **+0.00658909**，同样按 16 个 speaker 配对的 4,000 次 bootstrap 得到描述性 95% CI **[0.00358871, 0.00985383]**。coverage 差及其区间与原比较相同，因为 220 ms 和 240 ms 的实际 payload 选择完全一致。这没有创建新的确认性过门，也没有更改原 192 次执行、原 CI 或原 positive gate。

## 为什么增加唯一的 220 ms 诊断

原固定基线只在 80/240 ms 中选择，并未覆盖完整可行固定超时集合。已冻结网络律中，情境 0/2 的非丢弃延迟至多 60 ms，情境 1/3 至多 220 ms；情境 3 的 late 与 burst 项只叠加一次。220 ms 是 20 ms 决策网格点，末尾短音频 packet 的 release 又早于对应视频 slot 的 release。因此，固定 220 ms 可保留固定 240 ms 的全部可交付 packet，并逐 slot 不晚于其提交。

诊断只增加这一由原网络上界推导的常数，没有网格搜索、重拟合、样本替换或新 holdout。它先使用独立闭式公式精确复现原 64 个 source/scenario cells 的 240 ms 每 slot 提交时刻、delivery flags 和损失，再推导 220 ms。全部复现及同 payload 检查通过；220 ms 的单 slot 提前量最多 20 ms。

独立方法审查发现并在诊断执行前修复一个证据绑定缺口：**240 ms 的相同动作并不能唯一确定原到达表**，前序缺包的等待可能遮住 arrival 差异。因此，实际诊断还要求所有 finite packet headers 与原已 hash-pinned 240 ms `public_trace` 中 `arrived_headers` 的完整去重集合精确一致。专门 fixture 证明可以构造“240 动作不变、220 动作改变”的漂移，并确认新绑定会拒绝它。四个合成 fixture 及 `just fmt` 均通过；此前准备记录保留。

## 实际媒体、模拟时间与成本

MKV 中的 media PTS 保留 source clock；虚拟 commit/delivery 时间单独保留在 ledger 中，没有写成媒体播放时钟。正确 source PTS 的匹配配对使有效部分的条件时钟误差为 0，这是结构性质。缺失部分通过有效对齐 coverage 和缺失惩罚计入损失，不能算作完美同步。该条件时钟结果不能用来证明生理唇音同步改善。

220 ms 诊断**复用原 240 ms 已实际回读验证的媒体**，只派生不同的虚拟交付时间；它没有再次写出 append-only 媒体、没有生成新 MKV、没有新 codec 或服务时间测量。因此下表不为 220 ms 填入推测的实际耗时：

| 原实际执行的服务 wall time | 固定 240 ms | 固定 220 ms | 因果反馈 |
|---|---:|---:|---:|
| P50 | 1.221283 s | 未测量 | 1.220877 s |
| P95 | 1.403182 s | 未测量 | 1.424562 s |

原 192 次正式评价整进程 wall 为 **239.818279 s**、CPU 为 **225.547568 s**；codec pilot、完整 fit 网格、35 次 calibration 与正式评价四阶段合计 wall **291.854759 s**、CPU **276.526101 s**。来源准备及失败尝试另有完整回执。事后元数据诊断自身整进程 wall **0.419114 s**、CPU **1.061122 s**，与原服务时间分开记录；这些诊断计算量不能冒充 220 ms 媒体服务性能。

## 仍未证明的主张

更强的 220 ms 基线削弱了原观察到的反馈优势，但其余可行固定超时以及其他开环时变策略并未被完整比较。220 ms 也未被证明是当前风险效用下最优的固定超时。因此，当前结果提供有限家族的原登记证据和单一补充基线的事后敏感性证据，**不支持“只有动态反馈才能获得该收益”**。

这次试验的不确定性来自模拟 packet 到达与丢弃，政策也没有修正共享语义或生成新语音、视频内容。自然唇音同步的独立观察器资格、延迟共享语义的跨模态收益、原生生成器联合训练与开放场景外推仍需各自的新设计和独立证据。
