# Hepta development

`main` is the single development integration line. Module work must name an exact `main` commit and tree as its integration baseline rather than selecting an older implementation, archive or diagnostic branch by name. Retained historical refs are provenance, not competing development authorities. Ref retention and cleanup do not establish qualification, acceptance, runtime activation or release.

The sole global development authority remains [`docs/DEVELOPMENT.md`](docs/DEVELOPMENT.md). Its recorded administrative default at the V8 cleanup baseline is historical provenance; changing the repository's live default branch is a separate repository-administration action and must be verified from GitHub.

Module teams start at [`docs/modules/README.md`](docs/modules/README.md), which links the forty stable technical development guides and their closed-world source-binding index. These specifications remain subordinate to the one global plan. A source directory, canonical alias or external-source pin is not a production integration. The sixteen newly imported module candidates do not change existing work-package decisions: original pending execution, semantic review, physical and independent-acceptance requirements remain in force. Section 17 source-location receipts in module guides are not test-pass receipts.

The exact incremental import and conflict decisions are recorded in [`qualification/main-consolidation/SOURCE_IMPORT.json`](qualification/main-consolidation/SOURCE_IMPORT.json). The additional read-only consolidated-source workflow checks the sixteen Rust packages through the repository's `just test` entry point. Existing product, source-owner and learning qualification gates are retained; none are waived by consolidation.

Adaptive and longitudinal specifications start at [`docs/learning/README.md`](docs/learning/README.md). Paper evidence is recomputed from the original pinned commit retained in `main` ancestry, not from a mutable side-branch name or verifier constants. Preserve that ancestry in subsequent merges and recovery.

The distributed CNS, organ graph and embodied-control extension starts at [`docs/cns/README.md`](docs/cns/README.md). HNMF multimodal memory starts at [`docs/hnmf/README.md`](docs/hnmf/README.md). Both are qualification/reference layers and grant no production, physical-effect, acceptance, promotion or release authority.

Implementation state machines, typed readiness protocols, all-module lane bindings, embodied-control semantics and authorized external-system assimilation start at [`docs/readiness/README.md`](docs/readiness/README.md). There is one current document set, with module-specific detail retained rather than flattened or duplicated into competing plans.

The implemented HeptaBao connection starts at the [HTTPS consumer guide](codex-rs/hepta-bao-adapter/README.md) and [kernel final-use / independent issuer design](codex-rs/hepta-contracts/FINAL_USE.md). These describe the explicit host call point, signed operation binding, durable replay/revocation state, failure semantics and real service verification. [The external source record](external/HeptaBao/README.md) pins the reviewed service candidate. This bounded connection does not automatically enroll a global production caller or establish complete OpenBao replacement.
