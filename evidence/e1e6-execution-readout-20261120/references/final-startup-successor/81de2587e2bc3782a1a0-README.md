# NoUpdate15：完成验收拒绝的有限独立复核

**结论：8ce 的完整 NoUpdate15 父测试真实失败。当前原件把错误定位到完成验收的 Root handler 内，但没有保留该 handler 返回的原始内层错误，尚不足以支持一个具体行为修复。** 本复核不改源码、预算或验收，也没有新宿主调用、测试、模型调用或重放。

## 实际结果与边界

本轮原 7 组共 65 个组件用例、2 个 Root completion 组件和 1 个 Root lane 机制父通过；完整普通父为 1 FAIL、0 error、0 skip。这些组件通过没有转移为完整父或 cold 资格。源码为 `8ce582b0a8619ff9250bc3a0098456112110ef82`，tree `698ebaaf9cd8706a1850e2531aeb0bc2c37a1f25`，实际完整源码库存为 `019cee0f93b88145076b4a837c2bbdfdbd77181eeafa91dd35e622b1ace41d72`。

计时分开保留：testcase 99.065 s，nextest suite 99.072 s，原命令 99.79600353678688 s，wrapper 234.2414841419086 s，完整 pipeline 375.55694728996605 s。这些范围嵌套，不能相加。命令 `timed_out=false` 只说明执行器没有整体超时，不能排除内部 500 ms 上界内的某个原截止检查失败。source/tracked/compiler 身份、挂载 cleanup 和原单 ELF build-mode 恢复均为实际 true。

## 本轮确实走到了哪里

- A observer 的原 child 为 1 PASS；A Objective 的 receipt/publication/observation/RunStart 返回，A Root 原 stdio 无错误。原父成功返回 A 后才进入 post-A 路径。
- 独立 B source child 为 1 PASS。post-A 日志有 restore、Training、Evaluation、Selection、NextUse 的真实阶段记录。
- C 局部 Objective 日志确有 receipt-returned、publish-returned、observe-returned、final-run-start-returned；对应局部 elapsed 分别是 5,464,879 / 5,469,348 / 5,469,752 / 5,469,978 µs。
- historical 请求是连续 1…64；第 64 次 purpose 为 `runtime.learning.completed-acceptance.v1`。Root 进入其 handler 后拒绝；没有请求 65/read-limit 标签。
- **内部 NextUse 阶段和 C 局部 Objective 返回不等于外层 C 完整验收。** first acceptance ACK、成功退出后的 C 验证、cold D、Adopt、FinalUse/实际结算均未据此获得资格。

## 错误标签真正表示什么

Root 原 572 B stderr 的链为：`historical_task.recipient_action → historical_ledger.recipient_action → historical_ledger.refusal_context → historical_task.ledger/run_start/source_cell/handoff → historical.route_accept_completed → historical.observe_complete_task → peer.handler(ThreadId(15)) → historical.worker → cli.serve → Unavailable`。

`authority_host_historical_task.rs` 的 `RecipientAction` 标签在第 124–128 行包裹 **整个 caller action**。AcceptCompletedLearning 的 action 又包含 fixed 输入、原 task/profile、B、publication、7 个 journal、签名、first-acceptance 与多重 postcheck。因此该名称不能被解读成“已经证明 recipient 身份失效”。`authority_host_historical_read_runtime.rs` 第 197–211 行把 `observe_complete_task` 的所有原始 `io::Error` 映射成通用 `Unavailable`；当前日志没有更内层的错误分类或原因。

`peer.handler` 出现在 handler 调用点，尚未到 post-handler owner、response header/body 写入。本轮 **没有** 上一轮 `peer.response-header-write/detail`，没有相关 errno/revents，也没有 `ROOT_OBSERVATION_DIAGNOSTIC` unfinished-frame 标签。缺少这些标签不能证明旧 header 问题已修复，只能说明这次观测到了另一条拒绝路径。

A 和 post-A daemon 都有 session-drop/worker-drop 日志。这是原 fence/abort/drop 路径的观测，不是跨进程时间戳。不得将输出排列顺序或最后的 child lifetime dead 消息当作首因，更不能凭它们认定客户端取消造成 Root 拒绝。

## 当前源码能够进一步限定的事实

`CompletedLearningRecord::accept` 在 `action()?` 成功后才 initialize 首次接受事实。因此此次 callback Err 不能通过该调用创建成功的 first acceptance。这是控制流结论；本复核没有读取本轮物理 frontier，不能把它写成“物理文件已证明不存在”。

针对新 C drain 的有限交叉核对：同步 drain 在真实 submit 完成之后、generation 安装之前；`AcceptedPublication` 明确令 successor=None，不进入仅冷历史 successor 分支的 `require_original_next_use`。其直接 physical guard 要求 previous drained、核 target owner/genesis/稳定性，没有直接要求 target 必须未 drained。因此未发现“C 一 drain 就必被 AcceptedPublication 拒绝”的直接源码矛盾。这也没有证明所有被委托 helper 和本轮物理状态全兼容。

所有 22 份源正文均逐字对本轮 actual inventory 验 SHA/长度后保存，见 [SOURCE_PINS.json](SOURCE_PINS.json)。没有以旧源标签冒充当前源。完整结论与具体源码锚点在 [READOUT.json](READOUT.json)。
