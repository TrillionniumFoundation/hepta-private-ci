# E6「实际结算」入口与现有证明范围

**现有原件尚未把本轮 E6 绑定到独立的实际结算主测试和原付款凭据。即使后续 ordinary NoUpdate14 或 cold fresh D 通过，也不能据此把 settlement 资格改为通过。** 本次找到仓库内真实的结算实现及原测试，但它们的职责和当前学习实验必须分开。

这是只读源码审计：private 固定 `1a9799686243c2be0ee393ba364e091029cfb944`，Chain 固定 `de5f5766fe44fdc42507afe14b30873060c9e4d2`；另复用已核的 dbd6 FinalUse 源。17 份精确 GitHub 源码/API 原件和复用原件均保留。新增宿主、模型、训练、Cargo/native、测试、签名、凭据读取和 Git 变更均为零。本报告没有重跑所列测试，也没有改变原预算或制定新的 E6 验收。

## 1. 原 E6 明确保留的边界

[README_ADOPTION](local-originals/README_ADOPTION.md) 的 Explicit qualification boundary 明确：研究 journal 不能代替 CellOwner/agentd/HEPLCP 原件，不能授权链上结算；`settlement_verified`、`hepta_final_use_accepted` 等保持 false，权限为 DENY_ALL、资格为 HOLD_NO_GO。[adoption.execute](local-originals/adoption.py) 原代码保持这些字段。

[1a979 原 native 协议](local-originals/PROTOCOL_1a979.json) 的主测试为 `ordinary_main_retains_after_completed_independent_b_and_executes_original_c`，业务门是实际 Training、独立 B 的 Evaluation::NoUpdate、保留原 bundle、实际 C 与原 owner 退休；`qualification_limits.settlement_eligibility=false`。原 64 historical 预算和期限不变。[原 joint CURRENT](local-originals/CURRENT_PROGRESS_e4b_original.json) 也把 FinalUse 与 settlement_eligible 分列为 false。

最初 E1–E6 总冻结计划的精确原件当前未定位，因此不能把下面发现的独立原测试自动解释成该计划已经指定的「结算主测试」。准确状态是：**现有原件未绑定到该结算主测试**，而不是整个仓库没有结算功能。

## 3. 已找到的真实实现与原测试

AuthBus 的 signed claims 包含 issuer/key epoch、reservation、operation、Completed/Rejected、observed_cost、terminal evidence digest 和有效时间。原实现检查签名及这些身份、状态、成本上限与幂等性，再持久更新 reserved/consumed/available 和 reservation revision；host 返回前同步 authority checkpoint。原 [settlement_store_tests.rs](source/private1a/codex-rs/hepta-authbus/src/settlement_store_tests.rs) 中 `completed_settlement_is_conservative_and_idempotent` 覆盖正常结算、精确重复与 drift 拒绝。

更完整的原产品组合在 [Bao consume_kv_v2_with_authbus](source/private1a/codex-rs/hepta-bao-adapter/src/https_consumer.rs)：授权、reserve、dispatch fence、真实 Bao use、签名终态、quota settlement。其 [原测试](source/private1a/codex-rs/hepta-bao-adapter/src/https_consumer_tests.rs) `authbus_product_path_reserves_fences_final_use_and_settles_observed_cost` 和 `authbus_timeout_keeps_quota_held_as_indeterminate` 分别检查结转与不确定效果继续占用配额。**这是 Bao KV-v2 请求的配额产品测试，不是当前学习迭代的链上结算主测试。**

Chain 的原集成测试文件为 [native_task_operation_v2.rs](source/chain-de5/trillionnium/crates/trnm-pon-node/tests/native_task_operation_v2.rs)。`unknown_output_uses_native_once_fence_and_real_delivery_on_both_backends` 包含原 delivery/payment 路径；`current_paid_observation_rechecks_original_receipts_and_settlement_on_both_backends` 在 Legacy 与 Authenticated 两后端覆盖 same_operations、alternate_payment、alternate_receipt、refund、expiry。其 helper 确实在开发 Node 上签名并挖入 reservation、delivery 和 payment transaction，再读取原 journal/Node；资源值与客户密钥属于 fixture。这些名称是已有 source test anchors，**本审计没有执行它们，也没有它们与本轮 E6 同 operation 的新运行证据**。

## 4. 现有跨仓桥还缺哪张凭据

[原 business contract](source/chain-de5/docs/development/CELL_LEARNING_BUSINESS_READBACK_V1.md) 已规定 request/result 两个域：原 funded contract 的 `terms.request` 必须预先绑定学习 operation、invocation、source pair、初始 checkpoint、task receipt、冻结 evaluation profile 和 incumbent；原 native output 必须绑定该 request、completed head、Selection/NoUpdate、完整 bundle、下一 task/input、committed step 和 cost source。历史合同不能靠补 metadata 改成预先承诺。

该文档对两条保留学习例明确写 **`economics: []`，没有原 funded mapping**。已有 reader 的测试使用显式 synthetic funded mapping 只检验 parser，不能算训练或付款实验。现有 native paid export 的 monetary profile 为 `funded-service-contract-dev-v1`、单位为 `native-development-ledger-unit`；历史付款和当前付款观察不能相加成两次收入。

若原 E6 的「实际结算」指这条原生 Chain 合同，则仍需要绑定**同一次原学习 operation 的**原 funded request、真实 completion/delivery/payment operation、原支付主体/受益人/金额，以及原 Node/M12 的当前已付款观察（checkpoint、anchor、current branch membership、Settled/remaining 0）。现有 Python bridge 只能检查这些原件的结构一致性；它不能认证来源或补造支付。另 [chain_hepta_qualification.py](source/chain-de5/scripts/ci/chain_hepta_qualification.py) 已有单独 payment stage，检查原 effect intent、operation 与 `COMMITTED`；即使 supplied diagnostic flag 为 true，该只读 v1 仍不授予 GO。

**因此需保留两个未闭合点：原 E6 总协议究竟绑定哪个结算测试/原 owner；该 owner 对本轮同 operation 的真实 receipt 是否存在且被认证。** 这是对现有合同和现有证据缺口的定位，不是新增实验授权、补充预算或要求立即执行独立付款测试。独立 NoUpdate/Adopt/cold/FinalUse 成功都只能按其原测试范围记账。

精确源 SHA、Git blob、URL、符号及定位范围见 [SOURCE_ANCHORS.json](SOURCE_ANCHORS.json)；机器可读结论和未绑定项见 [READOUT.json](READOUT.json)。本报告不使用全局字符串未命中证明功能不存在，检索默认分支仅用于发现路径，结论仅依上述明确固定源和原件。
