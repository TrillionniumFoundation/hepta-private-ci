## Architecture and security

The Rust candidate has a target-neutral core and a framework-free semantic DOM
host. eframe 0.36.2's web integration discards AccessKit updates and does not
preserve the existing semantic accessibility contract. The canonical native
application remains eframe; this candidate adds no native framework.

The browser retains same-origin cookie/CSRF authentication and backend-owned
idempotency, admission and terminal facts. It receives no native keyring,
loopback bearer credential, runtime authority, OS capability dispatcher or
production update authority. All app logic is Rust; generated bindgen ABI and
bootstrap, HTML/CSS assets and qualification tooling are inventoried separately.

The browser theme is generated from Rust presentation tokens using the native
candidate's palette. Semantics, visible focus, reduced motion and forced-color
support remain. Native consumption waits for branch convergence.

## Independent adversarial fixes in this port

The following were caught during review of the new Rust source, not asserted as
unfixed defects of the current JavaScript candidate:

- Preserve an adapter's existing-record ambiguity instead of overriding it as
  definitely unsent and deleting the local reservation
- Treat verified already-absent terminal records as successfully settled cleanup
- Schedule session refresh independently from runtime polling so short sessions
  cannot starve snapshots, recovery or maintenance
- Reject forbidden object keys before acting on rejection ACKs or terminal
  observations; malformed rejection remains indeterminate and retains identity
- Normalize JS integer-valued decimal fields on recovery import and compare
  persisted numeric identity using JavaScript Number semantics
- Advance authenticated observation incarnation on every successful refresh,
  including byte-identical session envelopes
- Epoch-fence all asynchronous UI finalizers and reset busy interaction state
  when closing/reopening the same controller
- Release the application borrow before readiness event dispatch; read-only
  reentry cannot panic the WASM instance
- Propagate fatal recovery failures into startup readiness rather than reporting
  ready after the session was invalidated
- Close local authority for every SessionProvider authority-loss category,
  including CSRF preparation permission denial without an HTTP 403
- Enable serde_json float_roundtrip after the actual JS oracle exposed a
  near-safe-integer decimal rounding mismatch

The Rust core deliberately has no public raw terminalObserved reconciliation
entry. Only a session-bound authenticated lookup completion can advance local
terminal presentation. This is a safer boundary for the new Rust API; it does
not imply the old public trusted-caller API was an exploitable browser route.

## Unresolved execution gates

Actual browser execution did not start locally: system Chromium was rejected
at its process socket before page load, including the approved escalation path;
the Playwright Chromium archive was truncated. Firefox and WebKit downloaded,
but Firefox subsequently exited before page load with "Could not find profile
folder". WebKit lacks runtime libraries and system package-manager directories are
not writable here. The supported cloud browser also refused the isolated
loopback fixture with ERR_BLOCKED_BY_CLIENT. These are failures/limits, never
application passes. No browser screenshot or accessibility acceptance is
claimed for this Rust cut.

The additive `ui-control-rust-parity.yml` workflow is restricted to this task's
push branch, read-only permissions and explicit Rust artifacts. It resolves one
immutable integration base for both subjects and validates ordered parents,
trees and exact input hashes separately from the frozen JavaScript oracle.
It neither replaces JavaScript production CI nor creates/comments on PRs,
deploys, uses secrets or issues release authority.

Before any caller cutover: run all 72 real-browser cases and fault regressions,
review accessibility/visual results, resolve remaining compatibility gaps,
refresh source maps against the actual candidate and qualify the deterministic
merge. Native integration, public package ABI migration, deployment security,
real backend execution, independent acceptance and production release remain
separate gates. No handwritten JavaScript product entrypoint was deleted.
