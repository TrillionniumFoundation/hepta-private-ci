# Neuron DecisionCell five-arm bakeoff (experimental, no production authority)

Run from this directory with Python 3.10+. `bakeoff.py` uses only stdlib. `run_live.py` additionally requires a separately reviewed, version-pinned `laya` or `sentence-transformers`/NumPy/Torch environment. CI deliberately runs no downloads, model weights, GPU jobs, or model promotion.

## Contract and staged operation

1. Clone `plan.template.json`. Before collecting test results, freeze the *actual* Git SHA, correlation-group/time-separated train/calibration/future_1/future_2 corpus, independent observer, threshold, runtime/toolchain, full model repo commit/revision, tokenizer, model files, Head and license review. Replace every `null` and pending review with an independently verified value. The template intentionally fails validation. `source_head` is the 2026-10-16 repository baseline, not a claim about later releases.
2. Each gold JSONL row contains `id`, `source_group`, `split`, positive integer `timestamp`, `task_family`, `language`, `ood` boolean, `options` (two to 32 choices), `label` (one option) and optional `state`. Source groups must not cross train/calibration/future windows. Times of future windows must be strictly later than training and calibration. Do not train on holdout labels or re-select thresholds using future outcomes. Dataset SHA-256 is the byte digest of the frozen JSONL.
3. Supply offline checkpoints and an exact `files_sha256` inventory for each local model directory, including tokenizer/config files. `weights_sha256` is SHA-256 of UTF-8 JSON `[[relative_filename, file_sha256], ...]` with sorted weight filenames and compact separators for files ending `.safetensors`, `.bin`, or `.pt`. This is a *manifest digest*, not a single-file hash. `run_live.py` refuses missing/unlisted/modified local files and does not download weights. The approved runtime's actual hash remains an independent gate.
4. For Arctic and Harrier: `run_live.py fit --plan PLAN --model arctic-305m --checkpoint DIR --gold GOLD --output HEAD.json` (then repeat for Harrier) trains one bounded, deterministic softmax scorer on **train only** with identical SGD steps/seed/lr and frozen encoder. The tool emits the head SHA-256. Pin each `head_sha256` before inference; training time, token counts and actual compute must also be compared externally. A common step budget is not evidence of identical FLOPs.
5. Export a **blind** inference JSONL with only `id`, `state`, `options`, `language`, `instructions`, `split` (calibration/future only). There must be no gold labels, independent outcomes or hidden evaluation-only metadata. For each model run: `run_live.py predict --plan PLAN --model laya-english --checkpoint DIR --blind BLIND --output EN.jsonl`; encoder arms additionally pass `--head HEAD.json`. Concatenate all five output JSONL files. The Laya adapter uses typed `choice` questions; the encoder adapter uses state/option embedding interactions and its trained Head. These two interfaces are *not* assumed equal in capacity. For Arctic custom code, the reviewed/pinned `--allow-reviewed-remote-code` must be explicitly opted into; otherwise it fails closed.
6. `python3 bakeoff.py --plan PLAN --dataset GOLD --predictions ALL.jsonl --resources observed_resources.jsonl --lifecycle owner_receipts.jsonl --out report.json --fail-on-blockers`. The default analysis output does **not** grant model promotion. Resources require each of 64/256/1024/4096 logical-cell profiles for every arm, with `active_cells`, `host_id`, `driver_receipt`, `origin=observed-target-host`, `cpu_rss_peak_bytes`, `gpu_peak_bytes`, `throughput_per_sec`, `p95_latency_ms`, `p99_latency_ms`, `load_latency_ms`. Distinguish a logical cell count from concurrent execution. Lifecycle input includes real `artifact-cas`, `generation-fence`, `signed-final-use`, `rollback`, `restart-recovery`, `old-generation-rejected` events **per model**. JSON labels or digest strings alone do not verify actual signatures, CAS, fencing, revocations or hardware.

## What the analysis certifies (and does not)

The scorer verifies exact candidate/sample coverage, byte-frozen corpus, no source-group/time leakage, finite normalized probabilities and exact pinned runtime identity *declarations*. Calibration temperature is selected from a fixed grid using the separate calibration set. It reports future-window accuracy, macro-F1, multiclass Brier score, ECE (10 bins), NLL, OOD false acceptance, latency quantiles, per-source-group paired bootstrap gain intervals, subgroup support and old-task/language negative transfer. Gates require at least 400 independent source groups and 400 OOD groups per future window, positive lower confidence bound, OOD FPR <=0.005, no subgroup degradation >2 percentage points and fully observed resource scales. Baseline is fixed (`laya-english`); compare the typed-specialized checkpoint without mistaking vendor-trained performance for equal-budget head learning.

This tool is a **non-authorizing, research-only evidence consumer**. It cannot independently authenticate inference-driver receipts, training corpus provenance, Hardware/OS/GPU telemetry, independent outcome observers, ed25519 final-use signatures, immutable Artifact CAS, Generation Fence, or process-kill recovery. Such facts must be verified by the existing Hepta owner/issuer/verifier and trusted host. Consequently `production_qualified` is *always false* by design, even when all supplied fields look valid. Do not replace Hepta's actual artifact acceptance, security approval, NDU selector, operator approval, canary, promotion or release gates with this script.

### Local regression

`python3 -m unittest -v test_bakeoff.py`. These deterministic tests are **synthetic protocol fixtures**, not a score of real Laya, Arctic or Harrier weights.
