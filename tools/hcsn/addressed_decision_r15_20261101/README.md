## Experimental scope

This research continuation fixes explicit address binding before testing whether
conditional dynamics change valuable downstream actions. It derives its full-HX
financial parameterization and finite phase/recovery process from the exact
R14 base `ad32ceac6972e811ce74802ab5c44dc63b40bd4b`. The concurrent shared-address
neural study at `63b348005c468e29e89f9f309d525d87661ee06b` is an architecture
reference; its 51-fit campaign is not rerun or represented as this experiment.

Here typed addresses and WRITE/DISTRACTOR routing are supplied to every core.
They isolate the state/control question and do not establish learned semantic
binding. Four contents are tracked at four addresses through six queries,
including revisits, public overwrites and distractors. Every query has a fixed
deadline shared by all methods. A common Gillespie world tape prevents different
actions from silently changing the target. Every elapsed interval advances all
addresses, including those not currently queried.

READ is a noisy paid observation. REFRESH is a slower, more expensive and still
noisy observation. Neither changes the world or resets its content to truth.
Internal reset without new evidence is separately checked as information loss;
natural finite-state recovery is included in the common generator.

`PROTOCOL.json` is controlling. `law.py` owns the frozen finite model, `world.py`
the hidden execution world, `planner.py` causal memories and the shared bounded
controller, `calibration.py` raw-observation likelihood fitting, and `execution.py`
the real action/fee loop. Same-matrix HMM equivalence is mandatory. The finite
model is distinct from an exact continuous diffusion and from original financial
optimality. The current-query controller is not globally optimal across all six
queries. Production Rust, low-precision and device/energy qualification remain
separate work.

Reproduction uses Python 3.12, NumPy, SciPy and threadpoolctl. Invoke modules from
the repository root with `OPENBLAS_NUM_THREADS=1`. Source, training, freeze and
confirmation commands and exact commit identities are recorded in the final
report. Published runs refuse overwrite; development runs use separate folders.
