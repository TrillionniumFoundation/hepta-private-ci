# Independent R21 checkpoint review

The executor has exactly the intended functional edit: one owned checkpoint is evaluated immediately after the query's final propagation and reused for the query hash and persisted body's memory field. An AST comparison transforms the old function by these three edits and obtains the new function exactly. The two moved imports resolve to the same R20 implementations. Persistence, restoration, resume checks, action selection and the final fresh post-restore `checkpoint()` comparison are unchanged.

For the normal states produced by the current full, packed and anchored memory classes, the snapshot owns its probability lists and its copied integer operation counters. The checkpoint methods do not call `materialize`, advance time, increment counters or mutate arrays. The fields between the two original exports only read ordinary scalar data and append to executor-owned record/receipt lists. They do not update the actor or the owned snapshot. Persistence serializes synchronously, returns a separately parsed JSON object and does not mutate the original body. A single cached export therefore has exactly the bytes of both original exports in this profile.

This is an ownership and unchanged-interval argument, not structural immutability of a Python dictionary. Independent tests mutate the actor after export and mutate the exported snapshot, in both directions, for all three normal memory representations; neither mutation crosses the actor/snapshot boundary. A separate inherited counterexample is retained in `INDEPENDENT_COUNTER_SHAPE_LIMIT.json`: frozen R15/R16 `restore` accepts a rechecksummed malformed `operations.writes=[4]` value, whose nested list is shared by the shallow operations copy. Thus the alias-isolation statement is limited to normal internally generated integer-counter states. The cache edit does not introduce this validation gap or create a new actor mutation between exports. Hostile callers, concurrent mutation, side-effectful checkpoint overrides and future changed persistence implementations require a new argument.
