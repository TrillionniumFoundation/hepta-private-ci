# R21 snapshot reuse and local checkpoint admission

The executor takes one owned checkpoint after the final query-state advance and reuses it for the recorded state hash and persisted memory body. The intervening operations only construct public records, update a separate planner-work counter and read process time. They do not mutate owned memory. The inherited `persist` implementation only reads the body, performs file fsync, atomic replace, directory fsync and exact checksum/byte readback. The fresh checkpoint comparison after restoring memory remains unchanged.

This removes one duplicate export per completed query. It does not omit a restored-state verification or reduce the six storage acknowledgements. The V1 engineering run records actual export counts falling from18to12 per complete episode, exact wire identities and rejection of corrupted restored clocks. Its small mixed timing results remain V1 engineering evidence and are not transferred to V2 resource qualification.

Independent review found that the old memory restorers accepted arbitrary operation-counter JSON values and copied their map shallowly. Nested values can therefore remain aliased after an old restore and snapshot. The full-memory restorer also passed projection and method through without validating their types. The actual inherited counterexamples and V1 sources are retained.

All three generated memory schemas use exactly `propagations`, `observations` and `writes`, each initialized to Python integer zero and incremented by integer literals. They do not contain float CPU-time counters. V2 adds a local preflight before both new executor restoration sites. It requires those exact keys and nonnegative values of exact Python int type, excluding bool, float and nested JSON values. The full-memory schema additionally requires plain string metadata matching the caller's declared projection and the implemented expm method. Every inherited checksum, row-mass, clock, numerical-state and model-identity validation still runs afterward.

For admitted JSON memory states, the mutable arrays and anchor times are copied by the inherited restorers, the counter map is copied with immutable integer leaves, and the full-memory propagation metadata is a string. Generated snapshots consequently do not share mutable values with actor state. The snapshot object is an ordinary dictionary, treated as read-only inside the unchanged interval; the code does not claim that Python enforces dictionary immutability.

The old R20 source and inherited classes remain unchanged. Direct callers bypassing the new local wrapper retain their historical admission behavior. The new acceptance contract concerns this caller/restorer path and these three named schemas. It is not authentication, concurrent-owner fencing, machine power-loss qualification, mid-query external-provider exactly-once effects, a financial-kernel port or complete production admission.

V2 correctness controls are registered separately from V1 timings. Generated-state cold continuation, paid public history, malformed metadata refusal and preserved downstream validation must be checked at the frozen V2 source. No further full resource or efficacy campaign is authorized from V1's weak aggregate CPU result, and no original CPU/adoption gate is claimed passed.
