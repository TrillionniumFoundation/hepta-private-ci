# R21：查询快照复用与恢复元数据准入修复

**新调用端已拒绝畸形计数器及传播模式元数据，正常状态的冷恢复通过；查询快照减少一次重复导出。没有建立新的 CPU、内存或完整采用收益。** 历史 R20 的资源门失败保持原判。

## 实际代码修复

查询完成后，复用同一份 owned snapshot 的状态哈希和持久化 body。两次旧导出之间没有 actor 状态写入；文件 fsync、原子替换、目录 fsync、校验读回及恢复后的新 checkpoint 比较均保留。源差异在 `EXECUTOR_DIFF.patch`。

独立审核发现旧恢复器接受任意 JSON 计数器，并对 `operations` 浅复制；嵌套值能在恢复对象及快照间保留可变别名。R15 full 状态还会直接传递未验证的 `projection`／`method`。真实反例在 `INDEPENDENT_COUNTER_SHAPE_LIMIT.json`，旧源码和首次工程数据保留在 `development_01/executed_sources`。

源码检查确认三种已知 memory schema 的计数器都只有 `propagations`、`observations`、`writes`，均由整数零初始化并加整数常量，没有 CPU 时间浮点计数器。新 `admission.py` 在**初始恢复和每次持久化后恢复两处**先验证：键集合精确匹配、值为非负的精确 Python int；bool、float、列表、字典、缺键和额外键均拒绝。full 模式还要求普通字符串 projection 匹配调用端声明并属于既有合法域，method 为普通字符串 expm。

通过预检后仍调用原恢复器，原 checksum、概率质量、时钟、数值和模型身份检查未移除。旧 R20 文件及继承类没有修改；绕过这个新入口、直接调用旧类 API，仍保留其历史行为。修复范围是新 caller/restorer 路径，不能冒称整个历史 API 已改写。

V2 源码先发布并逐项读回：`df35a6d3869cbcafce8e15b9e40d4bcdd1164439`，manifest `9931324f4aa5c20daeb6b4340df7f14943680ed3c68655f8d3732583aa037112`，45 项输入身份固定。

- 独立 60 项准入、所有权及拒绝测试通过：三种正常状态、畸形 counter／projection／method、原 CRC／数值／时钟拒绝、实际冷恢复入口和持久化后入口的提前拒绝，以及恢复后再次篡改仍被最终 guard 捕获。原收据及压缩原始数据的 SHA256 已另行核对，未重复运行这 60 项。
- **117 个真实进程、54 个回复前 SIGKILL／冷恢复截点通过。** full、packed/block、anchored 三种 memory schema 分别运行 value、WAIT→READ、REFRESH→STOP；9 个旧 R20 参考语义记录与新正常状态输出一致。
- 标准库原始审核通过 3,078 项检查，验证 117 个保留状态的内外 checksum、精确计数器域、模式和概率行、付费动作历史及进程退出／fsync 记录；另外逐字节比较 9 组完整旧／新最终 wire。

这些是确定性正确性和准入验证，不是新质量、推理性能或采用实验。外部 provider 的查询中途效果、并发 owner、机器断电、网络和完整生产模型生命周期未据此资格化。

## 首次工程性能证据保持有限

V1 工程执行实际确认每个完整 episode 的 checkpoint 导出从 18 次变为 12 次；48 对 wire 身份相同，文件和目录 fsync 次数不变，四个被篡改的恢复状态均拒绝。独立测试另做 24 对完整 body／wire 字节比较及 8 项行为拒绝控制。

同一拟合种子、全部三模型／两表示／四 planner 的 24 组固定小样本中，384 次计时执行的旧／新 actor CPU＋准备合计为 **4.004133／3.938912 秒**，汇总减少约 1.63%。但组别 CPU 比为 0.911966–1.152725，内存峰值比 0.998790–1.000887，没有稳定的联合资源增益。

该阶段每组只有八个工程世界，且发生在 V2 准入加固前。其时间不得转移给 V2，也没有据此启动新的完整资源比较，更没有原 ≤0.90 CPU 门或 1,000 次复用采用声明。
