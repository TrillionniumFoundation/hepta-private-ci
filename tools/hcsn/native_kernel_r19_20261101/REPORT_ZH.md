# R19：实际 Rust 有限状态数值核

本轮把既有 R15 的 40 状态传播、Bayes READ／REFRESH、显式 RESET、缺测和首达／重复事件诊断接入真正执行算术的独立 Rust 二进制。**后继状态由 Rust 计算，输入不是 Python 后继重放带。** 金融参数到 Q 的构造仍在 Python，生产 owner 的实时数值回调仍未接通。

在远端源码冻结 `1bcc1b2c9a1d3deaf7cfe9cdc928cfe8c28ee3fc` 并逐 blob 核验后，命名空间 19110471 才生成正式确认的随机稠密初态。四个 HX 参数化模型和四个自由有限模型，共 64 个案例的八项原注册数值门全部通过：

| 检查 | 实际结果 |
|---|---|
| Rust 与独立 SciPy expm 的状态最大绝对差 | 8.88e−16 |
| 未来状态／存活状态最大差 | 1.18e−14／1.20e−14 |
| 首达概率／重复计数最大差 | 4.55e−15／1.41e−13 |
| 质量守恒最大差 | 1.04e−14 |
| 新进程保留数值状态后继续 | 64／64 精确一致 |

| 重复计数大于一／极小首达仍为正 | 48／32 项 |
| 具名坏输入及对应错误原因 | 14／14 拒绝 |

主确认包含 768 项原始因果操作；另执行 64 次后继恢复及 128 次时间切分进程。负例覆盖负边、非守恒矩阵、负时长、超范围时长、非有限数、非法 token、零似然、未知操作、时钟下溢、截断、错误 schema、负 emission、负 belief 和操作容量。没有概率裁剪、传播重归一化或 epsilon 补洞。首达与重复计数通过不同生成器积分，保留完整未触界后继；RESET 后下一次 PROP 使用完整调用时长。

另一位审查者只用标准库和独立两状态闭式解进行 7 项真实二进制检查，不导入本项目传播器或 SciPy；最大差 1.78e−14。该循环例在 t=20 的重复事件期望为 24.16，首达概率为约一，明确验证两者不同。独立源码审查与原始输入／输出保留在本目录。

正式确认原始 JSON 为 5,940,003 字节；483,425 字节 gzip 可恢复相同 SHA256。工程运行保留自己的原始输入、全部结果及执行源快照；工程之后仅改进校验器的具名负例和存储，并修正 flux 运算次序为 `p*(r/lambda)`，避免可避免的中间下溢。正式冻结和确认采用修正后的源。

四个继承源码文件的 Git blob 与固定基线逐一匹配，见 BASELINE_INPUTS.json。工程时的重建文件有额外末尾换行；随后按原远端身份恢复，记录见相邻 planner_r19 的 INPUT_RESTORATION.json。正式确认采用恢复后的准确字节。

确认计时记录父进程 0.954669 CPU 秒和已计入编译／数值／负例的子进程 1.628832 秒。两项是所记录区间的下界，不含最后版本查询和最终序列化、全部开发及独立审查投入；不是完整项目成本。工程与确认已记录 CPU 下界合计 65.515064 秒，其中工程参照默认使用多线程 BLAS，正式确认固定一个线程。没有据此比较 Python 与 Rust 的速度，更没有能耗结论。

本轮闭合的是声明的有限 FP64 数值原型与保留状态的冷进程续算。没有闭合原生金融核、连续自由边界、参数梯度、生产模型准入、实时 owner 数值回调、Q24／FP32、真实多模态、GPU 或焦耳。`production_activation=false`，原科学 D−B 和完整成本采用门保持未通过。
