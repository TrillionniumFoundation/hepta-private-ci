# Live finite numeric runtime contract

The owner receives a public model and an action plan. It never opens the provider's token catalog and does not receive precomputed posterior successors. A paid READ or REFRESH reaches a separately executing provider. Only its actual returned, durably recorded token enters the owner's Bayesian update. Numerical propagation, missing observations and reset successors are computed by the Rust numeric module.

The generic `HCSN_FINITE_40_V1` model carries 2,000 public numbers: Q, READ/REFRESH emissions and the initial prior. The additional `HCSN_FINANCIAL_3_V1 sigma liquidity maturity` profile carries only three physical parameters. It calls the native financial constructor in the adjacent `native_financial_r20_20261101/financial.rs` to compute the static H–X boundary and the finite R12/R15 generator, emissions and prior. No Python-constructed matrix is provided to that execution profile. This static finite parameterization is separate from a continuous financial/neural free-boundary solution.

`identify MODEL` is a read-only command that returns the model identity used by the plan, catalog, owner and provider. This identity covers the raw model input, every constructed Q/emission/prior FP64 bit pattern, an explicit numerical-semantics ABI and the checksum of the exact executable bytes. Replacing the executable or changing its ABI requires an explicitly new plan/catalog and recovery context. Existing state cannot silently resume under that change. The fingerprint is a trusted-local consistency check, not cryptographic authentication or a migration protocol.

The clock is an integer sum of plan durations in nanoseconds. PROP and MISSING evolve the full state for the complete duration. READ and REFRESH evolve for the complete duration, then condition on the returned receipt token. RESET first puts each content marginal into recovery phase zero and then evolves for the complete declared duration; recovery and any later events are retained. The initial public distribution is model input. These are finite synthetic task semantics.

The owner snapshot stores every posterior coordinate as the exact FP64 bit pattern, the applied cursor, integer clock, applied-prefix fees, a possible pending paid-action cursor, and every applied receipt. A pending action is durably prepared before its provider call. The provider atomically persists an effect keyed by the frozen run, model, plan, operation index, operation identifier, action and fee before replying. A retry returns that same receipt without creating another effect. The owner computes the actual successor and atomically commits it together with its applied receipt, cursor, clock and fee. An invalid numerical update terminates the owner while preserving the prepared action and actual provider bill.

Applied-prefix fees in an unfinished owner snapshot do not include a provider effect that has committed but has not yet been applied. That separately durable pending effect is bound by the owned pending cursor and frozen plan. An audit must account for it separately; only a completed owner has the same complete fee total as its provider ledger.

Every owner invocation opens a fresh loopback TCP connection and asks for the provider's current receipt prefix. Its retained applied receipts must agree exactly. The provider may be ahead by only the single currently prepared action. Missing owner state with existing paid effects, a missing or rolled-back provider prefix, changed model or plan, and incompatible receipt metadata fail closed. The checksummed provider catalog is also bound into the provider's durable snapshot, preventing a changed token catalog from silently replacing existing effects on restart.

One local file lock serializes invocations using the designated owner state path. The provider has its own local lock. Calls use stable public plan operation identities and fresh stream responses, without a PID-derived allocator or a cached SYNC response. The experiment assumes one trusted local filesystem and a trusted loopback endpoint. The FNV checksums detect byte corruption and bind records in this profile; they do not authenticate a provider or prevent deliberate collisions. Full paired-state rollback, malicious storage, machine power loss, cross-host ownership, authenticated transport and production model admission remain outside the qualified scope.

The fault windows are `owner_initialized`, `owner_prepared:i`, `owner_received:i`, `owner_computed:i`, `owner_committed:i`, `provider_effect_committed:i`, and `provider_reply_published:i`. A real marker is written and fsynced before a test process is killed. A restarted owner recomputes from its retained posterior and actual durable receipt; it does not replay an oracle after-state.

The numeric module derives from the immutable R19 finite uniformization kernel. Its positive series and admitted duration/rate limits are retained. That finite-model computation does not establish continuous financial optimality, a neural parameter gradient, a task-quality advantage over the same ordinary HMM, or an energy advantage.
