# R22 认证检查点与独立见证：限定范围通过

本轮在不修改R20 Rust数值所有者／provider源码及其精确ELF的条件下，实现Python标准库HMAC-SHA256认证的双角色检查点信封、真实独立TCP见证进程、持久单调记录链与恢复前准入。该组件提供单机受信任协调者范围内的真实认证／旧检查点拒绝证据，不是整个系统的生产安全资格。

科学源码、独立OpenSSL只读审核器及固定协议先在6bf394ba09633a250d0cb4521dd3285515361c1d发布并逐文件回读，再执行确认。SOURCE_FREEZE绑定七个源码／协议文件和30个既有输入；实际数值进程为R20精确ELF b30befcb76f00533029c60ce7a430a2b057bc152107625d7a5a4be3cd16f2798。PUBLICATION记录实际先后关系；回执文件是在执行后写入，不能将文件写入时间冒称为先前操作本身。

固定验证全部通过：

- 32个公开合成上下文，每个提交两个认证检查点并恢复最新状态。
- 80项拒绝控制，包括32次成对owner/provider回滚、32次字节篡改、旧CAS、重复JSON键、非有限值、布尔序号、错误密钥／域、密钥权限／符号链接、重复见证响应nonce、见证不可用、损坏见证记录，以及改变模型／计划／精确ELF上下文和检查点路径符号链接。
- 独立见证进程真实停止后重启，恢复全部68条已提交记录和单调tip；第三次启动对损坏日志拒绝。前两个见证进程按协议SIGKILL，退出-9；损坏日志进程退出1，都是预期控制。
- 在R20已存在的四个不同世界16/17/18/19中，对03/07/08/04故障快照加入认证准入后运行8个真实Rust进程。每个provider快照都已有实际付费效果；owner重新消费原收据，两个最终状态文件与同世界原不中断执行逐字节一致。它们不是四个新独立世界，也不提供新质量收益样本。

恢复先向见证发送认证的新nonce请求，验证响应nonce、context、MAC，再按见证返回的序号及摘要读取检查点。旧的合法信封即使同时恢复两个角色也无法与仍保留新tip的见证匹配。上下文绑定模型原始字节、计划、运行标识和实际可执行文件SHA256。只有同一精确ELF换位置的旧资格仍可使用；没有宣称任意跨版本升级。内部Rust原有状态／收据验证照常执行。

密钥文件须为当前用户所有的0600普通文件，O_NOFOLLOW拒绝符号链接；检查点和见证目录要求当前用户所有的0700目录。所有确认密钥都是源码可重新生成的PUBLIC TEST FIXTURE，不是运行凭据，也不构成真实部署密钥保密性证明。

必须保留边界：三个进程仍在同一机器。见证存储与密钥需要相对actor检查点独立保留；如果见证本身一起回滚，没有硬件或外部锚就不能据此检测。本实现排除活动的同UID恶意文件系统写者、密钥泄露和授权恶意签名者；后者仍可给旧语义状态签发新序号。真实多主机、断电／任意fsync中断、跨版本迁移和通用可用性均未验证。部分写入的新候选／日志可以拒绝服务并需要操作恢复；不能将fail-closed等同于所有故障下可继续服务。
