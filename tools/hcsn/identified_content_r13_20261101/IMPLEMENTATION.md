# R13 implementation semantics before confirmation

The registered unique deployment cost is the primary cost ratio. The all-candidate model-search ledger, equal-calibration-charge sensitivity, and inference-only ratio are additionally reported. A savings result attributable to reusing one calibration fit does not establish a faster kernel. All discarded ordinary candidate fits remain visible. CPU receipts include the entire child process using wait4, not just the optimization loop.

The dataset split is a fixed disjoint normalized-text split. The whole raw corpus is loaded and normalized for deduplication and partitioning; it is not hidden on disk. Confirmation text is never encoded or scored before actual READ. Raw text is encoded only at actual READ; unavailable recovery observations do not read or encode a message. The shared frontend is trained only on encoder_train. Core and validation examples are acquired from their separate pools. The nominal causal teacher uses the declared +0.5 smoothed core-training counts, including support for otherwise empty bins. It does not receive validation or confirmation emission frequencies. This teacher is not an exact posterior under heldout content shift. True class labels provide the actual heldout quality metrics; nominal teacher cross entropy is only a diagnostic.

The text frontend is shared and frozen before state-core learning. This is supervised content learning followed by differentiable state-core learning, not an end-to-end gradient through discrete text bins. The hidden CTMC and recovery labels are available only for offline training/scoring. Raw frontend coefficients and the trained physical model are shared across all value controllers. The generic HMM reference is intentionally equivalent to the analytic filter and receives the identical model.

The fixed 56-active-cell mesh and full HX reset boundary are used by training, model-based planning and the native batch actor. The native Gillespie engine separately executes paths of this same finite generator and preserves recovery events across process restarts. The finite matrix exponential is exact up to stated numerical error for the finite CTMC; spatial approximation to a continuous process is a separate claim. Native runtime uses f64. The compensated two-f32 numerical kernel is a separate optional precision investigation, not a silently substituted training backend.

The R12 tolerance-aware action resolver is applied at every R13 Bellman node and terminal/content decision. Continuation values therefore follow the same near-tie policy actually executed. Its tolerance boundary remains discontinuous; robust actions require a genuine value-gap/error certificate.

Development failures are retained: an unsmoothed nominal teacher rejected a validation bin absent from training, and an initialization-timing substitution caused a NameError before any decision. Both were corrected before confirmation. A failed no-overwrite frontend refit is retained; the successful deterministic refit matches the deployed weights exactly and supplies a full-process timing receipt.

Runtime accounting charges the whole evaluation-worker startup/import/global corpus/frontend/true-model setup to every counterfactual deployment, plus seed setup, amortized over 1000 episodes. Sensor and world construction are also charged; actual sequence benchmark generation and report serialization are evaluation overhead, measured in the global worker receipt. This is conservative repeated startup charging, not evidence that a production service must duplicate shared setup.
