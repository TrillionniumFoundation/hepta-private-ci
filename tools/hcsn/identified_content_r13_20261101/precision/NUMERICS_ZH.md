# R13 完整 HX 数值核：双 FP32 补偿后端

## 结论

新增的 **double-single 后端在每个实数上使用两个 FP32 分量**，完整保留 HX 的边界、权益、首达 F/G、债务及 5×10 一阶 Jacobian。它没有调用 FP64 数值核或 FP64 特殊函数作为隐蔽回退。原有单个 FP32 后端继续保留作为失败对照。

最终候选通过旧的 48 个记录与 33 个接缝点，并在冻结源码后通过 **128 个新 LHS 点、64 个固定 log-distance 压力点及 24 个资产边界点**。全部 297 个最终候选检查通过原值阈值 `8e-7` 和 Jacobian 阈值 `2e-5`。没有更改阈值，也没有通过缩小原参数盒排除失败点。[开发证据](DEV02_RESULTS.json)、[新样本汇总](FRESH_SUMMARY.json)

这解决了本轮有限检验中完整 HX 低精度算术路径的数值失败；**单个 FP32 的完整训练资格仍未通过**。double-single 每个数的有效载荷是 64 bit，且本 Python/NumPy 实现明显慢于 FP64。它不能被描述为 32-bit 内存节省、GPU 加速，或对整个连续参数域的统一误差定理。

## 精度身份与运算路径

| 层次 | 实际处理 |
|---|---|
| 输入 | 九个参数和状态一次量化为 FP32；参考也在这些已表示输入上评估 |
| double-single 中间数 | `hi` 与 `lo` 均为 FP32；四则运算、补偿、指数、对数、平方根、正态 CDF 近似都使用 FP32 运算 |
| 导数 | 同一两分量表示上的一阶前向切线；使用数学函数的解析导数，不使用有限差分或代理梯度来生成运行时 Jacobian |
| 输出 | 五个值和 5×10 Jacobian 舍入为 FP32 |
| 常数 | 离线以 mpmath 80 位构造并保存 hi/lo；JSON 的主机解析结果立即转换为已表示的 FP32 分量 |
| 导入 setup | 私有加载的原 R11 模块仍进行原有 FP64 常量与 `leggauss` 初始化；实际运行前节点被预存的两分量 FP32 常数替换，原特殊函数被本后端替换 |
| 审计 | 独立参考、误差统计、读数和文件生成允许 FP64/80 位；它们不是被测数值核 |
| 可选 checked wrapper | 只要执行 `mixed_check` 或 fallback，就显式标为含 FP64 的调用；不会记入纯 DS 执行 |

入口为 [ds_kernel.py](ds_kernel.py) 的 `evaluate(theta, state, coordinate=..., jacobian=...)`，输出结构与现有完整 HX 核一致。默认参数盒仍为 R11 的 LOWER/UPPER。`diagnostic_outside_box=True` 只用于保留的扩展检查，不构成训练域准入。

浮点舍入的 Jacobian 使用原 R11 的数值 AD 约定；不宣称一个离散量化器具有该经典导数。

## 为什么这次能够改善

原失败涉及大项抵消，特别是近违约边界下很小的权益与其导数、短期限下的大债务流量，以及接近相等根时的差商。仅把最终输出转 FP32，或仅补偿加法而保留普通 FP32 的 `exp/log/Φ`，都不能给出完整的精度路径。

[ds_math.py](ds_math.py) 对数值和切线使用两分量补偿算术。指数采用以 `ln(2)` 为单位的范围规约和固定多项式；对数采用二进制范围规约和固定奇次级数；平方根采用一次补偿 Newton 修正。`log Φ` 在有限区间使用离线高精度生成的固定 Chebyshev 系数，负尾部使用固定 64 层连分式，正尾部使用对称关系。全部运行时分量保持 FP32。

原 A5/A7 公式及其差商积分仍来自未改动的 R11 核。第一轮双 FP32 后端已通过 80/81 个旧点，但 `m=1e-4, x=.001` 的权益流动性导数误差为 `2.2611410893769168e-5`，超过原阈值。该失败、完整输出、Jacobian 与当时源码都保留在 [DEV01_RESULTS.json](DEV01_RESULTS.json) 和 `DEV01_*.gz` 中。

最终候选在近边界使用同一权益 ODE 的 Green 积分。设

\[
\tfrac12\sigma^2 E''+a\sigma^2E'-rE=-f(x),\qquad E(0)=E'(0)=0,
\]

则

\[
E(x)=-\frac1{z\sigma^2}\int_0^x
\left(e^{\eta(x-y)}-e^{-\gamma(x-y)}\right)f(y)\,dy.
\]

代码以 `expm1` 组合两个指数，并用生存概率与 `G-1` 的稳定增量计算现金流。积分限于 `eta*x≤1` 的有界区间，使用固定 24 点 Gauss 规则及已有平滑拼接；其余区域继续计算完整 A7。**没有把这个会包含增长指数的初值 Green 积分强行推广到整个半轴**，也没有把有限数值积分称为新的闭式解。[green.py](green.py)

这一修改将剩余短期限误差降至约 FP32 输出舍入的量级。另修正了补偿整数幂中最后一次不再使用的平方，消除无用中间值引发的溢出警告。旧失败的归档没有被删除。

## 验证协议与结果

先用旧 48 个记录和 33 个接缝点开发，再写入 [FRESH_PROTOCOL.json](FRESH_PROTOCOL.json)，冻结 [FROZEN.json](FROZEN.json)，随后才生成 [FRESH_INPUTS.json](FRESH_INPUTS.json)。新 LHS 种子为 `2026110113`，九个参数仍位于原 R11 盒内；波动率、流动性、期限和状态维使用已登记的对数映射。没有失败后替换抽样。

压力点覆盖长／短期限、正／负漂移、低／高波动、零／全恢复及固定边界上下位置。资产边界由独立高精度参考生成，再量化为实际 FP32 输入；因此没有让被测边界误差定义自己的真值。

误差计算保持

\[
\max_i \frac{|\widehat y_i-y_i^{\rm ref}|}{\max(1,|y_i^{\rm ref}|)}.
\]

Jacobian 同样逐元素归一化。独立参考继续是原 R11 的 80 位字面 A5/A7，导数采用 `1e-18` 与 `5e-19` 两个对称步长。新 216 点在存储的 FP64 参考读数上半步差为 0；这表示两次参考导数在报告精度内一致，不是宣称任意精度下恰好相等。

| 检查集 | 单个 FP32 通过 | 双 FP32 通过 | 显式 mixed64 通过 | 双 FP32 最大值误差 | 双 FP32 最大 Jac 误差 |
|---|---:|---:|---:|---:|---:|
| 旧 48 记录，最终候选 | 见 R12 保留记录 | 48/48 | 本轮不重测 | `5.344e-8` | `5.855e-8` |
| 旧 33 接缝，最终候选 | 3/33，R12 | 33/33 | 本轮不重测 | `5.099e-8` | `1.152e-7` |
| 新 LHS128 | 103/128 | 128/128 | 128/128 | `5.747e-8` | `5.056e-7` |
| 新 log 压力 64 | 36/64 | 64/64 | 64/64 | `5.754e-8` | `5.652e-8` |
| 新 asset 边界 24 | 13/24 | 24/24 | 24/24 | `5.754e-8` | `2.529e-7` |

新样本中最大 DS Jacobian 误差位于 `lhs_52` 的债务对流动性导数，实际 `773.9595336914062`，参考 `773.9599249734414`。单个 FP32 的最坏新结果位于负漂移配置的资产边界：边界误差改变了所处区间，Jacobian 归一化误差达到 `4.60998508611232`。这说明仅检查某几个前向数是否接近，不能代替边界与梯度验证。

完整新结果采用无损 gzip 保存：[FRESH_RESULTS.json.gz](FRESH_RESULTS.json.gz)。三个后端在这 216 点均无非有限结果、无拒绝、无运行警告；单个 FP32 的失败是精度未通过，不能被异常计数掩盖。

另对 `exp/log/sqrt/logcdf` 的固定扫描与分支附近输入做了独立 80 位检查。最大归一化误差分别为 `1.934e-13 / 2.872e-15 / 1.746e-15 / 4.378e-14`。[PRIMITIVES_DEV02.json](PRIMITIVES_DEV02.json) 这是有限扫描，不是全域逼近误差证明。

## 实测成本与训练诊断

下列为实际 CPU 串行循环，共 64 个单元，状态重复 `.001,.1,1,2`，包含每个单元完整构造成本，未缓存或向量化。环境为 Python 3.12.14、NumPy 2.3.5、Torch 2.10.0+cpu；CUDA 不可用。

| 后端 | batch64 前向秒数 | batch64 值+Jac 秒数 |
|---|---:|---:|
| 单个 FP32，R12 candidate | 0.3221 | 0.3961 |
| 双 FP32，R13 candidate | 23.7417 | 24.4406 |
| 显式 mixed64 | 0.1062 | 0.1248 |

双 FP32 当前实现的主要用途是验证“不借助 FP64 核也能达到原精度要求”的路径；当前 CPU 实现不具备性能优势。没有测量或推算 GPU 吞吐，也没有把 batch64 的结果当作 256/1024/4096 的实际测量。

保留的 12 步输出拟合使用 FP32 Adam，拟合完整 HX 输出而非内容任务。双 FP32 与 mixed64 都下降 `97.725473%`，耗时分别为 `28.9180s` 与 `0.1443s`。它验证可执行的梯度优化，不是内容模型质量或统计显著性证据。[COST_AND_FIT.json](COST_AND_FIT.json)

## 可计算诊断与显式回退

[guarded.py](guarded.py) 与冻结 DS 内核分开。它检查值与 Jacobian 的有限性及边界、权益、债务、首达概率不变量，可显式请求 mixed64 比较。对照差超过原门槛一半时回退 mixed64；一半门槛是保守选择规则，不是修改验收阈值。

`mixed_check=True` 无论是否回退，都会执行 FP64，元数据始终标记 `mixed_executed=True`。差值是可计算的失效诊断，不能用两个近似实现的相互一致冒充严格误差上界。离线检查新 216 点时，单个 FP32 有 129 点被该保守规则接受、双 FP32 有 216 点被接受；没有观察到接受后参考不通过的记录。这是对本批记录的确认后诊断分析，不是新的前瞻试验。[GUARD_EVIDENCE.json](GUARD_EVIDENCE.json)

另外实际保留两个超出冻结 `x≤2` 检验范围的诊断例子：

| 输入 | 观察及处理 |
|---|---|
| 基准参数、`x=81` | DS 的拆分乘法中间值溢出；显式 mixed64 回退成功，权益约 `1.016e37`，仍可由 FP32 输出表示 |
| 基准参数、`x=90` | 连最终权益都超出 FP32 输出表示范围；mixed64 再转 FP32 也溢出，wrapper 拒绝返回不合格结果 |

这些例子说明双 FP32 并未扩大 FP32 的指数范围，且中间运算也有额外范围限制。没有通过静默 FP64 计算把它们记为 DS 通过。

## 适用范围与交付

原参数盒、原误差门槛、原失败和参考源码均保留。结果支持在已检验的参数／状态范围内，把双 FP32 作为完整 HX 的可选后端进一步评估；不支持把单字 FP32 宣称为整个原盒内可训练，也不支持“所有连续输入都已证明正确”。在资产违约边界，原常数风险扩展的非 C1 性质仍存在，不能靠数值精度修复改变该数学事实。

当前主内容模型和 native 传播可以继续采用已有稳定 FP64 模型。低精度核结果不改变连续扩散离散化、状态截断、可识别性或任务质量的各项独立验收。

`check_chain.py` 另提供可选后端的接线诊断：在不修改 R12 有限单元的条件下，以 DS 金融输出接入 FP64 reset/Q/matrix exponential，再反复 Bayes 更新和计算内容／读取成本／答题收益损失。12/64 步的 DS 与 FP64 一阶梯度最大归一化差分别为 `2.877e-8 / 6.399e-8`；考虑量化的双步长 secant 最大误差为 `7.170e-4`，通过原 R11 的 `.01` cast-secant 检查规则，完整 HX Jacobian 的 `2e-5` 规则没有改变。该检查的结果单列为 [CHAIN_GRADIENT.json](CHAIN_GRADIENT.json)；它不是整个 recurrent 模型都为低精度，也不替代 R13 的独立内容实验。首次检查在结果序列化阶段因 NumPy 布尔类型报错，失败记录保留；只修正检查脚本的 JSON 类型转换后，重跑并保存了完整结果，冻结内核未动。

复核入口包括 `development.py`、`fresh.py`、`cost_and_fit.py`、`check_guard.py` 和 `check_chain.py`。生成脚本拒绝覆盖已有证据。`FROZEN.json` 标记新样本前的实际源码；最终文件清单与哈希由本目录 manifest 汇总。全部变更仅在 R13 `precision/` 内，R11/R12 源码保持不变。
