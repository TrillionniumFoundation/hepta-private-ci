## 实际事件

为了确定地见证所有所需事件类型，执行前固定候选 horizon 与 seed 顺序，取首个出现触界、恢复、复位和内容切换的路径。全部尝试保留：256 秒的 seed 131101 有 8 次复位但没有内容切换，seed 20261101 有 2 次复位但没有内容切换，seed 17 有 17 次复位和 2 次内容切换，故选用 seed 17。没有执行更大的 2048 秒候选。

选中路径共有 **11,721 次真实跳变、17 次触界、17 次恢复阶段推进、17 次复位、2 次内容切换**。第一组具体事件如下。每个 block 有 56 个 active cell 和 R1/R2 两个恢复态，因此内容 1 的 active0/R1/R2 分别为 58/114/115。

| 时间 | 跳变 | 语义 |
|---:|---|---|
| 0.053784761136522134 | 58 → 114 | 内容 1 的 active0 触界，进入 R1 |
| 0.6295525063764607 | 114 → 115 | R1 → R2 恢复阶段推进 |
| 0.7794258195151884 | 115 → 64 | 复位到 active cell，保留内容 1 |
| 1.602407738900205 | 115 → 17 | 再次复位，内容 1 切换为内容 0 |

独立脚本对全部跳变核对 `Q[from,to] > 0`、时间严格递增、相邻状态连续、模型版本一致及恢复/内容语义，并从事件轨迹重新计算计数。没有从 posterior 质量推算或伪造事件次数。

## 真实恢复与拒绝

整段 256 秒路径用一个新 CLI 进程执行。另一条执行路径分别启动三个真实的新进程，推进 `0.5`、`63.5`、`192` 秒，中间从磁盘 checkpoint 恢复；三个片段的事件列表拼接后与整段事件列表完全一致，最终 checkpoint 的字节也完全一致。

最终 checkpoint SHA-256 为 `5357998dcbd25c1b707f14ad1fa8921bff7f8ef58835cc4cd5d0a12630966ce1`。所有进程输出的 model identity 都与上表精确 Q/版本身份一致。错误的期望版本被拒绝；将 checkpoint 中一个 Q 浮点位改动并重新计算文件 checksum 后，仍因 model identity 不匹配被拒绝。两次拒绝均未写新的 checkpoint。

该见证补齐了“真实已学模型 Q → 原生事件 → 磁盘 checkpoint → 新进程恢复”的直接链条。较早 fixture 的 `reset_x=.325` 只证明同族模型的执行；不能用它冒称已经验证过所有真实 fit，此处特意绑定一个具体冻结 fit。

## 结论边界

这是选取确定性路径的事件覆盖和重放见证，不是无偏事件频率估计、Monte Carlo 与 posterior 的统计收敛证明或新的任务确认实验。256 秒超过父实验网格上域截断证书的 29.4 秒 horizon；本结果验证的是同一有限 Q 在该时长的执行语义，不能把 29.4 秒的连续模型误差证书外推到 256 秒。

本次没有修改 Q、网格、金融核、动态库、事件 CLI 或既有确认结果，也没有激活生产默认路径。所有摘要为可复现绑定与损坏检测，不代替生产认证及 witness 权限。
