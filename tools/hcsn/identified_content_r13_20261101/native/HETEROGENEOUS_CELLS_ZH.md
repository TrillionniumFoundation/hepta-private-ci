# 不同参数、不同 Q 的多 cell 成本与内存

## 结论

本次补测的是 1、16、64、256 个具有不同 `sigma`、流动性参数和 `Q` 的 cell。每个 cell 从完整金融核边界构造固定 116 状态的生成元，独立准备三种时间的 transition，再执行八步传播加观测。它补上了此前“多行共享同一个 Q”的批量基准不能回答的扩展问题。

**全部数值检查通过，但完整初始化、准备及八步在线工作的 native CPU 成本仍是合法 cached NumPy 基线的 1.74–2.20 倍。** 当前库每进程只允许 128 个 live model，第 129 个明确返回 `work_limit`。256 cell 的成功测量使用两个独立 worker，各持有 128 cell；两种后端采用同样分片，不能把它描述为单进程已支持 256 个常驻模型。

主 CPU 与精度证据在 [heterogeneous_cells/RESULTS.json](evidence/heterogeneous_cells/RESULTS.json)，程序为 [heterogeneous_cells.py](heterogeneous_cells.py)，源 SHA-256 `bbc08ba9df5fa83eb450bdff9ce5c13304cf869929e47f2447bd5686023d7fe2`。三次重复的每个原始 worker、完整子进程计费及输入身份全部保留。没有修改本轮冻结源、动态库或确认结果。

## 输入、计时与公平参照

参数按固定 index 公式分布于预注册的 `sigma∈[0.15,0.4]`、流动性参数 `∈[0.005,0.04]`，其他金融参数保持固定。每个 cell 调用冻结的 `contract.model_terms(prices=False)`：完整 He–Xiong 五输出/Jacobian 核产生边界，随后生成 R13 有限体积 `Q` 与 prior。没有使用简化的占位边界，也没有把所有 cell 的 `Q` 合并共享。

这里 `prices=False` 明确不计算每个网格点的价格/任务 payoff；本项测量金融边界到生成元、原生传播及观测，不包含文本编码、训练、规划树或相互连接的神经网络通信。每 cell 的 likelihood 是固定随机种子产生的非负数值输入，用于性能与数值一致性测试，不是新任务质量确认。

每个模型缓存 `dt={0.15,0.45,2.1}` 的三个精确 transition，共八步更新。两个后端都构造不可变模型、执行合法性检查、缓存全部三种 `P` 并保留规划器导出矩阵；NumPy 允许直接引用其 cache 数组，native 的 API 导出是另一份数组。全部参数、Q、prior、likelihood 的输入摘要逐 shard 一致；每个设置内的 Q 摘要均互不相同。

四个规模、两种后端、各三次重复，共 24 个配置执行、30 个新 worker。使用单线程 BLAS；256 cell 的两个 worker 并行，CPU 按两个进程相加。每个配置有真实进程 user+system CPU 回执。初始化、准备、在线三个阶段均计时，解释器启动/导入及数值核验也分别保留，不能只挑选在线阶段作为全流程结果。

异质单行更新的在线阶段 native 在此设置下更快，但准备与初始化抵消了八步内的节省。此前同 Q 大 batch 的 NumPy BLAS 比较是另一种负载。实际是否受益，取决于每个 Q 在失效前重复使用的时长、batch 组织和参数更新频率；本次没有实测更长复用周期的 break-even，也没有用八步结果外推 GPU 或大规模网络训练速度。

所有 24 个配置的最大 posterior 差为 `4.107825191113079e-15`，通过统一的 `3e-11` 阈值。NumPy 比较使用相同 float64 输入及合法 cached `expm`，没有要求它每步重算矩阵来制造 native 优势。

## 缓存增长与真实 RSS

116×116 的 float64 transition 占 107,648 字节。三种时间每模型占 **322,944 字节**，所以独立模型数为 `M` 时，仅三个内部 dense cache 就需要 `322,944×M` 字节。本测试还保留 planner 导出：native 额外保存三个独立数组，NumPy 的 planner 列表引用已有 cache。

| cell 数 | 两后端各自内部 P cache，MiB | native 独立 transition payload，MiB | NumPy 独立 transition payload，MiB |
|---:|---:|---:|---:|
| 1 | 0.307983 | 0.615967 | 0.307983 |
| 16 | 4.927734 | 9.855469 | 4.927734 |
| 64 | 19.710938 | 39.421875 | 19.710938 |
| 256 | 78.843750 | 157.687500 | 78.843750 |

这些是可逐数组核对的 payload 字节数，不包括 Q 副本、先验与工作缓冲区、metadata、allocator 或解释器。避免不必要的 planner 导出复制是后续可测量的工程方向，本轮没有修改冻结接口来取得这个优化。

首次基准发现环境的 `/proc` 挂载位于外层 PID namespace。`os.getpid()` 返回内层 PID，直接读取 `/proc/<该数字>/status` 会取到其他进程或空值。首次结果中的 `baseline_rss_after_imports_bytes`、`execution_current_rss_bytes`、`sampled_peak_sum_worker_rss_bytes` **无效，不应引用**；`resource.getrusage` 和 `wait4` 的 high-water RSS 不依赖该路径，原有 CPU、payload 字节和精度结果不受影响。

没有覆盖或重写首次程序/结果。新增 [heterogeneous_memory_audit.py](heterogeneous_memory_audit.py) 复用完全相同的数值 worker，只把 worker RSS 改成 `/proc/self/status`，并通过 `Pid/NSpid` 握手把外层 PID 交给父进程采样。每个设置做一次内存复测，同输入与精度再次通过；源 SHA 为 `edcf34cb09d9efda2d2afb824699724ef0c0ae7ad9736fb58492052c3fffcc9d`，回执在 [memory_corrected/RESULTS.json](evidence/heterogeneous_cells/memory_corrected/RESULTS.json)。这次内存复测没有替换三次重复的 CPU 中位数。

|---:|---:|---:|
| 1 | 281.004 / 285.801 | 281.188 / 285.109 |
| 16 | 286.078 / 289.027 | 282.387 / 286.973 |

每个 worker 导入后的 RSS 已约 269 MiB；256 cell 的两个 worker 因此共同承担约 536–538 MiB 的依赖栈基线。表中的“整体采样峰值”每 5ms 采样一次，包含计时后核验与序列化。RSS 合计会重复计算共享 resident page，并非唯一物理内存或严格的连续时间峰值。内核 `ru_maxrss` 与 `/proc` 的记账/采样时刻也可能有小差异；证据同时保留两者，不将这些观测数当成生产资源上界。

## 上限与后续范围

真实 256-model 单进程尝试在成功创建 128 个模型后，于第 129 个返回 `work_limit`，已存在的模型仍可合法传播。两 worker 方案没有放宽这个限制。异质规模测试前后的所有冻结源、fit 和动态库哈希仍匹配。

运行时 cgroup limit 为 8 GiB，开始时已使用约 6.84 GB。请求的 256 cell 已完整测量，本轮不再尝试可选的 1024 cell：按当前实现至少需要八个独立 worker，依赖栈与独立缓存都要额外预算。该选择不是 1024 cell 的失败实验，也不意味着已经支持该规模。

本结果量化了独立 Q 的准备成本、每模型内存线性增长以及当前进程上限。它没有覆盖相互耦合 cell、模型每 tick 更新、高维训练反传、自然数据到达、GPU、生产 checkpoint 吞吐或生产准入。若改变缓存布局、导出所有权或模型上限，应在新的实现身份下重复相应测量。
