# R20 implementation contracts

The new executor is shared by the legacy R16 planner, R18, R19 and R20. Every query from zero through five performs the same storage sequence: serialize complete owned memory and public completed-action/fee history, flush and fsync a temporary file, atomically replace the current checkpoint, fsync its directory, verify checksum and exact byte readback, then restore owned memory. A successful query-boundary call returns only after that sequence. Neither hidden targets nor scorer rewards are persisted into the policy memory. A restarted owner recomputes past scores without repeating completed actions or fees.

The profile has a trusted single writer and local Linux filesystem APIs. It validates process-death recovery after completed query commits and three atomic-replace process-death windows. It does not establish mid-query external-provider exactly-once effects, concurrent-writer fencing, network authorization, machine power-loss behavior or a complete production model lifecycle. Those distinctions matter even when all six query commits and restores pass.

The recovery controls kill real subprocesses after completing each query but before returning a reply. Fresh interpreters resume each checkpoint and compare the complete eventual semantic output to uninterrupted execution. Separate wrappers call the real `os.fsync`, inspect each actual file descriptor and check the alternating six regular-file and six directory calls. Receipt counters in performance records are additionally checked against source and those syscall probes; counters alone are not treated as syscall evidence.

`BatchOwnedPlanner` inherits R19's freshly allocated in-place posterior normalization and exact C-layout guarantee. Its changed helper performs the same R18 batched finite/nonnegative/row-sum predicates, then releases the merged validation buffer before projection outputs are allocated. Block projection keeps every original matrix operand shape, projection and positive-support check. Full projection retains C-contiguous inputs to subsequent BLAS operations. No check, tolerance, clipping rule, action tie or matrix reduction is weakened or changed.

The before/after predicate cases include one and three frames, finite rows, NaN, infinity, excessive negative entries, wrong row mass, wrong width and the inherited tiny-negative distinction between full and block state. Exact value comparisons use immutable inputs across all eight frozen fitted seeds. Legacy owner comparisons verify that adding every-query restoration preserves the original finite task's actions, fees, rewards and state hashes on the recorded fixtures.

The formal resource campaign has eight fitted seeds and 64 new owner worlds per seed. All three fitted core models and both representations share those worlds; all four planner variants receive identical six-query persistence work. There are 512 unique worlds and 3,072 model/representation world uses, rather than 3,072 independent worlds or 1,000 actual uses per fit/group. Old query2-only timings are not pooled with this new storage contract.

CPU includes each actor's actual persistence and restoration plus separately added model-copy preparation. Matrix and wrapper-cache preparation inside the actor is already included. Wall throughput is a serial actor rate and excludes separately recorded preparation and common world generation. Allocation peaks are eight warmed executor calls per variant/group, not every timed call or per-arm process RSS. The complete child maximum RSS is reported separately for the common process containing all variants and retained records.

The original CPU threshold remains at most 0.90 of R16 for every fit/group. The newly declared joint resource gate requires R20 CPU no greater than R18 and peak allocations at most 0.90 of R18 in every fit/group. Actual failures remain failures; no pooled average overrides a failed fit/group. Recorded historical investment and all newly measured costs are retained without extrapolated reuse or nested-timer addition. Shared planner gains do not establish HX-exclusive D−B, real multimodal quality, GPU or joule advantages.
