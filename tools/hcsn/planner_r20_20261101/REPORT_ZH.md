# R20：实际六次查询提交与八拟合种子资源验收

本轮修复了 R19 只有第三次查询写盘的缺口：**每次查询均实际执行临时文件 fsync、原子替换、目录 fsync、校验读回及状态恢复；冷进程与付费动作历史恢复通过。CPU 采用门仍失败，不能用平均节省或内存下降改判。**

## 固定源码和共享执行合同

正式源码 `86e9128aa7498343bddc4a2435435af72d39de85`，manifest `a5bfa4585170b2650e7cf56c15c587d8bc3ae94a0df26b0def7993b6b42f69a2`，先发布并读回，再开始运行。R16、R18、R19、R20 四个实现全部使用同一新的六次查询提交／恢复 executor，费用、状态、动作与时间语义相同。

R20 将与 R18 相同的概率检查批量执行，并在投影输出分配前释放验证合并数组；保持 R19 的新建 joint 原地除法及精确 C 布局。原容差、支持检查、矩阵形状和动作平局规则未变。详见 `PROOF_AND_SCOPE.md`。

八个原冻结拟合种子、每个 64 个新世界，三种模型和两种表示构成 48 个 fit/group。512 个独立世界在各模型／表示／实现间共享；共有 12,288 次计时执行，另有 1,536 次八次预热内存诊断执行。**每个 fit/group 的实际复用数是 64，不是 1,000。**

- 原 CPU 阈值失败 **1/48** 组：`151101 / hx / anchored`，R20/R16=1.050461457。
- 联合 CPU／内存门失败 **10/48** 组；全部是 CPU 失败。最差 R20/R18=1.271132678。

## 实际冷恢复及付费历史覆盖

正式冻结后，**107 个真实进程**覆盖 48 个查询提交后、回复前 SIGKILL 案例，另有三个临时文件 fsync／替换／目录 fsync 窗口；新解释器恢复到相同最终语义记录。八个完整参考执行通过真实文件描述符包装器记录六次文件和六次目录 fsync，不能只凭自报 receipt 计数作结论。

独立审核发现该正常 value-policy 参考世界只产生查询 5 的一次 READ。原记录与该限制保留。随后另行前瞻冻结辅助源码 `cb40ef17a0c27250a8fa6445b6c761b7044cc8d1`（manifest `12b92be88363ae7461064fe19877b720e03d67c02963189b467dbe0dcd254823`），主七个源码文件均未变。

辅助 **52 个进程**验证两个公开脚本策略：每次查询 WAIT→READ，或 REFRESH→STOP；full／anchored 两种表示的全部查询截点，共 24 次回复前 SIGKILL 和对应冷恢复。所有查询都含真实收费观察；从查询 0 起，已完成的动作／费用历史在后续继续执行前精确保留。独立审核通过 984 项核对及全部 48 个保留状态。它是动作覆盖控制，未并入 value-policy 质量或性能样本。

这些结果限定于可信单写者、本地 Linux、已完成查询的边界。未建立查询中途外部 provider 效果的恰好一次执行、网络、并发 owner、机器断电或完整生产生命周期。

## 独立核验与完整成本

开发检查通过 4,608 个精确值比较、192 个旧 executor 语义比较与 28 个输入控制。独立审核另覆盖 864 个稀疏／恢复／只读拟合模型案例、672 个输入控制及实际行质量边界。正式数据的标准库审核通过 692,160 项核对，独立资源审核通过 449,472 项；原恢复通过 1,386 项，并独立检查全部 96 个正常查询状态。10 个主冻结文件、三项辅助冻结文件、35 项主输入及 38 项辅助输入身份全部匹配。

实际 actor CPU＋模型复制准备总计：R16 72.974345 秒，R18 57.718733 秒，R19 58.983339 秒，R20 56.615738 秒。R20 相对 R16 实测节省 16.358607 秒，低于既有 R18＋R19 投资下界 384.991471 秒；仅扣历史投资，净值已为 -368.632864 秒。`full_investment_gate=false`，没有线性放大复用次数来宣称回收。

正式资源完整子进程 CPU 344.301457 秒、壁钟 544.788684 秒；共同子进程最大 RSS 78,184 KiB。正式恢复与辅助动作控制另分别花费 40.672646、20.759500 子进程族 CPU 秒。包含开发及所有独立审核后，本轮已记录非重叠 CPU 下界为 492.602677 秒；详见 `COST_LEDGER.json`。actor／cache／准备等嵌套计时未再次加到其完整进程收据中，父进程启动、来源传输及元数据等仍有未计量范围。

发布辅助收据时的 ENOSPC 是单列的元数据写入失败；清理后、辅助运行前成功写回并核对。它未改变已完成 48 组的源码或结果，事件记录在 `PUBLICATION_RECEIPT_IO_FAILURE.json`。
