# R16：补偿 FP32 金融神经算子的独立数值验证

本阶段把完整 He–Xiong 金融核推进到**双字补偿 FP32 的有限数值验证通过**。
每个金融标量和每个切向分量使用两个 FP32 字；它不能被称作普通单字
FP32，也没有替代原有 R14 科学准入或生产网络准入。

原始源、冻结协议、完整成功与失败记录、独立审阅和复现入口均位于
[capsule/README.md](capsule/README.md)。该封存目录逐字节复制，数值源未
经过重排或格式化。外层 CI 适配器和本说明不改变其中的冻结候选。

## 1. 实际结果

两项原门槛保持不变：数值误差不超过 `8e-7`，完整 Jacobian 误差不超过
`2e-5`；每项误差都除以 `max(1, abs(reference))`。每行检查五个输出
`[boundary, equity, F, G, debt]` 和九个参数加一个状态坐标的十列导数。

| 实现与证据                 | 通过行数 | 完整参数案例通过数 | 最大值误差 | 最大 Jacobian 误差 |
| -------------------------- | -------: | -----------------: | ---------: | -----------------: |
| 原普通 FP32                |  136/432 |               0/18 |  0.0162873 |            61.8149 |
| 新普通 FP32 代数候选       |  344/432 |               0/18 | 1.35219e-5 |         0.00325252 |
| 双字补偿 FP32，原开发矩阵  |  432/432 |              18/18 | 5.66508e-8 |         9.43964e-7 |
| 同一冻结候选，独立 V1 验证 |  512/512 |            128/128 | 5.71866e-8 |         7.18919e-6 |

普通 FP32 新候选还有两个旧通过点回退，失败证据保留。原开发矩阵的
432 行只包含 419 个不同输入，不能称为 432 个独立案例。独立 V1 在
执行前冻结候选、协议和 128 点 Latin hypercube 清单，随后每点检查
四个状态；所有 128 点均被独立域检查接受，512 个输入均不同，没有
丢弃失败点或改变门槛。

V1 实际覆盖 36 行 default 分支、128 行近边界 Taylor、128 行混合区和
220 行原 A7 分支；34 个参数点进入小 B 分母区域，76 个进入小 A 分母
区域。参考使用 80 位十进制精度的原公式，步长减半差异最大为
`4.7788e-59`。候选源码在整个执行前后保持一致。准确数据见
[V1 汇总](capsule/R16_HOLDOUT_V1_SUMMARY.json)和
[独立复核](capsule/tmp_r15_compensated_independent_review.json)。

这些结果验证已声明的有限输入集合。完整参数盒的统一误差界、极端
指数范围、每个参数点的精确边界状态以及实际训练收益尚未获得证明。
再次使用 V1 只能计作回归；未来修改候选须重新冻结并使用新的独立验证。

## 2. 数学含义与 BP 的边界

候选保留原有自由边界、equity、debt、首次触及函数 F/G、分母接近零时
的求积表达、近边界 Taylor 和混合方法。改动的是其算术与基本函数。
失败的单字正项重排没有被混入通过的补偿候选。

这里的 F/G 是首次触及相关函数，不能未经证明就当成另一个满足同一
smooth-pasting 条件的 vanilla put。独立复核确认 equity 在边界满足
`E(0)=E_x(0)=0`；F/G 在 default 一侧为常数，而另一侧具有非零状态
导数，debt 也有右侧斜率。因此完整双通道并非全局 C1。

当前 AD 返回对应分支上的数学导数，不是浮点舍入映射的导数。保留连续
数值和可计算的分段导数有利于实现训练接口，但不能据此宣称已经消除
所有阈值处的不光滑性、证明训练稳定，或得到一个已验证的多层脉冲网络。
独立审阅还检查了名义尺度齐次性、default 回收值和坐标链式导数。

双字算术仍有通用范围限制：`sqrt(0)` 产生 NaN，以及 splitter 对
`1e35 * 1e-10` 溢出的反例均被保留。它是受控金融算子的实验实现，
不是适用于整个 FP32 范围的通用数值库。

## 3. 成本没有隐去

下面是相同量化输入、完整边界构造、五个输出和十列 Jacobian 的实际
Python CPU 计时。18 个原参数案例各取三个状态；每种模式和条件先做
完整 54 次预热，再做一批 54 次测量。所有请求均得到有限输出。

| 模式                    | 每状态完整求值 | 每三个状态复用一次边界，含构造成本 |
| ----------------------- | -------------: | ---------------------------------: |
| 原 FP64                 |       2.339 ms |                           2.358 ms |
| 原普通 FP32，数值未准入 |       2.562 ms |                           1.965 ms |
| 双字补偿 FP32           |     219.005 ms |                         175.510 ms |

补偿原型完整求值成本约为 FP64 的 **93.65 倍**，普通 FP32 的
**85.49 倍**。本阶段没有测得 CPU 加速。固定常量准备和导入不计入
这次内核计时；单批测量也不是延迟分布、整网训练或 GPU 能耗证据。
下一步编译实现须把各精度基线放在同一编译框架中比较。
完整原始读数见 [CPU 收据](capsule/R16_CPU_COST_V1.json)。

## 4. CI 如何判定

封存的审计器是 create-only 诊断写入器；即使数值检查失败，它们完成
诊断后的退出码仍可能是零。新增 [verify_regression.py](verify_regression.py)
对每个值和每列导数重新计算误差，要求行数、案例数、输入顺序、有限性、
参考收敛和冻结身份全部满足原契约，再决定 CI 成功。没有把脚本执行
完成当成数值合格。

[CI_GATE_REVIEW.json](CI_GATE_REVIEW.json) 保留了有效完整结果通过，
以及缺行、NaN、误差超限、缺导数列、显式失败、放宽门槛、非有限基本
函数误差和缺案例全部被拒绝的检查。补充审阅还关闭了空身份表、改动
参数或状态、行次序变化，以及同时改写参考值和候选值的漏检路径；
15 个无效结果都被拒绝，冻结 V1 参考值与输入身份均绑定到原始档案。
新 CI 会重算 701 个基本诊断、
432 行开发回归和 512 行冻结 V1 回归，并保留完整输出。

## 5. 对总体 HCSN 结论的影响

本阶段为高抵消金融公式提供了一条可行的数值实现路径。普通 FP32
准入、低成本实现、生产神经元状态归属、全模态和长程语义优势、GPU
与焦耳测量仍需独立完成。R14 已打开的负确认结果和普通 HMM 同矩阵
等价关系继续保留；本阶段没有改变这些结论。
