# R20：实际原生金融参数到有限算子的构造

本轮 Rust 从 sigma、liquidity、maturity 三个参数直接计算静态金融边界，以及 40 状态 Q、两种 emission 和 prior；不需要 Python 提供这些矩阵。六个其余金融参数沿用 R12 固定值。新 owner 的 financial profile 已接入同一构造器，联合执行／恢复另有独立正式 campaign。

源码先发布到 `aebb58339dda8010888569d78d29cfdb226bb712` 并按 Git blob 回读，随后才生成正式命名空间 202011017 的参数与 CDF 随机点。8 个角点与 64 个新参数抽样、129 个 CDF 参数和 7 个负例全部完成并通过原数值门：

| 检查 | 正式结果 |
|---|---:|
| 边界对独立 80 位 mpmath 直接表达式的最大绝对差 | 2.8422e−14 |
| 全部 Q／emission／prior／边界对未改动 R12 的最大差 | 1.1653e−12 |
| 生成器行质量差 | 1.7764e−15 |
| 正态 CDF 相对差，含 −12 的正尾 | 3.6063e−15 |
| 合法案例失败数／出域拒绝数 | 0／7 |

原生 B 函数使用光滑导数积分；80 位参照使用独立直接差商；原 R11／R12 是第三项有限模型参照。CDF 通过正尾积分计算，没有概率 floor、裁剪或重归一化。完整源、输入、结果、参照与误差保存在确定性 gzip 中，原始 SHA256 见 SUMMARY.json。

完整正式子进程（含导入、编译、数值参照、全部 native 调用、原始输出及 summary 序列化）实测 2.589815 CPU 秒，内部 parent／child 段不再相加。未计量的初始 smoke 编译、依赖定位、首轮启动失败及全部审查／运输仍不构成完整项目成本。第一轮 verifier 因 mpmath 未在默认路径而未启动；随后首轮数值运行完成但 NumPy bool 导致 summary 序列化失败。该轮完整 raw、部分 summary、执行源及失败说明全部保留，未覆盖或把费用计零。
