# R19：保持精确布局，减少瞬态分配

本轮把 R18 的规划瞬态分配降至原基线附近，完成每个部署组 1,000 次实际执行。**相对 R18，分配峰值下降约 29.4%–34.8%，CPU 增加约 5.0%–6.7%；计入既有投资后的采用收益仍未通过。**

## 修复与保留的真实失败

新实现复用刚创建的 joint 数组完成后验除法，逐帧验证，移除仅为验证而合并的数组。第一版错误保留非 C 布局，在零费用控制上把 READ 值从 0.6852519168216207 改成 0.6852519168216206；该失败、源码和诊断保留在 `development_02_layout_failure`。修正版用 `np.ascontiguousarray` 保持原全状态投影的 C 布局，再进入相同形状的矩阵乘法。

修正版通过 1,152 个直接只读输入数值比较和 12 类概率控制；独立审核另通过 288 个拟合模型数值案例及 1296 项布局／所有权／控制核对。标准库原始审核通过 876,114 项检查，另一独立审核通过 522,090 项记录核对；冻结的四个 Git blob 与全部 17 项源码／输入哈希匹配。查询行为一致仅是本研究有限实现内的执行证据。

本地取回的 15 个继承文本文件原先各多一个 LF；移除该单字节后均恢复至既有冻结 manifest 的精确 SHA256。原取回字节和改正记录完整保留，见 `INPUT_RESTORATION.json`；没有修改原数值源码。

## 全部投入仍未回收

六组实际 actor CPU＋准备总计：R16 86.914634 秒，R18 59.670000 秒，R19 63.254522 秒。相对 R16 实测共节省 23.660112 秒，仍低于 R18 已记录的优化投资下界 141.098189 秒；仅扣除这部分旧投资，净值已为 -117.438077 秒，因此 `full_investment_gate=false`。这是实际 1,000 次／组的结果，不是线性盈亏平衡外推。没有把当前比较实验的全子进程 CPU 再叠加到这些 actor 成本中。

正式确认完整子进程 CPU 223.288790 秒，壁钟 339.199916 秒；包括导入、全部世界生成、三个实现、内存诊断和归档。父进程导入、最初失败控制等仍有未计量范围，详见 `COST_LEDGER.json`；嵌套计时不重复相加，记录总额始终是下界。

## 冻结协议勘误与开放项

冻结 `PROTOCOL.json` 错写了“all query boundaries fsynced”。真实继承源码只在 `query==2`（第三次查询结束）执行磁盘 fsync／恢复；其他查询只有内存中的状态哈希。保留原冻结文件，勘误在 `ERRATA.json`，`literal_all_query_fsync_requirement_met=false`。性能结论仅适用于实际 query2 检查点口径，不能称全部查询边界持久化通过。

当前没有建立解析核心独占 D−B、八拟合种子推广、完整项目投资收益、GPU／焦耳或真实多模态采用。生产激活与全部 blocker 闭合均为 false。本优化同样惠及普通 HMM。
