# R9：五条验收的执行结果

本轮完成了连续积分修复、价值头训练与独立确认、Rust 内容及概率状态统一执行、流式状态实现和成本核算。**没有把五项验收标成全部通过。** 最有判别力的结果是：现有任务中，固定公共动作后，改变神经边界只改变事件费用，不改变质量或调用数。这个任务结构尚不能证明“边界为了有价值的计算而发放”。

实验开始时核验的基线为 `333fb9b036b80cf5d892aed222a1aac7aad80e53`。工作过程中上游把此前恢复的 R8 native 源码、成本及证据正式发布到 `00b94d54a9b85f285298d1a964777bdecfa85385`。本轮在交付时保留该新父提交；所有实验的原始来源、冻结权重和失败记录均有独立摘要，未把随后到达的文件冒充实验开始时已存在的来源。

这里的“预先登记/冻结”指运行前写入并绑定本地协议、源码和权重摘要。本轮 Git 提交在运行后交付；没有宣称具备公开托管的事前预注册时间戳。

## 1. 任务价值：修正动作值，但边界目标仍未闭合

新增 `CostFactoredHead`，精确扣除已知当前动作和延迟成本，仅拟合 continuation 的增量；STOP 使用精确锚点。三类模型均使用原任务、相同公开信息、32 隐藏单元、1,091 参数和 2,400 次迭代上限，各训练五个 fit。训练条件为八个原名义 contract 加八个扩展 contract，另预先列明八个留出参数组合。

原 673 个公开输入继续使用未改 R8 头，其他输入实际运行新头。这个预先登记的兼容路由同时适用于三个 family，没有通过拒绝业务制造好结果。单独的新头、不经路由的结果也保留；不能把名义域完全不回退解释为新头泛化能力。

共计 612.207 CPU 秒训练：解析 first_passage 299.335 秒，clocked 301.886 秒，direct 10.935 秒。direct 的重复潜态行及标签严格相同，因此可在保持同一加权损失和迭代上限的情况下消除重复计算。

### 边界的真实干预结果

固定公共状态 oracle 动作，改变 `raw_boundary`，并运行普通无 cell 对照，共 5,120 组、15,360 次实际执行。质量、task_return 和调用数逐对完全相同；全部净效用变化来自事件收费：

\[
\Delta U=-0.0002\,\Delta\mathbb{E}[N].
\]

| 干预 | 期望 events | 净效用 | 正确率 | 决策次数 |
|---|---:|---:|---:|---:|
| 原边界 | 0.817941 | 0.653603599 | 0.8442125 | 3.003875 |
| raw boundary 增加 5 | 0.345640 | 0.653698060 | 0.8442125 | 3.003875 |
| 普通公共策略，无 cell | 0 | 0.653767188 | 0.8442125 | 3.003875 |

有限生成元的 Fréchet 收益梯度与三档中心差分核对，最细步长的最大差约 8.05e−10。当前收益梯度推动减少发放，不能证明边界创造质量、发放后业务价值或实际计算调度收益。这个反例针对当前有限任务，不是对全部脉冲网络的否定。[干预协议和结果](value/diagnostics/RESULTS.json)

完整证据包括 76,800 对策略比较、25,600 个基础 episode 键、153,600 次策略执行；全部 raw 重新核算、3,600 次分层真实重放零行为差。重复起点导致前向质量流漏计的问题由独立审计抓出并修复，失败 attempt、源码、amendment 和未改的 15 个权重均保留。最终结果只认 `confirmation02`。[独立审计](value/audit/RESULTS.json)

## 2. 连续事件：三类实质积分修复

两个生产文件的改动为新增 91 行、删除 14 行。两段边界组合改为标准化第一段 killed endpoint 坐标，并显式解析第二段的窄过渡层。正漂移 renewal 改用首达 normal 坐标；额外加入 Erlang 恢复分位点，避免极短恢复又产生一个漏采样的过渡层。

低噪声 CTMC 的 `15,31,63,127,255` 网格仍被局部方差条件拒绝。次数尾界也不被当成梯度尾界。上述模型限定于标量 Brownian、两段仿射边界和独立 Erlang 恢复；非正漂移极端恢复、共享噪声、耦合细胞、任意非线性边界仍未覆盖。[完整修复及原始证据](dynamics/README.md)

## 3. 原生执行：同一 owner 和真正进程恢复已验证

冻结 FullHX 的文件读取、特征构造、binary32 递推和 binary64 ridge solve 已进入 Rust，与概率状态、时钟、复位、不应期、RNG/剩余 hazard、模型身份、内容结果和计数使用同一个 acknowledged owner/checkpoint。Python 仅发送公共请求和测量，NumPy 只用作独立离线参照。

原生概率传播仍是已冻结 R8 的五态有限链；本轮修复的 Python 连续积分尚未替换这个 Rust 传播核。

真实 Rust 进程退出并启动新进程的 24 对恢复全部匹配；总计 48 runs。48 个唯一名义包 observation 全同，准确率 100%，最大 logit 差 `3.57628e−6`；另 8 个长度及不规则时间 probe 的最大差 `1.31130e−5`。这是端口一致性及固定 fixture 结果，不是开放语言任务的质量证书。

原仓库 `just fmt` 与真实 nextest 经 `just test` 的 11 项测试通过。构建使用当时核验后的缓存 rlib、匹配编译器和当前源码重新编译；没有把它写成 fresh Cargo build 或整个 Hepta 仓库测试通过。交付时独立复核发现 86 个历史依赖缓存中 84 个已不在原路径，当前缓存复建门保持未通过。已验证的 owner/test binary 另行归档，供同环境重放；这不替代干净源码重建。[构建状态](integration/NATIVE_REBUILD_STATUS.json) · [可执行文件身份](integration/NATIVE_EXECUTABLES.json)

## 4. 状态与成本：压缩有效，普通精确模型同样实现

流式实现维护两个充分统计量、补偿误差与计数，每条流的数值状态 40 bytes（不含共享参数、Python 对象及 JSON 元数据）。它符合固定潜在 drift、未来路径条件独立的原任务；不能直接当成已存活吸收路径或变动未知 drift 的完整滤波状态。

四个原确认条件、三个冻结 fit 及普通精确滤波器的动作均一致；相对 Torch 最大概率差 `1.36e−6`，同 partition 的 JSON 恢复精确，分块方式改变的最大概率差 `4.44e−16`。独立审阅发现的累计器、计数和 logits 溢出问题已修复；原 v1 源码与证据保留，v2 全部 14 个异常/恢复检查通过。这里的 JSON roundtrip 不含磁盘持久化，不能替代 native 的真进程恢复结果。

上游发布了更强的 NumPy 实现后，本轮增加同后端比较：四个 regime、两个 family、三种 batch、三种负载，720 个原始计时样本，32 次查询使用不同 horizon。对原 NumPy 的 16,384 个预测，最大概率差 `3.25e−7`、动作全同。

解析实现的 2048 条批量、32 个不同 horizon 查询提速约 `1.75–2.55×`；批量在线更新查询约 `1.36–1.53×`。单样本在线更新反而慢约 `1.49–1.61×`。普通 exact 的对应批量收益几乎相同。全部结果及回退均保留，不能用旧 Torch 较慢或普通对照未优化制造解析优势。[流式报告](streaming/README.md)

价值头另补完整启动和保留内存：R8 加载约 3.143 ms，R9 双头及 support 加载约 6.785 ms；support 离线构造约 26.485 ms。当前留出 first_passage 相对 direct 的精确净效用差均值 `−.000238`，区间 `[−.018064,+.017589]`；推理每 session 多 `.513 ms`，并有更高训练成本。未证明二者等价，也没有解析方案占优的证据。[完整成本](value/deployment/RESULTS.json)

本环境无可用 powercap/NVIDIA 设备能耗计量，所有 energy 字段为 `null`。CPU 秒和写入字节均未冒充焦耳。

## 5. 接下来需要改变的具体接口

当前真正缺失的是统一的任务语义。需要让 `task.py::step` 和 `finite.py::targets` 的 posterior、任务时钟、pending observation、remaining budget、deadline、动作及实际费用进入 `Owner::interval/commit` 与 `Pair/content::State`。策略必须在内容读取之前以同一公共信息决定 READ/WAIT/FIRE，而不是先解码再生成与调用无关的物理信号。

R7 value 的 30 维输入与 native 的 5 维 `causal_input` 尚未统一。直接把两个已验证模块接到一起，不能继承当前证据为新的端到端证明。新的验收必须在同输入、同预算、同普通对照下，同时测真实解码次数、质量、动作 regret、完整净效用以及恢复；这项闭环不在本轮完成声明中。

本轮没有激活生产，也没有改写旧失败来制造“新神经元已优于普通方法”的结论。各 lane 的冻结源码、权重、原始记录、失败记录、成本及来源摘要均随分阶段提交交付。
