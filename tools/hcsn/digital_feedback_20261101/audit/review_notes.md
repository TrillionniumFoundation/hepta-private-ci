# Cold publication, raw artifact and cost review

This is a code/provenance review performed while the six-fit development batch was running. No independent-confirmation outcomes were read. It does not rerun scientific tests or certify outcomes. The reviewer authored `diagnostics.py` and `quality.py`; their checks remain author verification. Review of orchestration, archive, freeze, training and statistical code was performed by a separate contributor from those implementations.

## Current source and attempt custody

At the in-progress inspection, development fits 1103, 1109 and 1117 had STARTED records whose complete source maps equaled the LAUNCH map and the then-current local bytes. Their attempt directories contained 6, 5 and 5 completed candidate-attempt records respectively. Fits 1123, 1129 and 1151 had not yet started. No conclusion that all 90 attempts were complete was drawn from that snapshot.

`study.sources` verifies every inherited source identity in the historical `SOURCE_FREEZE.json`, then hashes every top-level Python file in the new stage and the selected protocol. Thus changing a scientific module while a worker is running is detected at the worker's final source recheck. The archive and freeze implementation are also top-level Python files and belong to this identity. Adding a review document or an independent auditor under `audit/` does not change the running scientific source map.

Every candidate call writes its model, training receipt and separate attempt record when it returns. A returned candidate can remain scientifically invalid or CPU-noncompliant; it is not deleted. Thrown exceptions receive an attempt with error/traceback and elapsed call/persistence CPU. A worker-level exception receives FAILED, when the worker folder exists. The external parent records exit status and process CPU with `wait4`, including terminated workers. A SIGKILL cannot produce a Python traceback, so its exit status, partial files and logs are the available evidence.

Before formal model publication, the manifest requires all registered fit process receipts, source-matching STARTED/FINISHED records, and the exact required per-fit artifact set. It checks actual fit/model/arm identities and the returned-model hash. The confirmation loader checks the exact all-fit custody maps, exact per-fit required file set, bytes, start/finish provenance, process receipt, remote verification receipt and model-manifest identity. Any missing formal arm must block its contrast; no success-only subset is an accepted replacement.

## Label and teacher boundary

The content generator writes hidden labels to evaluator files and writes public metadata and packet digests separately. Those evaluator paths are not input features. Real READ completion opens the packet through the frozen content adapter. `FactorRuntime.predict` receives only public causal metadata, completed-observation state and the realized finite-cell index. It receives no evaluator label or oracle object.

The common teacher uses the confusion matrix fitted only from training calibration packets. Teacher belief/Q supply training targets and diagnostic scores. They are not policy inputs. Actual episode labels are read after terminal execution, and `study.evaluate` adds the evaluator label only after `run_episode` returns. Raw behavior and training probe records may contain evaluated outcomes for audit, but `encode_rows` reads only the declared input, probability, legality and supervision fields; it does not consume those outcome fields as features.

The independently fitted ridge decoder consumes training-cohort posterior targets and actual paired features. It must be published with all models before confirmation generation. Test-group absence or missing training support remains null; confirmation pairs cannot fit or recalibrate a decoder. The decoder target is the fitted-law posterior, not a newly observed binary label and not an information-theoretic optimum.

## Raw archive and cold restoration

`archive.pack` preserves original file bytes in a deterministic gzip/tar stream, splits it into bounded base64 Git files, and records stored/decoded part hashes plus the whole archive and each member's size/SHA256. `archive.restore` checks those identities, verifies member-set equality, rejects duplicates, absolute paths, `..` traversal and non-file members, refuses existing targets, then checks each restored member's bytes.

The network publication procedure still has to verify the actual remote manifest/blob and every transport part; a local `all_blob_hashes_verified` boolean is not independent evidence by itself. The receipt must identify the same model-manifest hash used by the seal. All required model/data/receipt files must be members of the published archives, not just locally hashed paths. A later cold restoration and comparison against the sealed raw-file map is the decisive delivery check; this code review has not performed that future check.

Two operational boundaries remain. First, restore should target a newly created empty directory: the helper rejects unsafe archive names, but does not establish that a pre-existing destination has no symlinked ancestors. Second, absolute training-cohort folder strings are preserved as raw evidence. Byte-identical restoration does not automatically relocate those paths for a new training/replay workspace. Confirmation model loading uses the recorded model/receipt bytes and generates new worlds; complete historical rerun may require an explicitly documented path mapping.

## Cost accounting and runtime limits

The per-candidate timer includes model/optimizer setup, behavior encoding, feedback collection, head optimization, rollback, export and receipt assembly. It excludes common data/content preparation and serialization after return; those are real costs in the surrounding worker. The per-fit maximum-minus-minimum check and individual 8±0.16-second contract are separate from training validity and task quality. Actual update counts and CPU failures remain visible.

The authoritative whole-worker CPU is the external `wait4` user+system measurement. The internal `FINISHED.whole_stage_cpu_seconds` starts after Python/module imports; confirmation's internal timer also starts after model/provenance loading. These internal values are useful attributions and must not replace external whole-process cost. Conversely, adding candidate CPU, episode CPU, shared preparation, oracle diagnostics or internal FINISHED CPU to an already inclusive wait4 worker total would count work twice. Parent orchestration, archive/restore, publication, independent analysis and earlier failed development processes are additional disjoint costs only when separately measured. Historical package installation, network transport, all past research effort and device energy are not covered by the present worker timers.

The reference Bayes path still performs its own oracle work, and common teacher diagnostics may be prepared outside individual episode timers. Worker CPU includes those operations. A narrow per-episode Bayes timing is not an optimized deployment-economic reference.

Python, NumPy and Torch versions are recorded, and scientific Python/content-weight files are hashed. Binary runtime/library bytes, full BLAS dispatch identity, CPU power state and energy are not completely frozen by those records. CPU-bounded training deliberately selects a count of completed updates determined by measured host work; an identical cross-host retraining checkpoint is not promised. Saved-model byte identity and deterministic finite-law replay have narrower meanings than cross-platform training reproducibility.

These criteria are pre-formal qualification gates, not a retrospective selection of DEV002 models. The original DEV002 protocol/results remain unchanged.
