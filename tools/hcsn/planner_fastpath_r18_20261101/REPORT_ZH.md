# R18：保持动作与状态精确一致的Bellman规划加速

**本轮新增闭合的是受限有限模型中的规划器在线CPU门：六个value策略组均省22.3%–36.2% CPU，动作和状态记录精确一致。** 同时，所测峰值分配增加21.6%–23.5%；研究投资摊销、完整模型采用、解析核心独立收益和生产资格仍未闭合。

## 固定身份与执行范围

最终源码先在远端 `43bed3e4821bfe967e7f9e830e4559b62436daa0` 发布并逐文件读回，再打开namespace180831。SOURCE_MANIFEST.json绑定44项源码、协议、旧模型和收据。八份原拟合、生成矩阵、发射、奖励、费用、动作优先级与答案argmax规则保持原值，没有重新训练。

正式confirmation_02执行8 fits×2域×8世界，即128个共享owner世界；HX、free和同矩阵普通HMM，各测full/anchored与value/fixed READ_REFRESH，共1536组、三个实现合计4608次执行。原实现、无缓存forest、带缓存forest轮换执行顺序；每arm有独立law/cache。

所有查询的动作、答案、目标、token、费用、效用、逻辑belief_evaluations和检查点哈希精确相同；既有query2、即第三查询结束后的实际磁盘快照字典也精确一致。没有以数值容差改判任何动作差异。快照范围仍不是每个中间状态、冷进程或挂起动作恢复。

## 实际优化与失败保留

基线192次真实执行剖析显示，choose/values约52%，project约34%（有重叠），而expm约9.6%。规划器重复的概率检查与递归调度比单独矩阵加速更值得处理。

最终forest保留每个原始BLAS操作的数组形状和浮点运算顺序，只集中检查同一层的概率行，复用相同的一步传播，并避免终态负无穷表分配。固定缓存只保存与law、dt有关的原始transition/readout，不缓存动作或未来观测。归一化检查仍为同样的2e−11绝对门槛；只是把rtol=0、参考值为1的通用allclose写为等价的abs(sum−1)<=2e−11，同时保留FP64转换、有限性和原负值资格。证明与适用条件见PROOF_AND_SCOPE.md。

开发V1曾直接拼接数值矩阵，2304项值比较的最大差仅3.33e−16，却改变53个零观测费近平局动作，因此明确失败并保留。V2/V3改为保留每个原矩阵形状；最终V4b在2304个固定值案例中逐位一致，192个实际执行开发案例也全部精确一致。直接helper的FP32转换差异由独立审计发现后补回原始asarray(dtype=float)，没有放宽误差门。

先发布的V3正式确认confirmation_01虽保持全部行为一致，但free/anchored成本比约0.9094，未通过≤0.90的六组联合门。该轮全部源码、原始数据、43.279104 CPU秒和失败结论保留；最终V4b换新命名空间确认，不与旧轮结果混合。

## 完整计量与摊销边界

最终正式确认的完整八个child为 **37.370500 CPU秒**，包括解释器/import、owner生成、所有模型/候选、准备、检查点、输出与退出。内部actor合计32.109599秒，arm构造0.161042秒；其余5.099859秒完整保留。若将共同余项按各候选尝试均摊，六个value组比率仍为0.6686–0.7945；这是事后分摊假设，不是另一次测得的逐arm进程成本，也不改注册门。

基线剖析、所有开发版本、失败正式确认、最终正式确认及内存诊断的互不重叠已计量child CPU下界为 **141.098189秒**。重复出现的旧开发档已逐字节核对，按同一执行计零增量。父监督器、发布与部分独立审计/账务CPU未完整计量，因此仍不是完整项目/部署成本。
